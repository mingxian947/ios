Coruna 与 DarkSword 的 MITRE ATT&CK 战术映射与检测覆盖缺口

编制日期：2026-10-18 数据来源：MITRE ATT&CK Enterprise / for Mobile 矩阵、Google Project Zero、Citizen Lab、Amnesty International（Pegasus 项目）、iSight Partners、Lookout、MDM 厂商遥测实践 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

ATT&CK 的价值不在于"给攻击打上编号"，而在于它强制你把攻击拆成可独立观测的行为单元，然后暴露你的观测盲区。

对 iOS 商业间谍软件使用 ATT&CK 时，绝大多数组织会撞上同一个陷阱：矩阵里的技术 ID 是 Windows 世界长大的，直接套到 iOS 上做红蓝对抗，会得到一张"全绿"的假安心地图——每个战术都有对应技术，每个技术都被标为"已覆盖"，但没有任何一个数据源真正落地。

本文做三件事：

  1. 把 Coruna 与 DarkSword 的完整攻击链逐战术映射到 ATT&CK 技术，并标出两者在同一技术上的实现差异（同一 ID 下的不同行为工件）
  2. 明确 ATT&CK for Mobile 与 Enterprise 矩阵在 iOS 上的适用性边界——哪些 ID 可用、哪些是硬套、哪些攻击行为根本没有对应技术
  3. 从映射出发做检测覆盖度核算：以"iOS 端真实可用的四类数据源"为约束，算出每个战术的可检测上限，从而把防御预算投向少数几个真正有信号的位置

核心结论：iOS 上 ATT&CK 的可检测面集中在"网络侧"与"投递侧"，而不是"主机侧"。把它当成 Windows 那套 EDR 驱动的检测项目来建，是资源错配。

在开始映射前必须先建立"ID 可信度分层"，否则后续所有表格都会被误读。

必须承认的矩阵空洞："靠注入既有系统进程存活、重启即消失、磁盘零写入"这一整套驻留模型，在 ATT&CK 里没有恰当位置。它是 DarkSword 的关键特征（#45、#47），也是持久化战术检测清单对其完全失效的原因。

实践建议：给"无持久化驻留"在项目内部自定义一个 ID（如 IOS-RESIDENT-01），并将其与"持久化战术全部为空"绑定成一个正向信号——持久化痕迹缺失本身可以是检测线索，而不是"没中"的证明。

这是 iOS 防御的主战场。原因很简单：网络侧是少数攻击者无法通过架构手段消除工件的地方——即使完全无持久化、无文件、清除所有痕迹，流量必须发生（除非使用完全离线触发）。

网络侧检测的工程要点（与 #46、#48 一致）：

日志保留期是最常被低估的成本：一旦攻击者走无痕驻留路线，事后取证只有网络与备份两条时间机器。DNS/SNI 日志保留 7 天的组织，对 #45/#47 类攻击等于完全失明。

4.9 影响（TA0040）

两套体系均不投入。唯一需保留的映射是内部自定义 ID 用于"设备锁定/数据破坏"类变体（如 T1479 Device Lockout），以及供应链中断场景。窃密型攻击中把它列为空是正确的，不要为了表格美观补 ID。

结论表：

#结论
1iOS 上 ATT&CK 覆盖度应按数据源约束算上限，不按技术清单算完成度
2高可检测战术只有两个：C2 与外泄——防御预算的 60% 以上应投在网络元数据
3执行/提权/防御规避三战术在架构层面不可批量观测，应作为"接受盲区"而非"待补需求"
4持久化战术的覆盖度取决于对端是哪套体系：对 Coruna 型可测，对 DarkSword 型不可测
5崩溃遥测是唯一有批量性价比的主机侧信号，但它是滞后指标，不能进实时告警逻辑
6无 ID 可用不等于无风险：无持久化驻留、PAC/SPTM 对抗、0-click 消息入口都是矩阵空洞

与锁定模式的联动：若采用 #48/#57 讨论的锁定模式（含禁用 JIT 的强缓解），映射表会发生变化——初始访问战术的成功率下降，执行战术的攻击面收窄。这是少数能真正改变攻击链成本结构的防御动作，也是"移除型防御"优于"检测型防御"的实证位置。

8. 总结

#结论
1ATT&CK 用于 iOS 的第一步是给技术 ID 分可信度档位（A/B/C），而不是补全表格
2Coruna 与 DarkSword 在战术分布上高度相似，差异集中在持久化与防御规避两列
3T1070 相同 ID 对应相反实现（清除工件 vs 不生成工件），检测策略不能按 ID 复用
4iOS 上唯一可批量观测的高信号战术是 C2 与外泄，防御预算应向网络元数据倾斜
5执行、提权、防御规避三战术是架构级盲区，应明确"接受"而非"投入补齐"
6攻击链中至少四个关键环节在矩阵里没有恰当 ID，需项目内自定义并保持版本化
7日志保留期是映射表能否兑现的先决条件，不是运营细节

一句话总结：对 iOS 间谍软件而言，ATT&CK 的正确用法是"用攻击链的战术分布告诉你在哪里根本测不到"，而不是"用技术清单告诉你已经覆盖了多少"——两套主流体系的差异恰好落在同一批不可观测战术上，因此防御的真实竞争力只存在于网络元数据的深度与保留期里。
