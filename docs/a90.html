iOS 漏洞按攻击者起始位置分类：从"预认证远程"到"物理接触"的六道门槛

本文是防御视角的分类框架与处置方法，不提供可利用代码，不包含任何投递构造、链条拼接或可照做的攻击操作。面向需要判断"我该防谁、先防哪一段"的个人用户、企业安全负责人与咨询场景。

1. 为什么还需要这根轴

系列里已有的分类方式各答各的问题：

轴回答的问题出处
系统层错在哪个子系统#2
缺陷类别错成什么形态（UAF/越界/逻辑误用…）#81
组件与通路打的是谁（驱动、App 配置、锁屏、分发、智能输入、侧信道、支付）#82–#89

这三根都不回答"攻击者出发的时候手里已经有什么"。而现实里决定损失的恰恰是这个：同样一个内存越界，出现在预认证远程通道和出现在只有本地低权限进程能碰到的辅助服务里，风险差三个数量级。

按起始位置分类的价值就在这里——它把"漏洞有多严重"换成一个可以直接问客户的问题：你面对的是哪一档对手，他需要几步才能站到你设备面前。

2. 三个维度合成一个位置坐标

单独说"远程"或"本地"太粗，用三个维度定坐标：

  • 投递距离：预认证远程 / 认证后远程 / 近场无线 / 本地进程 / 物理接触。
  • 交互要求：无需交互（0-click）/ 需要一次交互（1-click）/ 需要被诱导完成多步 / 无需交互但需已解锁。
  • 落点权限：受限沙箱进程 / 非沙箱系统服务 / 内核外特权 / 内核 / 硬件与固件。

三维压成六档，从最贵到最便宜：

档起始位置交互典型落点需要设备已有漏洞吗
P0预认证远程（可任意送达内容）0-click媒体/字体/消息解析等服务是，且通常需要链条
P1预认证远程1-click浏览器与 WebKit 栈是
P2认证后远程 / 账户侧接管无需设备交互备份、云同步、MDM、钱包加卡、配对不一定（见 #89 结论）
P3近场无线（蜂窝/Wi-Fi/蓝牙/NFC 半径内）0-click 或后台基带与无线固件是
P4本地低权限起点（已装 App、已连电脑、共享设备）无需沙箱边界、内核接口是，需逃逸+提权
P5物理接触（锁屏态或解锁态）无需数据保护等级、启动链、配件视状态而定（#84）

一个 CVE 在这根轴上的坐标，和它在另外两根轴上的坐标是独立的。举例：#38 那次字体解析问题，在 #2 上是"媒体/文本解析子系统"，在 #81 上是"越界写入"，在这根轴上是 P0——三个描述都对，但只有 P0 这个描述告诉你"任何人都能把这个字节流送到你手机上，不需要你做任何事"。

3. 每档的门槛由什么抬高

不同档位的成本曲线不一样，抬门槛的机制也不一样：

档把门槛抬起来的东西抬完之后剩下的现实入口
P0BlastDoor 独立沙箱、送达即解析的面收敛、锁定模式关停部分自动处理（#52/#34）能进 BlastDoor 的解析面仍有价值，链条要额外一段逃逸
P1WebKit 硬化、GOT/PAC、进程隔离、站点隔离钓鱼仍是主变量：这类链条的第一段常常是人不是机器
P2账户侧因子强度、设备清单治理、eSIM/号码约束因子弱的地方（短信验证、运营商线上补卡）与不修账户只修设备的错配（#89）
P3基带与无线固件的更新周期、协议层特性开关版本长尾：老机型与新固件的支持周期不同步（#72）
P4沙箱策略、entitlement 收紧、SPTM/TXM 与 PAC（#27/#41）已装恶意 App 或已越狱设备是既成事实的起点，只能靠分发治理（#86）
P5数据保护类与解锁次数策略、DPUI/配件限制密码强度与设备四态决定损失范围；启动链老芯片是不可修补项（#84/#88）

一个容易被误读的点：P2 和 P5 往往不需要任何设备漏洞。这两档上"对手能力"的评估口径要从"他有没有 0-day 预算"改成"他能不能拿到你的合法流程"。

4. 谁买得起哪一档（预算视角）

对手类型现实可负担档位说明
国家级/采购商业框架P0–P5 全档只有 P0/P3 需要买或自建链条
商业间谍软件客户P0/P1/P2单目标高价值，P0 一条链能用数年（#15 的版本覆盖讨论）
企业犯罪与诈骗团伙P1/P2/P4钓鱼 + 账户接管 + 滥分发，几乎不打内存漏洞
跟踪骚扰与家庭暴力场景P2/P4/P5共享账户、已装 App、短时可及的设备（#86 的 stalkerware 结论在这里同样成立：账户优先）
opportunistic 盗窃P5（且多为已解锁态）目标不是数据，是设备本身 resale 价值

这张表的用处是把预算讨论从"要不要防 APT"变成"我的处境落在哪两三行"。绝大多数咨询场景的真正风险行是 P2/P4/P5，而这三档恰恰不需要 Apple 出补丁，也不需要用户买昂贵工具，需要的是账户与设备状态治理。

5. 三步定位法（可直接执行的评估）

  1. 谁能把内容送到我设备上：公开手机号/iMessage、邮箱、常见群组成员、可发布内容到你的时间线的人 → 决定 P0/P1 是否要当真。若答案是"没有陌生人渠道"，P0 类链条对你的优先级应显著下调。
  2. 我的哪些东西能被合法流程改到：Apple ID 登录方式与受信设备清单、运营商号码变更约束、每张卡的加卡验证因子、家庭共享与屏幕使用时间管理员 → 决定 P2 暴露面（可执行清单见 #89、#80）。
  3. 我的设备离开视线的频率与状态：是否经常解锁交给他人（维修、代拿、试用、餐厅结账）、密码是否 6 位数字、是否连接过不可控电脑或配件 → 决定 P5；共享设备与已装不明 App 则决定 P4。

结论落点：每档只需要加固对应的那一两件事，不需要为了 P0 把自己活成情报机构。个人可执行的分层清单在 #80，这里只补一句：先定档，再决定要不要开锁定模式——为 P2/P5 开锁定模式几乎没有收益。

6. 五个常见误解

误解事实
"CVE 数量多说明我更危险了"数量不分档。当年新增里大量是 P4/P5 起点的本地问题，对无接触者的现实风险接近 0
"0-click 是最严重的类型"0-click 是最贵的能力，不是最普遍的损失来源；P2 的账户接管便宜得多也常见得多
"把 iOS 升到最新就挡住了 P0"升版本解决的是暴露窗口（#75），但 P2/P5 与补丁无关，取决于验证因子与设备状态
"有 MDM 就不用管 P2"MDM 管设备，不管发卡行、运营商与 Apple ID 登录方式（#76/#89 的边界结论）
"近场无线（P3）对我不适用"只要人在公共场所带设备，P3 半径就存在；只是它的现实门槛与成本使它主要出现在高价值目标场景

7. 一句话结论

按系统层、缺陷类别、被攻击组件分完了"错误在哪"，这一篇分的是"对手从哪儿出发"。

  • 对个人：先回答上面三步定位法，把注意力放在自己实际命中的两三档，其余档位的焦虑可以删掉。
  • 对高危个体：P0/P3 是你必须假设对手具备的能力，锁定模式、更新纪律与"敏感内容不落在这台设备上"才是主战场。
  • 对企业：把资产清单按档位而不是按 CVE 分数排优先级，P2 类风险要走账户与身份治理，不要塞进设备加固项目里。

系列里的 #91 会把这根轴换成另一个视角——同一个起点，造成的损失本身也可以分类；#92 专讲最被低估的一类后果。
