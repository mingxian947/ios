iOS 第三方 App 与配置类缺陷：Apple 补丁修不到的那一片攻击面

编制日期：2026-10-28 数据来源：Apple Platform Security 文档、Human Interface Guidelines 与 App Store 审核指南、WWDC 安全/隐私议题、Google Project Zero、Citizen Lab 与 Amnesty 披露、OWASP MASVS/MASTG、MITRE CWE、公开 App 安全审计报告与 CVE 情报库、本系列前 79 篇分析 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

本系列的 #2 按"层"分类、#81 按"缺陷类别"分类，两轴都在讲系统与框架。这一篇讲第三片领地：App 自身与它的配置。它的特点是——Apple 的补丁周期与它无关，锁定模式对它的保护有限，而用户的"只从 App Store 装"也防不住它。

七条结论：

  1. iOS 上"漏洞"这个词被过度等同于系统 0-day。实际数据外泄事件里，App 侧缺陷与配置错误的占比远高于零日利用，因为它的成本是"读一遍文档"而不是"买一条链"。
  2. App 侧缺陷的主型不是内存安全，而是边界语义错误：密钥的可访问条件、文件的保护等级、URL 的归属校验、共享容器的分区、日志与备份的暴露范围。这一类在 #81 里归到"逻辑/授权误用"，不吃任何内存安全缓解。
  3. 攻击者偏好它有三个原因：不需要逃逸与提权（在自己的权限里就能拿到东西）、结果稳定（不像利用链要赌版本）、归因干净（出事后可以写成"App 的问题"）。
  4. iOS 给了 App 开发者一整套免费的默认安全（沙箱、数据保护类、Keychain、ATS、剪贴板保护、备份加密），大部分缺陷来自"主动关掉默认值"：为了后台可用性把密钥设成解锁前可用、为了调试把容器设为可豁免备份、为了兼容把 ATS 例外写进 plist。
  5. 对防御方，App 面是唯一可以由用户/组织直接收敛的一面：撤销授权、删除描述文件、卸载宿主 App，都能立刻缩小面（对应 #80 §4 与 #66 §3 的"B 路径宿主"）。
  6. 对企业，App 侧风险应通过上架准入 + MDM 策略治理，而不是等 Apple 公告；本系列 #67 讲过"合法签名链上的入侵"，本篇讲"合法 App 里的数据泄露"。
  7. 检测方式与系统漏洞完全不同：App 面可以审计（静态配置 + 权限清单 + 备份内容抽样），不需要狩猎。把两者混在一张威胁清单里，会导致预算错配。

2. 三片攻击面的分工

① 系统/框架层   WebKit、内核、IOKit、媒体与图形栈        ← Apple 发补丁（#1、#58、#68、#82）
② 平台机制层     沙箱、TCC、Entitlement、签名、备份、SEP  ← Apple 设计 + 用户开关（#66、#73、#74、#84）
③ App 与配置层   第三方 App 代码 + plist/权限/密钥配置    ← 开发者的责任，Apple 不修（本篇）
维度① 系统② 平台机制③ App 与配置
谁修补AppleApple（架构）+ 用户（开关）App 开发者
是否出现在安全公告是部分否
是否需要提权配合通常需要视通路通常不需要
锁定模式是否覆盖部分入口部分很弱
防御方可直接动作只能等补丁开开关、最小授权卸载/撤销/准入
检测手段崩溃基线、出口分析授权与描述文件核查配置审计、备份抽样

3. 缺陷清单（按"配置项/接口"组织，防御可直接对照）

3.1 密钥与数据保护类

缺陷表现触发条件加固方向
Keychain 可访问性等级过松把长期凭据存成"首次解锁前即可用"（为后台刷新/推送取令牌）设备锁屏状态下即可读出按用途分级；只有真正需要后台的项放宽，且配 Access Control（生物特征/设备口令绑定）
把密钥明文写入 UserDefaults/文件依赖"沙箱隔离"当作机密性保证备份被提取、越狱/提权后可读、iCloud 同步进键值存储机密只进 Keychain；文件级用数据保护类（NSFileProtection*）显式声明
未指定文件保护等级敏感文件落到默认保护，锁屏后可读窗口比预期大取证/盗窃场景对所有含个人数据的路径显式设定保护类，并在启动早期避免访问（会失败）
备份豁免配置为"减小备份体积"把目录排除，或反之让机密进入未加密备份备份被拿到（#74）明确"哪些数据可以出现在备份里"，与隐私分类绑定；机密类一律不豁免
密码学误用自实现加密、IV 复用、把设备标识当密钥材料与密钥一起泄露即可解密用平台原语（CryptoKit/Keychain），密钥不落地；对齐 #81 §3.9

这一族的共同根因：开发者把沙箱当成机密性保证，而 iOS 的机密性保证其实是"沙箱 + 数据保护类 + Keychain 访问控制"三件叠加，少一件就等于没做。

3.2 输入与信任边界类

缺陷成因现实后果加固
Deep Link / 自定义 URL Scheme 未鉴权scheme 是全局的，任何 App（含恶意 App）可构造跳过登录态、越权访问内部路由、以他人身份打开功能不通过 URL 传令牌；一次性 nonce + 服务端校验；scheme 参数视为完全不可信
Universal Link 关联域配置过宽apple-app-site-association 覆盖了不该覆盖的路径钓鱼域/合作方域可截获本应给 App 的链接（登录/支付流程）只声明实际需要的路径前缀；域所有权与服务端路由一起审
WebView 与 JS Bridge 暴露原生能力为业务方便注入 bridge，未校验加载来源内容注入 → 调用原生能力 → 越权；与 #70 的 WebView 工件同源域白名单在加载前判定；bridge 参数做服务端授权；禁用不必要的 evaluateJavaScript 入口
openURL / 分享扩展输入未清洗外部 App 与网页可构造参数路径穿越式误用、界面劫持（与 #66 §3 路径 C 的 UI 欺骗同族）最小能力原则，扩展宿主进程当作不可信输入处理
剪贴板读写未收敛复制令牌/验证码后长期残留任何已授权读取剪贴板的 App 可读（系统会提示，但不阻断，#66）用共享面板/直接分享替代剪贴板；敏感值设短期有效
推送载荷携带敏感数据把内容/令牌放进 APNs payloadAPNs 中继链路上的数据可见（#65 讨论过该通路）；备份/日志中也会留痕推送只发"拉取信号"，内容由认证通道取回

3.3 进程能力与签名配置类

配置项风险与本系列的接口
get-task-allow 未关（调试 entitlement 残留）进程可被调试/注入，等价于把"宿主借用"（#66 §3 路径 B）的门留着#73 的加载链与调试通道边界
Entitlement 过度申请（后台模式、共享容器、URL scheme 前缀）能力越多，被借用的可能性越大；与"哪些进程既有敏感授权又处理外部输入"这一审计问题直接对应#66、#68、#82
App Group / 共享容器分区过大一个成员被攻破，整组共享数据可读；备份时整组一起带走#74、#45（模块化落地）
自定义 extension（键盘、分享、媒体）键盘扩展能读到输入内容；扩展宿主与被扩展 App 的信任关系常被忽视#73 的宿主借用、#66
内嵌第三方 SDK/框架供应链：SDK 的密钥、日志、网络实现不受主 App 团队控制#28 供应链、#18 凭据窃取
描述文件/配置携带的能力（企业分发）合法通道上的额外能力面#67

3.4 界面与交互类（最便宜、最常用的攻击方式）

缺陷说明防御
权限时序操纵先以"必要功能"话术索取麦克风/相册，用户在高完成率压力下同意（#66 路径 C）只在功能真正需要时请求；拒绝后可用降级路径
伪造系统弹窗/界面劫持用与系统相似的 UI 诱导输入凭据App 不得自绘系统权限样式；登录页域名可见；组织侧培训
后台快照（系统截图）含敏感内容任务切换器预览里出现卡号/验证码敏感界面前台切换时做遮罩；系统提供的隐私遮盖能力要用
锁屏通知内容暴露通知显示验证码/消息内容内容裁剪、仅在解锁后可见（与 #84 同一控制面）
日志/崩溃上报泄露os_log 打了 PII、崩溃收集器带文件路径与令牌脱敏；对齐 #76 的日志可见性边界

4. 为什么攻击者偏爱 App 面（成本对照）

项系统 0-click 链App 与配置缺陷
需要稀有漏洞是否
需要版本赌注是（目标必须停在未修补版本，#75）否（缺陷随 App 长期存在）
需要逃逸与提权是（#40、#43、#41）通常不需要
失败后果崩溃 → 留下工件（#82 §8）不崩溃 → 几乎无工件
归因难度高（可指向国家级能力）高（可写成"第三方 App 问题"）
单目标成本极高（百万美元级投入）极低（读一遍配置就能发现）

这是本篇的核心防御判断：对绝大多数真实数据泄露事件，对手不是 L3/L4（#80 §2 的分层），而是 L1/L2 级别但对 App 面做了针对性工作。因此"我只从 App Store 装 App 所以安全"是错的（App Store 审核不覆盖密钥可访问性选择、备份豁免、scheme 鉴权这类问题），而"我开了锁定模式所以数据面安全"也是错的（锁定模式主要收缩系统入口，不改变 App 的存储配置）。

5. 审计方法（三层，均可执行）

5.1 开发侧（App 团队自查清单）

□ 每个 Keychain 项：可访问性等级是否与用途匹配？是否需要 Access Control？
□ 每个文件路径：是否显式声明数据保护类？敏感目录是否豁免备份？
□ Info.plist：LSApplicationQueriesSchemes / URL types / ATS 例外 / background modes 逐项过一遍
□ 所有入站边界（scheme、Universal Link、推送、分享扩展、WebView bridge）：是否有鉴权？
□ entitlement 清单：能否删掉一半？（get-task-allow 是否为 false）
□ 第三方 SDK：谁有网络出口？谁持有密钥？日志写到哪？
□ 崩溃/日志上报：字段抽样检查有无 PII、令牌、内部路径
□ 备份抽样：做一次未加密备份，列出"外人能拿到什么"（最直接的一课）

对齐外部标准：OWASP MASVS（存储、加密、网络、平台、代码）可作为验收框架，但不替代平台原语选择。

5.2 企业/MDM 侧

动作说明依据
上架准入：把 §3.1–§3.3 作为审核项自研与采购 App 都要过；重点问"密钥存哪、备份里有什么"本篇、#74
描述文件与能力登记任何授予额外能力（代理、拦截、容器）的配置都要登记并定期清理#67
权限状态纳入可见项MDM 可见"授予了什么"，不可见"提权后做了什么"（诚实表述边界）#76、#66
高危角色 App 白名单只允许清单内 App 承载业务数据；减少 §3.3 的组合面#80 §8

5.3 用户侧

动作频率
撤销非必要 App 的麦克风/相机/定位/相册授权；"始终允许"归零每月（#80 §10）
检查 VPN 与设备管理里的描述文件，删除不认识项每月
卸载"只为一次功能"装的 App；检查可登录设备与浏览器会话每月
通知预览关闭（验证码/消息类 App）一次性
关闭非必要 App 的后台 App 刷新（减少锁屏可用窗口）一次性

6. 真实形态对照（不含具体厂商指名的通用案例）

事件形态缺陷族若只看本系列系统视角会漏掉什么
"备份被提取后，聊天与凭据全可读"§3.1 保护等级 + 备份豁免会误判为"设备被攻破"（实际是备份通路，#74）
"登录链接被第三方域截获，账户被接管"§3.2 Universal Link 关联域过宽会被归成"钓鱼"，实为配置问题（#18 相关但不同因）
"键盘扩展/输入法读取了输入内容"§3.3 扩展信任边界会被归成"木马"，实为合法授权的宿主
"SDK 把设备标识与令牌发到自建服务端"§3.3 供应链 + §3.4 日志会被归成"数据滥用"，但对攻击者等价于凭据泄露（#18）
"推送里带了完整内容，中继链路可见"§3.2 推送载荷会被当作"通知通路漏洞"，实际是设计选择（#65）
"调试 entitlement 残留导致内容注入即接管"§3.3 get-task-allow会被归成"越狱攻击"，实为无需越狱（#16、#73）

方法论提示：这六条都不会出现在任何 Apple 安全公告或 CVE 数据库里，因此任何以"CVE 数量"为口径的 iOS 风险汇报（#75、#81 §5）天然漏掉了它们。做 iOS 风险统计时必须把 App/配置类作为独立一列，否则数字会系统性低估现实风险。

7. 常见误解纠正表

误解事实
"过了 App Store 审核就没问题"审核不覆盖密钥可访问性、备份豁免、scheme 鉴权、SDK 数据出口这些配置选择
"沙箱隔离了，App 里的密钥别人读不到"沙箱隔离进程，不隔离"备份、提权后、调试通道、共享容器、Keychain 宽松可访问性"
"越狱检测能发现 App 数据被偷"多数 App 面缺陷不需要越狱，也不需要任何工件（#82 §8 的表述纪律同样适用）
"锁定模式保护我的 App 数据"锁定模式收缩系统入口与部分能力，不改变 App 自己的存储/密钥配置
"用加密库就安全了"密钥存在哪、谁能读、备份里有什么，与加密算法实现无关（#81 §3.9）
"只有敏感行业才需要管这个"App 面攻击是 L1/L2 成本最低的入口，普通用户与中小企业受影响的绝对数更大
"配置类缺陷可以自己发版修，不用急"修复确实只需 App 更新，但缺陷存续期间没有任何外部信号，暴露窗口完全不可见（对比 #75 的系统补丁窗口）

9. 总结

#结论
1iOS 攻击面分三片：系统与框架（Apple 修）、平台机制（Apple 设计 + 用户开关）、App 与配置（开发者责任，Apple 不修）
2App 面缺陷以边界语义错误为主，属逻辑/授权误用类，不吃内存安全缓解，也不需要提权
3攻击者偏爱它因为成本是"读配置"而不是"买利用链"，且失败不留崩溃工件
4大部分缺陷来自主动关掉平台默认安全：Keychain 可访问性、文件保护类、备份豁免、entitlement、ATS
5App 面是防御方唯一可以直接收敛的一片：卸载、撤销授权、准入、清理描述文件都能立刻生效
6这类问题不出现在 CVE/公告里，任何以 CVE 数为口径的 iOS 风险统计都系统性低估现实；必须单列一栏
7审计方式与系统漏洞不同：配置审计 + 备份抽样即可覆盖，不需要狩猎能力

一句话总结：iOS 上最常被真正用走的不是零日利用链，而是"某个 App 把密钥设成锁屏也能读、把敏感目录放进了未加密备份、把登录令牌塞进了 URL scheme"——它不先进、不性感、不会出现在任何安全公告里，但它同时绕过了 Apple 的所有硬化和你的所有开关。
