Coruna 与 DarkSword 漏洞武器化工程与利用链编排架构

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Synacktiv、8ksec、Apple 安全公告、公开 CVE 情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

把"一个 CVE"变成"一次成功的定向入侵"，中间隔着大量工程工作。漏洞武器化（Weaponization） 不是编写一个 exploit，而是构建一套能应对真实世界不确定性的工程系统：目标版本探测、多条利用链选择、原语逐级升阶、失败降级与重试、载荷分发与安装。

Coruna 与 DarkSword 在这一层的成熟度差异，比它们在单个漏洞质量上的差异更能解释其实际战果：

  • Coruna：一个利用链编排引擎——同时维护 5 条利用链、23 个 CVE，覆盖 iOS 13–17.2.1，运行时按目标指纹动态选链
  • DarkSword：一个高精度单链执行器——围绕少数组件（JSC DFG GC、ANGLE/GPU、媒体服务）深度优化，追求单次成功率

本文从武器化工程的六个层面（目标适配层、链选择与编排、原语升阶梯、可靠性工程、失败处理、载荷交付）解析两套体系，并给出防御者如何利用工程特征反推攻击状态的方法。

2. 武器化的层次模型

理解 exploit kit 工程，先要建立"从代码执行到完全控制"的层次视图：

┌──────────────────────────────────────────────┐
│ L6 运营层：目标选择、投递、任务下发、数据回收    │
├──────────────────────────────────────────────┤
│ L5 载荷层：采集模块、持久化/驻留、外传          │
├──────────────────────────────────────────────┤
│ L4 权限层：内核读写 → root → 数据保护类突破      │
├──────────────────────────────────────────────┤
│ L3 逃逸层：跨出沙箱边界，触达高权限组件          │
├──────────────────────────────────────────────┤
│ L2 原语层：addrOf / fakeObj → 任意读写 → 控制流  │
├──────────────────────────────────────────────┤
│ L1 执行层：一个漏洞换来的"进程内执行代码"        │
├──────────────────────────────────────────────┤
│ L0 投递层：URL / 消息 / 附件触达解析器           │
└──────────────────────────────────────────────┘

关键认知：每一层都不足以单独构成威胁，但每一层的失败率会相乘。假设每层 95% 成功率，六层串联后整体成功率约 74%——这解释了为什么武器化必须包含多链冗余与失败重试。

3. Coruna 的武器化工程

3.1 多链并行架构

Coruna 最突出的工程特征是同时维护多条独立利用链。根据 Citizen Lab 的公开分析，Coruna 至少包含 5 条链、涉及 23 个 CVE，覆盖 iOS 13 至 17.2.1。

                 ┌─ 链 A：适用 iOS 13.x  (组件集 A)
                 ├─ 链 B：适用 iOS 14.x  (组件集 B)
 目标探测 ──→ 版本判定 ─┼─ 链 C：适用 iOS 15.x  (组件集 C)
                 ├─ 链 D：适用 iOS 16.0–16.x (组件集 D)
                 └─ 链 E：适用 iOS 17.0–17.2.1 (组件集 E)

设计动机：

动机说明
目标版本不可控现实中目标设备版本参差不齐，单链只能覆盖一个窗口
降低零日消耗复用已修补但目标未更新的漏洞（N-day），成本远低于新零日
冗余容错一条链失败可尝试备选
延长套件生命周期每次 Apple 修补，只需增加新链而非重做整套

3.2 目标适配层（Target Fingerprinting）

武器化第一步是在触发漏洞前确定目标环境，避免在无收益的场景浪费零日或暴露载荷。

探测维度：

探测项手段用途
iOS 版本navigator.userAgent 中的 OS 版本字段决定选哪条链（最关键）
设备型号/架构UA + JS 特性探测、屏幕参数判断 PAC 是否启用（A10+）、内存布局
是否 SafariUA 与特性差异影响沙箱 profile 与可用 API
是否已越狱文件系统可访问性、私有 API避免重复工作 / 避免暴露
是否锁定模式JIT 可用性探测（关键能力缺失即为信号）多数链会直接中止，节省零日
语言/时区/网络Intl、Date.getTimezoneOffset、连接类型目标筛选（只投递给特定人群）
重复访客判定本地存储/指纹避免同一目标反复触发导致发现

关键工程实践：Coruna 的页面会先做无害的环境探测，只有全部条件匹配才加载实际利用代码。这一"预检"设计大幅降低了无关触发与暴露概率——也给了防御者一个可检测信号：存在只做探测、不加载内容的可疑请求序列。

3.3 原语升阶梯（Primitive Escalation Ladder）

单个漏洞换来的只是很弱的能力，武器化的核心是逐级把弱原语放大成强原语：

[漏洞] 一个类型混淆 / GC 缺陷
    ↓
[原语 1] addrof(obj)  → 读出 JS 对象的机器地址
[原语 2] fakeObj(addr) → 在任意地址伪造 JS 对象
    ↓
[原语 3] 任意读写（Relative R/W）
    （通过伪造 ArrayBuffer 的 backing store 指针）
    ↓
[原语 4] 绝对读写 + KASLR slide 泄露
    （从进程内存中定位 dyld shared cache / 内核基址）
    ↓
[原语 5] 控制流劫持（绕过 PAC）
    ↓
[原语 6] 沙箱逃逸（跨进程 IPC / 驱动接口）
    ↓
[原语 7] 内核读写
    ↓
[能力] 完全设备控制

Coruna 的工程特点：

  • 每一步都依赖前一步产出的原语，形成严格的依赖 DAG
  • 各步骤在 iOS 不同版本上使用不同实现（对应不同链）
  • 每步都有校验点（校验读写是否真的生效），失败即中止而不继续冒险

3.4 可靠性工程

武器化与 PoC 的最大区别在于对可靠性的要求：PoC 跑成功一次即可发表，武器必须在数千次真实目标上稳定成功。

技术手段说明
堆布局塑形（Heap Feng Shui）通过大量分配/释放特定大小的对象，控制目标对象落在可预测位置
喷注（Spraying）在 WebKit 中常见 ArrayBuffer 喷注、JS 对象喷注，提升命中概率
重试与幂等设计关键步骤失败可在同一次会话中重试多次
确定性偏移搜索不依赖硬编码偏移，运行时搜索特征字节（应对 ASID/KASLR 变化）
保守中止策略一旦检测到不确定状态就中止，避免半成功导致崩溃（崩溃会留下取证价值极高的报告）

Coruna 的规模证据：其代码量与逻辑复杂度（Citizen Lab 分析显示包含大量混淆、多层解码、条件分支）表明这是一个长期投入、多轮迭代的工程产品，而非一次性研究代码。

3.5 混淆与代码保护

Coruna 在武器化层面投入了大量反分析工作：

层级手段
JavaScript 层多层字符串编码、控制流平坦化、变量名随机化、死代码注入
载荷层分片下发、逐层解密、避免一次性暴露完整逻辑
基础设施层代码不内置在页面，运行时从 C2 拉取，便于更换与规避静态抓取
执行层关键计算通过多层解释器 / JIT 生成，减少可搜索的静态字符串

防御者要点：Coruna 的混淆主要面向"抓取页面后静态分析"，但运行时行为（网络请求序列、JS API 调用模式）无法被混淆隐藏——这往往比逆向代码更快定位问题。

4. DarkSword 的武器化工程

4.1 单链深度优化

DarkSword 采取与 Coruna 相反的工程选择：不追求覆盖广度，追求单点成功率与隐蔽性。

根据 Project Zero 分析，DarkSword 的核心链条为：

JSC DFG 层 GC 缺陷（CVE-2025-43529 类）
      ↓ 提供 WebContent 进程内原语
ANGLE / WebGPU 层两阶段逃逸
      ↓ 触达 IOGPUDevice 等内核驱动接口
内核读写 + PAC 绕过
      ↓
媒体服务注入（mediaserverd）
      ↓ 获得系统级采集能力
内存中执行采集 → 外传 → 无痕

工程取舍：

取舍选择代价
版本覆盖只覆盖较新的 iOS 窗口（如 18.6–18.7）老版本目标无法攻击
链冗余少（几乎单链）一处失败整体失败
优化重点逃逸与注入的精细度、隐蔽性开发周期长
持久化完全放弃重启后需重新投递

4.2 攻击面选择的产品化

DarkSword 在逃逸面上的选择体现了很强的攻击面工程思维：

为什么选 ANGLE/WebGPU？

判据说明
沙箱放行渲染进程必须能与 GPU 通信（否则页面无法渲染），是合法可达通道
攻击面新WebGPU 相对年轻，审计密度低于传统 IPC/IOKit 面
C++ 实现ANGLE 是 C++ 库，相比 Swift/Objective-C 组件更易出内存缺陷
跨进程分层"WebContent → GPU 服务 → 内核驱动"形成天然多级跳板
复杂度带来缺陷密度图形语义复杂，验证逻辑难以完全覆盖

这一点对防御者的启示极为重要：攻击者不是随机找洞，而是系统性选择"合法可达 + 审计不足 + 实现复杂"三重叠加的组件。同类逻辑适用于评估自有产品的暴露面。

4.3 无持久化对武器化的约束

DarkSword 的无持久化策略反向塑造了其武器化工程：

约束工程响应
每次重启需重新投递页面必须能被反复触发且保持稳定成功
无法后台等待任务一次性下发全部任务，减少往返
会话时间短采集与外传必须在分钟级完成，不能"持续监听"
无配置文件可留C2 地址、密钥全部通过页面下发或 DGA 推导
崩溃 = 零收益且暴露中止策略比 Coruna 更保守

4.4 0-click / 低交互设计取向

DarkSword 相关系列展现了向更低交互成本演进的趋势：

1-click（用户点击链接）   ← 主流（水坑）
    ↓
0-click（消息自动触发）   ← 高价值但漏洞消耗大、暴露风险高

0-click 的武器化难度显著更高，因为没有环境探测的机会：

挑战说明
无法预先探测版本必须在同一载荷中处理多版本，或接受失败率
无法中止触发即执行，半成功会直接暴露
解析器路径受限只能依赖预渲染/自动解析环节
一次机会目标可能在崩溃前收到通知

这也解释了为何多数套件仍以 1-click 水坑为主力——工程可控性优于交互便利性。

5. 两套体系武器化对比

5.1 工程特征对比

维度CorunaDarkSword
利用链数量多条（≥5）少（1–2）
CVE 覆盖23 个集中少数组件
版本跨度iOS 13 – 17.2.1集中在新版本窗口
目标探测完整（版本/型号/锁定模式/时区）有，但更精简
载荷交付分层、多阶段、运行时拉取一次性、内存中构建
混淆强度极高（多层 JS 混淆 + 编码）中（更依赖无痕而非混淆）
可靠性策略多链冗余 + 重试单链精细优化 + 保守中止
迭代方式增补新链重写关键组件
工程质量画像平台化产品精工单点武器

5.2 背后组织能力推断

从工程特征可反推研发组织的形态——这是威胁情报中"归因"的重要侧面：

推断CorunaDarkSword
团队规模较大（需并行维护多链与运营基础设施）中（精专团队）
资金来源稳定长期（多链储备成本高）稳定（长周期单链研发）
漏洞获取渠道多元（自研 + 采购 + 泄露复用）偏向高质量单一来源
商业模式面向多客户可复用套件可能是客户定制或单一运营
迭代节奏快（持续增补）慢（大版本重写）

注：以上为工程特征推断，非归因结论。真实归因需结合基础设施、时间线、目标画像等多维证据。

6. 从武器化特征反推攻击状态（防御实用）

武器化工程必然留下可观测的行为特征，防御者无需逆向代码即可判断"是否正在被武器化利用"。

6.1 探测阶段的信号

信号说明
异常密集的 JS 特性探测正常网站极少同时探测 UA、时区、语言、JIT 可用性、越狱状态
无内容的探测请求页面加载后不请求任何资源，仅上报探测结果
探测后二次加载探测返回后才拉取"利用脚本"资源（分层交付特征）
条件化返回同一 URL 对不同参数返回完全不同的内容（目标筛选特征）

6.2 利用阶段的信号

信号说明
大量同尺寸对象分配堆喷注在 JS 堆统计中表现为异常分配速率
长时间同步 JS 执行利用循环阻塞主线程，WebContent CPU 突增
WebContent 异常内存映射出现大量可执行匿名页
WebGPU/ANGLE 异常调用简单页面产生大量 GPU 资源创建/销毁
媒体服务进程行为异常mediaserverd 出现非常规线程或网络连接

6.3 交付与外传阶段信号

信号说明
利用成功后立即外连时间与页面加载强关联的新 DNS 解析
上行流量突增采集数据打包外传
短时会话后静默DarkSword 类特征：一次连接后完全静默

6.4 网站完整性监控（水坑防御）

对自有站点（潜在水坑目标）：

  • 启用 Subresource Integrity (SRI) 固定第三方脚本哈希
  • 部署 Content-Security-Policy，限制脚本来源，可阻断注入式水坑
  • 页面内容变更监控：定时抓取渲染结果，对比脚本哈希变化
  • HTTP 缓存基线：检测响应体异常变化（中间层注入）
  • 访客侧异常请求监控：服务端日志发现"只做探测不加载资源"的可疑 UA 序列

7. 武器化的成本结构与供应链

7.1 单个链条的成本构成

成本项说明
漏洞发现需长期投入模糊测试、代码审计人力
漏洞购买商业市场上单条 iOS 全链价格常达数百万美元级
武器化工程从 PoC 到稳定链通常需数月工程工作
版本适配维护每次 Apple 更新可能致链条失效
投递运营水坑站点获取、基础设施维护、目标识别
消耗率每条链被公开后价值归零

7.2 泄露与复用生态

一个重要的现实：漏洞在生态中会流通。

流通形式影响
内部工具泄露某厂商被攻破，其 exploit 库流出
样本提取后公开防御者捕获页面后公开发布，链条价值归零
跨套件复用一套件使用另一套件已泄露的链（GHOSTBLADE 即为此类）
研究者持有学术/安全研究者掌握未公开漏洞，构成潜在泄露风险

GHOSTBLADE 案例的意义：它证明了"利用链作为可复用资产"的市场现实——同一组漏洞可以在不同套件、不同客户之间流转。对防御者来说，修补一个漏洞可同时防护多个套件，这是补丁优先级排序的重要依据。

8. 防御建议

建议针对的武器化环节优先级
快速强制升级使版本探测阶段直接判定"不可攻击"极高
启用锁定模式探测到 JIT/WebGPU 关闭 → 攻击中止极高
CSP + SRI阻断水坑脚本注入与第三方劫持高
站点完整性监控早期发现被水坑高
浏览器行为异常检测捕捉堆喷注、长时间同步执行、异常 GPU 调用中高
网络时序关联"加载页面 → 数秒内新域名解析" 是强信号中高
减少零日暴露窗口关注 Apple 安全通告与 CVE 时间线，识别"已修补但未部署"的自有资产高
威胁情报订阅掌握已知链的组件组合，用于检测规则设计中

核心策略性认识：

武器化工程的最大软肋不是技术，而是它对"目标未修补"的依赖。 Coruna 覆盖 iOS 13–17.2.1 这一事实本身就说明：它的战斗力来自目标延迟更新，而非不可防御的技术。 把组织的"补丁部署时延"从 90 天压到 7 天，可以直接摧毁这类套件的大部分战术价值。

9. 总结

结论内容
1. 武器化是系统工程从 L0 投递到 L6 运营，每层都会引入失败率，串联后必须靠冗余与可靠性工程弥补
2. Coruna 赢在广度多链 + 版本路由 + 目标筛选，本质是"平台化"思路，覆盖长尾版本换取战果总量
3. DarkSword 赢在深度单链精细 + 攻击面选择 + 无持久化，本质是"精品武器"思路，用隐蔽性换取难检测
4. 攻击面选择有方法论"合法可达 + 审计不足 + 实现复杂" 是 GPU/ANGLE 被选中的原因，同样可用于自评暴露面
5. 工程特征可被观测无需逆向代码，探测行为、堆异常、时序关联即可判定武器化活动
6. 补丁时延是最有效的反制多链套件的战斗力来自目标更新延迟，缩短部署时延的性价比高于任何检测工具
