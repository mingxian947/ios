iOS 安全研究文章库 · 第 143 篇 · 防御性安全研究，不含可利用代码

iOS 维修、替换件与硬件完整性的攻击面：修一次手机，改的是这台设备对外证明自己是谁的那套属性

1. 执行摘要

  • 这一族的名字应该叫"唯一一次由第三方物理介入改变的设备身份"。前面二十七根竖条全部发生在逻辑层：字节、调用、信号、内容、派发、调度、凭证、下发、判定。本篇是第二十八根，它把攻击面（更准确说是"变化面"）搬到工作台上：换一块屏幕、换一块电池、换一颗摄像头、掉进水中后主板做过修复、二手机到手时你不知道上面哪几件不是出厂那几件。这些动作没有一次涉及漏洞、提权或越权，但它们都会改变这台设备向外声明自己是谁的那组属性。
  • 先讲清本族的正当性，因为它是全系列少见的"限制有合理理由"的一族：部件配对与完整性校验的存在理由是真实的——防止假冒配件、防止翻新件当原装卖、防止带摄像模组与电池的安全风险件流入、防止被盗设备被拼装洗白。本篇不主张取消它。本篇处理的是它的三项外部性：维修史对当事人不可携带、对买方不可查询、对判定层不可解释。
  • 核心命题：维修通路的失效几乎从不是"换到了坏件"，而是"设备的一组身份属性在一次物理干预之后变了，而变更记录的三份副本分别在你不知道的三个人手里"。 于是同一个物理事件会产生四类互不相干的后果：功能层面的降级与提示、交易层面的信息不对称、安全层面的判定输入变化（#142）、以及法律层面的归属与激活锁纠纷。
  • 三层切分：H1 物理干预层（谁拆了机、换了哪一类部件、件从哪来、有没有维修记录、你在场还是不在场）；H2 身份与登记层（序列号/IMEI 这类持久锚点、部件级的配对与授权、零件历史、以及激活锁与网络侧名单在服务端的登记，这五样各写各的、互不同步）；H3 后果层（功能与提示、交易价值与信息不对称、判定输入、隐私暴露、可用性失能）。风险密度在 H2（因为登记分散且不一致），不可逆点在 H3 的判定与纠纷两格（一次维修可能长期影响这台设备在外部系统里的样子，而没人会告诉你）。
  • 一条方法论结论，也是第十六个系统性漏检：用 #66 的隐私面板、#95 的指纹清单、#96 的设备流转处置表、#142 的症状观察法去做这类审计，全都会漏掉本族。原因是同一个：这些视图审计的单位是"设备当前的属性快照"，而本族的最小风险单位是"属性的一次物理变更 + 该变更在各处的可见性差"。 一台设备在系统设置里看起来完全正常、隐私面板毫无异常、任何安全自检都会通过，但它的外观、部件与"是否原装"这三项已经在三天前的一个工作台上变了，而唯一记录这件事的地方是那张你随手扔掉的维修单。这是全系列第一次出现"最重要的证据是一张纸质单据"这种结论。 本篇需要的是第十六个补丁：一份"维修档案"——每一次物理干预留一行（日期、部位、件来源、执行方、是否留单、是否当场验证功能），它与 #104 的季度巡检表同级，但完全不同源。
  • 后果上它给出第十七种不提权的伤害形状：修一次，身份变一次。#131 借你自己的手、#140 无需到场的改版、#141 一次解锁即一次登录、#142 以设备名义作出的账户判决；本篇的形状是"一次合法、正当、你花钱买的服务，改变了这台设备向外部世界自证的那组属性"——并且这是全系列十六种形状之外唯一一个"不需要任何人为恶意"的：没有人攻击你，你只是修了手机。 与 #142 的因果链必须写死：#142 讲属性进入判定之后会发生什么，本篇讲属性会因为一次物理干预而变——两篇互为上下游，单独引用任何一篇都会漏掉这条完整的因果线。
  • #131 的"显示即属主"在本族第七次成立，且是它最字面的一次：设置里那行"未知部件"或"无法验证此设备使用了原装零部件"的提示，说的不是这台设备安不安全，而是它的这组属性和某条登记对不对得上。你把这两件事混为一谈，就会同时犯两个错误：把一次正常维修读成被入侵，以及把一次真正有风险的替换读成"只是弹个提示"。 本族的判读纪律要求这两条永远分开写（§11 第 1、2 条误解）。
  • 可观测性的诚实定位：能核对的比 #142 多得多，比 #137 少。你能核对：这台设备自己显示的部件与序列信息、部分品类的能力开关状态（面容 ID、原彩显示、电池健康与循环信息是否可见）、系统里与"零件与维修历史"相关的页面（存在与否、覆盖到哪些部件、显示什么，随机型与版本差异很大，必须当场看）、以及维修方给的单据。你核对不到：某一颗件是不是原装、它从哪来、上一任使用者换过什么、外部系统对这台设备持有什么登记、以及任何"这台机器的部件历史全貌"。
  • 正向结论只有一句：把维修当成一次"身份属性变更事件"来管理，而不是当成一次消费。三条动作当场可验：送修前把数据面收起来（用系统提供的维修期间数据隔离能力，并当场确认它生效）、修时或修后把单据与部件信息留下、修完逐项验证功能并记录哪些提示出现了。交易场景再加一条：买二手设备时把"部件与提示状态"当成一项可当场核对的验收项，而不是听卖家说（接口 #96）。

2. 这根竖条补的是哪一块

系列里已经有多篇擦到过：#96 测绘了设备流转与退出边界（二手机、维修、回收、离职交接上被忽略的那一半风险——那一篇讲的是处置与数据），#121 测绘了配件与有线连接（外来物件如何与设备握手），#84 测绘了锁屏状态、生物识别与强制解密边界（物理通路上的另一半攻防），#142 测绘了设备证明与风控指纹（属性如何变成判决），#124 测绘了密码学与密钥生命周期，#115 测绘了软件更新链，#131 测绘了标识与呈现。

但这些位置都缺同一格：设备是由几十个可更换的物理部件构成的，而其中一部分部件现在带有身份属性；一次维修会改变这组属性，且改变的结果同时被功能层、交易层、判定层和法律层各自以不同方式读取——没有任何一处负责把这件事整合成一个当事人能理解的答案。 #96 讲的是"这台设备要交给别人了，数据怎么办"；本篇讲的是"这台设备被拆开过，它自己怎么说它自己"。#121 讲的是外面的东西接进来；本篇讲的是里面的东西被换掉。#84 讲的是物理通路上的攻击；本篇讲的是物理通路上的常规服务——它同样改变设备状态，但没有威胁模型把它算进去。

这是第二十八根竖条，也是全系列第一根完全发生在设备物理层的竖条：它不需要网络、不需要 App、不需要用户点击，只需要一把螺丝刀和一个工作台。这决定了本篇的气质与前面二十七根完全不同：不谈漏洞，谈登记、单据与验收。

与相邻各篇的分界必须写死：

  • 与 #96（设备流转）：那一篇 owns 数据侧处置（退出账户、抹除、备份、回收前的准备）；本篇 owns 部件与身份侧后果（换了什么、系统怎么说、买方可核对什么、外部登记怎么变）。同一台二手机，那一篇关心里面有没有你的数据，本篇关心上面有没有你的设备的部件、以及它的这组属性还说不说得清自己。
  • 与 #142（设备证明与风控）：上下游，必须成对引用。那一篇讲"属性进入判定之后会发生什么"，本篇讲"属性会因为一次正当的物理干预而变"。两篇合起来是本系列关于'设备属性不是稳定事实'这一命题的完整论证。 具体接口在 §7 的 C4/C5 与 §12。
  • 与 #84（锁屏、生物识别与强制解密）：那一篇 owns 物理接触下的数据暴露与生物特征边界；本篇 owns 送修时的数据面收敛（维修期间用不用隔离能力、当场怎么确认它生效）与面容相关组件更换后的功能后果。"把手机交给一个陌生人"这一格在 #84 是威胁模型，在本篇是日常消费——这是本篇最重要的一个提醒：日常消费也应该走 #84 的那套纪律。
  • 与 #121（配件与有线连接）：那一篇是外部物件接入；本篇是内部物件替换。两篇共用"物件即属性"的律：接入的配件会成为设备状态的一部分，替换掉的部件也是。
  • 与 #124（密码学与密钥生命周期）：部件级密钥与配对关系属于那一篇的一般框架；本篇只取后果侧的一格——当一项能力依赖某个具体部件里的密钥材料时，更换该部件在密码学上等价于更换信任根，而当事人只知道"这个功能不能用了"。
  • 与 #131（标识与呈现）：本族是其"显示即属主"律的最字面案例（§1 倒数第三段）；呈现机制与判读方法归 #131，本族只负责说明这些提示为什么会出现、以及读错它的两种代价。
  • 与 #117（理赔与欺诈核查）/#102（数字遗产与紧急访问）：激活锁与归属证明是这两篇里最常见的实物争议来源：一台设备"是谁的"这个问题，在维修与二手场景里最终靠的是单据与服务端登记，而不是谁手里拿着它。

3. 三层切分：干预、登记、后果

3.1 H1 物理干预层——一次维修到底改了什么

干预类型常见动因会被改变的属性类别功能后果的典型形态交易后果
屏幕更换碎裂、触控失灵显示组件身份原彩一类依赖环境光与配对的能力可能失效；出现部件提示二手机价值与"是否原装"争议高发区
电池更换健康度衰减、鼓包电池身份与循环统计电池健康度与循环信息可能不再显示；提示卖家最常隐瞒的一项
摄像头/面容组件进液、故障光学与安全组件身份面容 ID 一类生物识别可能永久失效（组件级绑定）争议最重的一格，因买方难以当场判定
主板修复/换板进水、断路序列号/IMEI 类持久锚点可能变动网络注册、激活、保修核验异常与激活锁、找回、封禁名单直接冲突的高发区
后壳/结构件外观部分机型与身份无关一般无提示影响"是否拆过"的判断
第三方"改装机"扩容、双卡改单卡等存储/基带相关身份更新与恢复时风险显著上升本族最不该碰的一格，见 §10

四条结论：第一，维修不是"换个件就完事"，它是一次跨层的属性变更：同一块电池被换掉，同时在功能层（健康度显示）、交易层（循环数不可考）、判定层（#142 的属性输入）与法律层（保修与归属）各产生一份后果，而这四份后果由四个互不相干的主体保管。 第二，部件之间的"可换性"差异极大：结构件换了无事，安全组件换了可能永久失去一项能力，而这个差异在送修前几乎无法从任何当事人可见的地方读到——它只在工作台与售后系统里。这意味着"修之前先问清楚会影响哪些功能"是本族唯一有效的事前动作，而且这句话只能由你问出来，不会有人主动说。 第三，主板级维修是本族唯一会动摇"这台设备是这台设备"的干预：序列号/IMEI 一类锚点一旦与实际登记不一致，网络侧、激活侧、保修侧、找回侧的反应会各自发生且不一致，这类问题不是维修质量问题，是登记一致性问题，维修方无法解决，只能由原登记方处理（接口 #117 的核查思路）。第四，"改装机"与"维修"必须分开：维修恢复功能，改装改变规格。 改变规格的设备在恢复、更新与验证环节上遇到的困难，本质上是因为它对外声明的属性与自己内部的结构不再一致（#131 的律在物理层复现）。

3.2 H2 身份与登记层——五份各写各的账

这是本族真正的结构性问题所在。一台设备的"身份"从来不是一份记录，而是五份互不同步的登记：

登记由谁保管当事人可见性与另外四份一致吗
设备内自述（设置里能看到的型号、容量、序列信息）设备可见（但只显示当前值，不显示历史）与出厂记录可能已不一致
部件级配对/授权状态设备 + 服务方校验接口以提示的形式部分可见常与"实际装的是什么"有出入
零件与维修历史记录页设备 + 官方服务链路部分机型/版本有，非官方渠道维修的覆盖情况各异只反映走过官方链路的那些
销售方/服务方服务端（保修、激活、找回）厂商不可见，需通过正式渠道查询是归属与激活锁争端的仲裁依据
网络侧名单（丢失、封禁、跨网登记）运营商/行业机构完全不可见与厂商登记不同步，且滞后

三条结论：第一，"这台设备是什么"没有权威单一答案，只有五个口径；本族的绝大多数纠纷都源于拿其中一个口径去否定另一个口径。 卖家说"官方查不到维修记录"（第四份）与设备上显示"未知部件"（第二份）可以同时为真，且都不构成谎言。第二，官方链路的维修历史对用户可见性最好，非官方链路的可见性最差——这一不对称直接把维修选择变成了信息资产问题：走官方链路你得到一份可查的记录，走非官方链路你得到的记录只在一张纸上（那张纸就是你的全部证据，§1 的"纸质单据"结论）。第三，第五份登记（网络侧名单）是本族唯一一个"当事人完全无法自查、且会直接影响设备可用性"的项：二手机到手发现无法注册网络，通常不是设备坏了，而是这台设备在某个与卖方、与维修都无关的名单里。 处置只能走 #117 的核查思路，个人侧唯一能做的是买前把归属与网络状态当成验收项。

3.3 H3 后果层——四类后果，四种主体，四种救济

后果触发谁来修当事人有救济吗属于哪一篇
功能降级或能力永久失去部件级绑定更换经授权/配对的件有（但成本与知情权问题大）本篇
部件提示与"无法验证"登记不一致由原登记方链路处理有，但提示的含义常被误读（§1）本篇 + #131
二手价值与欺诈争议信息不对称无技术解靠单据与事前验收本篇 + #96
维修后进入风控判定属性变化成为判据输入服务方极难（#142 的 D3）#142
送修期间的数据暴露设备在他人手里事前隔离有（维修期间的数据隔离能力）#84 + 本篇
激活锁/归属争议服务端登记只有原登记方能解靠购买凭证#117 + #102
更新与恢复失败结构改动恢复规格有但常需返工本篇 + #115

三条结论：第一，本族的救济分布是错位的：功能后果当场可验、登记后果需要正式渠道、判定后果几乎无法救济——而这三种后果发生在同一个下午，没有任何一份提示把它们连起来告诉用户。第二，"送修期间的数据面"是本族唯一完全可以在事前消除的风险：系统提供了维修期间的数据隔离能力（不同版本入口与名称不同，必须当场确认它生效），而绝大多数人从没用过——这是本篇对普通用户最实用的一句话，也是 §10 个人清单第一项。第三，也是最要紧的一条：维修后果里的判定那一格（第四行）在当事人视角是隐形的——手机修好了，功能都正常，但一周后某个服务开始反复要求验证、某个额度下调（#142 的 S1/S2）。没有人会把这两件事联系起来，因为维修发生在物理层，判定发生在服务端。 本篇要求把这条因果写进方案书（#108）：对高价值个体，维修是一次需要预先安排的风险事件，而不是随手找家店的一小时。

4. 八个核对点（全部可当场在本机验证）

  • H-P1 看设备自述。 设置 → 通用 → 关于本机：型号、名称、容量、序列/标识类信息，截图存证并记下日期。这是你唯一能免费得到的第一份口径。
  • H-P2 看部件与维修历史相关页面。 设置里与"零件与维修历史"有关的条目，是否存在、覆盖哪些部件、写的是什么，随机型与版本差异很大——本篇不给结论，只要求你当场看一次并截图（这是本篇"需当场验证"纪律的典型一格）。
  • H-P3 逐项验证受部件影响的能力。 面容 ID 录入、原彩/环境光相关开关、电池健康与循环信息、每个摄像头与麦克风、无线与蜂窝注册。验收标准是"逐项都能用"，不是"能开机"。
  • H-P4 记录所有提示原文。 任何与"未知部件/无法验证原装"有关的提示，原文截图 + 出现位置。读法见 §1：它说的是登记对不对得上，不是安不安全。
  • H-P5 索要并保存维修单据。 部位、件来源类别（原厂/售后/第三方）、serial 或部件编号（若提供）、执行方、日期。没有单据的维修，等于放弃本族唯一的证据。
  • H-P6 送修前先做数据面收敛并当场确认生效。 用系统提供的维修期间隔离能力；确认后要能说出：现在解锁需要什么、哪些数据不可达（细则归 #84）。备份按 #96 的处理规则做，不要把"备份了"当成"隔离了"。
  • H-P7 交易场景的双向核对。 买方：按 H-P1–H-P4 当场走一遍，并把归属与网络状态作为验收项（向正式渠道查询，接口 #117）；卖方：把维修档案与提示状态主动说明——隐瞒的成本最终落在交易争议上（#96）。
  • H-P8 维修后做一次更新/恢复演练。 在合适的时间点（有备份的前提下）确认这台设备仍能正常完成一次系统更新流程。改过规格的设备最容易在这一格暴露（接口 #115）。注意顺序：先备份，再演练。

判定顺序建议：H-P6 → H-P5 → H-P3 → H-P4 → H-P1 → H-P2 → H-P7 → H-P8。 送修前的两项排在最前，因为它们是唯一"错过就无法补"的动作。

三条结论：第一，本族的不可逆项比预期多：组件级绑定失效的能力不会随"再换一颗好件"回来；网络侧与判定层的登记没有过期语义。因此"修之前先问会影响哪些功能"不是一句谨慎话，而是本族唯一防止不可逆损失的动作。 第二，当事人持有的那一行（单据与截图）在技术上是全表最弱的，在争议里常常是最强的——因为其它各行都由别人保管，且互相不一致（§3.2）。第三，倒数两行是本族向 #142 递出的那根线：一次正当维修造成的属性变化，其后果之一是在一个你永远看不见的系统里长期存续。 这也是本篇把"维修档案"与 #104 巡检表并列的原因——它是把物理层与服务层串起来的唯一一份材料。

6. 七类契约违背

  • M1 提示即安全（读错方向）。#131 的"显示即属主"在本族第七次成立，且是它最容易被双向误读的一次：那行"无法验证此设备使用了原装零部件"说的是登记对不对得上，不是这台设备安不安全。两种典型错读都要写死：把一次正常维修读成被入侵（无谓恐慌、继续找店返工、甚至抹机），以及把一次真正有风险的替换读成"只是弹个提示"（比如来源不明的摄像模组，风险在物理与光学层，不在提示层）。本族的判读纪律：提示只回答"登记一致性"，安全结论要由 §4 的 H-P3 功能验收与件来源判断来给。
  • M2 属性即身份，而身份有五本账。一台设备"是什么"没有单一权威答案（§3.2）。这条是本族整个问题的成因：所有纠纷、所有误判、所有"卖家没说谎但买方觉得被骗"，都发生在拿一本账去否定另一本账的时候。
  • M3 拆解即变更。物理干预会改变设备对外声明的属性，而这件事没有任何一个界面在干预之前告知你。#134 讲"没人按下也在执行"，#140 讲"没人更新也在改变"，本族讲得最朴素：没人做任何数字操作，只是有人拧了几颗螺丝，设备的自述就变了。
  • M4 无单据即无记录。官方链路留下可查记录，非官方链路只留下一张纸。于是"维修史"这一事实在当事人世界的可见性，取决于当初为了省多少钱——这一条不是道德判断，是信息结构：没有系统会替你补上那份记录。
  • M5 不可逆被隐藏。哪些能力会因某次部件更换永久失效，这一信息只在工作台与售后系统里，送修前当事人无法从任何公开界面读到（§3.1 第二条结论）。这是本族唯一一个"事前无法知情"造成的不可逆损失，也因此是本族对供给侧最实在的一条改进要求：把"更换该部件会影响哪些功能"做成下单前可查的一项。
  • M6 判定不解释。一次维修造成的属性变化会进入 #142 的判定输入，而两个系统之间没有任何衔接：维修方不知道会影响服务可用性，服务方不解释判定与硬件的关系，用户只看见"最近很多验证"。这条断裂是本族最隐蔽的后果：它把一次消费行为转化成一个长期的、不可见的、无法申诉的外部判断（§3.3 第三条结论）。
  • M7 失败即信息。第十三次成立（#123 N6、#125 M7、#129 M7、#131 M7、#132 M7、#133 M7、#134 M7、#138 M7、#139 M7、#140 M7、#141 的 S 型、#142 的 S 型）：某项能力某天开始不可用、电池信息不再显示、面容 ID 要求重录却总失败、系统更新卡住或恢复后异常、蜂窝注册开始报错、以及修完之后"哪里说不上来但不对"。本族的 M7 与前面各族不同，它是可当场验证的（H-P3 就是为此设计），因此本篇把"修完当天做逐项验收"写成硬要求而不是建议——这是全系列少有的、当事人自己就能闭环的一族。

其中 M1、M3、M5、M6 不是软件缺陷：M1 是提示文案的表达选择（#93 的 L1，改进成本极低、收益极高），M3 是部件配对机制的固有语义（L1，其理由正当，见 §1 第二段），M5 是信息披露缺口（L3，可改），M6 是两个互不相干系统之间没有衔接（L1，属于治理问题）。M2 与 M4 处在事实结构侧：多本账各写各的、非官方链路无记录，这两条几乎无法通过任何一方"修好"，只能靠当事人自己的档案来补。所以本篇的处置重心罕见地落在两件低技术动作上：单据与验收——这两件事没有任何厂商能替你做，也没有任何设置项能替你完成。

7. 后果落点（接 #91 的后果轴）

  • C1 数据与内容外流：本族的数据风险主要是送修期间的物理暴露（设备在他人手里、解锁条件被绕过、备份被读取），细则归 #84 与 #96。本篇只登记两个本族特有的口子：一是"H-P6 没做"，即没有用维修期隔离能力就把设备交出去；二是改装与返修常伴随"恢复/刷机"环节，而该环节会把设备恢复到可读取状态（接口 #84 的解密边界）。这两格都在事前可完全消除，这是本篇个人清单把它们排在前两位的原因。
  • C2 行踪与习惯的持续采集：较弱的一格，但存在：更换涉及蜂窝或网络组件后，设备重新注册网络会产生新的运营商侧记录；此外维修期间被读取的日历、照片与位置历史会形成对方的持有（归 #137/#128 的持有规则）。
  • C3 归属与操作（不提权）：第十七种伤害形状：修一次，身份变一次。 没有攻击者、没有漏洞、没有任何人做错事：你花钱做了一次正当服务，这台设备向外部世界自证的那组属性变了。与 #142 的分界写死：#142 讲"属性进入判定之后会发生什么"，本篇讲"属性会因一次物理干预而变"——本篇是那一条因果链的上游，而且它是全系列十六种形状之外唯一一个不需要恶意存在的形状：其它形状都需要某个机制被利用，本族只需要你去修个手机。
  • C4 经济损失与交易欺诈：本族是全系列经济后果最直接的一族：电池循环数不可考、是否换过屏与摄像头难以当场判定、改装扩容机当原装卖、二手机到手发现某项能力永久失效、以及"卖方没说谎但双方看的不是同一本账"（M2）。救济靠事前验收（H-P7）与单据（H-P5），不靠技术。 接口 #117 的核查思路在物理层的对应版本就是这一格。
  • C5 可用性代价：本族包含两种失能，且都常被误归因：能力永久失效（组件级绑定的那些，H-P3 可当场发现）与激活锁/归属争议造成的整机失能（一台无法解除归属的设备，在功能与法律上都不完全属于持有者）。归 #92 的是消耗型代价；本族的失能是配置与登记型失能，#92 不接管，本篇保留。 归属争议的处置走 #117/#102 的凭证与关系侧。
  • C6 判定污染：本族不新增该格的成立次数（其正主与最近几次见 #125、#130、#131、#133、#134、#137、#138、#140、#142），但本篇给出它的物理来源：#142 里那些"设备可疑"的判断，其中相当一部分的成因是这里的一次正当维修。于是形成一条完整的污染链：一次换屏 → 属性变化 → 判定输入变化 → 分数变化 → 处置变化 → 这条处置在若干服务里以"系统显示存在风险"的形式反复出现。 链条上没有任何一环是错的，也没有任何一环会向当事人解释它是从一块屏幕开始的。 这一格赔钱的是当事人；能改善它的只有 M6 那个衔接动作（供给侧）。
  • C7 归因失效：本族的失效方式是跨层断裂——物理层的事实（换了什么、什么时候、有没有单据）与服务层的后果（功能、可用性、判定）之间没有任何共同记录，两端各自完整、连起来一片空白。#142 讲"材料在对方手里"，本篇讲的是更糟的情况：根本不存在一份材料把这两件事放在一起，除非你自己写。 这也是本篇与 #104 的合并结论：维修档案是本系列唯一一个必须由用户手工创建、且无法从任何系统导出的跨层证据。

8. 审计法与判定式

8.1 个人侧：三步（本族是唯一"事前动作重于事后排查"的一族）

  1. 送修前收敛数据面（H-P6）：使用维修期间的数据隔离能力并当场确认它生效（能说出现在解锁需要什么、哪些数据不可达）；备份按 #96 的规则做，但不要把"备份了"当成"隔离了"。
  2. 修时留下证据（H-P5 + 先问）：动手之前问一句"换这个件会影响哪些功能、有没有不可逆的"——这是防止 M5 型损失的唯一动作；然后索要并保存单据。
  3. 修完当天做逐项验收（H-P3 + H-P4）：面容录入、每个摄像头与麦克风、原彩一类开关、电池健康显示、蜂窝注册、以及一次更新/恢复演练（H-P8）。验收结果与提示原文一起归档进维修档案。

8.2 判定式（可执行、当场自证）

"我现在看到的这行提示，说的是登记对不对得上，还是说的是安全？"

三个衍生问句：

  • 这个功能今天还能不能用？（能/不能，比提示重要十倍——以 H-P3 的结果为准）
  • 这次干预动过哪些件、件从哪来、有没有单据？（答不出 = 你在放弃本族唯一的自有证据）
  • 如果这台设备明天要卖或要举证，我能拿出什么？（只有截图和一张纸——所以现在就把它存到设备之外）

8.3 组织侧：五个动作

  1. 把"送修纪律"写进设备管理：交出设备前的隔离动作、期间要求替换或借用机、返回后的逐项验收。尤其对承载业务账户与门禁凭证的设备（#101/#89），维修应视为一次设备状态变更事件。
  2. 维修必须留组织内台账：部位、执行方、日期、验收结果——离职与设备回收时（#120/#96），这份台账是归属证明的一部分。
  3. 高价值岗位走可留痕的链路：不为省一笔钱而让承载企业账户的设备进入无记录渠道（M4 的直接应用）。
  4. 不要把"未知部件"提示当安全事件开单：先做功能验收，再判定——误开的安全事件工单会污染记录（M1/C6），且让真正的问题淹没在里面。
  5. 采购与配置阶段就把可维修性算进来：电池与屏幕是必换件，其更换在贵方设备上会造成哪些能力损失，应当在选型时就问清楚（这条是 M5 在组织侧唯一可行的解法：把问题前置到买之前）。

8.4 高危个体（接 #108）

  • 把维修当成一次风险事件排期：不与关键行程、关键交易、关键任务相邻安排（失能与验证循环的恢复时间不可控）。
  • 可隔离才送出：无法在物理接触下保护数据面的设备，不要让它带着高价值身份离开你的视线；必要时用 #110 的分身设备承担维修期的业务连续性。
  • 优先可留痕链路，并保留全部单据（维修档案在争议里的效力高于任何技术解释，§5 第二条结论）。
  • 避免一切改装：扩容、改卡一类改变规格的干预，会让这台设备在更新、恢复与外部验证环节上长期处于"自述与结构不一致"的状态（#131 的律在物理层）。

9. 设备端可观测性——本篇的诚实边界

能核对的：设备自述的属性（当前值）、部件提示的存在与原文、各项能力今天能不能用（这是最硬的一类）、官方链路覆盖到的维修历史条目（是否存在、覆盖什么，随机型与版本差异很大，只能当场看）、以及你自己保存的单据。

核对不到：某颗件是否原装及其来源、上一任使用者做过什么、非官方链路的维修史、服务端保修/激活/找回登记的内容、网络侧名单状态、以及 #142 那条判定链上这台设备现在是什么样子。

必须写死的三句：第一，本族的可观测性在物理层是最差的一档，在功能层却是全系列最好的之一——你能百分之百确认"面容 ID 现在能不能用"，但完全无法确认"这台设备被打开过几次"。 所以本篇的方法论是用功能层的可见性去补偿物理层的不可见性。第二，提示不是安全结论，验收才是（M1）；把这两件事分开，是本族最重要的判读能力。第三，本族的档案无法从任何系统导出：它是全系列唯一一个必须用户手工创建、且一旦丢失（单据扔了）就永久不可重生的证据——这是本篇反复把"留单"排在"设开关"之前的原因。

10. 加固清单（按当场可验证排序）

10.1 个人

  1. 送修前用维修期间的数据隔离能力，并当场确认生效（H-P6）。验收：能说出现在解锁需要什么、哪些数据不可达。
  2. 动手前先问"会影响哪些功能、有没有不可逆的"，答案写进档案。这是本族唯一防止永久能力损失的动作（M5）。
  3. 索要并保存单据：部位、件来源类别、执行方、日期、编号（若提供）。存到设备之外。
  4. 修完当天逐项验收（H-P3）：面容录入、每个摄像头与麦克风、原彩一类开关、电池健康显示、蜂窝注册。验收以功能为准，不以提示为准。
  5. 提示原文截图（H-P4）：将来无论是转卖、保修还是被判定的申诉，它都是起点。
  6. 改过件之后安排一次更新/恢复演练（H-P8）：先备份再演练；异常时按登记不一致处理，不要反复抹机。
  7. 二手交易把上述四项当验收单用（H-P7）：买前当场走一遍，不接受的项写进交易记录（#96 的处置纪律）。
  8. 不做改变规格的改装（扩容、改卡一类）：它制造的是长期的"自述与结构不一致"，后果出现在更新、恢复与外部验证上（§8.4 末条）。

10.2 组织 / 供给侧

  1. 送修纪律入设备管理流程：隔离动作、替换机、返回后逐项验收，三件齐备才算一次完整变更。
  2. 维修台账（部位/执行方/日期/验收）纳入资产记录，与 #104 巡检表、#120 交接清单一源。
  3. 承载企业账户与门禁/支付凭证的设备，维修按设备状态变更事件处理（#101/#89/#141 的凭证复核）。
  4. 供给侧改进三条：把"更换该部件会影响哪些功能"做成下单前可查（M5）、提示文案明确写"这表示登记一致性，不代表安全风险"（M1，成本几乎为零）、非官方链路维修也给出一个当事人可自查的口径（M4）。
  5. 不要要求用户"抹机后再送修"：这是把可用性代价转嫁给当事人；应引导使用系统提供的隔离能力（与 #84 的处置纪律一致）。

10.3 高危个体

  1. 维修排期避开关键窗口；期间用分身设备承担连续性（#110）。
  2. 无法在物理接触下保护数据面的设备不带高价值身份出门（#108 的落点原则）。
  3. 只走可留痕链路，全部单据外部留存。
  4. 修完后主动观察一周内的服务侧症状（#142 的 S1/S2），并把"某月某日换过 X 件"写进时间线——那是将来唯一能解释判定变化的材料。

11. 十条常见误解

  1. "弹出'未知部件'说明我的设备被入侵/不安全了。" 它回答的是登记一致性，不是安全（M1）；安全结论由功能验收给。
  2. "只是个提示，无所谓。" 反方向同样错：来源不明的部件风险在物理与光学层，把提示一概忽略等于放弃唯一的可见信号。
  3. "能开机、能打电话就说明修好了。" 本族的损失常在能力层（面容、电池信息、原彩）与登记层，开机不覆盖这些（H-P3 的意义）。
  4. "官方查不到维修记录，说明没修过。" 那是五本账里的一本（M2）；设备上的提示与件的实际状态可以同时指向"修过"。
  5. "卖家没骗我，所以没问题。" 双方看的常不是同一本账——这不是欺诈也照样产生争议，只有当场验收能避免（H-P7）。
  6. "电池换了就和新的一样。" 换件后健康度与循环信息可能不再显示：信息缺失本身就是交易损失（C4）。
  7. "面容 ID 用不了，重录一次就好。" 若源于组件级绑定，这一项可能是永久失效，反复重录只会消耗时间并产生"设备有问题"的误判（M5）。
  8. "先抹掉数据再送修最安全。" 抹机牺牲可用性与数据，而系统提供的隔离能力本就为此设计：用隔离，不用自残（§10.2 第 5 条）。
  9. "维修和服务端那些限制没关系。" 属性变化会进入 #142 的判定输入，而这条链没有任何一环会通知你（M6/C6）。
  10. "扩容便宜，看不出来。" 改变规格的设备在更新、恢复与外部验证环节上的异常，往往在几个月后才出现，且那时你已经没有原始配置可以对证（§8.4 末条）。

12. 与既有各篇的接口

  • #142（设备证明与风控）：上下游，必须成对引用。本篇是那一条因果链的物理起点：一次正当维修 → 属性变化 → 判定输入变化 → 处置变化；#142 讲后半段。
  • #96（设备流转与退出边界）：同一台设备的两面——那一篇管数据侧处置，本篇管部件与登记侧后果；二手交易时两份清单要一起用（H-P7）。
  • #84（锁屏、生物识别与强制解密）：送修期间数据暴露的机制与边界在那一篇；本篇只负责把"维修前必须收敛数据面"变成交付动作（H-P6）。
  • #121（配件与有线连接）：外部物件接入 vs 内部物件替换，共用"物件即属性"的律。
  • #131（标识与呈现）：部件提示是"显示即属主"律最字面的案例（第七次成立，M1）；呈现机制与判读方法归 #131，本篇给读错它的两种代价。
  • #124（密码学与密钥生命周期）：组件级绑定失效在密码学上等价于更换信任根；那一篇解释为什么不能靠软件恢复，本篇说明用户会把它误读成"手机坏了"。
  • #115（软件更新链）：改过规格的设备在更新与恢复环节的异常是主要暴露面（H-P8）。
  • #117（理赔与欺诈核查）/#102（数字遗产与紧急访问）：归属证明与凭证要求在这两篇里最硬的实物场景；激活锁争议完全走这两篇的关系侧路径。
  • #101/#89（门禁、钱包凭证）：承载物理入口与支付凭证的设备，维修应视为状态变更事件并复核凭证。
  • #104（季度巡检）/#110（多身份与备用设备）/#108（高危个体方案书）：维修档案并入巡检表；分身设备承担维修期连续性；"被误伤"在 #108 的威胁模型里现在有了第二个来源：#142 的判定与本篇的维修。
  • #107（撤销不对称，本族成立但不新增计数）/#91（后果轴，第十七种形状）/#92（C5 属登记型失能，本篇保留不交还）/#93（M1/M3/M5/M6 归 L1/L3）/#78·#116（C7 跨层断裂：两端各自完整，连起来空白）。

13. 总结

本篇把二十八根竖条里唯一发生在物理层的一根测绘成表：H1 物理干预（跨层属性变更事件，而"哪些能力会永久失效"送修前当事人无法读到）、H2 身份与登记（结构性问题所在：一台设备的"是什么"是五本互不同步的账）、H3 后果（救济错位：功能后果当场可验、登记后果要正式渠道、判定后果几乎无法救济）。三个不可回避的结论是：这一族不是缺陷而是信息结构——部件配对的限制有其正当理由（假冒件、翻新件、盗机拼装），但它的三项外部性（维修史不可携带、对买方不可查询、对判定层不可解释）没有任何一方负责补齐；它的伤害形状是修一次、身份变一次，全系列唯一一个不需要恶意存在的形状；以及它的处置全部落在两件低技术动作上：单据与验收——这两件事没有厂商能替你做，也没有设置项能替你完成，它们是当事人世界里仅有的两项确定资产。

它与最近七篇构成一条完整链条：#138 问你亲手搭的链在替谁执行，#139 问你装进来的那块内容会被读成什么，#140 问行为在你不知情时由谁改掉，#141 问"证明你是你"依赖哪些物件与身体，#142 问这些物件如何反过来替你被定罪，#143（本篇）问一次正当的维修怎样改写这台设备的自我陈述。 七篇合起来是同一件事的七个维度：执行序列、送达内容、下发决策、身份凭证、设备判据、物理部件，是彼此独立的层，而当事人手里连接这些层的材料，从头到尾只有一张维修单和几张截图。
