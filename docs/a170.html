Coruna 与 DarkSword 场景下的跨境取证与司法协助：数据在谁手里、谁能取、以及时间为什么是主要成本

1. 执行摘要

  • 这一篇处理一个几乎每起本族事件都会撞上、却很少被提前规划的问题：关键证据不在你的法域里。账户记录在服务商的境外机房、投递域名注册在另一个国家、运营商日志由第三国公司持有、受害者是跨境出差的员工——而你能直接命令的只有自己机房里的那几台服务器。前二十篇里，#105 处理"服务商收到合法请求会不会给"，#117 处理"民事理赔方要你怎么配合"，#169 处理"向本国主管部门报送什么"。没有一篇处理中间那一段：你需要的材料在境外，而取它的通道不由你控制。
  • 核心命题一：跨境取证的瓶颈不是法律难度，是日历。 一条司法协助请求从起草到收到回执，公开讨论中的常见量级是数月；而本族事件的证据半衰期以天计（#116 的证据衰减表）。这两条时间尺度差了两个数量级，因此任何"等材料回来再判断"的方案，在它开始执行的那一刻就已经失败了。
  • 核心命题二：保存与调取是两件完全不同的事，而多数人只做后者。 向服务商发一份保存请求（要求其冻结某账号、某域名在某时段的记录，不要求交出内容）通常快得多，且在很多情形下不依赖司法协助；而调取（要求其交出内容）才需要完整程序。只做调取、不做保存，等于在等一份正在被自动删除的材料——本族事件的日志保留窗口常短于程序周期（#167 的 90–180 天条款正是为此设的）。
  • 核心命题三：证据能力分三级，而多数组织在错误的那一级上花了全部预算。 内部判断（谁被命中、影响了什么）只需要你自己能看到的东西；民事诉讼需要可被对方质证的东西；刑事程序需要符合取证规范的东西。三级的要求逐级上升、可复用性逐级下降。先明确你要的是哪一级，否则会用刑事级的标准去做一份内部判断，或者用内部判断的材料去打一场需要质证的官司。
  • 核心命题四：等待期不是空档，是唯一能完成"不依赖他法域"的动作的窗口。 冻结自己的日志、固化时间线、分离已确认与待确认、给受影响人一个不需要等材料的处置方案——这五件事全部在你自己的边界内（第 7 节），而且它们的价值会随时间下降：晚一天做，能做出来的东西就少一天。
  • 核心命题五：最容易犯的错都发生在等待期，而且都不可逆。 为了"先弄清楚"而重启设备、为了"减少暴露"而清除账号、为了"配合调查"而把原始材料导成截图、为了"尽快恢复"而用旧备份回滚——这四件事各自都会永久销毁一条本可以等的证据（第 8 节）。
  • 一句正向结论：跨境场景的正确姿势是"两条并行的时间线"：一条由你控制、在 72 小时内跑完；另一条由他法域控制、以月计。前一条负责不让局面恶化，后一条负责补齐归因。把两者串成串行流水线，是本族跨境事件最常见的结构性错误。

2. 这一篇补哪一格

#105 处理的是云端数据的合法获取边界：数据在哪、谁拿得到、保护层级与密钥托管如何决定"云端副本是否可产出"。那一篇站在"请求方与被请求方"的制度视角，回答的是能不能给。

本篇站在受害组织的视角，回答的是什么时候能拿到、拿到的东西能用来干什么、在拿到之前做什么。三个问题的答案都不是法律问题，而是时间与流程的工程问题。

#117 处理的是民事理赔与第三方调查方的索取：索取强度的 S1/S2/S3 阶梯、可替代材料、反向风险。那一篇的对手是合同相对方，压力来自合同违约；本篇的对手是日历，压力来自证据在消失而程序没走完。

#169 与 #175 处理的是出口侧的两条通道（报送与公开披露）。本篇处理的是入口侧：材料从境外进来的那条路。三者合起来才是一张完整的"证据流"图：进来靠本篇，出去靠那两篇。

3. 为什么时间是主要成本：三个并行的时钟

一起跨境事件里，至少有三个时钟同时在走，而它们的速度差了两个数量级。

时钟起算点典型量级谁在走它你能否加速
证据时钟事件发生（往往早于你知悉）以天计；部分日志以小时计服务商与运营商的自动轮转、设备自身的写入只有保存请求能停住它，且必须在轮转之前
业务时钟你知悉的那一刻以小时到天计业务连续性、客户信任、合同 SLA（#173）能，但加速的代价是取证质量
程序时钟你决定走跨境程序的那一刻以月计他法域的司法机关、中央机关、服务商的响应队列几乎不能；只能提前准备、减少往返

三个时钟的相互关系决定了一切战术：

  • 证据时钟最快、程序时钟最慢，因此"先保存、后调取"不是建议而是唯一可行的顺序。
  • 业务时钟与证据时钟竞争同一批资源：要求立刻恢复业务的压力，往往正是要求"清除感染、重装、回滚"的压力，而这些动作会停掉证据时钟能给你的一切（#166 的清除判定与复机验收标准正是在这一对张力上写的）。
  • 程序时钟的不可压缩性，意味着你必须在事件之前就把通道准备好：谁是你所在法域的联络律师、哪些服务商有公开的执法请求入口、哪些国家的程序走得更快——这些知识如果在事件当周才开始收集，你就已经落后程序时钟一个月了。

一个反直觉的推论：跨境事件里，"什么都不做、等程序走完"通常比"边等边做一些看起来无害的清理"更安全。因为清理是不可逆的，而等待只会让你丢掉那些本来也留不住的东西（除非你先做了保存请求）。

4. 数据在谁手里决定谁能取：四类所在地

同样的"账号记录"，落在四个不同的位置，可获取性差一个数量级。

类型典型持有者典型位置你能直接要求吗主要通道
A. 你自己的系统你的服务器、你的 MDM、你的邮件网关你能控制的机房/云能内部流程 + 你与云厂商的合同（#167）
B. 消费级平台账号平台服务商（iCloud、邮件、协作工具）服务商全球基础设施，落盘地由其策略决定不能平台自身的执法/数据请求入口；跨境时叠加 #105 的制度问题
C. 基础设施层注册商、DNS、CDN、托管商、VPS常与他法域重叠，且层层转租不能保存请求 + 司法协助；常需逐层穿透（#162）
D. 运营与接入层电信运营商、企业专线、酒店与机场 Wi-Fi各司法辖区本地不能本地程序为主，跨境只覆盖用户归属地

四类的处置逻辑完全不同，而事件中最常见的错误是用 A 类的直觉去处理 B/C/D：以为"发一封邮件要求配合"就够了。恰恰相反：

  • A 类是你唯一能在半小时内冻结的，因此它必须在事件第一小时就完成（第 7 节的第一件事）。
  • B 类多数有标准化的自助入口，其中"保存"与"调取"往往分开申请，且"保存"的响应快得多。把 B 类当成纯法律问题，会让你在最有价值的头两天里什么都不发。
  • C 类最容易断层：域名注册商、DNS 提供商、CDN、实际托管方常常是四家公司，跨三个法域（#162 的水坑链路服务商协作与此同构）。穿透链条要提前画好，因为事件中你不会有时间重新查 Whois 的每个层级。
  • D 类的留存期最短、覆盖最碎，而且往往需要受害者本人而不是组织去申请。这一点决定了：跨境出差的员工在出发前就应该知道自己该做什么（#109 的行程三段式），而不是在回国后补。

5. 保存与调取：两个动作，两种速度

这是本篇最实用的一节，也是最容易被跳过的一节。

维度保存请求（Preservation）调取请求（Production / Disclosure）
目的阻止数据在轮转中被删除把数据交到你手上
需要的程序多数情形下只需平台内部流程或一封合规请求通常需要法律程序；跨境时叠加司法协助
典型响应快（数小时到数日）慢（周、月至数月）
有效期有，通常需要定期续期无（一次性）
谁可以发组织自身常可发；个人在部分平台也可自行发起多数需要适格主体，跨境时需经法定通道
常见失败忘了续期，材料在第 N 天后被释放在保存之前就发了调取，回来的是空壳

四条操作纪律：

  1. 对每一个 B/C 类对象，先发保存、再谈调取。 保存请求不丢人、成本低、且不构成对任何人的指控；它只是"请别删"。
  2. 保存有期限，必须记进日历。 把"续期日"写进事件时间线（#116 的时间轴），并指定一个人负责续。
  3. 保存请求里要写清范围与时段，而不是诉求。 "请保存账号 X 自某日至某日的登录、认证与邮件元数据"比"请协助调查"有效得多。
  4. 保存不产生证据能力，但产生"以后能调取"的前提。 它解决的是第 3 节那条"证据时钟"，不是"程序时钟"。

一句话：保存是你能控制的唯一一段证据时针，调取不是。

6. 司法协助的四种通道与各自的量表

跨境获取材料在公开讨论中一般被归纳为四条通道。它们的速度、适用条件与"你作为受害组织能推动的力度"各不相同。

通道大致适用速度量级受害组织能做什么主要风险
司法协助请求（中央机关转递的正式请求）需要当地强制力才能取得的材料月级提供精确、完整、可被直接采纳的请求材料，减少往返材料写得含糊导致多次补充，每次补充都是一轮月级等待
执法直接协作（对口单位之间的快速通道）紧急情形、有明确对口关系周级（不保证）通过本国执法提出，附完整时间线是否进入快速通道不由你决定
服务商的执法请求入口B 类平台账号天到周如实提交、按格式提交与跨境程序叠加时谁来提交、提交给谁
当事人自愿提供 / 合同路径你有权要求的一方（供应商、外包、关联方）天级直接依合同主张（#167 的协查义务）只覆盖合同相对方，不覆盖平台与运营商

由此得到三条判断规则：

  • 优先找"不需要强制力"的那条。 凡是持有者自愿就能给的（合同相对方、你自己委托的服务商、员工本人同意的个人账号），都应当先走合同与同意路径，因为它们是以天计的。
  • 强制力通道的成败，八成取决于你提交的材料质量。 一份写清"要什么数据、什么时段、为什么与本案相关、以什么格式"的请求，与一份只写"请协助调查一起网络攻击"的请求，往返次数可能差三倍。这部分的准备工作完全在你手里，且应当在事件之前就有模板。
  • 不要在等待中反复补充同一件事。 每补充一次，程序时钟就重置一次方向；把"可能被问到的问题"一次性答完，是缩短程序时钟的唯一杠杆。

7. 等待期不能等的五件事（全部在你自己的边界内）

这五件事不依赖任何他法域，且价值随时间下降，因此应当在 72 小时内跑完（与 #166 的处置时间线对齐）。

#动作为什么必须现在做验收信号
1冻结 A 类日志与时间同步你自己的日志也在轮转；且时钟不同步会让后面所有时间线无法拼接关键系统日志已转存到独立介质，各源时钟偏差已记录
2固化一条"只增不改"的事件时间线事件中新建的表格会被反复改写；先写下的原始记录才可作内部依据时间线只追加、带来源字段（谁说的、来自哪个系统）
3把所有材料分成"已确认 / 待确认 / 已排除"三栏与 #151 的三栏陈述同构；它让"等材料"期间的所有沟通都不越界每一栏都能说出"依据是什么"
4对受影响人给出一个不依赖归因的处置方案受影响人不需要知道是谁干的，就需要知道现在该做什么（#150 的处置动作）处置方案已发出，且明确"后续可能更新"
5把 C 类的穿透链条画出来并发保存请求这是唯一能在程序时钟启动前停住证据的动作（第 5 节）每一层都有联系人、请求编号、续期日

这五件事的共同点：它们的产出不因"后来发现是误报"而作废。 一条干净的时间线与一份干净的处置方案，在事件被证伪之后仍然是你下次的基础资产。

8. 等待期最容易犯的三个不可逆错误

错误看起来的理由实际销毁了什么正确替代
重启或重装受害设备以"先让它干净"业务要恢复、用户要能用内存态、未落盘的临时文件、部分开启的文件句柄、崩溃与内核记录（#116 的第一条硬规则）先隔离网络、保持开机、做只读快照，再决定（#166）
清除账号、重置密钥以"减少暴露"怕攻击方还在用登录历史、会话与令牌的留存、服务商侧的异常行为观测先导出记录、再按 harm 排序撤销（#99 的"先记录后撤销"）
把原始材料导成截图/转录件方便传阅、方便给律师元数据、时间戳、完整性与可核验性（#117 的"给话/给数据/给载体"阶梯）保留原始载体，另做派生件；派生件标注来源

三者的共同结构是："为了马上安全"而做的动作，恰恰消掉了"以后能说清楚"的能力。 在跨境事件里这一点被放大了，因为你等材料的时间长，中途"做点什么"的冲动也强。

9. 证据能力的三个分级

跨境材料的用途决定你该付出多少成本。三级之间的差距不是"好一点/差一点"，而是能不能用。

级别用途最低要求常见不足何时够用
L1 内部判断决定处置动作、决定是否升级、决定对谁说什么你自己能看到的记录 + 说得清来源单源、无时间同步、来自二手转述事件早期、需要快速决策时
L2 民事可用向对方主张违约金/赔偿、向保险人证明损失（#168）可追溯到原始系统、有时间基准、有保管链说明只有截图、只有平台导出的汇总报表与合同相对方、保险人交涉时
L3 程序可用刑事程序、监管调查、需要被质证符合取证规范、原载体完好、保管链完整可陈述在 L1 阶段就被"整理"过决定追责或进入正式程序时

关键判断：L3 的达成几乎不可事后补救。 如果在事件第一周就把设备重装、把日志导出成 Excel、把账号清干净，那么无论后来花多少钱，都回不到 L3。因此分级不是"以后再说"，而是"现在决定要不要保留那条路"：

  • 如果事件可能在数月后进入刑事或监管程序（本族的高价值目标场景下这是常态），那么第一周就必须按 L3 的保留要求行事，即使当下只需要 L1。
  • 如果事件确认只是钓鱼误报、且无第三方受损，按 L3 保留的成本可以按比例下降——但"不重启"这一条不应下降，因为它的成本几乎为零。

10. 跨境场景的七个现实约束

这些约束无法通过努力消除，只能被提前接受并纳入方案。

  1. 你无法加速他法域的程序。 任何以"我们能推动对方"为前提的计划都是脆弱的；计划里必须有"材料晚到三个月"的分支。
  2. 你不是程序的当事人。 你提供材料、陈述损失，但程序的节奏与结果不由你掌握；因此不要把组织的对外表述建立在"程序结果"上（#151 的 B2/B3 分级正是为此）。
  3. 不同法域对"数据出境"的限制是双向的。 你把材料交给境外律师、境外取证方，本身也可能触发你所在法域的限制（#169 的报送与共享边界在此同样适用）。
  4. 服务商的实体分布与法律辖区不总是一致。 合同主体在 A 国、机房在 B 国、母公司所在 C 国，请求要发给谁是一个需要提前查清的问题。
  5. 运营层证据往往只覆盖"某一段"，而不是"某一个人"。 运营商日志能证明连接，不能证明访问了什么；指望它回答"他拿了什么"会落空。
  6. "境外"也包括你自己的境外分支与境外员工。 同一个组织在两地，内部调取也会撞上数据出境规则。
  7. 时间越长，口径越难统一。 三个月后不同人给出的数字会不一致；这就是为什么第 7 节的"只增不改的时间线"必须在第一周就建立。

11. 加固清单（事前准备，全部可在平静期完成）

#准备项产出物完成标志

2为 B 类平台整理"执法/数据请求入口"清单一张表：平台 → 入口 → 保存/调取是否分开 → 主体资格要求至少三家主力平台已核实

4准备"保存请求"模板与"司法协助请求"素材模板两份可填空的文档含范围、时段、格式、联系人与续期规则
5建立日志转存与时钟同步的常态机制独立的日志存储与时钟偏差记录任何时候都能给出"某日某时"的一致版本
6在出差流程中前置个人侧取证常识（#109）出发前清单里增加"设备与账号如何保留现场"出差人知道出事时不要做什么
7把"跨境材料可能晚到"写进沟通口径三栏陈述的模板中预留"待境外材料"一栏对外沟通不因材料缺口而失信
8每年走一次桌面推演，只演"等待期"一份演练记录与改进项演练中不出现重启、清除、导出截图这三个动作

12. 八条常见误解

  1. "我们有全球律师，所以程序会快。" 律师能提高材料质量、减少往返，但无法压缩他法域机关的排队；把律师当成加速器会在第一次月级等待时被打回原形。
  2. "先把设备恢复了，证据以后再说。" 恢复是不可逆的，而且恢复动作恰好覆盖证据密度最高的那几个区域；这是本族跨境场景里最常见、最贵的一个决定。
  3. "保存请求没用，反正最后要调取。" 没有保存就没有可调取的对象；日志按天轮转，程序按月推进，两者一交叉，回去的就是空壳。
  4. "平台后台能导出，就等于拿到了证据。" 导出件通常是汇总报表，缺原始事件、缺时间基准、缺保管链说明，且大量平台导出件不含被删改与否的校验信息；它至多支撑 L2 的一部分。
  5. "跨境取证是法务部门的事。" 保存请求、日志冻结、时间线固化全部是 IT 与安全团队的活；法务只能处理"调取"那一半。
  6. "等材料回来再告诉受影响的人。" 受影响人的处置不需要归因（第 7 节第 4 项）；等三个月再通知，是把一个技术事件升级成信任事件。
  7. "我们不是当事人，所以不用准备材料。" 受害组织在多数程序里以"提供材料的一方"出现，材料质量直接决定程序能不能用得上你给的东西。
  8. "境外就等于更慢，没有别的差别。" 真正的差别是不可控：你不知道何时回、不知道会回来什么格式、不知道会不会被要求补充——因此方案必须是分支式的，而不是线性期待。

14. 总结

问题一句话答案
跨境事件的主要成本是什么日历：证据以天计、程序以月计
第一件该做的事发保存请求并冻结自己的日志，而不是发调取请求
等材料期间做什么五件不依赖他法域的事（第 7 节），全部在 72 小时内
什么绝对不能做重启/重装、清除账号、把原始材料导成截图
要保留到哪一级先判断最坏情况下需要哪一级（L1/L2/L3），再决定第一周的保留力度
什么可以提前准备律师、平台入口清单、穿透链条图、两份请求模板、日志与时钟机制

把跨境取证当成一条以月计的慢线，把处置与沟通当成一条以小时计的快线——两条线并行，而不是串联。

  • 本篇是防御与准备视角的流程分析，不提供任何规避取证、规避调查或在明知材料将被调取时销毁材料的做法；文中"不要重启/不要清除"的理由是保留可核验信息，与妨碍程序无关。
