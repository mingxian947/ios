Pegasus 攻击链总体结构

编制日期：2026-10-13 数据来源：Citizen Lab、Amnesty Tech、Google TAG、Apple Security、公开安全研究 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

Pegasus 是由以色列 NSO Group 开发的商业间谍软件，被公认为全球最复杂的移动端攻击平台。其攻击链不是单一漏洞利用，而是一个工程化的多阶段系统，涵盖投递、初始访问、提权、驻留、数据采集、外传、C2 通信等完整功能模块。

本文从系统架构视角解析 Pegasus 攻击链的总体结构：

  1. 攻击链分层架构：从投递到清除的完整功能栈
  2. 各代攻击链结构对比：Trident → ImageIO → FORCEDENTRY → M.O.
  3. 核心模块解析：投递层、利用层、驻留层、采集层、C2 层
  4. 模块化设计：Pegasus 的插件化架构
  5. 反检测体系：环境感知、自毁、反取证
  6. 基础设施架构：C2 服务器、域名轮换、代理网络

核心结论：Pegasus 的攻击链是一个高度工程化的软件系统，其设计思想（模块化、环境感知、反取证）对理解高级威胁架构具有重要参考价值。防御方需从系统层面理解攻击链，才能在每一层设置有效阻断。

2.2 各层职责

层职责关键特性
L0: 反检测贯穿全链，保护自身不被发现环境感知、自毁、反取证
L1: 投递将载荷送达目标设备零点击/1-click、多通道
L2: 初始利用获得首个代码执行点解析器漏洞、内存破坏
L3: 提权/逃逸从受限进程到完全控制多漏洞串联、PAC 绕过
L4: 驻留持续控制目标设备文件/内存/进程注入
L5: 采集提取目标敏感数据静态/实时、加密资产
L6: 外传将数据安全传回 C2加密、隐蔽、低速
L7: C2远程指挥控制DGA、代理、操作员控制

3. 各代攻击链结构对比

3.1 第一代：Trident（2016，1-click）

[投递] SMS 钓鱼链接 → 用户点击
        ↓
[利用] WebKit 漏洞（CVE-2016-4655）→ 信息泄露
       + 内核漏洞（CVE-2016-4656）→ 内核提权
       + 内核漏洞（CVE-2016-4657）→ 代码执行
        ↓
[驻留] 文件系统驻留（隐藏目录）
        ↓
[采集] 消息/通话/照片/位置/钥匙串
        ↓
[外传] HTTPS → C2 服务器

特点：

  • 需要用户点击链接（1-click）
  • 3 个漏洞串联
  • 文件系统驻留
  • 首次被公开披露（Citizen Lab / Lookout）

3.2 第二代：ImageIO 零点击（2018–2019）

[投递] iMessage 发送恶意图片/视频 → 无需用户交互
        ↓
[利用] ImageIO 解析漏洞 → 代码执行
       + 沙箱逃逸 → 脱离渲染进程
       + 内核提权 → root 权限
        ↓
[驻留] 文件系统驻留 + 进程注入
        ↓
[采集] 消息/通话/照片/位置/钥匙串
       + 实时监听（麦克风/摄像头）
        ↓
[外传] HTTPS + DGA → C2 服务器

特点：

  • 零点击（无需用户交互）
  • iMessage 投递（利用预渲染机制）
  • ImageIO 解析漏洞
  • 实时监听能力

3.3 第三代：FORCEDENTRY（2021）

[投递] WhatsApp 视频通话 → 无需用户交互/接听
        ↓
[利用] CoreText 字体解析（CVE-2021-30860）→ 代码执行
       + 沙箱逃逸 → 脱离渲染进程
       + 内核提权 → root 权限
        ↓
[驻留] 文件系统驻留 + 进程注入
        ↓
[采集] 全量数据 + 加密消息（Signal/WhatsApp）
       + 实时监听
        ↓
[外传] HTTPS + DGA + 合法服务 → C2

特点：

  • 零点击（WhatsApp 无需接听）
  • CoreText 字体解析（非 WebKit）
  • 可提取加密消息内容
  • 被 Apple 修复后引发全球关注

3.4 第四代：M.O. 非感染模式（2022+）

[投递] 水坑网站 / iMessage → 触发利用
        ↓
[利用] 多个零日 → 临时代码执行
        ↓
[驻留] 无文件驻留（内存驻留）
       + 不写入文件系统
       + 重启后清除
        ↓
[采集] 实时采集 + 即时外传
        ↓
[外传] 即时外传 → C2
        ↓
[清除] 自动清除所有痕迹

特点：

  • 无持久化（不在设备上留下文件）
  • 重启即清除
  • 降低检测风险
  • 需要每次重新攻击
  • 针对 Lockdown Mode 的适应

4. 核心模块解析

4.1 投递层（Delivery Layer）

功能：将初始载荷送达目标设备。

模块机制交互需求
iMessage 投递利用 iMessage 预渲染/解析0-click
WhatsApp 投递利用 VoIP 呼叫/媒体处理0-click
水坑投递恶意网页 + WebKit 漏洞1-click
SMS 钓鱼短链接 → 恶意网站1-click
邮件钓鱼恶意链接/附件1-click

设计特点：

  • 多通道冗余（一个被封，切换另一个）
  • 零点击优先（成功率低但隐蔽性高）
  • 社会工程辅助（1-click 配合钓鱼）

4.2 利用层（Exploitation Layer）

功能：利用漏洞获得代码执行。

模块漏洞类型目标组件
WebKit/JSC类型混淆、UAF、OOBSafari/WKWebView
CoreText字体解析溢出PDF/文档渲染
ImageIO图像解析溢出图片/视频处理
IOKitUser Client 内存破坏内核驱动
内核内存管理、竞态条件XNU 内核

设计特点：

  • 多漏洞储备（按需使用）
  • 漏洞轮换（暴露后切换）
  • 链式利用（多个漏洞串联）

4.3 驻留层（Persistence Layer）

功能：在目标设备上维持持续访问。

模式驻留方式检测难度重启存活
文件驻留隐藏目录/文件中✓
进程注入注入系统服务高✓
启动项修改启动配置中✓
无文件内存驻留极高✗

设计特点：

  • 多模式支持（按客户需求选择）
  • M.O. 模式无持久化（降低检测）
  • 进程注入隐藏于系统服务

4.4 采集层（Collection Layer）

功能：提取目标设备上的敏感数据。

模块采集目标方式
消息采集iMessage/SMS/邮件数据库读取
通话采集通话记录/录音系统 API + 麦克风
联系人通讯录数据库读取
照片/视频相册文件系统读取
位置GPS/网络位置位置 API
钥匙串密码/凭证Keychain API
App 数据WhatsApp/Signal/Telegram数据库读取 + 内存提取
实时监听麦克风/摄像头设备 API

设计特点：

  • 模块化采集（按需启用）
  • 加密消息提取（从内存/数据库）
  • 实时+静态双模式

4.5 C2 层（Command & Control）

功能：远程指挥控制受感染设备。

模块功能
C2 服务器接收数据、发送指令
DGA动态生成域名（防封禁）
代理网络多层代理（隐藏真实服务器）
操作员控制台人工操作界面
任务调度自动/手动任务分配

设计特点：

  • DGA 防封禁（域名持续轮换）
  • 多层代理（溯源困难）
  • 操作员友好（GUI 控制台）

5. 反检测体系

5.1 环境检测

Pegasus 在执行前进行环境感知：

检测项目的反应

调试检测避免被安全研究者分析中止

iOS 版本选择匹配的漏洞调整利用链

语言/时区确认目标身份中止/继续

6.1 C2 服务器

操作员控制台
        ↓

        ↓

        ↓

设计特点：

  • 多层代理（溯源困难）
  • DGA 域名（防封禁）
  • 分布式部署（全球多地）

6.2 DGA（域名生成算法）

种子 + 日期 → 算法 → 生成域名列表
        ↓
受感染设备尝试连接
        ↓
攻击者注册其中一个域名
        ↓
建立 C2 连接

特点：

  • 域名持续轮换
  • 无法提前封禁
  • 需要威胁情报追踪

6.3 域名伪装

技术说明
相似域名类似合法服务的域名
CDN 伪装使用 CDN 隐藏真实服务器

8. 攻击链与防御映射

8.1 各层防御

攻击层防御措施效果
投递层网络过滤、用户教育阻断 1-click
利用层Lockdown Mode、及时补丁阻断 JIT/解析器漏洞
提权层SPTM/TXM、PAC提高提权难度
驻留层安全启动、APFS 快照检测文件驻留
采集层Data Protection、SEP保护敏感数据
外传层网络监控、DGA 检测检测异常通信
C2 层威胁情报、域名封禁阻断 C2 通信
反检测运行时检测、MVT发现隐藏威胁

8.2 阻断点分析

攻击链：投递 → 利用 → 提权 → 驻留 → 采集 → 外传 → C2

阻断点：
  [1] Lockdown Mode → 阻断利用层（JIT/解析器）
  [2] 及时补丁 → 阻断利用层（已知漏洞）
  [3] SPTM/TXM → 阻断提权层（内核提权）
  [4] 网络监控 → 阻断外传层（DGA/异常流量）
  [5] MVT 检测 → 发现驻留层（文件/进程）
  [6] 威胁情报 → 阻断 C2 层（域名封禁）

9. 总结

Pegasus 攻击链是一个高度工程化的多阶段系统：

维度现状
架构7 层功能栈 + 模块化插件
演进4 代（Trident → ImageIO → FORCEDENTRY → M.O.）
投递零点击优先（iMessage/WhatsApp）
利用多漏洞串联（3–5 个零日）
驻留从文件驻留到无文件驻留
采集全量数据 + 加密消息 + 实时监听
反检测环境感知 + 自毁 + 反取证
C2DGA + 多层代理 + 操作员控制台

对防御的启示：

  1. 系统层面理解：需从整体架构理解攻击链
  2. 多层阻断：在每一层设置防御
  3. Lockdown Mode：最有效的单点防御
  4. 威胁情报：追踪 DGA/C2 基础设施
  5. 运行时检测：发现无文件驻留

对未来威胁的展望：

  • 攻击链将更加模块化/自动化
  • AI 辅助攻击可能降低门槛
  • 无文件/无驻留将成为主流
  • 需要更强的运行时检测 + 行为分析
