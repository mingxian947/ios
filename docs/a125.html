iOS 定位与传感器子系统的攻击面：设备没被攻破，它也知道你在哪、在做什么

1. 执行摘要

  • 这一族的名字应该叫"采集与推断的问题"，不叫"传感器漏洞的问题"。绝大多数真实伤害来自授权语义与融合推断被误用，不需要任何内存安全缺陷；因此 #79 那条硬化曲线在这里几乎不生效（同 #81 的 3.8/3.9 两格）。
  • 三层切分：F1 物理与信号层（GNSS、Wi-Fi/蜂窝可见性、蓝牙广播、UWB 测距、MEMS 传感器、麦克风/摄像头电气通路）、F2 系统与融合层（解算、围栏几何、坐标↔地址反查、时间戳与新鲜度、把多来源合成一个结论）、F3 语义与授权层（档位、精确位置、指示器、HealthKit 分组、系统服务消费项）。缺陷密度在 F2/F3；F1 不是缺陷而是性质——信号没有身份概念，也就没有"修好"的那一天。
  • 六个"到达即采集/推断"的触发点 T1–T6。最反常识的两个：T3 原始运动与环境传感器不进授权模型、也不点指示灯（活动识别与计步才需要"运动与健身"），以及 T2 定位的一部分在你的设备之外完成，那些查询本身就是"我在这一带"的披露，留存与用途端侧不可见。
  • 十个来源族的"缺陷倾向 × 谁能修 × 个人能关吗"表里，个人真正能关的只有三类：权限档位、精确位置、系统服务消费项；原始运动/环境量与信号层的欺骗不在可关闭集合内，只能由策略更新或环境改变处置。
  • 七种反复出现的契约被违反模式 M1–M7：来源即位置、授权即语义、新鲜度假设、名字与对象分离、融合不可归因、指示器即完整可见、失败即信息。M5/M7 是本篇的硬结论：推断出来的字段追不回当初那次同意，权限被拒后还能换成不需同意的代理量得出同一结论。
  • 后果分两种，处置手段完全不同：采集/披露类落在 #91 的 C2 且不可召回（服务端与下游已留存）；判定污染类落在 C6，伤的是别人的记录（考勤、门禁、理赔、执法轨迹），需要的是提前留证而不是事后关闭。
  • 端侧可观测性是本系列最弱的一档之一：指示器与隐私报告只覆盖摄像头/麦克风/定位这几类，运动与环境传感器基本不留工件。所以本篇的处置原则是"用降级代替发现"。
  • 对个人最有用的两个动作不是"关权限"，而是给推断链降级（精确位置 + 系统服务逐项）和把位置当对外披露来管（哪个出口、留存多久、谁能引用）。

2. 这根竖条补的是哪一块

系列里已经有多根竖条碰到过"位置"和"传感器"，但都不是从这一层的实现缺陷出发：

已有它回答的问题本篇不重复的部分
#20 / #23间谍软件能采集哪些数据类别（能力清单）不讲采集能力与战术，只讲这一层的授权语义、融合与判定缺陷长什么形状
#26 / #72基带与无线固件的远程边界不触碰射频固件实现；本篇从"信号被软件解释成位置"之后开始
#87视觉/语音/键盘等语义输入通路输入通路是"别人往系统里喂什么"；本篇是"系统从物理量里推出什么"
#88微架构侧信道（不需要漏洞也能拿到比特）那是 CPU 执行泄漏；这里是传感器与位置的采集与融合
#89 / #101支付凭证与车钥匙/门禁凭证的信任链本篇只在"广播即身份"这一点上与之相接，其余不重复
#95追踪与指纹：谁在观察你、能不能关掉那篇是隐私面与可关闭性诚实表；本篇是实现层缺陷族 + 归属与审计
#118 / #123字节到达即被解析传感器不解析外部字节，它生产字节；风险来源与缺陷类别不同

一句话：这是"物理量→结论"这条链的测绘，不是"外部输入→解析"那条链。

3. 一次定位、一次采样触发的三层

层里面有什么归属缺陷密度
F1 物理与信号GNSS 卫星信号；周边 Wi-Fi 网络名与接入点可见性；蜂窝小区；蓝牙广播（含 iBeacon 类标识）；UWB 测距；MEMS 器件（加速度、陀螺、磁力、气压、环境光）；麦克风与摄像头的硬件通路不在这台设备的软件里：信号本身没有身份、没有完整性、没有"谁发的"这个概念低（不是 bug），但是唯一无法由一次软件更新关闭的一层
F2 系统与融合位置解算与首次修复、围栏几何与边界判定、坐标↔地址反查、精度与新鲜度字段的传播、多来源合成"你在哪/你在做什么"的推断、活动识别与计步的阈值Apple（系统实现）+ App 自己的二次融合最高：边界舍入、样本乱序、精度不传播、缓存当现值
F3 语义与授权授权档位（关闭 / 询问一次 / 使用期间 / 始终）、精确位置开关、状态栏指示器与隐私报告、"运动与健身"与 HealthKit 的分组、系统服务消费项（重要地点、基于位置的建议与广告、警报、查找网络、路线与交通）Apple、开发者、用户三方共同持有高，且几乎全是 #81 里的逻辑/授权误用类——硬化对它无效

要点：F1 决定"这件事永远不能被完全相信"，F2 决定"结论会不会算错"，F3 决定"这算不算越界"。多数事故是 F3 的问题被当成 F1 的问题（"定位怎么可能错"）或者反过来（"我关了权限它怎么还知道"）。

4. 六个"到达即采集"的触发点

编号触发点谁在读需要你同意吗端侧工件
T1显著位置变化 / 围栏进出唤醒系统代你持续判"有没有越过那条线"，命中才把 App 拉起来需要定位授权，但不需要 App 在前台定位指示、隐私报告计数
T2定位的服务侧那一部分辅助定位要向网络侧查询接入点/小区信息没有独立同意项几乎没有；查询与留存都在对面
T3原始运动与环境传感器订阅任意 App 可直接订阅加速度/陀螺/磁力/气压/环境光不进授权模型；活动识别、计步与健康数据才需要"运动与健身"无
T4被唤醒后的短时采样推送、通知、后台任务把进程拉起几十秒，其间照常采样（与 #65 的交界就在这条）沿用已有授权少量计数
T5系统功能替你采集重要地点、基于位置的建议与广告、路线与交通、查找网络（周边设备匿名中继）、诊断日志（与 #76 交界）出厂即开，藏在 系统服务 那一屏只有开关状态可查
T6配件与另一台设备上的传感器车机、手表、耳机、家居设备各自有传感器，授权模型与本机不同（与 #113/#121 交界）由那一侧的策略决定本机不可见

最反常识的两项：T3（"没亮指示灯"不等于"没在采"，因为这一类根本没有指示灯）和 T2（披露发生在设备之外，因此任何端侧审计都看不到它）。

5. 来源族 × 缺陷倾向 × 谁能修 × 个人能关吗

缺陷倾向用 #81 的类别名，便于和其余竖条对齐。

来源族典型缺陷倾向谁能修个人能关吗
GNSS 卫星定位逻辑（欺骗/丢星被当作真实移动）、新鲜度假设无人：信号无身份，只能增加交叉校验部分（可整体关，不能验真）
Wi-Fi/蜂窝辅助定位边界处语义不一致、披露外流Apple + 网络侧否（关掉就等于放弃服务）
蓝牙广播 / iBeacon 类标识来源即身份（广播无认证）部署方（谁用它做判定谁负责）部分（App 级蓝牙权限）
UWB 精确测距中继、配对留存后跨侧失效Apple + 规范方部分（车钥匙/门禁见 #101）
加速度 / 陀螺无授权采集被用于推断（按键、活动、设备姿态）Apple（策略层可收紧）否（无独立开关）
磁力 / 气压 / 环境光同上，且被用于楼层与室内判定Apple否
麦克风权限前置 + 指示灯 + 唤醒词设备侧模型Apple + App是（App 级 + 指示灯可核对）
摄像头同上，另有硬件遮挡问题Apple + App是
活动识别 / 计步 / 健康授权分组、降级未传播、二次共享Apple + App是（"运动与健身" + HealthKit 逐项）
系统服务消费层授权与信任边界误用（出厂默认即采集）Apple是，而且这里是收益最大的一屏

新格式即新面积在本族的表现是"新的来源即新推断"：每接入一类新可观测信号（新的近场测距、新的可穿戴传感器、新的设备侧模型），F2 就多一条推断路径，而 F3 的授权表通常不会同步增加一行——这正是 #93 说的 L4/L5 演化回归。

6. 七种反复出现的"契约被违反"模式

模式现实形态对应分析
M1 来源即位置"能收到这个广播 / 连上这个名字的网络" ≈ "你在那个地点"，于是把可见性当成了身份与位置证明#101、#89
M2 授权即语义"使用期间"被实现成"进程活着就一直采"；或"精确位置已关"只作用在坐标上，不作用在下游推断与外发字段#66、#81 3.8
M3 新鲜度假设把缓存坐标当现值（首次修复未完成、室内/隧道丢星），或乱序样本覆盖新样本，于是"轨迹"出现穿墙与跳跃#93 L4
M4 名字与对象分离地址反查出来的"家/公司"与坐标不是同一个对象；围栏的多边形边界与舍入让同一天多次"进出"抖动#118 的"名字与对象"同族
M5 融合不可归因"在开车""在睡觉""在店内"这类推断字段追不回当初那次同意，撤销时无从撤销本篇与 #107 的"撤销不对称"同一律
M6 指示器即完整可见状态栏箭头与橙/绿点被理解成"任何传感器都在看着"；反过来"没亮"被理解成"没在采"#66
M7 失败即信息某项权限被拒后，改用不需要同意的代理量（运动、网络可达、蓝牙邻近）得到同一结论；判定者以为关掉了，其实只是换了路径#83、#95

M5 与 M7 是本篇的硬结论：它们意味着逐条撤销在这条链上不成立，能成立的只有从源头少给（降级精度、少给消费项、少留出口）。

7. 后果落在 #91 的哪一格，以及两种不可逆

  • 采集/披露类 → C2（数据可见性）。已经外发出去的位置轨迹与推断字段不可召回：留存与可引用者在对面（对齐 #105 的请求方阶梯与 #116 的证据衰减）。处置手段是"减少出口"，不是"删除内容"。
  • 判定污染类 → C6（对他人的判定被扭曲）。你的设备成了别人记录里的证据来源：考勤、门锁日志、理赔时间线、执法轨迹。它伤的是第三方的系统，因此受害者无法通过加固自己来消除风险，只能通过时间对齐 + 端侧工件去反证（与 #62、#117 交界）。这类是本系列少见的"你做了全部正确动作仍然可能中招"的形状。
  • 可用性侧（C5）在这一族几乎不出现，除非把"定位失败导致依赖它的工作流卡住"算进去——那是业务问题，不是安全缺陷。

8. 清点与判定五步法

  1. 列来源：这台设备上有哪些"无需同意也在产出"的量（运动、环境、网络可达、蓝牙邻近、气压/光照）。这一步的产出是一张清单，不是设置截图。
  2. 列判定：谁把哪个量变成了结论——App 内的"在店/在家/在开车"，还是外部系统的"到岗/通行/合规"。没有判定就没有风险，只有数据。
  3. 列出口：结论走没走本机之外（服务端、第三方、企业平台），按 #107 的出口分档标出 E0–E4；E4（授权级批量出口）在本族表现为"整个健康/运动图库被同步"。
  4. 降级：精确位置 → 关闭；App 授权 → 使用期间或关闭；系统服务消费项 → 逐项；"运动与健身"/HealthKit → 收回；唤醒词/语音 → 按需关。这一步是唯一能当场完成的。
  5. 验证：用授权档位、"上次使用时间"、隐私报告与状态栏指示交叉核对；并明确接受运动与环境类没有工件这条边界——对它们只能验证"关掉了出口"，不能验证"没有采集"。

9. 加固清单

个人七项（按收益排序）

  1. 设置 → 隐私与安全 → 定位服务：把"始终"改成"使用期间"，能关的关；这一屏是收益最高的一次点击。
  2. 精确位置默认关：只给真正需要导航的那两三个 App；其余按"知道在哪个街区就够了"处理。
  3. 进"系统服务"逐项审：基于位置的建议与广告、重要地点、路线与交通、警报类、查找网络相关项——多数人只看过 App 那半张表。
  4. 收回"运动与健身"与 HealthKit 分享，同时明白原始运动数据不在这一组里：关掉这一开关不等于对方拿不到姿态与活动线索。
  5. 麦克风/摄像头/蓝牙按最小给，不需要的语音唤醒就关掉；指示灯是核对手段，不是覆盖手段。
  6. 把位置当对外披露来管理：知道哪些服务会把位置或推断送到对面并留存多久；对齐 #105（谁能调取）与 #107（撤销只对未来生效）。高危个体走 #108 的最低档。
  7. 周期性核对（并入 #104 的季度表）：档位、精确位置、系统服务、健康分享四项各记一次"上次检查时的状态"，并把"集中变化本身就是信号"这条规则用在这里（同 #99）。

组织五项

  1. 车队 / 考勤 / 巡检类位置系统：把"设备上报 = 事实"降级为"证据之一"，明确留存期、可引用者与争议处理路径；否则争议时你只有一份单方可改的记录。
  2. MDM 的定位上报能力（见 #67）按高权限项单独审批、登记到期；它属于"机制本身合法、结果等价于持续监视"那一类。
  3. 门禁 / 访客 / iBeacon 部署：广播不构成身份。任何"到达即授权"的自动化必须在链路另一端再有一次认证，且要有"_relationship 结束但凭证仍有效_"的回撤检查（同 #101）。
  4. BYOD：把"位置判定"与"设备归属"分开处理，离职时按 #120 收回关系型授权，只撤描述文件不会终止那些关系。
  5. 演练：用一个"污染判定"场景（设备在 A、对方记录说在 B）跑一遍取证与申诉流程，检验 #63 与 #116 里那套时间对齐能力是不是真的存在。

10. 端侧可观测性：能看什么，看不到什么

能看看不到
App 的定位/蓝牙/麦克风/健康授权档位与"上次使用时间"原始运动与环境传感器的订阅与频率（根本没有这一层的记录）
状态栏定位箭头与麦克风/摄像头指示点由这些量推断出来的字段（活动、场所、作息）
隐私报告里的访问计数与共享清单T2 的服务侧查询、对面留存与二次使用
系统服务各开关的当前状态配件、手表、车机、家居设备上那一侧的采集与判定
健康类 App 的授权列表撤销之前已经外发并在对面留存的历史

诚实边界：本族的端侧可见性低于 #122 与 #123。后两根竖条至少还能靠崩溃工件与解析日志间接发现异常；这里连"被采集"这件事都不产生用户可见记录。所以本篇不承诺"你可以自查有没有被采集"，只承诺"你可以验证自己少给了多少"。

11. 常见误解纠正表

误解事实依据
"关了定位权限就安全了"关掉的是坐标，关不掉的是运动/环境量与网络可见性，M7 会换路径本篇 M7
"指示灯没亮，说明传感器没在录"指示灯只覆盖麦克风/摄像头（定位另有箭头）；运动与环境类没有指示T3、M6
"定位准不准是地图厂商的事"F2 的围栏边界、精度传播与新鲜度是软件缺陷，能修，也确实修过§3、§5
"关闭精确位置后对方就不知道我在哪了"精度字段的传播不一定覆盖下游推断与外发（M2）M2
"收到某个广播就等于我在某个地点，这是铁证"广播不构成身份也不构成位置（M1），它只构成"附近有可能"M1、#101

"这是监控问题，只有高危个体会遇到"判定污染类伤的是考勤/门禁/理赔这类日常系统，普通人反而是主要暴露人群§7

12. 与既有各篇的接口

  • #81：本篇的缺陷类别几乎全部落在 3.8（授权与信任边界误用）与 3.9（身份误用）两格，#124 处理的是密钥那一半，本篇处理的是授权与推断这一半。
  • #20 / #23：能力清单与本篇互补——那两篇回答"能不能拿到"，本篇回答"拿到之后形状在哪、谁能修、能不能关"。
  • #65 / #71：T4 的唤醒路径由那两篇展开；本篇只接它之后的采样与推断。
  • #72 / #88 / #89 / #101 / #121：射频固件、微架构泄漏、支付与门禁凭证、有线配件；本篇与它们的接缝分别是 T2（网络侧）、T3（推断量）、M1（广播即身份）、T6（配件侧传感器）。
  • #95：追踪与指纹那篇给可关闭性诚实表，本篇给实现层缺陷族与五步审计；两篇的"能不能关"结论一致（原始传感器不可关）。
  • #105 / #107 / #116 / #117 / #120：出口、留存、撤销不对称与对外披露；§7 的"判定污染"处置直接引用 #116 的双时钟模型与 #62 的可采性讨论。
  • #108 / #109：高危个体与商业关键人物方案书里，本族的条目应写作"降级 + 少留出口"，不要写成"检测 + 阻断"，因为可观测性不足以支撑前者。

13. 总结

这一族最难接受的地方是：它大部分不是漏洞。F1 的信号没有身份，F3 的默认值是选择，F2 才是真正的缺陷密集区。于是三个反常识结论自然成立——第一，"没亮灯"和"关了权限"都不等于"没在采"；第二，推断字段追不回当初那次同意，所以逐条撤销在这里不成立，只有从源头少给；第三，风险最大的那一屏不是 App 列表，而是"系统服务"那一屏，因为它出厂就在跑，而且没有对应的可见性。

对个人，最小动作是三个：把定位与精确位置降到够用、把系统服务消费项逐项过一遍、把位置当成对外披露来管出口与留存。对组织，最小动作也是三个：设备上报降级为"证据之一"、广播类到达不直接换授权、MDM 定位能力单独审批并登记到期。坐标归 Apple，推断归你，出口归你们双方。
