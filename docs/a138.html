iOS 快捷指令与 App Intents 自动化编排的攻击面：你以为审的是那条链，实际执行的是它当时拿到的那个值

1. 执行摘要

  • 这一族的名字应该叫"执行器由受害者本人搭建"。前面二十二根竖条的位置依次是进来的字节（#118 格式、#122 卷、#123 报文）、进来的调用（#119 接口、#127 插槽）、进来的设备与信号（#121 配件、#125 定位、#129 号码）、进来的操作请求（#126 辅助功能）、被合在一起的内容（#128 索引与聚合）、画到屏幕上的内容（#130 显示与捕获）、到达时被你认出成谁（#131 标识与呈现）、验证之后存续下来的能力（#132 凭证与会话）、按下之后交给谁执行（#133 派发）、什么时候被执行（#134 调度）、内容生产那一瞬被顺手多写的上下文（#137 采集与外发）、一次发送覆盖多少人（#135 批量投递）、很多身份怎么被组织成一种气氛（#136 群控与协同）。本篇是第二十三根竖条，它补的是这条链上一个从未被单独测绘过的位置：当执行序列不是别人写好的代码，而是你自己一步步搭出来的时候，"同意"这件事发生在哪一层。
  • 核心命题：快捷指令与 App Intents 的失效几乎从不是"链被写坏了"，而是"链在运行时拿到的那个值没人复核过"。 一条链由若干动作串成，动作之间传的是值，不是"这个值从哪来、是不是你期望的那种东西"。剪贴板里的一段文本、上游 URL 返回的一段字节、共享表单递进来的一个文件、远端工作流平台推来的一个参数，都可以原样填进"打开链接""发送信息""存储文件""运行子链"这些动作的位置上。审链的人看的是动作列表；出事的是动作的参数。
  • 三层切分：E1 编排层（动作序列、参数引用点、子链间接调用、文本字段里驻留的凭据）；E2 触发层（手动、Siri、小组件、操作按钮、共享表单、URL 调起、个人自动化的条件事件、经工作流平台的远程触发，以及"运行前询问 / 立即运行"这个由你自己拨动的档位）；E3 权限层（执行时用的是快捷指令这个 App 已经拿到的授权和被调用意图所属 App 的能力，而不是"这条链"的授权）。缺陷密度在 E1，因为它没有任何参数校验；不可逆点在 E2，因为它决定执行发生在有没有你在场的那一刻；长期风险在 E3，因为它把二十几条链的风险合并到面板上的一行。
  • 一条方法论结论，也是第十一个系统性漏检：用 #66 的隐私面板、#134 的后台名义清单、#132 的凭证存续表、#127 的扩展点清单去做这类审计，全都会漏掉本族。原因是同一个：这些面板审计的单位是"某个 App 有什么权限"，而本族的最小风险单位是"某一条链在某个触发时刻带着某个值跑了一次"——这个三元组在系统里没有任何可查对象。 设置里那一行"快捷指令：相册、位置、健康"是真的，但它不回答"你装的那 14 条链里，有哪一条会读相册、哪一条会把读到的东西发出去"。本篇需要的是第十一个补丁：一张"链台账"——每条链记三列（外部内容入口 / 参数引用点 / 离机出口），审计看这三列，不看权限面板。
  • 后果上它给出第十二种不提权的伤害形状：本人搭建的执行器。#126 借系统辅助功能、#127 借你请进来的扩展、#134 靠调度模型赠予的窗口、#137 伤害作为随件附带的上下文；本篇的形状是"程序是你自己写的，密码是你自己填的，确认是你自己关的，然后它替你发了一条消息"——不需要漏洞、不需要提权、不需要越权，甚至不需要第二次点击。
  • 撤销不对称在本族第九次成立（#107）：删掉链、关掉自动化、把共享链接撤回，全部只对未来生效。已经随 .shortcut 副本同步到另一台设备的那份、已经被别人导入你发布过的那份、以及写在文本字段里发出去的那个令牌——删除动作对它一概不起作用，因为令牌活在那条链之外。"链被删了"与"链携带的凭据失效"是两件事，且只有第二件有意义。 #91 的 C6 判定污染在本族第六次成立（#125 首创、#130 第二次、#133 第三次、#134 第四次、#137 第五次）：由链在无人时刻发出的消息与由你手动发出的消息，在服务端记录里通常是同一个发送方。
  • 可观测性的诚实定位：能核对的比 #134 多，比 #137 少。你能核对：链的完整动作列表、每个动作的参数与引用来源、每条自动化的触发条件与运行档位、快捷指令 App 当前的权限清单、它在哪几台设备上出现过（iCloud 同步面）。你永久核对不到：某一次执行实际填进去的值、执行历史（iOS 上没有这个视图）、子链在云端被改动过的版本、以及任何"这条链向哪个地址发过什么"的出站记录。
  • 正向结论只有一句：把审计对象从"动作列表"换成"参数流"，然后在离机、发信、开门、扣款这四类出口前面各留一次人工在场。 具体动作三类且全部当场可验证：把每一个引用上游输出的位置当作一次输入校验点重写为字面量或加上判断；把"立即运行"改回"运行前询问"，只为那些不含出口动作的链保留静默档；把凭据从链的文本字段里搬出去，交给不会随链同步与共享的位置。

2. 这根竖条补的是哪一块

系列里已经有多篇擦到过自动化：#126 测绘了辅助功能与外设（系统的替人操作能力被借用），#127 测绘了第三方扩展点（你请进来的代码在旁边看着），#133 测绘了链接与回调派发（一下点击最终交给谁执行），#134 测绘了后台执行与唤醒权（没有你按下的时候谁还在跑），#132 测绘了凭证与会话（执行时手里还留着哪些能力），#128 测绘了本地索引与聚合（散落在各 App 的内容被合成一个可查询对象）。

但这些位置都缺同一格：存在一条合法、可见、由用户亲手搭出来的执行通道，它的动作序列完全透明，而它的风险全部藏在透明序列所消费与生产的那些值里。 #133 讲链接交给谁，本篇讲交出去之后由一段你自己写的程序去执行；#134 讲谁让 App 在后台跑，本篇讲你在什么时刻不再需要在场——而且这个时刻是你自己设置的一个开关；#126 讲系统替你点击，本篇讲你预先写好的序列替你点击。

这是第二十三根竖条，仍然在 iOS 内部（用户态编排层），但它造成的可见性缺口是系统口径的：系统按"App + 权限 + 触发档位"暴露风险，而本族的最小风险单位是"链 × 参数 × 触发时刻"三元组，三者不同尺度。

与相邻各篇的分界必须写死：

  • 与 #126（辅助功能与外设）：那一篇的执行者是系统的替人操作能力，被借用去模拟你的手指；本篇的执行者是你自己写的动作序列，它不需要模拟点击，它调用的是公开接口。分界线：本篇不讨论指针事件、外设输入伪造与辅助功能授权被借用的路径。
  • 与 #127（第三方扩展点）：那一篇的扩展是被动观察（在别人的界面旁边看你输入什么）；本篇的意图是主动执行（把一个动作做完）。同一个 App 可以同时暴露两类，但缺陷形状不同：扩展的问题是看见了什么，意图的问题是替谁做了什么。
  • 与 #134（后台执行与唤醒权）：那一篇讲系统调度模型赠予的执行窗口，你无从设置也无从查看；本篇讲你亲手登记的一个条件到动作的映射，它看得见、能删，但删的是登记不是能力。两篇合起来才覆盖"无人在场时的执行"：#134 是系统自己决定的时刻，本篇是你替系统决定过的时刻。
  • 与 #133（链接与回调派发）：那一篇止于"这个链接被交给了哪个处理者"；本篇从"处理者拿到之后做了什么"开始。#133 的参数落点在本篇是 E1 的入口之一——链接把值递给一条链，链再决定这个值变成一次发信还是一次开门。
  • 与 #132（认证凭证与会话）：那一篇的存续主体是能力（会话、令牌、已登录状态）；本篇的存续主体是携带能力的文档（把令牌写进文本字段的那条链，以及它的同步副本与共享链接）。#132 说"收回发生在对方服务器上"，本篇补一句更糟的形态：这里的"对方服务器"就是你自己填的那个工作流平台。
  • 与 #137（采集与外发）：那一篇讲一张图带着上下文走；本篇讲一条链可以把那张图（连同上下文）自动发出去，把 #137 的"导出方式判断"从人的动作变成无人时刻的既定程序。两篇的接口在 §12 明确列出一行。
  • 与 #99（人身安全场景）：那一篇的持续控制靠外部施加；本篇提供它的本地实现物——一条被远程触发的链，就是"控制"在设备内的落地形式，而且它在设备上的外观与你自己为了省事装的天气提醒完全相同。

3. 三层切分：编排、触发、权限

3.1 E1 编排层——透明的动作列表，不透明的参数流

一条链在界面上是一个动作列表，逐项可读、可停可改，这是它相对任何闭源程序最大的优点。也正因为动作可读，审计者普遍只读动作。真实的构成是这样的：

层内容审计者通常看得见吗风险所在
动作序列做了什么类型的事（取、算、写、发）看得见通常不是问题源
字面量参数写死在动作里的文本、URL、号码、路径看得见，但容易被跳过凭据驻留、地址驻留（§3.1 末）
引用参数指向上游动作输出的"变量"看得见引用，看不见值本族核心缺陷：类型与来源都不校验
控制结构重复、判断、"如果出错则"看得见循环可与 E2 组合成自激（§7 C5）
子链调用按名字运行另一条快捷指令只看得见名字间接性：你审的是调用方，被调用方可被替换
外部内容入口剪贴板、网络取回、共享表单输入、文件、健康/位置/日历读取看得见入口入口之后没有任何净化步骤
离机出口发送信息/邮件、POST、打开链接、存储文件、拨打电话、控制家居看得见出口不可逆动作全在这一列

四条结论：第一，引用参数是本族唯一系统性的信任缺口。 一个"打开链接"动作的 URL 位置如果填的是引用，那么被打开的东西由上游决定；上游如果是"从 URL 获取内容"，决定权就转移到了那台服务器；如果那台是一个工作流平台或一个任何人都能改的笔记字段，决定权就不在你的设备上了。这条链在字面上仍然全部合法。 第二，子链调用把"审过"这件事变成一次性的、会过期的状态：调用方没变，被调用方随 iCloud 同步更新之后，同一条链的语义就变了，而界面上看不出任何差异。第三，"共享表单接收"是一个静默入口：从别的 App 用"分享 → 快捷指令"进来时，被分享的内容直接成为输入变量，链的动作可以立刻消费它，全程不需要你确认这条链看过这个内容。第四，文本字段是凭据的常见住宅：API Key、Bearer 令牌、包含会话参数的回调地址、SSH 主机与用户、"基础认证"的用户名密码——它们与动作一起被保存、一起被同步、一起被打包进共享链接。这是本族最朴素也最高频的真实损失，处置动作永远不是"删掉那条链"，而是撤销那个凭据。

3.2 E2 触发层——执行发生在谁在场的时刻

触发方式你在场吗有确认吗与其它篇的交界
手动（App 内 / 小组件 / 快捷指令按钮）在视链内动作而定—
Siri 短语在（但语音不证明说话者是谁）通常无#131 的名字与对象分离
操作按钮 / 背部轻点在，但动作是单手完成的通常无与 #126 的物理输入面相邻
共享表单（别的 App 递内容进来）在，但注意力在另一个 App视档位#133 的派发落点
shortcuts:// 一类调起在（一次点击）视档位#133 → 本篇的唯一入口
个人自动化：时间 / 地点进出 / 充电器 / 蓝牙 / 耳机 / NFC / 二维码 / App 打开 / 专注模式 / 天气 / 日历 / 健康事件不在取决于档位（下一段）#125 的位置读取、#134 的窗口
自动化档位："运行前询问"在有本族唯一由你自己拨动的关键开关
自动化档位："立即运行"不在无与 #134 的无人在场执行在这里合流
远程触发（工作流平台 → 推送/链接 → 本地链）不在无或不可靠#132 的会话、#103 的出口、#99 的控制

三条结论：第一，"立即运行"这个档位是本族全部的不可逆性来源。 它不是缺陷：一条每次都要问一次的提醒链没有存在价值，所以系统必须提供静默档。但当你把静默档给了一条含离机出口的链，你就把"是否发送"这个判断从每次执行时前移到了配置时一次——而配置时你看不到它当时会拿到什么参数。第二，触发条件本身是一项数据读取。 "到达某地时"要求持续的位置判定，"打开某个 App 时"要求使用信息，"心率超过某个值时"要求健康读取。这些读取是自动化功能的组成部分，通常不在隐私面板里作为独立条目出现——这是 M4 的成因。第三，远程触发把决定权外移了一格。 只要链的某一段是"从某个地址取回内容并按其中的指示执行/发送"，链的语义就不完全在你设备上了。这一段在个人用户那里常常以"我自己搭的提醒服务"的面目出现，在攻击者那里则是一个可被接管、可被改写的普通 Web 服务。#105 的云端披露边界在这里同时生效：那条平台上留着你的触发历史与参数。

3.3 E3 权限层——执行时用的是谁的能力

这是本族与所有其它竖条最不一样的一层，需要用三句话把它钉死：

  1. 授权对象是编排器，不是链。 快捷指令作为一个 App 持有相册、位置、联系人、健康、麦克风等授权；你新增一条链不产生第二次授权事件。设置里那一行"快捷指令：位置、健康"覆盖的是你库里所有链的总和，包括上周从别人那里导入的那条。这就是"面板口径无法覆盖本族"的技术原因（§1 的第十一个漏检）。
  2. 意图的执行发生在被调用 App 一侧。 通过 App Intents / 快捷指令动作调用某个 App 的能力时，实际执行与鉴权由那个 App 完成，链只是把参数递进去。于是"参数信任"缺口有了第二个落点：被调用方信任的是"这是一个合法意图请求"，不是"这个参数经过你复核"。 涉及支付、门禁、车钥匙、账户改绑这类高危意图时，链的角色等价于一个把方向盘接过去的转接器。
  3. 意图的名字与入口不由你登记。 App 可以自己声明意图、可以把自己塞进桌面长按菜单与系统建议、可以注册与别家同名的短语类别。用户看到的是一行中文，运行到的是某个 App 的某个处理者——#122 P4、#123 N4、#134 M4 那条"名字与对象分离"的律，在本族以"链名与链实义分离"的形态再次成立，而且本族多一重：链的内容还会变。

因此本篇的处置重心天然不在"关掉什么"，而在"链台账 + 出口在场 + 凭据搬家"三件事上。

4. 八个核对点（全部可当场在本机验证）

  • P1 清点链与自动化。 打开快捷指令 App，"库"与"自动化"两个标签逐项截图存证，标出每一条是"我写的"还是"导入的"。注意同 Apple 账户的另一台设备上会出现同一批链——清点范围是所有设备之和，不是本机可见项（接口：#110 多设备、#106 共用设备）。
  • P2 走读参数流。 对每条链，把每个动作的输入分类为字面量或引用。凡是引用上游输出的位置，都在台账上记一行"参数信任点"。审计的产出物是这一行的数量，不是动作列表的截图。
  • P3 标记外部内容入口。 逐个链找：剪贴板读取、"获取 URL 内容"、共享表单输入、"获取文件"、健康/位置/日历/通讯录读取、"从某 App 取数据"的意图。每有一个入口，就存在一条"值不是你能预见的"路径。
  • P4 标记离机出口。 发送信息/邮件、POST/GET 到远端、打开链接、复制到剪贴板（会被下一个 App 拿走）、存储文件（会进 #137 的相册或 #128 的索引）、拨打电话、控制家居/门锁/车辆、修改系统设置项。一张只标了入口没标出口的台账等于没做。
  • P5 查凭据驻留。 检查所有文本字段、URL 参数、认证类字段里是否含令牌、密钥、带会话参数的回调地址、主机与账号。判据：把这条链的分享链接发给同事，他导入后能不能直接跑通？能，就说明里面有凭据。
  • P6 查档位与可达入口。 每条自动化：是"运行前询问"还是"立即运行"；是否允许在锁屏时执行；是否可从小组件、建议、Siri 短语、URL 调起。高危组合是"立即运行 + 含 P4 出口"，本族所有真实事故几乎都在这一格。
  • P7 查编排器的权限面。 设置 → 快捷指令：列出它当前拿到的全部权限，与 P3/P4 的台账交叉核对——某条链用到而面板里没有的权限意味着它其实跑不通，面板里有但没有任何链用到的意味着可以收回。这一步是面板与本族唯一能对齐的地方，别把它当成审计本身。
  • P8 查共享面与同步面。 你发布过哪些共享链接（快捷指令库的共享历史不给你一个完整视图，按 P5 的判据自查更可靠）；链是否随账户出现在备用机、旧机、家庭共享成员的设备上；家庭类自动化是否覆盖他人设备。注意：撤回一个链接与从别人设备里删掉一条链是两件你做不到的事。

判定顺序建议：P5 → P6 → P4 → P2 → P3 → P1 → P7 → P8。 先查驻留凭据与静默档，因为它们决定了后面所有事情的可挽回程度。

5. 存续表：一条链写出去之后活在哪里、多久

位置存续到什么时候你能收回吗后果
本机链库手动删除为止能删除后不再可触发，但不撤销已发生的执行
同账户其它设备（iCloud 同步）同步链路存在期间不能逐台收回备用机/旧机上的链仍会被 E2 触发（接 #110、#96）
你发布的共享链接链接可达期间；被导入后即永久不能他人手里是一份完整副本，含 P5 的凭据
导出的 .shortcut 文件副本接收方删除为止不能与上一条同性质，且更容易批量分发（接 #135）
子链独立于调用方存续能改，但改动会静默影响所有调用方审计结论过期（§3.1 第二条结论）
链内凭据令牌自己的有效期只有撤销凭据才是收回删链无效，这是本族最常被误解的一行
工作流平台的触发记录与字段值平台留存策略决定按 #105 走正式流程成为第三方证据，也是远程触发的控制点
由链发出的消息/邮件/提交与手动发出的一模一样不能（#121 双侧存储律）归属上是你的（§7 C6）
由链写入的相册/文件/日历条目进入 #137 的存续表按 #137 的规则本族的输出会喂给别的竖条

三条结论：第一，本族的"删除"从来不是收回动作，因为可收回的对象（本机链）与造成损失的对象（凭据、副本、已发出的内容）不在同一处。第二，链的输出会带着链的产物进入其它竖条的存续表——一条自动保存截图或自动存图的链，实际是在替 #137 制造导出物、替 #128 制造可聚合对象。第三，最后一行是 §7 C6 的物理基础：链发出的东西在协议层与手动发出的东西不可区分，所以"那是自动化发的"这句话在任何正式场合都不是可举证的事实，至多是一个需要你自己重建的解释。

6. 七类契约违背

  • M1 构造即资格。只要一条链能被写出来、能被系统接受为合法动作序列，它就获得了用编排器现有权限执行的名义，与你是否为这条链单独同意过无关。这是 #131 M1（显示即属主）、#133 M1（声明即属主）、#134 M1（声明即资格）在本族的第六次成立，并且是它最反直觉的一版：前面几次的资格是别人声明的，这一次的资格是你亲手搭的——所以连"我从没同意过"这句话都不成立。
  • M2 引用即信任。动作之间传的是值，不携带来源、类型与意图。任何上游输出都可以落进任何下游参数位。这条是本族整个问题的成因：不是有什么开关藏着，而是这一层从来没有做输入校验这个概念。与 #118 的"进来的字节没人替你验"结构相同，但 #118 的解析器是系统代码，本族的消费方是你自己的链——修的人是你，这一点在本系列是第一次。
  • M3 授权对象是容器不是内容。面板按 App 分类，不按链分类；新增一条链不产生授权事件，所以也不产生同意事件。这一格与 #134 M2（授权即通道）同形，但后果更具体：审计者看到"快捷指令：位置"这一行时，无法知道这个位置权限会被几条链、在什么时刻、发到哪儿去。
  • M4 条件即读取。个人自动化的触发判断需要持续读取位置、使用信息、健康或蓝牙状态，这些读取是功能实现而非数据访问事件，因而不以你能拒绝的形态出现。它与 #125 的定位档位、#134 的窗口叠加：三处读的是同一类数据，但登记在三个互不相见的地方。
  • M5 共享即携带。一条链的可读动作列表与它的不可读载荷（字面量里的凭据、指向你服务的地址、依赖的子链名字）是同一个文档。#107 的撤销不对称在本层的第九次成立，且形态是本系列最干净的一版：删链、撤链、撤回链接三个动作没有一个能撤销已经写出去的那个令牌。
  • M6 静默即你选的。"立即运行"是设计给用户的功能，它把"是否执行"从每次判断前移为一次配置。这一格是本族最危险的判读错误来源：用户以为自己在优化便利，实际在放弃在场。 反向必须一起写："运行前询问"也不是一项保障——确认框显示的是链名与"好/不允"，不显示这一次它将拿到的参数值，多数人在多数时候读不到决策所需的信息。
  • M7 失败即信息。第八次出现在系列里（#123 N6、#125 M7、#129 M7、#131 M7、#132 M7、#133 M7、#134 M7）：提醒没有按时出现、自动化条件明明满足却没跑、某条链突然多出一个动作、家居设备在你没碰手机时被切到一个不属于现在的场景、备用机上出现一条你不认识的链、共享给我的家人的链在某天之后行为变了——这些差异本身就是判读输入。本族可用的正向判据只有 M7：链是可见的，所以"链变了"是可比对的；把 §4 的台账做成带日期的截图，是本系列里少数真正能在个人设备上落地的完整性基线。

其中 M1、M3、M4、M6 不是软件缺陷：M1 是编排功能的设定（#93 的 L1），M3 是权限面板口径的选择（L1），M4 是触发判定的实现必需（L1 与 L3 交叠），M6 是可用性与安全之间的显式取舍（L3）。只有 M2 处在缺陷侧——参数校验这件事在链的模型里根本没有对应构造，它更接近 #119 那类"接口不校验调用方意图"的实现层问题。所以本篇可改的代码量是本系列最低的之一，而可改的用户行为量是全系列最高的：链是你的，档位是你的，凭据放哪儿也是你的。

7. 后果落点（接 #91 的后果轴）

  • C1 数据与内容外流：一次无人时刻的执行可以把剪贴板、相册最新一张、当前位置、某段健康数据发到链里写好的地址。单位不是"某个 App 拿到权限"，而是"某条链的某个出口动作被跑了一次"。出口走 #107 的第三方出口面，落点常在你自己搭的工作流平台上——这是本系列第一次出现"披露对象是受害者自己的服务器"这种形态，处置时它同时是对方的记录与你的证据。
  • C2 行踪与习惯的持续采集：地理围栏与时间型自动化把你的作息写成了设备的既有配置。它有两层后果：一是条件判定本身的持续读取（M4），二是这份配置是一份你亲笔写的作息表——谁拿到设备或同步副本，就拿到"每天 07:40 离开某地"这样一条断言（接 #95、#99、#106）。
  • C3 账户级操作（不提权）：第十二种伤害形状：本人搭建的执行器。 没有漏洞、没有提权、没有人做错事：一条合法的链、一个合法的触发、一份合法的权限，发出了一条消息、确认了一次改绑、开了一次门、下了一次单。与 #134 的 C3 分界要写死：那里连手势都没有、也没有一份人能读的执行序列；这里有，而且它是你自己写的——所以本族的争议焦点永远不是"有没有越权"，而是"这个序列当时是否还在你的意图范围内"。
  • C4 服务与费用滥用：短信与彩信、电话、按量计费的第三方接口调用、家居与车辆的执行器动作，都记在"这台设备这个账户"的账上（与 #132、#134 的 C4 同一本账）。本族独有的一格是这些调用可以由一条看起来像提醒的链产生，账单上没有任何字段回答"人写的还是链跑的"。
  • C5 可用性代价：电量、通知洪泛、存储与网络占用。这一格归 #92（破坏类专篇 owns 它），本篇只登记两件本族特有的事：一是自激——A 链产生的事件触发 B 自动化、B 又满足 A 的条件，形成循环，这是全系列里少数由用户配置直接制造出的可用性故障；二是这类消耗是合法功能的正常行使，修复路径不在补丁侧，只在链侧。
  • C6 判定污染第六次成立（#125 首创、#130 第二次、#133 第三次、#134 第四次、#137 第五次）：服务端的"该账户于 02:14 向某号码发送了一条消息"会被写进风控、工单、平台裁决与理赔记录，成为一条长期存在的第三方证据，而那个时刻没有任何人在操作手机。本族的污染比 #134 更难反驳：#134 至少还能说"那是同步"，本族的操作在业务语义上就是"发消息、下单、开门"，与人的行为完全同形。赔钱的仍然不是设备厂商，处置走关系侧（#120/#117/#105 同一路）。
  • C7 归因失效：本族的失效方式与前几篇都不同——执行序列存在、且完全可读，但"那一次跑的是哪个版本、拿的是哪个值"没有任何工件。iOS 上没有链的执行历史视图；链内容会被 iCloud 静默更新；子链可以被替换；参数来自上游输出而非你的输入。#78/#116 的时序模型在这里失效不是因为痕迹被清，而是因为链是一个可变更程序却被当成一次性配置来管理。更糟的是反向：由于 §4 的清单全部由用户手工完成，绝大多数受害者连"当时有哪些链"都无法重建——本系列第一次出现"举证材料只能靠事前自查产生"的彻底形态，这也是 §10 把台账列为第一项而非最后一项的原因。

8. 审计法与判定式

8.1 个人侧：三步，当场可做完

  1. 先堵凭据（P5）：把所有链文本字段里的令牌、密钥、账号、带参数的地址清出去。搬去的位置必须是不会随链同步与共享的地方——现实里只有两类：需要时人工输入，或由目标服务自己发的短期确认。这一步的收益高于后面所有步骤之和，因为它把"不可收回"变成"可撤销"。
  2. 再分档（P6）：把每条含 §4 P4 出口动作的自动化改回"运行前询问"；只给纯提醒、纯展示类链保留静默档。判据只有一句：这条链跑完之后，世界上有没有多一件收不回来的东西？
  3. 最后建台账（P1+P2+P4，带日期截图）：三列表——链名 / 外部入口 / 离机出口，加上"我写的还是导入的"一栏。台账的价值不在审计当下，而在下次出问题时有个基线可比（M7）。

8.2 判定式（可执行、当场自证）

"我运行的是这条链，还是这条链当时拿到的那个值？"

三个衍生问句，任何一条答不上来就说明该链需要处理：

  • 这个参数位上的值，上一次实际填进去的是什么？（答不出 = 引用参数无校验，M2）
  • 这条链如果现在分享给同事，他能不能直接跑通？（能 = 里面有凭据，M5）
  • 它下一次静默执行时，世界上会不会多一条收不回的消息、一次扣款或一次开门？（会 = 档位错了，M6）

8.3 组织侧：五个动作

  1. 不要把快捷指令当成"用户个人生产力工具"排除在管理范围外：它能触达 MDM 注册的设备设置、企业内系统入口与业务 App 的意图，且不产生任何审批记录。
  2. 把"高影响意图"的确认留在业务侧而不是编排侧：涉及支付、门禁、改绑、审批流的操作，其二次确认必须由被调用 App 自己完成，不能因为"链在用户设备上跑的"就假定有人在场。
  3. 在事件响应清单里加一条询问："是否可能由用户自建自动化触发？"——漏掉这句会直接把内部风险事件误判为外部入侵（本族 C6 在组织侧的代价最高）。
  4. 交接时把链纳入台账（#120）：离职人员的个人自动化可能绑定着企业服务的地址与凭据，链随个人账户离开而凭据仍有效。
  5. 用配置约束而不是用培训约束：可用的约束面（禁用 Siri 与快捷指令的哪些部分、是否允许共享、是否允许锁屏执行）随版本变化，必须按当前版本在你自己的托管配置里逐项验证后再写进制度，不要引用任何文章（包括本篇）的版本描述。

8.4 高危个体（接 #108）

  • 导入的链一律当"含未知出口"处理：读完动作列表不算审完，要看它引用的每个上游、调用的每个子链、写入的每个地址。
  • 绝不在链里放任何凭据：本族对高危个体的首要风险不是被利用，而是你的取证副本会带着它一起被同步、被导出、被拿到。
  • 静默档只给无出口链；含发送、含开门、含提交的链保持每次询问，即使这削弱了它的实用价值。
  • 不要在主力设备保留工作流平台的长期触发链路：一条"远端可推"的链等价于一个自己写的、只有你自己不知道有没有别人也有权限的后门入口（#99）。

9. 设备端可观测性——本篇的诚实边界

能核对的：链的完整动作与参数（逐项可读，这是本族相对所有闭源竖条的唯一优势）、每条自动化的触发条件与运行档位、快捷指令 App 的权限清单、链在哪些设备出现（同账户下的同步面可从"另一台设备上打开看一眼"获得）。

核对不到的：任何一次执行的实际参数值（没有执行历史视图）、子链与远端提供内容在历史上的版本、链向外部地址发过什么（无出站记录）、被工作流平台侧改写过的字段、以及"这条链是不是我上次审过的那条"（除非你自己存了带日期的台账）。

必须写死的两句：第一，链可读 ≠ 行为可核对，可读的是意图序列，出事的是参数值，这两者不在同一个视图里。第二，iOS 上没有"链的执行日志"这件事不是遗漏，而是这一层的常规口径——与 #134 的"哪一次被谁拉起"、#128 的"谁聚合了我的索引"、#137 的"这张图最终到了哪儿"是同一类系统级缺口，因此本族的取证责任第一次完全落在用户自己的事前记录上。

10. 加固清单（按当场可验证排序）

10.1 个人

  1. 逐链清除文本字段里的凭据（P5），改为运行时人工输入或短期确认。验收：任何一条链分享给同事都跑不通。
  2. 把含离机出口的自动化改回"运行前询问"（P6）。验收：台账里"立即运行 × 含出口"这一格数量为 0。
  3. 给每条链补"子链调用"审查：凡按名字调另一条链，把被调用方也过一遍同样的三列。验收：台账行数 ≥ 链数 + 子链数。
  4. 删除所有"导入且看不懂它在干什么"的链，包括看起来无害的壁纸、记账、翻译类。验收：库里每条链都能被你说出它的外部入口与出口。
  5. 关闭不需要在锁屏执行的自动化的锁屏可达性；把操作按钮/背部轻点上绑定的高影响链换成无出口链。
  6. 建带日期的链台账截图，与 #137 的导出物核对表放在一起；这是你唯一的完整性基线。
  7. 检查备用机、旧机与家人设备上的同一批链（P8），能收回的先收回，不能收回的先撤销其中的凭据。

10.2 组织 / 企业侧

  1. 把用户自建自动化纳入资产与事件响应范围；在事件分级里明确"自动化触发的业务操作"这一类。
  2. 高影响意图（支付、门禁、改绑、审批）在业务 App 内保留独立二次确认，不依赖编排侧。
  3. 员工离职交接检查表加一行：其个人自动化中是否登记了企业服务地址、回调、令牌。
  4. 用 MDM 托管配置约束可用面，且每项约束先在测试机上验证生效（口径随版本变）。
  5. 安全提示只写一句可执行的："不要在快捷指令里存任何口令或令牌。" 比"注意安全"有效得多。

10.3 高危个体

  1. 主力设备上不留任何远程可触发链；需要远程能力时用一个不含执行能力的通知通道。
  2. 凭据零驻留 + 链库最小化（只留自己从零写的、无出口的）。
  3. 设备之间按 #110 的落点原则分离：编排链与业务账户不同设备，避免一条链跨身份生效。
  4. 台账做双份并留在设备之外；一旦发生 C6 型争议，事前台账是唯一能出示的机制性材料。

11. 十条常见误解

  1. "快捷指令只是个自动化，它没有自己的权限。" 错——它有，而且是按 App 汇总的一整套；你新增链时不会看到第二次询问（M3）。
  2. "我把这条链从头到尾看过一遍，所以知道它会做什么。" 看过的是动作序列，不是它每次拿到的值；子链和远端内容还会变。
  3. "共享链接删掉，那份链就收回来了。" 已经被人导入的副本不受影响；里面写着的令牌继续有效（M5）。
  4. "关掉那条自动化就安全了。" 同一条链仍然可以由 Siri、小组件、URL 调起或别的自动化触发；要收回的是链与凭据，不是某个触发器。
  5. "文本里放个 Key 没人看得见。" 它跟着同步、跟着导出、跟着你随手发出去的那条分享链接一起走。
  6. "'立即运行'只是少点一次确认。" 它把"是否执行"从每次判断改成一次配置判断——你放弃的不是便利，是在场（M6）。
  7. "'运行前询问'就是安全保障。" 确认框不显示本次参数值；它证明有人在点，不证明那个人知道要点什么。
  8. "Siri 短语只有我才会说。" 语音在共享空间里不是身份认证；能说出短语的人与能拿到解锁设备的人常常重叠。
  9. "自动化的触发条件不算读取我的数据。" 算——位置、使用信息、健康、蓝牙都在被持续判定（M4），只是不以你能拒绝的形态出现。
  10. "这类事情苹果发个补丁就解决了。" M1/M3/M4/M6 是设定不是缺陷（§6 末段）；唯一会被"补"的是 M2 那一格，而它什么时候补、怎么补，都不在你能等的范围内。

12. 与既有各篇的接口

  • #133（链接与回调派发）：那一篇的终点是本篇 E2 的入口之一——链接把一个值递给一条链。两篇合起来才是完整的"点击之后发生了什么"。
  • #134（后台执行与唤醒权）：本篇的"立即运行"与那一篇的无人值守窗口在 §3.2 表格最后一行合流。分界：那是系统决定的时刻，这是你替系统决定过的时刻。
  • #126（辅助功能与外设）：同样是"替你操作"，那里的执行器是系统输入通路，这里是用户自己写的序列。
  • #127（第三方扩展点）：扩展被动观察、意图主动执行；同一个 App 的两类暴露面，审计要分开列。
  • #132（认证凭证与会话）：那一篇管能力本身，本篇管携带能力的文档；"链被删了 ≠ 令牌失效"这一律是 #132 在本族的投影。
  • #137（采集与外发）：一条自动存图、自动分享的链在替 #137 制造导出物；两篇的出口动作应共用同一张核对表。
  • #128（本地索引与聚合）：剪贴板与被写入的文件/日历条目会立刻成为可聚合对象，本族的输出是它的输入。
  • #125（定位与传感器）：地理围栏型条件的持续读取归在那一篇的档位表下管理。
  • #131（标识与呈现）/#130（显示与捕获）：链名、意图名与桌面建议里的入口，是"名字与对象分离"律的又一处出口；确认框只显示名字这一点在 §6 M6 已写明。
  • #99（人身安全）/#106（照护）/#109（差旅）：远程可触发的链是持续控制与越俎代庖在设备内的落地形式；也是共用设备场景里最容易被他人在你设备上留下的配置。
  • #110（多身份与备用设备）/#96（设备流转）/#120（离职交接）：链与其中凭据随账户同步、随设备流转、随人离职而存续，三处都要把"链台账"纳入清单。
  • #107（撤销不对称）/#91（后果轴）/#92（破坏类）/#93（前置条件轴）/#78·#116（归因与时间轴）：本族贡献的是第九次撤销不对称成立、第十二种伤害形状、C6 第六次成立，以及全系列第一个"举证材料只能靠事前自查产生"的竖条。

13. 总结

本篇把二十三根竖条里最后一个未被测绘的位置——由受害者本人搭建的执行链——测绘成表：E1 编排（唯一完全可读的一层，但可读的是序列不是值）、E2 触发（决定有没有你在场，其中"立即运行"这一档由你自己拨动）、E3 权限（授权按 App 汇总、意图在被调用方执行、名字与入口由别人登记）。三个不可回避的结论是：这一族的入口不是缺陷而是编排模型的固有构造——动作之间传值而不传来源与类型，按 #93 归 L1，只有 M2 那一格落在实现侧；这一族的伤害形状是本人搭建的执行器，没有人做错任何事，所以 #78/#116 的归因在此失效的原因既不是没有形态也不是没有记录，而是链被当成配置管理、实际上它是程序；以及这一族的处置完全在用户侧：搬走凭据、收回静默档、留下台账——这三件事本系列没有任何一篇能替你做完，也没有任何一篇像本篇一样，把"事前记录"变成事后唯一可用的材料。

它与最近三篇构成一条完整链条：#134 问没有你按下的时候谁还在跑，#137 问内容离开设备时带着什么，#138（本篇）问你亲手搭的那条链在替谁执行，#133 问这一下最终交给谁。 四篇合起来是同一件事的四个维度：执行的时刻、执行的载荷、执行的序列与执行的对象，是四层各自独立的东西，而 iOS 没有在任何一处替你核验它们是不是你当初要的那个组合。
