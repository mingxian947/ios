Coruna 与 DarkSword 反检测机制对比

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Amnesty International、MVT (Mobile Verification Toolkit)、Lookout、公开 CVE 情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

反检测（Anti-Detection） 是商业间谍软件能否长期存活的关键能力。一款利用套件即便拥有完美的零日利用链，若能在一次例行取证扫描中被识别，其战术价值将急剧下降。

Coruna 与 DarkSword 代表了反检测设计的两条不同技术路线：

  • Coruna：主动清除型（Active Scrubbing）——会落地、会持久化，因此必须具备精细的痕迹管理能力，主动删除已产生的工件
  • DarkSword：天然无痕型（Inherent Ephemeral）——不落地、不持久化，通过架构设计本身消除大部分工件来源

本文从工件面（Artifact Surface）这一取证核心视角出发，逐层对比两套体系在文件系统、进程、内存、网络、日志、启动项六个维度上留下的可检测痕迹，并结合 MVT 等公开检测工具的实际能力，分析各自的有效性与失效场景。

2. 检测体系概览：防御者在看什么

理解反检测，必须先理解检测方的信息源。当前 iOS 商业间谍软件检测主要依赖四类工件：

2.1 备份取证工件（Backup Artifacts）

信息源说明典型价值
iCloud 备份用户主动云备份，包含 App 数据、短信、通话记录、部分设置无需接触设备即可远程取证
iTunes/Finder 本地备份未加密备份可含 Keychain 与更多 App 数据内容最丰富的单一来源
iMazing / AFC 提取通过 USB 直接读取 App 容器与系统目录可发现未备份文件

MVT（Mobile Verification Toolkit） 是 Amnesty International 开源的自动化备份解析工具，核心机制是 IOC 匹配 + 工件异常检查：在备份中搜索已知恶意文件路径、域名、进程名。

2.2 设备运行时工件（Live Artifacts）

信息源说明
进程列表与线程枚举发现异常进程/异常线程
打开的文件句柄发现未记录的落地文件
网络连接表发现隐蔽外连
内存转储发现注入代码、字符串、C2 配置

2.3 系统日志与分析工件

信息源说明
Crash Report（/private/var/mobile/Library/Logs/CrashReporter/）进程崩溃记录含调用栈与内存映射，价值极高
PowerLog / Analytics进程生命周期、CPU 使用异常
sysdiagnose综合诊断包，含内核日志、网络状态、进程表
netlog / DNS 缓存外连域名记录

2.4 网络侧工件

信息源说明
DNS 解析日志（路由器/企业网关）记录被访问域名，含已失效的 C2
TLS 握手元数据（JA3/JA4 指纹）识别非标准 TLS 实现
出口流量画像异常外传量、异常时间分布

关键洞察：攻击者无法控制防御者的网络侧工件与 iCloud 备份的服务端留存——这是反检测能力的天然上限。

3. Coruna 的反检测机制

3.1 设计前提

Coruna 采用部分持久化 + 多链复用架构，这意味着它必然在文件系统上留下痕迹。其反检测策略因此围绕"产生后清除"展开。

3.2 具体技术

3.2.1 落地文件最小化

措施说明
载荷集中于单一目录避免散布到多路径，便于一次性清除
使用系统风格命名文件名模仿合法缓存/日志，降低人工审查发现率
混淆扩展名与目录层级隐藏在 /Library/Caches/ 等低关注路径

3.2.2 元数据伪装

措施说明
时间戳伪造修改 mtime/ctime 至系统安装或更新时刻，绕过"最近新增文件"检查
权限设置模仿使用与系统文件一致的 owner/mode，避免异常权限告警
避免可执行位滥用部分实现通过解释器加载而非直接 chmod +x

3.2.3 进程与线程隐藏

措施说明
宿主进程伪装不创建新进程，注入到合法系统进程（如 media/图形相关守护进程）
线程命名对齐恶意线程命名与宿主进程合法线程一致
低活动占空比采集任务分片执行，避免持续高 CPU 触发 PowerLog 异常

3.2.4 主动痕迹清除

措施说明
崩溃规避精心处理异常路径——Crash Report 是 MVT 与人工取证最高价值工件，一次崩溃可能暴露整条链
日志删除在提权后清理相关系统日志条目
Safari/WebKit 缓存清理删除水坑页面的历史记录与缓存（初始访问的直接证据）
自毁指令C2 可下发一次性清除所有工件并卸载

3.2.5 网络侧对抗

措施说明
CDN / 云服务混入中转层流量与合法云 API 调用不可区分
标准 TLS 栈避免自定义 TLS 实现产生的 JA3 异常
域名生命周期短前端域名使用后即弃，等防御者分析完成时已失效

3.3 Coruna 的残留工件（已知泄露点）

尽管具备上述能力，Coruna 仍会留下以下可检测痕迹：

工件说明对备份取证的可见性
落地载荷文件若清除不彻底或在中途被捕获✅ 高（iMazing/AFC 可见）
持久化启动项用于重启后恢复⚠️ 部分备份可含 plist
WebKit 缓存残留清除前被备份捕获✅ 中
DNS 缓存条目系统 DNS 缓存✅ 中（sysdiagnose 更完整）
采集数据临时文件大数据打包瞬间⚠️ 短窗口
崩溃报告一旦触发✅ 极高（含栈与模块基址）

4. DarkSword 的反检测机制

4.1 设计前提

DarkSword 的核心决策是不在文件系统上留下任何持久化痕迹。这使得它的反检测更多来自架构选择而非清除动作——不产生，自然无需清除。

4.2 具体技术

4.2.1 架构级无痕

措施说明
零文件写入所有代码通过匿名内存页执行，不创建文件
无启动项不注册 LaunchDaemon/LaunchAgent，启动项检查完全失效
不修改配置不写 plist、不改系统设置，完整性校验无从触发
备份不可捕获内存中内容不进入任何备份通道——iCloud/iTunes 备份看不到

4.2.2 内存层反取证

措施说明
用后覆写敏感数据外传后立即覆写并释放
加密驻留模块在内存中以加密形态保存，执行时按需解密
短生命周期模块每段代码执行完即卸载，缩短内存捕获窗口
禁用 core dump防止异常时将内存写入磁盘

4.2.3 网络与会话层

措施说明
短会话单次连接数秒至数分钟，网络分析窗口极窄
DGA 域名域名按算法生成，黑名单在生效时已过期
系统原生 TLS使用设备自身 TLS 框架，JA3 指纹与正常 Safari 完全一致
API 路径伪装请求路径模仿合法 REST 接口

4.2.4 时间维度的自我消解

DarkSword 最独特的反检测能力是"重启即清"：

攻击执行 → 完成任务 → 用户重启设备 → 所有痕迹物理消失

这意味着即便防御者事后获得设备，只要期间发生过一次重启，几乎所有运行时证据都已随 DRAM 断电消失。攻击者甚至不需要主动清除。

4.3 DarkSword 的残留工件

工件说明对备份取证的可见性
水坑页面访问记录Safari 历史 / WebKit 缓存⚠️ 中（重启或清理后消失）
DNS 解析记录路由器/企业网关日志✅ 高（攻击者无法控制）
异常进程行为运行时内存取证✅ 仅在设备运行时可捕获
崩溃报告若利用失败触发⚠️ 可能暴露漏洞细节
内核状态异常重启后消失❌ 事后取证不可见

关键观察：DarkSword 在设备侧几乎无痕，但网络侧 DNS 日志与流量元数据仍是其最可靠的暴露途径。

5.2 对抗 MVT 类工具

结论：MVT 类基于备份工件 + IOC 匹配的检测范式，对 Coruna 有效性显著高于 DarkSword。这也解释了为何 Coruna 系列能被大规模公开归因分析，而 DarkSword 的检测依赖 Project Zero 的运行时研究。

6. 战略权衡分析

6.1 隐蔽性 vs 控制力

两套体系本质上是同一权衡的两端：

      长期控制力 ←──────────────────────→ 高隐蔽性
         ↑                                      ↑
       Coruna                              DarkSword
   (持久化+主动清除)                    (无落地+自然消解)
   暴露面大 / 可回溯                    暴露面小 / 不可回溯
权衡项Coruna 的选择DarkSword 的选择
被检测到后能否快速重建✅ 能（多链、多域名、基础设施分层）⚠️ 需重新投递全部链
单次入侵能持续多久✅ 数月至数年❌ 至多到下次重启
被公开归因分析的概率✅ 高（工件多）⚠️ 低（工件少）
对高警觉目标的适用性⚠️ 差✅ 好
运营成本低（植入后自运转）高（需反复投递）

6.2 与目标画像的匹配

Coruna 适合：

  • 需要长期持续监控的对象（活动人士、政治对手、记者）
  • 目标设备重启频率低、不易被取证检查
  • 攻击方拥有充足漏洞储备支撑长期运营

DarkSword 适合：

  • 短期高价值窗口（会议、谈判、特定事件期间）
  • 目标可能被反复取证扫描（如已被公民社会保护的记者）
  • 攻击方漏洞储备有限，需节省零日消耗

6.3 演化趋势

从公开报告时间线可观察到两个方向的趋同：

趋势说明
Coruna 向 DarkSword 学习新一代套件减少文件落地、增强内存驻留比例，降低备份可捕获性
DarkSword 向 Coruna 学习在保持无持久化的同时引入备用信道与轻量重投递协调机制
共同的新方向利用合法云服务与第三方基础设施承载数据，使工件天然存在于攻击者无法清除、防御者无法归因的位置

7. 攻击者视角的常见失误

分析已公开的归因案例，两套体系都曾因以下失误被捕获：

失误后果案例类型
崩溃报告未清理泄露漏洞组件、模块基址、部分调用栈Coruna 类持久化载荷
域名跨套件复用一次归因暴露多次行动基础设施管理失误
证书复用通过证书序列号/公钥关联多个 C2通用
利用失败但留下记录水坑页面被完整抓取并分析通用（尤其 DarkSword）
目标误判向安全研究人员投递，导致完整分析公开目标识别失误
iOS 版本探测不严谨在已修补版本上触发，暴露载荷而不成功通用
清除逻辑有缺陷部分路径未覆盖，留下残留Coruna 类

对防御者的启示：反检测机制的强度取决于运维纪律，而非仅代码质量。基础设施管理失误（证书、域名复用）往往是归因突破点。

8. 防御建议

8.1 分层检测策略

针对两套体系的不同弱点，应采取差异化检测：

检测层针对 Coruna针对 DarkSword
备份/文件系统扫描✅ 主力手段❌ 无效，不要依赖
IOC 域名黑名单✅ 有效⚠️ 需 DGA 情报支持
运行时行为监控✅ 有效✅ 主力手段
内存取证✅ 有效✅ 唯一可靠设备侧手段
网络元数据/DNS 日志✅ 有效✅ 最实用的通用手段
Crash Report 巡检✅ 高价值⚠️ 中等价值

8.2 具体行动清单

对高危个人：

  1. 启用锁定模式——直接关闭 WebKit JIT 与 WebGPU，切断两套体系的入口
  2. 定期重启设备（每日）——强制清除 DarkSword 类内存驻留
  3. 定期导出并检查备份——用 MVT 扫描，发现 Coruna 类落地痕迹
  4. 避免不明链接——两套体系主要依赖 1-click 水坑

对组织/企业：

  1. 保留 DNS 与流量元数据——这是发现 DarkSword 类攻击的最实用信号
  2. 部署 TLS 检测（受控环境）——检查加密通道内容
  3. 建立设备行为基线——异常外连/进程告警
  4. MDM 采集 sysdiagnose——支持快速内存与进程检查
  5. 威胁情报订阅——Citizen Lab、Amnesty 等公开的 C2 基础设施更新
  6. 对目标设备做前置取证基线——入侵后差异比对

8.3 关键提醒

DarkSword 类无持久化攻击意味着"扫描干净"不等于"从未被入侵"。 设备重启后一切证据消失，防御者获得的是"当前无残留"，而非"历史上无入侵"。 唯一能跨越这个盲区的证据来源是网络侧日志和攻击者自身泄露的样本。

9. 总结

结论内容
1. 两条路线，一个目标Coruna 走"落地+主动清除"，DarkSword 走"不落地+自然消解"，都服务于同一目的：降低被归因分析的概率
2. 架构优于技巧DarkSword 的实践证明：最好的反检测是不产生工件，胜过任何精巧的清除逻辑
3. 检测范式必须升级以备份扫描为核心的传统检测（MVT 类）对无持久化攻击基本失效，必须引入运行时与网络层检测
4. 网络侧是不可控盲区攻击者无法清除防御者路由器/网关的 DNS 日志，这是对抗双方共同的"第三方证人"
5. 权衡不可回避极致隐蔽必然牺牲持续控制力；DarkSword 每次重启后失去设备，这是其无持久化架构的硬代价

从攻防演化看，"无持久化"正在从一种限制转变为一种设计标准。下一代商业间谍软件更可能采用"内存驻留为主、按需最小落地"的混合模式——这要求防御体系尽早具备运行时检测能力，仅靠"找文件"的时代已经结束。
