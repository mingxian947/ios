iOS 设备流转与退出边界：二手机、维修、回收与离职交接上被忽略的那一半风险

本文是防御视角的处置流程与核对清单，不提供可利用代码，不包含解锁绕过、数据恢复手法或任何可照做的取证操作。面向需要处理转卖、回收、维修与人员交接的个人用户、IT 管理员与咨询场景。

1. 为什么这是独立的一个方向

整个漏洞系列有一个隐含前提：这台设备一直属于你。#2/#81/#90–#94 讨论的都是"外人怎么进来"。

但咨询里有一类高频问题跟入侵无关：

  • 我把旧 iPhone 卖了，里面到底还剩什么？
  • 我接手一台二手机，该检查什么才敢登录我的账户？
  • 员工离职交回设备，公司怎么证明数据已经处理干净？
  • 设备维修换件之后，之前那份暴露还在不在？

这些问题的共同结构是设备在时间轴上换主人。风险有两个方向：下行（你的残留暴露给下一任）与上行（上一任的残留与配置继续影响你）。这一层几乎不需要漏洞，主要损失来自账户关系、注册状态与密钥归属——所以它与 #84/#89/#92 的"账户优先"结论是同一条原则在流转场景里的应用。

2. 四个流转场景

场景下行风险（你留给别人的）上行风险（别人留给你的）关键控制点
个人转卖 / 以旧换新 / 赠送账户未退出导致的锁与关系残留、备份与云侧仍在、iMessage 与通话继续路由到这台设备—退出账户与所有权转移，而不是只"抹掉"
企业离职回收 / 批量处置员工个人数据留在公司设备（上行反向）、公司凭据留在个人设备BYOD 边界最乱的一格：谁的数据、谁有权擦事先约定边界 + 处置留证明
维修 / 部件更换维修期间设备的可见性与临时解锁更换件带来的既往配置与信任状态维修前的账户与可见内容收敛（#84 配件与时长原则）
丢失 / 被盗 / 被扣押后回流已被他人长期持有形成的暴露史回流设备带着未知既往当成不可信设备重新开始，不做"看起来干净就行"

一句读法：转卖场景管下行，接手场景管上行。两个方向的清单不一样，混用会漏。

3. 残留物按类型清点（这是本篇的核心表）

残留类型是否随"抹掉所有内容和设置"消失需要额外动作
本地照片、消息、备忘录是（本机侧）但云侧与备份仍在：核对 iCloud 与本机备份条目（#74）
Apple ID 登录态与设备清单条目通常需你主动退出登录从账户设备清单移除，否则这台设备仍在你的受信集合里
钥匙串与已保存密码本机消失云钥匙串成员关系不变；改密才是有效动作
钱包卡片与 Pass（含门禁/房卡/车钥匙）需从钱包移除且发卡方撤销凭证撤销由发卡方/门禁方执行，抹机不替代它（#89）
eSIM 与号码绑定不会因抹机自动释放运营商侧删除或转移，否则套餐与号码关系仍在（#72/#89）
描述文件与证书、MDM 注册多数随抹机移除，但注册记录在服务端企业侧需在管理控制台注销设备并归档（#76）
家庭共享 / 屏幕使用时间管理员关系否这是关系型暴露，必须在组织者账户里移除（#92 的"合法擦除权限"来源之一）
配对的电脑与配件信任部分保留在对方侧信任电脑需在那台电脑上取消；配件重新配对
订阅、自动化与快捷指令随账户而非设备核对账户侧订阅与自动化触发器
位置共享与"查找"需退出且从共享清单移除关系型暴露（#95 第 5 节的同一动作）

读法："抹掉所有内容和设置"只解决第一行的本机部分。剩下的要么在服务端（账户、运营商、MDM 平台、发卡方），要么是关系型（家庭组、共享），都不会因为设备被重置而自己消失。这是流转场景里最普遍的错误认知。

4. "清除是否可信"的诚实边界

被问得最多的一句话是："我抹过了，别人还能拿到什么？"

需要如实回答的三点：

  1. 本机侧：现代 iOS 的设备密钥随账户与本机保护层级绑定，抹机在常规意义上会让本机数据不可读——这是可以给的结论。
  2. 不可证明的部分：外部无法验证那一任使用者是否在抹机前做过备份、导出或云同步。"设备干净"不等于"数据没走过"。任何声称能证明"彻底清除"的第三方说法都应存疑。
  3. 仍然活着的副本：iCloud、本机加密备份、App 自有同步、邮箱与聊天服务的服务器侧、运营商记录。这些才是流转场景里的主要泄露通路，而且都不在这台设备上（#74 的密钥归属结论在这里同样成立）。

所以对个人转卖的正确心态：抹机是必要的第一步，不是处置的全部；真正的收尾动作都在账户与关系侧。

5. 两套可直接执行的流程

A. 交出设备前（个人，按顺序做）

  1. 先决定这台设备是否还要接收任何东西：iMessage 转发、通话接力、邮件提醒都会继续路由到它。
  2. 从钱包逐张移除卡片与 Pass，并让发卡方/门禁方撤销（#89）。
  3. 退出 Apple ID（这会解除激活锁与"查找"），并在账户设备清单里确认它已经不在了。
  4. 组织者身份检查：家庭共享、屏幕使用时间管理员、共享日历与位置（#95）。
  5. 号码与 eSIM：若计划保留号码，先在运营商侧处理；若不保留，明确释放（否则号码关系跟着设备走）。
  6. 取消与此前电脑的配对信任（在那台电脑上操作）。
  7. 最后一步再执行抹机，并保留一次"我已退出账户"的界面证据（自用留档）。

B. 接手二手机 / 回流设备（按顺序做）

  1. 先重置再登录自己的账户——不要带着上一任的状态登录（否则你的数据进入一台既往未知的设备）。
  2. 更新到当前支持版本（V2 暴露变量见 #94）。
  3. 核对：描述文件与证书清单、是否有企业 App 残留、MDM 注册状态提示（出现"管理"字样即为已注册，必须要求对方注销后再用）。
  4. 核对激活锁确已解除、账户无关联（否则这台设备的所有权并不干净，属于 #92 里的锁类不可逆问题）。
  5. 登录后再检查一次：订阅、屏幕使用时间管理员、位置共享清单里是否出现不属于你的项。

C. 企业回收与批量处置

  1. 边界事先约定：BYOD 场景里个人与公司数据的分界必须在下发策略时说明，而不是在离职时讨论。
  2. 处置动作分步并留记录：先撤销访问（证书、SSO 会话、邮箱同步），再注销管理注册，最后执行抹除。顺序反了会留下"设备已清但凭据仍可访问"的窗口（#91 剧本 A 的同一原则：先服务端后设备）。
  3. 台账要能回答三件事：哪台设备、什么时候、以什么方式处理，由谁执行。这是合规争议里唯一有用的东西。
  4. 离职员工的个人设备里公司数据的处理权边界要按当地规则走，技术动作不能替法律判断（本系列一贯口径：不构成合规意见）。
  5. 回收设备重新下发前，按 B 的第 1–4 步当作接手设备处理一遍。

6. 与维修、扣押与丢失相关的三条

  • 维修：送修前收敛可见内容（锁屏通知、面容替代项、短期解锁窗口），维修时长本身是风险参数（#84/#88 关于物理接触时长的结论）。更换件带来的既往配置无法从设备外观判断，收修后按 C/B 流程核对一遍。
  • 被扣押后回流：按"不可信设备"处理，不要复用原有登录与钥匙串状态；能重新走一遍开户与账户治理的最省事。
  • 丢失/被盗：立即动作在服务端而非设备端（标记丢失、锁卡锁号、退出会话），设备端取证价值有限且可能被清除（#92 的顺序原则）。

7. 五个常见误解

误解事实
"恢复出厂就彻底干净了"只解决本机数据；云侧、备份、关系型暴露与注册记录都不随之消失
"抹机就等于退出了账户"不退出登录可能保留锁与设备清单条目，所有权与路由都不干净
"激活锁能保护我的数据"它保护设备 resale 价值，不保护已同步到云端的数据；对使用者它同时是"不可逆锁"（#92）
"企业 MDM 注销就是数据清除"注销解除管理关系，抹除才是数据处理；两者都要做且要留证
"二手机看着干净就能直接登录"上一任的描述文件、MDM 注册与账户关系是看不见的，必须先重置再登录

8. 一句话结论

设备流转是"账户与关系治理"问题，不是"设备加固"问题——它属于 #93 里的 L1/L3 格（设计选择与配置），指望补丁没有任何意义。

  • 对个人：交出设备前按 A 顺序做完，重点在钱包撤销、退出账户、号码与家庭组关系；接手二手机按 B，先重置再登录。
  • 对企业：把回收流程写成"先撤访问、再注销、后抹除、留台账"，并把 BYOD 边界事先讲清楚。
  • 对高危个体：任何回流、维修、赠机都按不可信设备重新开始，不要复用既往登录与钥匙串状态。
