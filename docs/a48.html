Coruna 与 DarkSword 防御与检测指南

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Amnesty International、MVT、Apple 安全公告、NIST/OWASP 移动安全指南 性质：防御性安全研究指南（Defensive Security Guidance），不提供可利用代码

1. 执行摘要

本文是 Coruna / DarkSword 系列文章的防御落地手册。前序文章剖析了攻击链各环节的技术原理，本文将其转化为可直接执行的检测流程、加固清单与应急响应步骤。

核心结论前置：

  1. 升级 + 锁定模式可消除约 90% 的实际风险——两套体系依赖已知漏洞，修补后链条断裂
  2. 传统"扫文件"检测对 DarkSword 无效——必须建立运行时与网络层检测能力
  3. 定期重启是最廉价有效的对抗手段——针对无持久化架构的定向消耗
  4. 备份 + sysdiagnose 是取证的双主力——覆盖静态与运行时两个证据域
  5. 威胁情报新鲜度决定检测成功率——DGA 域名使静态黑名单快速失效

2. 威胁建模：先确定保护谁

不同风险等级的投入产出差异极大。盲目对全员部署高强度监测会造成成本失控与误报泛滥。

2.1 风险分层

层级典型对象威胁来源建议措施强度
T0 极高危调查记者、人权活动家、政治异议者、他国政要、核心谈判代表国家级商业间谍软件定向投放锁定模式 + 定期取证 + 网络监控 + 专项响应
T1 高危政府公务、军工/外交从业人员、企业高管、法务与并购负责人定向水坑、商业间谍锁定模式（可选）+ MDM 基线 + 异常告警
T2 中危拥有敏感 IP 的技术/研发人员机会定向、鱼叉投递强制升级 + 安全意识 + MDM
T3 普通一般员工与消费者大规模低成本投放自动更新 + 常规谨慎

2.2 攻击者视角的选择逻辑

商业间谍软件售卖方通常按"目标授权数"计费，攻击方会优先选择 T0/T1 中防护最弱的个体。因此：

团队防御强度取决于最薄弱的成员，而非平均强度。 一个未升级 iOS 的助理设备，可能成为获取整个组织数据的入口。

建议：将 T0 人群的关联人员（家属、助理、同事）也纳入 T1 措施覆盖范围。

3. 加固：阻断攻击链入口

3.1 第一优先：系统升级

项目说明
目标版本升级至 Apple 最新正式版（当前 iOS/iPadOS 18.7.3+；iOS 26 用户至 26.3+）
原理Coruna/DarkSword 依赖的 WebKit/JSC/GPU/内核漏洞全部已在公开版本修补
执行要点建立设备清单 + 版本基线 + 落后设备强制升级窗口
常见失败点老机型无法升级（iPhone X 及更早）；用户长期推迟；MDM 未强制执行

关键提醒：Coruna 覆盖 iOS 13–17.2.1，意味着停留在 17.x 及更早版本的设备完全暴露于多条已公开利用链。

3.2 第二优先：锁定模式（Lockdown Mode）

项目说明
适用对象T0/T1 强烈建议；T2 视敏感程度
切断的攻击面禁用 JIT（削弱 JSC 利用）、禁用 WebGPU/ANGLE（削弱 GPU 逃逸）、限制消息附件、阻断未知 iMessage 载荷、限制部分网络栈
实际效果已公开的多条高级链在检测到锁定模式时会主动中止（避免在受保护环境中消耗零日）
代价部分 Web App/视频通话/企业内网功能受限
注意事项开启后不要随意关闭再开启（状态变化本身可被探测）；Apple 明确提示"不要告诉别人你开启了"

3.3 第三优先：减少 1-click 暴露面

两套体系的主要投递方式是水坑/钓鱼链接，因此降低链接点击风险的价值很高：

措施说明
默认浏览器改用强沙箱产品部分第三方浏览器沙箱策略不同，可形成异构防御
关闭 Safari 自动打开下载文件减少自动解析路径
禁用 JavaScript（高危场景）对极端敏感人员可考虑，直接消除 WebKit RCE 面
链接预览关闭减少自动渲染触达解析器的机会
陌生人消息限制关闭未知发送者消息预览，缓解 0-click 面

3.4 备份与账号加固

措施说明
启用加密备份加密本地备份会保护 Keychain，显著降低凭证泄露风险
启用高级数据保护（ADP）iCloud 端到端加密覆盖大部分数据类，削弱"备份捕获"检测面同时也削弱攻击面
Apple ID 开启 2FA + 强设备密钥防止通过 iCloud 侧信道获取数据
谨慎使用第三方云备份工具iMazing 等工具的本地留存需要同等保护

4. 检测：可执行流程

4.1 检测能力矩阵（选择依据）

攻击特征备份扫描网络日志运行时监控内存取证
Coruna（落地/持久化）✅✅✅✅✅
DarkSword（无持久化）❌✅✅✅✅✅
0-click 消息链⚠️⚠️✅✅
C2 长期心跳⚠️✅✅⚠️✅

结论：没有任何单一手段能覆盖两者。网络日志是唯一同时有效的低成本手段，运行时/内存取证是 DarkSword 的唯一设备侧解。

4.2 流程 A：基于备份的静态检测（适用 Coruna 类）

所需条件：未加密 iTunes/Finder 备份（加密备份会限制可见范围）；或 iCloud 备份下载。

1. 获取备份
   iTunes/Finder → 立即备份（不加密，需知情同意）
   或 iMazing → 导出文件系统

2. 安装 MVT
   python3 -m venv venv && source venv/bin/activate
   pip install mvt
   # macOS 用户需安装 unbound
   brew install unbound

3. 运行检查
   mvt-ios check-backup --backup-path /path/to/backup
   mvt-ios extract-backup --backup-path /path/to/backup \
       --extract-folder /path/to/extract
   mvt-ios check-ioc --backup-path /path/to/backup \
       --ioc-file https://raw.githubusercontent.com/muses-team/MVT/main/ioc.json

4. 手工补充审查（MVT 覆盖不到的部分）
   - 遍历 /private/var/mobile/Library/Logs/CrashReporter/
     关注 WebContent、GPU、媒体相关守护进程的异常崩溃
   - 检查 LaunchDaemons / LaunchAgents plist 的最近修改时间
   - 检查未知 App 容器与异常目录名

结果解读原则：

  • 命中 IOC → 高置信度，立即进入应急响应（第 5 节）
  • 无命中 → 不能得出"未感染"结论，尤其对 DarkSword 类
  • 异常崩溃报告但无 IOC → 中置信度，转入流程 B/C

4.3 流程 B：网络侧检测（性价比最高）

核心思路：iOS 设备难以持续做内存取证，但网络元数据可以长期留存。

1. 数据采集
   - 企业：DNS 解析日志（递归服务器/防火墙）、出口 NetFlow/sFlow、
           TLS 握手元数据（JA3/JA4）
   - 个人：家用路由器启用 DNS 日志；或使用支持 DoH 日志的解析器

2. 保留周期
   ≥ 60 天（覆盖攻击周期与情报公开延迟）

3. 分析要点
   a) DGA 特征
      - 域名长度异常、高熵子域、无历史注册记录、
        注册龄 < 30 天、同一注册人批量注册
   b) TLS 异常
      - ClientHello 与声称的 User-Agent 不一致
      - 自签名 / 短期证书 / 与声称服务不符的证书链
      - JA3 指纹与合法 Safari 库偏离
   c) 流量画像
      - 非人类时间分布（精确周期性心跳）
      - 上行流量突增（照片/录音外传）
      - 同一设备短时间多次访问不同低信誉域名
   d) 关联分析
      - 多设备同时命中同一低信誉域名 → 定向水坑特征
      - 通过证书公钥/ASN 关联多个域名 → 基础设施聚类

个人用户可用简化手段：

  • 在路由器上配置 Pi-hole/AdGuard Home 并启用日志
  • 使用 Threat Intelligence 阻断列表（含 Citizen Lab 公开 IOC）
  • 定期查看"最近解析的可疑域名"

4.4 流程 C：运行时/内存检测（DarkSword 唯一设备侧解）

适用场景：T0 人群、sysdiagnose 可采集、设备在线。

1. 采集 sysdiagnose
   按住 音量上 + 音量下 + 电源 约 1.5 秒（面容机型）
   → 设置 > 通用 > VPN 与设备管理 > 共享分析 中查看
   或通过 Xcode / Apple Configurator 直接抓取

2. 检查项目
   a) 进程与线程
      - 全进程列表与预期基线比对
      - 每个进程的线程命名是否有异常（与宿主职责不符）
      - mediaserverd / backboardd / SpringBoard 等非浏览器进程
        是否存在异常网络连接
   b) 内存映射
      - 扫描具有 PROT_EXEC 的匿名内存区（非 JIT 进程中出现 = 高危）
      - 检查异常大小的 RWX/R-Exec 区段
   c) 内核完整性
      - 系统调用/关键函数指针异常
      - 内核扩展与合法列表比对
   d) 网络状态实时快照
      - 处于 CLOSE_WAIT / ESTABLISHED 的意外外连

注意：必须在设备运行中且未重启时采集。重启后 DarkSword 类痕迹消失。

4.5 流程 D：Keychain 与数据保护异常检测

检查项异常信号
Keychain 访问审计非 App 上下文的批量读取、异常时间访问
备份中 Keychain 条目未知服务名条目、异常 kSecAttrAccessible 等级
数据保护类变更敏感数据被降级到 CompleteUntilFirstUserAuthentication
iCloud 密钥包异常的密钥轮换记录

5. 应急响应流程

假设：检测流程给出了阳性信号。

5.1 立即动作（0–1 小时）

步骤动作理由
1不重启、不关机、不重置设备重启会摧毁 DarkSword 的全部运行时证据
2断网（开启飞行模式，保留物理状态）阻断 C2 心跳与远程擦除；注意飞行模式仍保留蜂窝/部分状态
3保护现场与证据链记录时间、操作人、设备状态（电量、是否锁屏、时间戳）
4变更凭证（从另一台干净设备）Apple ID、邮箱、通讯应用密码；假设已泄露
5通知相关人员若为组织事件，法务/安全/管理层同步

5.2 取证保全（1–6 小时）

1. 优先采集 sysdiagnose（运行时证据，易逝）
2. 采集完整未加密备份（用于 MVT/AFC 分析）
3. 抓取网络侧证据
   - 路由器/网关 DNS 日志（对应时间窗）
   - 出口流量元数据、TLS 会话记录
4. 采集 iCloud 活动记录（登录历史、设备列表、密钥轮换）
5. 哈希所有证据文件并记录（SHA-256），建立完整性链

关键顺序：先内存/运行时，后备份——运行时证据一旦丢失不可恢复。

5.3 清除与恢复（6 小时–数天）

步骤说明
唯一可靠的清除手段是完整刷机设置 > 通用 > 传输或还原 iPhone > 抹掉所有内容和设置。"还原"不等于"抹掉"
不要从受感染备份恢复备份可能含落地载荷（Coruna 类）；应使用感染前基线备份
刷机后立即升级至最新版恢复设备时先应用补丁
重置所有凭证密码、Token、2FA 设备重注册
重新登记设备MDM/MDM 证书、Apple ID 设备列表清理

5.4 事后复盘

复盘项输出
入口在哪修补具体投递路径（如某水坑站点、某消息渠道）
潜伏多久由 DNS 日志与备份时间戳推定首次外连时间
采集了什么依据数据基线变化推断损失范围
是否针对组织关联其他设备命中同一 C2 的信号
检测延迟多久从首次异常到发现的时间差，用于改进监控

5.5 何时寻求外部支援

建议立即联系专业机构的情形：

  • 目标是 T0 人群（记者、活动人士、政要）
  • 涉及刑事/商业机密/国家安全事件，证据需具备法律效力
  • 内部无 iOS 取证能力（多数组织不具备）
  • 需要跨组织归因与情报共享

可求助方向：Citizen Lab、Amnesty Security Lab、Access Now Digital Security Helpline、专业数字取证公司。

6. 常见误区纠正

误区现实
"杀毒软件能查出来"iOS 沙箱不允许第三方 App 做全设备扫描；App Store 上无真正反间谍软件引擎，多为 IOC/行为启发式
"扫描干净说明没被入侵"只能证明"当前无落地痕迹"；无持久化攻击重启后完全无痕
"我没点可疑链接就安全"水坑攻击无需"可疑"——被入侵的正规网站正常访问即触发
"越狱检测能发现"商业间谍软件不做越狱，它做的是提权；越狱检测对其无效
"重启一下就好"对无持久化攻击有效，但会同时摧毁取证证据——诊断前不要重启
"iOS 更新会自动装"更新需用户确认；企业环境需 MDM 强制
"只用一次不影响"单次会话可完成密钥包提取与批量数据外传
"关掉 Safari 就没事"WebKit 被所有 iOS 浏览器共用，换浏览器不消除引擎层风险

7. 分角色实施清单

7.1 个人（T0 高危）

  • [ ] 系统升级至最新正式版，开启自动更新
  • [ ] 启用锁定模式，且不对外告知
  • [ ] 每日完整重启设备一次
  • [ ] 启用加密备份 + 高级数据保护（ADP）
  • [ ] Apple ID 启用 2FA，检查已登录设备列表
  • [ ] 关闭陌生人消息预览与链接自动加载
  • [ ] 路由器启用 DNS 日志与威胁阻断列表
  • [ ] 每月运行一次 MVT 备份扫描
  • [ ] 预先联系可求助的支援渠道
  • [ ] 建立"可疑时刻"记录习惯（异常发热、耗电、延迟、重启）

7.2 企业安全团队（T1–T2）

  • [ ] 清点全部 Apple 设备资产与 iOS 版本基线
  • [ ] MDM 强制最低版本 + 强制更新窗口
  • [ ] 保留 ≥60 天 DNS/NetFlow/TLS 元数据
  • [ ] 建立异常外连告警（非浏览器进程发起连接、上行突增）
  • [ ] 订阅 Citizen Lab / Amnesty / Apple 安全通告
  • [ ] 编写 iOS 入侵应急预案（含"不重启、先采内存"关键原则）
  • [ ] 演练一次完整应急流程
  • [ ] 为高管与敏感岗位提供锁定模式支持与专项监控
  • [ ] 与外部取证机构建立预先合同关系

7.3 家庭/非技术用户

  • [ ] 打开设置中的自动系统更新
  • [ ] 不安装描述文件（配置描述文件是企业证书滥用常见入口）
  • [ ] 不点短信/邮件中来源不明的链接
  • [ ] 定期在设置中检查"登录的设备"
  • [ ] 使用强密码与双重认证

8. 检测规则速查表

可直接用于 SIEM/监控平台的信号定义：

规则逻辑置信度
低信誉域名首次解析新注册 (<30 天) 域名被 iOS 设备解析中
DGA 特征命中域名熵 > 阈值 且 长度 > 阈值 且 无历史中
iOS 设备异常上行单设备 5 分钟内上行 > 基线 3σ中
守护进程外连mediaserverd/图形相关进程产生网络连接高
匿名可执行内存页非 JIT 进程存在 PROT_EXEC 匿名区高
JA3 与 UA 不一致TLS 指纹与声称客户端不匹配中高
精确周期心跳请求间隔方差 < 阈值 且 持续 > 1 小时中
Crash Reporter 新增异常WebContent/GPU 进程崩溃报告出现中
启动项 plist 新增备份中出现未知 LaunchDaemon/Agent高（Coruna 类）
同 C2 多设备命中≥2 设备解析同一低信誉域名高（定向水坑）

9. 总结

针对 Coruna 与 DarkSword 的防御本质上是一个纵深 + 时效问题：

  1. 纵深：单一检测手段必然有盲区。升级/锁定模式（入口）、备份扫描（静态工件）、网络日志（不可清除的第三方证人）、运行时监控（内存驻留）四层缺一不可。
  2. 时效：攻击方通过域名轮换、DGA、版本适配快速迭代。防御方的情报与规则更新速度直接决定检测成功率——过期的 IOC 库几乎无价值。
  3. 架构演进必须被预期：无持久化正在从特例变成标准。今天为 DarkSword 设计的检测缺口，明天会成为整个行业的通用缺口。投资运行时与网络层能力比扩充文件特征库更有长期价值。

最重要的三条行动，按投入产出比排序：

① 强制升级到最新版 → ② 对高危人群启用锁定模式 → ③ 保留 DNS/流量元数据 ≥60 天

这三项覆盖了绝大多数现实风险，且实施成本可控。
