Coruna 与 DarkSword 场景下向平台方请求记录：你能要到的比你以为的少，但比你现在的做法多

1. 执行摘要

  • 设备出问题之后，很多人的第一反应是"让苹果查一下"。这个反应方向没错，但"请求"和"得到"之间隔着一整套法律、隐私与工程约束，不了解这些约束的请求，通常连回执都拿不到。
  • 核心命题一：平台方不是你的取证机构。 它受自己的隐私政策、所在法域法律、以及"不针对个体提供账户内容"的公开立场三重约束；它能为全体用户做的事，远多于它能为你一个人做的事。
  • 核心命题二：请求的形态决定结果。 同一件事，描述成"我怀疑我被黑了，帮我看看"，和描述成"某账号在以下时间窗内出现了非我发起的登录与会话，请确认账户侧是否存在异常访问记录"，得到的响应完全不同。
  • 核心命题三：你要的往往不是"记录"，而是"一个可以写进报告的结论"。 而结论可以由三类材料共同支撑：你自己的设备侧证据、平台给出的账户侧事实、以及第三方鉴定意见（#195）。
  • 核心命题四：在等待期间你不能空手。 平台回执周期以周计，而设备侧可保全的内容以小时计衰减——先把本地能留的留下来，再谈向谁请求。
  • 核心命题五："要不到"不等于"没有问题"。 请求被拒、超期、或答复"未发现异常"，只能证明"在该口径下没有可披露的异常"，不能证明设备干净。
  • 一句话结论：把对平台方的期待，从"替我查明真相"下调到"为我确认某几个具体事实"，请求才可能被受理。

2. 这一篇补哪一格

本系列已经讨论过平台方的两个位置，但都不是这个方向：

篇目讨论的是方向
#149 平台方主动通知与被告知窗口平台先知道、再决定是否告知你平台 → 你
#157 高价值目标名单治理与分层保护组织内部如何给目标分层组织内部
本篇 #187你先怀疑、再去向平台要某几个具体事实你 → 平台

三者的差别不是措辞，而是举证责任的位置。#149 里你等的是别人给的信息；本篇里你必须先把"要什么、为什么、凭什么"写清楚，对方才有理由动。

同时本篇与 #177（外部事件响应服务商的委托与授权边界）互补：#177 讲你委托的人能看什么，本篇讲你不委托也绕不开的那个主体能给你什么。

3. 你实际能向平台方要到的四类东西

先做一次现实的分类。下面的"可得性"不是承诺，而是按公开披露政策与实践归纳出的量级判断；具体以服务条款、隐私政策与所在法域法律为准。

类别典型内容可得性通常以什么形式回来
账户侧访问事实登录记录、会话建立、设备列表、账户变更中你自己的账户页面可自查；异常时可能收到通知
购买与订阅事实订单、退款、订阅变更高自助可查
设备侧使用数据诊断日志、崩溃报告、部分系统日志低到中需你主动上传诊断；平台不按请求逐一提供
设备内容照片、消息、备份内容极低一般只在法律程序下，且受加密设计限制

第一列是事实，第四列是内容。 绝大多数"帮我查查"的请求失败，是因为请求者要的是第四列，而平台在架构上就不持有（端到端加密、仅设备密钥可解），或在政策上不针对个人开放。

把请求限定在第一、二列，成功率会显著上升；而这两列，恰恰是判断"是否存在账户侧入侵"的主要依据——因为定向投放的持久化往往不在设备上，而在账户上（#159 服务端与账号侧处置闭环）。

4. 为什么大多数请求得不到像样的回应

三类原因，按出现频率排序：

  1. 政策原因：不针对个体提供"是否被攻击"的判断。 平台方普遍不做"你这台设备是否被定向攻击"的个体结论。原因不是不愿意帮忙，而是这类结论一旦做出，就要承担错误判断的责任，而平台掌握的输入并不足以支撑它。
  2. 法律原因：跨法域的数据提供受严格限制。 账户数据通常存放在特定区域，向个人披露他国存储的数据，往往需要正式的法律程序（#170 跨境取证与司法协助的时间尺度）。
  3. 工程原因：很多数据根本不长这样。 "谁在什么时候动了我的手机"这类问题，在系统上并没有一张可查询的表。系统日志以设备为边界滚动覆盖，服务端只保留为运营所需的最小集合。

理解这三条，请求就不会写成"请告诉我发生了什么"，而会写成"请确认这三件事中的哪一件成立"。

5. 请求的正确形态：五个必须写清的要素

要素写错的样子写对的样子
时间窗"最近一段时间"具体到小时，且给出你的时区与来源（#146 时间与顺序基准）
对象"我的账号"账号标识、关联设备标识、关联邮箱/电话的完整清单
事实"我是不是被黑了"三个可判定命题：是否新增设备、是否新增会话、是否发生凭据或恢复方式变更
目的未说明明确用途（内部处置、监管报送 #169、诉讼准备 #183），并说明披露范围
依据无引用的服务条款条款、适用法律、或已有案号

"三个可判定命题"这一条最容易被忽略，也最有效。 把开放问题拆成可判定的封闭问题，对方才能给出"是/否/无法确认"，而"无法确认"本身就是一个可以写进报告的事实。

6. 等待期间：你必须在设备侧自己留下的东西

平台回执以周计，设备侧证据以小时计衰减。等待期间至少完成以下五项：

  1. 停止写入。 若怀疑设备被控，先降低活动（不是关机——关机可能触发某些保护性清空或丢失内存证据）。具体操作以专业意见为准（#177）。
  2. 导出可导出的。 系统设置里的隐私报告、屏幕使用时间、已安装描述文件与 VPN 配置、已登录设备列表——这些都能自助导出。
  3. 截图并记录时间。 任何异常界面、异常通知、异常耗电曲线，截图时保留状态栏时间（#178 调查记录的分层与被读风险）。
  4. 保留网络侧线索。 路由器的连接日志、运营商账单中的异常流量时段，往往比设备侧更完整（#192 电信运营商侧的可用信号与协作）。
  5. 建立一份事实表。 只写"何时、何地、发生了什么、由谁观察"，不写推论——推论进另一栏（#178 的"事实轨 / 意见轨"）。

这五项不需要等任何人批准，且它们构成后续所有请求的附件。

7. 平台回执的三种形态，以及它们各自能证明什么

回执形态字面含义能证明不能证明
"未发现异常访问"在该口径的时间窗与字段内没有命中账户侧无已知异常设备未被本地化攻击
"记录已按保留期清理"数据不存在了无任何方向性结论
"请通过法律程序获取"政策/法律限制你已履行请求义务事实本身

第二与第三种回执最容易被误读。 它们是"程序性答复"，不是"事实性答复"；把它们写成"平台确认没有问题"，会在后续任何一次复核中变成硬伤（#181 审计与认证中的历史事件陈述）。

正确写法示例："截至 X 日，平台方就 A、B 两项命题答复为'未发现异常'；C 项未获答复。该答复范围为账户侧记录，不覆盖设备本地状态。"

8. 要不到的时候：四条替代路径

  1. 自助复核。 重新检查设备列表、恢复联系方式、受信任号码、家庭共享成员——账户侧的入侵往往留下可自查的痕迹（#159）。
  2. 法律程序。 涉及重大损失或诉讼时，由律师评估是否启动正式程序（#170、#183）。这条路径慢，但它是唯一能突破政策限制的路径。
  3. 监管与通报渠道。 在受监管行业，报送本身会产生一条独立的时间线（#169），这条时间线不依赖平台配合。
  4. 独立鉴定。 由具备资质的机构就设备侧状态出具意见（#195），把"平台不答复"转化为"已通过独立途径评估"。

四条路径不是互斥的，通常需要并行推进；但它们对应的时间尺度差别很大，排期时必须分开（#184 多法域并行处置的冲突管理）。

9. 五类常见错误请求

错误形态为什么无效改法
群发式求助（同时发给多个渠道）触发反滥用流程，进入模板回复单一渠道、单一诉求
情绪化陈述（"我全家都被监控了"）无法转成可判定命题拆成三条封闭问题
附带大量未整理的截图与录屏超出处理能力，被视为噪音一份事实表 + 五个关键截图
要求"完整日志"不存在这样的数据集合要求"特定字段在特定时间窗的取值"
要求平台"确认是否被国家级攻击"平台不做此类归因（#174 跨案对比方法与统计口径的另一面）改为请求确认账户侧异常事实

10. 加固清单（八条）

  1. 先自查再请求。 设备列表、恢复方式、受信任号码三项，自己两分钟就能看。
  2. 把请求写成三条封闭命题，每条给出时间窗、标识符与判据。
  3. 附一份事实表，事实与推论分栏，标注观察者与时间来源。
  4. 明确说明用途与披露范围，这是对方评估可否响应的前提。
  5. 设定自己的回执期限（例如两周），到期未回复即转入替代路径。
  6. 保留全部往来回执原文，包括自动回复——它们构成"已履行请求"的证据。
  7. 不要替平台下结论。 回执写什么，报告里就写什么。
  8. 把"要不到"写进报告的局限段，而不是隐去。

11. 八条常见误解

  1. "平台能远程看我的手机。" 在正常架构下，平台不持有设备内容；这正是端到端加密的意义，也意味着它无法替你"看手机"。
  2. "报了就能查。" 请求受理与事实查明是两件事；多数请求止步于程序性答复。
  3. "回执说没问题就是没问题。" 回执只覆盖其口径内的字段与时间窗。
  4. "记录会一直保留。" 保留期普遍很短，这是趋势而非例外。
  5. "多个渠道同时问会更快。" 通常更慢，且更容易进入模板流程。
  6. "带越多材料越好。" 未整理的附件降低可信度；结构化的一页纸更有效。
  7. "请律师是翻脸。" 法律程序是把"政策问题"转成"义务问题"的唯一稳定路径。
  8. "要不到就没法写报告。" 报告的结论可以是"在该口径下无法确认"，这本身有信息量。

13. 总结

向平台方请求记录，是一件形式上很软、实质上很硬的事：软的是一句话就能发出，硬的是必须同时满足法律、政策、工程三重约束才能得到有效回应。

真正可操作的原则只有三条：

  1. 要事实，不要结论。 结论由你自己基于设备侧、账户侧与鉴定意见拼出来。
  2. 要特定的，不要全部的。 "全部日志"不存在；"某字段在某时间窗的取值"存在。
  3. 要不到也要留痕。 请求与回执本身，是"已尽力核实"的证据。

把这三条做扎实，即便平台一个字也不回，你的报告依然立得住。
