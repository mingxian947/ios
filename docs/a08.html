内存无文件攻击（In-Memory / Fileless Attack）· 分析文章

编制日期：2026-10-02 数据来源：CyberDefenders、ScienceDirect、MemInspect（内存取证研究）、Volatility 社区、SASA、公开威胁情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 什么是"内存无文件攻击"

内存无文件攻击（In-Memory / Fileless Attack） 指攻击者的恶意代码与状态只存在于内存（RAM）中，不向磁盘写入可执行文件（或仅极少落盘）。其核心目标：规避基于磁盘文件扫描的传统防病毒与事后取证。

典型特征：

  • 无落地恶意文件：载荷在内存中解密/反射加载执行，进程结束即消失。
  • Living-off-the-Land（LotL）：大量复用系统自带合法工具/解释器（如脚本引擎、系统服务），减少"可疑二进制"。
  • 内存驻留 C2 / 注入：通过进程注入、内存映射等方式在合法进程内运行。
  • 重启即失效（或部分失效）：纯内存形态通常不跨重启持久化；攻击者或以其他手段补偿持久化。

与 iOS 的关联：DarkSword 的"无持久化、短时驻留后清除痕迹"设计正是无文件/内存驻留思路在移动全链条攻击中的体现——不落地长期 implant，靠内存中短暂完成窃取与外传。

2. 攻击者为什么选择无文件

动机说明
规避磁盘 AV传统签名/静态扫描依赖文件；无文件则无扫描对象
规避事后取证关机/重启后内存内容丢失，磁盘取证难以还原
降低 IOC 暴露无恶意文件哈希、无落盘路径，网络与行为成为主要线索
复用合法工具LotL 使行为"看起来正常"，抬高检测阈值

3. 典型手法分类（防御视角）

以下为公开研究归纳的手法分类，用于检测与建模，不含具体利用代码。

类别手法检测线索
反射加载 / 内存执行在内存中解密并映射执行载荷，不写盘进程内存区异常可执行页、无对应磁盘映像
进程注入将代码注入合法进程（如系统服务）内存运行合法进程出现异常线程/内存段、异常子行为
LotL / 脚本引擎滥用用系统自带解释器/服务执行内存中指令解释器进程异常网络外联、异常父进程链
内存驻留 C2C2 逻辑驻留内存，经加密通道通信异常加密外传、DGA、非常规端口
凭据/密钥内存窃取直接从内存读取凭据、密钥（如 LSASS/钥匙串类）对敏感进程/密钥库的异常读取
无持久化短时攻击完成目标即清除，不跨重启事件窗口短、痕迹少，依赖实时捕获

4. 检测与取证（关键：从"磁盘"转向"内存 + 行为"）

由于无文件，磁盘扫描基本失效，检测重心必须转移：

运行时 / 行为检测

  • 监控进程内存属性：出现无磁盘 backing 的可执行页、异常 RWX 页
  • 监控进程注入迹象：合法进程异常线程、异常内存段、异常 API 调用序列
  • 监控 LotL：解释器/系统服务的异常网络外联、异常父进程、异常参数
  • 监控敏感内存读取：对凭据/密钥进程的异常访问

内存取证（事后）

  • 使用 Volatility / MemInspect 等工具对内存镜像分析：还原注入代码、内存驻留 C2、被篡改结构
  • 关键：尽快捕获内存镜像（重启即丢失），并结合网络流量佐证

网络层

  • DGA / 伪随机域名、异常加密通道、非常规端口外传
  • 与已知水坑/伪造门户的访问关联

5. 缓解与防护建议

个人 / 高危用户

  1. 保持系统最新：无文件攻击依赖的底层漏洞（Web/内核）修复靠系统更新。
  2. 高危时启用 Lockdown Mode：收紧攻击面，使全链条前置环节（含内存载荷投递）失效。

企业 / 组织

  1. 部署行为/内存级 EDR，而非仅依赖文件签名 AV；启用内存扫描与注入检测。
  2. 限制 LotL：对脚本引擎/系统工具做应用白名单与命令行审计（如约束解释器执行、记录参数）。
  3. 网络层封禁已知恶意门户，监控 DGA 与异常加密外传。
  4. 建立内存取证能力：制定"可疑事件→尽快内存镜像"的响应流程（重启前捕获）。
  5. 对高价值人群分层防护（Lockdown Mode + 专用网络 + 行为监控）。

研究 / 防御团队

  1. 威胁建模覆盖"内存驻留 + LotL + 无持久化"组合；回归测试相关 CVE 补丁。
  2. 结合 Volatility/MemInspect 做内存取证演练，提升对无文件痕迹的还原能力。

6. 结论

内存无文件攻击把战场从"磁盘"搬到"内存"，使传统文件扫描与磁盘取证失效；其核心是反射加载、进程注入、LotL、内存驻留 C2 与无持久化短时行动的组合。iOS 侧的 DarkSword"无持久化"设计即此思路的移动化体现。防御必须转向"运行时行为 + 内存属性 + 网络遥测 + 快速内存取证"：行为/内存级 EDR、LotL 约束、DGA 监控与"重启前捕获内存"的响应流程，是对抗无文件攻击的关键。及时补丁 + Lockdown Mode 仍是削减攻击面的第一道防线。
