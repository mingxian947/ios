Coruna 与 DarkSword 漏洞供应链与商业采购生态

编制日期：2026-10-18 数据来源：Citizen Lab、Amnesty International、Washington Post / Guardian 调查报道、Project Zero、WikiLeaks Vault7 相关公开分析、CVE 情报库 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

公众讨论 iOS 零日时通常聚焦"漏洞本身"，但真实的产业结构是：绝大多数发动攻击的组织并不自己发现漏洞。漏洞是一条分工明确的供应链上的商品——有研究者发现、有中间商打包、有集成商组装成套件、有客户按目标采购。

Coruna 与 DarkSword 的技术差异，在很大程度上可以被它们在供应链中所处的位置解释：

  • Coruna 展现出大规模采购 + 长期复用的特征：23 个 CVE、跨 5 个大版本、包含大量 N-day
  • DarkSword 展现出高质量单一来源特征：组件集中、链条精悍、明显针对较新版本窗口

本文解析这条供应链的角色分工、定价结构、流通与泄露机制，以及防御者如何利用供应链知识提升检测与补丁效率。

2. 漏洞供应链的角色分工

2.1 角色模型

[发现者]
  安全研究者 / 内部研究团队 / 竞赛参赛者
  产出：单个 CVE 级漏洞 + PoC
        ↓
[采集方 / Broker]
  与研究者签约、批量收购、组织竞赛
  产出：漏洞组合、可交付 exploit 模块
        ↓
[集成商 / 套件厂商]
  NSO、IntelCere、Var-11(Linear)、Cytb Technologies 等
  产出：完整利用链 + 载荷 + C2 + 运营平台
        ↓
[转售方 / 区域代理]
  面向政府客户的销售与部署支持
        ↓
[最终用户 / 客户]
  情报、执法、军方机构（按目标授权数付费）

2.2 各层的经济学特征

层收入模式成本结构关键约束
发现者单洞出售（数万至数十万美元级）时间与研究能力漏洞唯一性一旦泄露即归零
采集方差价 + 长期合同关系网络、法律风险需持续供给，不能断货
集成商套件许可 + 部署 + 支持研发人力（重资产）需覆盖多版本以维持客户
转售方佣金低合规与客户关系
客户—按目标数/年费需要结果，不关心技术

2.3 为什么这条链条存在

核心原因：漏洞价值的时效性与不可储存性。

漏洞价值 = f(唯一性, 版本覆盖范围, 未被修补时长)
   ↓
一旦被公开 / 被修补 → 价值趋近于零（仅剩旧版本设备）
   ↓
持有者必须在窗口期内变现，不能"存着以后用"

这催生了专业化中间商——研究者不擅长销售、买家不想被追溯，中间层负责匿名化与组合包装。

3. 从套件特征反推供应链位置

防御者与研究员可借助技术特征推断一款套件的资源来源——这对归因与优先级判断都有价值。

3.1 判据表

观察到的特征供应链推断
大量 N-day（已修补漏洞）强调成本控制，采购成熟漏洞或复用泄露库
覆盖极宽版本跨度长期多批次采购积累，非一次性投入
单版本窗口 + 组件极少高质量单批采购或自研，赌新版本
多个不相关组件被精确组合有专业集成团队（非个人研究者）
使用同一供应商的多代漏洞长期供应商合同关系
漏洞组合与他人泄露高度重合复用泄露库（如 GHOSTBLADE）
组件新颖、公开研究中无先例内部研究能力或独家买断
有明确的 ABI/模块化架构平台型厂商，服务多客户

3.2 应用到 Coruna

特征推断
23 个 CVE、跨 iOS 13–17.2.1长期多批次采购 + 复用积累
多条独立链并行维护具备规模化的集成工程团队
大量使用已修补漏洞明确以 N-day 控制零日消耗成本
分层 C2 + 平台化载荷服务化产品，面向多客户运营
版本覆盖到 17.2.1 截止供应链存在供给断点——某时点后未能拿到新漏洞或未完成集成

供应链视角下最有价值的一条：覆盖范围的截止点往往反映供应商交付能力的问题，而不是攻击者意愿。这类"断供"信号对预测下一代套件的能力边界有帮助。

3.3 应用到 DarkSword

特征推断
组件集中于 JSC + 图形栈单批次高质量供给，可能来自同一供应商
针对较新 iOS 窗口获取漏洞的时间较近，积累浅
无持久化、模块化程度低载荷工程投入偏向隐蔽性而非运营广度
链条精悍但冗余少更像"精工单点武器"，非平台产品
面向特定运营场景客户数量可能有限，或高度定制

4. 漏洞的流通与泄露机制

4.1 四种流通形式

形式说明对防御的意义
正常商业销售供应商 → 集成商 → 客户不可见，只能通过攻击反推
跨集成商复用同一 exploit 出现在不同套件一次分析保护多场景
内部泄露供应商被攻破/员工外泄/客户间流转突然出现的"新"套件使用旧漏洞
被捕获后公开防御者抓取样本并公开发布该链价值归零，生态共享情报

4.2 GHOSTBLADE 的教科书意义

GHOSTBLADE（2024）直接使用了已泄露的其他套件利用链，其价值在于证明了三件事：

  1. exploit 作为资产可在生态中流转，不绑定于原始买家
  2. 泄露使攻击能力快速民主化——原本只属于头部厂商的能力，二线厂商也能立即使用
  3. 防御的乘数效应：修补一个被复用的漏洞，同时防护多个套件、多个客户场景

对补丁优先级排序的直接指导：不要问"这个 CVE 影响我们多少产品"，要问"这个 CVE 出现在多少条已知在野链条中"。

4.3 泄露的常见触发点

触发点说明
供应商内部安全事件邮件/存储被入侵，资产外流
客户间流转某客户的部署被另一客户/机构获取
员工离职携带研究者/工程师流动
分析样本公开防御机构公开完整分析，代码逻辑随之扩散
执法/司法披露诉讼、听证中文件被公开
内部举报员工出于伦理动机泄露

4.4 泄露对防御者的双面影响

正面负面
突然获得完整技术细节，检测规则可快速建立更多组织获得攻击能力，攻击者基数扩大
可预测同类链条在其他套件中的复现旧漏洞在存量设备上永久有效，长尾风险
归因与法律行动获得证据供应商会加快转向更难获取的新面

5. 定价与消耗结构（概念性）

5.1 漏洞价值的决定因素

因素说明
交互模型0-click 远高于 1-click（无探测机会 → 更稀缺）
组件稀缺度基带/SEP > GPU 驱动 > WebKit
版本覆盖范围能覆盖多个大版本的价值高于仅一版
成熟度可直接集成的完整链 >> 需大量工程的 PoC
独家性是否已出售给多家
预期寿命距离 Apple 修补预计多久

5.2 为什么集成商必须大量采购

一个客户授权投放 100 个目标
   ↓
每条链条预期成功率有限 + 版本参差 + 部分被修补
   ↓
需要多条链 + 多版本适配 + 备用漏洞
   ↓
Coruna 式的"23 个 CVE / 5 条链"是这种成本结构的必然产物

关键推论：多链架构不是技术偏好，而是采购成本摊薄的结果。 单链方案在大规模投放下会因失败率与版本失配导致整体收益不足。

5.3 消耗率与供应链压力

压力来源效应
Apple 修补速度加快漏洞窗口期缩短 ⇒ 采购需求上升
分析机构公开披露漏洞价值归零 ⇒ 需持续补充
客户交付压力促成复用泄露链（GHOSTBLADE 路径）
研究者供给有限推动竞赛/ bounty 与自研团队投入

可预测的趋势：随着单洞寿命缩短，集成商会越来越多地选择"用已有资产做无持久化突击"（DarkSword 式）而非"建立长期驻留"——因为无法保证驻留期间的持续供给。这条逻辑把供应链压力与架构选择直接连了起来。

6. 供应链视角下的防御策略

6.1 补丁优先级重构

传统优先级（CVSS 分数）在商业间谍场景下指引性不足。建议改为"链条覆盖加权"：

优先级 = CVSS 基础分
       × 该 CVE 出现在已知在野链中的条数权重
       × 该 CVE 影响的存量未更新设备比例
       × 组件稀缺度（0-click/基带/SEP 类加权更高）

实操表：

情形处理
Apple 标注 "actively exploited in the wild"立即部署，不等维护窗口
CVE 出现在 Citizen Lab/Project Zero 报告的链条中最高优先级
图形栈/内核驱动类"仅影响显示"的措辞仍按提权入口对待（见 #58）
信息泄露类（无 RCE 措辞）与 RCE 同等优先（缺它链条不成立，见 #51）
影响范围覆盖大量存量设备即使无在野证据也需提升

6.2 缩短"供给—部署"时延差

Apple 发布修补（Day 0）
     ↓
组织实际完成部署（Day N）
     ↓
N 就是攻击者的免费作战窗口
措施效果
MDM 强制最低版本 + 自动更新窗口直接压缩 N
提前验证兼容性（而非等补丁发布再测）消除测试阻塞
对 T0/T1 单独走快速通道关键设备优先
盘点"无法升级"设备（老机型）识别永久性风险资产

供应链最脆弱的一环正是这个 N。Coruna 覆盖到 iOS 17.2.1 这一事实说明：即使漏洞已被修补数月，仍有大量设备处于暴露状态。

6.3 情报投资方向

情报类型价值获取渠道
在野利用清单最高（直接指导补丁）Apple 公告、Citizen Lab、Project Zero
漏洞供应链市场动态中高（预测下一代能力方向）研究会议、行业报告
套件基础设施 IOC高（网络检测）MVT IOC 库、Lookout、商业 TI
目标人群威胁画像高（决定投入强度）内部风险评估

6.4 异构与冗余防御

由于攻击者的核心优势是"知道所有人用同一版本、同一配置"：

措施原理
版本异构（在可行范围内）使单一链条无法覆盖全员
配置异构（部分人开锁定模式）迫使攻击者维护多套投递逻辑
平台异构同一水坑需适配多种目标
补丁时间错峰减少"同一批漏洞同时暴露"的规模

7. 伦理与治理维度

作为防御性研究，需要正视这条供应链的治理现实：

议题现状
出口管制多国已将入侵软件纳入管制清单，但跨境执行难
客户滥用报道显示被用于记者、活动人士、政治对手，超出"执法"用途
问责机制供应商多主张"客户自负合规"，缺乏实际审计
研究者角色出售漏洞是否合乎伦理存在持续争议；bounty 与灰色市场并存
受害者通知部分项目（如 Pegasus Project）通过媒体/公民社会而非厂商通知

对防御研究者的实践建议：

  1. 公开披露前评估：公开分析会摧毁该链的攻击价值（防御收益），但也可能泄露受害者的取证线索（需与当事人协商）
  2. 与公民社会/专业机构协作而非单打独斗
  3. 敏感目标群体的取证需注意证据法律效力与人身安全（见 #62）

8. 总结

#结论
1iOS 攻击产业是分工明确的供应链：发现者→采集方→集成商→转售方→客户，绝大多数攻击者不自己发现漏洞
2漏洞不可储存——其价值随公开与修补迅速归零，这决定了中间商与囤货式采购的必然存在
3套件的技术特征可以直接反推其供应链位置：多链宽覆盖 = 长期多批次采购；单链窄覆盖 = 单批高质量供给
4Coruna 的多链架构不是技术偏好，而是采购成本摊薄的结果
5GHOSTBLADE 证明 exploit 会跨套件流转——修补一个被复用的漏洞可同时防护多个套件与客户
6补丁优先级应按"该 CVE 出现在几条在野链条中"加权，而非仅看 CVSS
7攻击者真正的弹药库是"存量未更新设备"——组织暴露时长 N 天，就有 N 天免费窗口
8供给断点（覆盖版本截止点）是可预测的信号，反映供应商交付能力而非攻击者意愿
9供应链压力（单洞寿命缩短）正在推动架构向"无持久化突击"迁移——DarkSword 是这个压力的产物

一句话总结：

把 iOS 零日理解为"天才黑客的发现"会误导防御投资。 它是一个受时效性约束的商品市场：库存会过期、供给会断链、商品会流通。 因此最有效的防御不是"防住最厉害的漏洞"，而是缩短自己的部署时延——那是这个市场唯一无法绕过的需求侧变量。
