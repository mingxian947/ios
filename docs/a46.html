Coruna 与 DarkSword C2 通信协议分析

编制日期：2026-10-02 数据来源：Google Project Zero、Citizen Lab、Lookout、Amnesty International、公开 CVE 情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

命令与控制（Command and Control, C2） 是攻击链中连接"已入侵设备"与"远程操控者"的核心通道。无论漏洞利用多精妙、提权多彻底，若 C2 通道被截断或检测，攻击者将无法下发指令、获取数据——整个入侵即告失败。

Coruna 与 DarkSword 作为两代 iOS 商业间谍利用套件，在 C2 设计上展现了截然不同的哲学：

  • Coruna 采用多阶段、模块化、分层 C2 架构，支持持久化运营与细粒度任务下发
  • DarkSword 采用极简、内存驻留、短暂会话模式，与无持久化策略高度一致

本文从 C2 基础设施架构、通信协议与加密、心跳与任务下发、数据回传通道、反检测策略五个维度，系统对比分析两套 C2 体系，并给出防御检测建议。

2. C2 基础设施架构

2.1 Coruna 的多层 C2 架构

Coruna 的 C2 基础设施采用典型的三层洋葱架构，每一层增加一层抽象，保护后端真实控制节点：

┌─────────────────────────────────────────────────┐
│  前端层（Frontend）                              │
│  - 水坑/钓鱼网站、CDN 边缘节点                   │
│  - 仅负责投递与初始连接引导                       │
├─────────────────────────────────────────────────┤
│  中转层（Relay / Redirector）                    │
│  - 合法云服务（AWS、GCP、Azure）或 VPS            │
│  - 流量转发与负载均衡                            │
│  - 可频繁更换 IP，低成本重建                     │
├─────────────────────────────────────────────────┤
│  后端控制层（Backend C2）                         │
│  - 真实任务管理、数据存储、操作员交互界面          │
│  - 部署在隐蔽网络环境，最小化暴露面               │
└─────────────────────────────────────────────────┘

设计特征：

特征说明
域名分层前端用一次性域名，中转用合法云服务域名，后端用私有域名
IP 轮换中转层 IP 频繁更换，避免被 IP 封禁追踪
合法基础设施伪装中转层部署在 AWS/GCP/Cloudflare 等知名平台，混入合法流量
模块化载荷下发后端按需下发功能模块（采集、监控、外传），非一次性推送完整载荷

2.2 DarkSword 的轻量 C2 架构

DarkSword 的 C2 架构与其无持久化策略一致——极简、短暂、不留痕迹：

┌──────────────────────────────────┐
│  单一入口点                       │
│  - 水坑页面（触发漏洞 + 引导连接） │
├──────────────────────────────────┤
│  C2 节点                         │
│  - 通常 1-2 个服务器             │
│  - 处理任务下发与数据接收         │
│  - 会话结束后清理日志             │
└──────────────────────────────────┘

设计特征：

特征说明
扁平架构无多层中转，减少延迟（适合短暂会话）
少节点1-2 个 C2 节点即可，降低基础设施成本与维护复杂度
日志最小化服务器端不持久化日志，会话结束后清除
DGA 域名使用域名生成算法（Domain Generation Algorithm），每天/每小时生成新域名

2.3 架构对比

维度CorunaDarkSword
层级数3 层（前端→中转→后端）1-2 层（入口→C2）
节点数量多（10+ 域名/IP）少（1-3 个）
基础设施类型云服务 + VPS + CDNVPS + DGA 域名
部署复杂度高低
抗封禁能力强（可快速替换中转层）中（DGA 提供域名轮换）
会话持续时间长（持续连接）短（任务完成即断开）
重启后恢复自动（持久化 C2 配置）需重新投递

3. 通信协议与加密

3.1 Coruna 的协议栈

Coruna 在传输层和应用层之间构建了一套自定义协议栈：

┌──────────────────────────────┐
│  应用层：自定义二进制协议      │
│  - 消息类型：任务下发/结果回传 │
│  - 压缩：zlib / LZ4           │
│  - 分片：大数据分段传输        │
├──────────────────────────────┤
│  加密层：AES-256 / ChaCha20   │
│  - 会话密钥：ECDH 密钥协商     │
│  - 密钥轮换：定期重新协商       │
├──────────────────────────────┤
│  传输层：HTTPS / TCP           │
│  - 标准 443 端口              │
│  - TLS 1.2/1.3               │
├──────────────────────────────┤
│  网络层：IPv4 / IPv6           │
└──────────────────────────────┘

协议特征：

特征说明
双信道主信道（HTTPS 443）传输常规指令与数据；备用信道（DNS / ICMP）在主信道被阻断时激活
消息认证每条消息附带 HMAC-SHA256，防止中间人篡改
序列号防重放递增序列号 + 时间戳窗口，拒绝重放攻击
加密元数据不仅加密载荷，还加密消息类型、任务 ID 等元数据

3.2 DarkSword 的协议栈

DarkSword 采用更轻量的协议设计，适配其短暂会话模式：

┌──────────────────────────────┐
│  应用层：简洁 JSON / Protobuf │
│  - 少量消息类型               │
│  - 一次性任务下发 + 数据回传   │
├──────────────────────────────┤
│  加密层：TLS Pinning + AES    │
│  - 依赖系统 TLS 框架          │
│  - 载荷层额外 AES 加密        │
├──────────────────────────────┤
│  传输层：HTTPS                │
│  - 模拟合法 API 请求模式      │
│  - User-Agent 伪装            │
└──────────────────────────────┘

协议特征：

特征说明
单信道仅使用 HTTPS，不维护备用信道（减少检测面）
TLS 指纹伪装使用与 Safari/Chrome 一致的 TLS ClientHello 指纹，混入合法浏览器流量
HTTP 请求伪装C2 请求路径与参数模仿合法 REST API（如 /api/v1/config、/api/v2/update）
无状态设计每次会话独立，不维护长连接或会话 ID

3.3 加密方案对比

维度CorunaDarkSword
密钥协商ECDH（X25519）ECDH 或静态预共享密钥
对称加密AES-256-GCM / ChaCha20-Poly1305AES-256-GCM
消息认证HMAC-SHA256TLS 内置 + 载荷级 HMAC
密钥轮换定期（每 N 条消息或每 M 分钟）每次会话重新协商
证书固定（Pinning）是（自定义 CA 证书）部分实现
加密粒度消息级 + 会话级会话级 + 载荷级

4. 心跳机制与任务下发

4.1 Coruna 的心跳模型

Coruna 采用分层心跳机制，不同阶段使用不同的频率和通道：

[植入阶段]  高频心跳（30-60 秒）→ 确认植入成功，等待初始任务
     ↓
[稳定阶段]  中频心跳（5-15 分钟）→ 正常运营，随机抖动
     ↓
[静默阶段]  低频心跳（1-6 小时）→ 高警觉期，降低被检测概率

心跳消息结构（简化）：

┌────────────┬────────────┬────────────┬────────────┐
│ 设备 ID    │ 时间戳     │ 状态标志   │ 加密校验   │
│ (8 bytes)  │ (4 bytes)  │ (1 byte)   │ (32 bytes) │
└────────────┴────────────┴────────────┴────────────┘

任务下发模式：

  • Pull 模式：心跳响应中携带任务指令（"从 C2 拉取"）——攻击者不主动推送，而是等待设备来取
  • 模块热加载：C2 可动态下发新的功能模块（如加密数据采集模块），设备在内存中加载执行
  • 分级任务：任务分为"立即执行"和"条件执行"（如"设备连接 Wi-Fi 时执行"、"屏幕锁定时执行"）

4.2 DarkSword 的心跳模型

DarkSword 的心跳设计更简洁，与其无持久化策略一致：

[初始连接]  投递后立即建立连接 → 接收任务
     ↓
[任务执行]  一次性接收所有任务 → 内存中执行 → 回传结果
     ↓
[结束]     断开连接、清除内存 → 不再心跳

心跳特征：

特征说明
短会话单次连接完成所有通信，不维护长连接
批量任务一次下发所有任务，不逐步拉取
无静默阶段任务完成即断开，不存在"持续监控"心跳
随机延迟初始连接可能加入随机延迟（30 秒 - 5 分钟），避免投递与 C2 连接的时间关联

4.3 任务下发能力对比

任务类型CorunaDarkSword
即时采集（短信/通话记录）✅ Pull 模式随时触发✅ 初始连接时一次性下发
持续监控（位置/麦克风）✅ 条件执行 + 后台心跳❌ 需要持续在线，不适合无持久化
模块热加载✅ 下发新模块到内存执行⚠️ 有限支持（单次会话内加载）
设备管理（截图/录音）✅ 远程指令✅ 初始任务中包含
自毁指令✅ 收到指令清除所有痕迹✅ 自然自毁（重启即清除）
重新投递协调✅ 持久化 C2 配置支持⚠️ 需水坑页面协调

5. 数据回传通道

5.1 Coruna 的多通道回传

Coruna 建立了丰富的数据回传通道体系，根据数据量、紧急程度和隐蔽需求选择不同通道：

通道适用场景特征
HTTPS POST常规数据（消息、联系人、通话记录）主通道，伪装为 API 上报
分块上传大数据（照片、录音、视频）分片传输，每片伪装为独立请求
DNS 隧道小量关键数据（凭证、密钥）将数据编码在 DNS 查询的子域名中
备用 IP 直连主域名被封时硬编码备用 IP 列表，直接连接
iCloud 同步极隐蔽场景（利用合法云同步）通过被控设备自身 iCloud 账户同步

数据回传流程：

[采集] → [内存中压缩/加密] → [按通道分片] → [加密外传] → [C2 接收/解密/重组]

5.2 DarkSword 的简洁回传

DarkSword 的回传策略更直接：

通道适用场景特征
HTTPS 单次上传所有采集数据一次性打包上传，不分多次
TLS 加密传输层保护使用系统 TLS 框架
内存中打包数据组装压缩+加密全在内存完成，不写临时文件

关键约束：

  • 无备用通道：如果 HTTPS 被拦截，任务数据无法回传（攻击失败但不暴露）
  • 分片上传：大文件（如照片集）需分片上传，每片伪装为独立 HTTP 请求
  • 即时清除：上传完成后立即从内存中清除数据

5.3 回传能力对比

维度CorunaDarkSword
通道数量5+ 种1-2 种
抗封锁能力强（多通道冗余）弱（单通道）
大数据传输✅ 分块 + 断点续传⚠️ 受限于会话时长
元数据回传✅ 丰富（设备信息、环境参数）✅ 精简（仅任务结果）
实时回传✅ 支持（持续心跳可即时发送）❌ 不支持（需等待会话）

6. 反检测策略

6.1 Coruna 的 C2 反检测

技术说明
域名轮换定期更换前端和中转域名，使用 DGA 或人工管理
合法服务伪装中转层部署在 AWS/GCP/Cloudflare，流量与合法应用无异
TLS 指纹一致性ClientHello 与真实 Safari 完全一致
流量混入C2 请求频率、大小、时间分布模仿合法 App API 调用
Honeypot 检测对"过于热心"的安全研究人员 IP 返回假内容
连接认证验证请求来源的设备指纹，防止自动扫描器探测

6.2 DarkSword 的 C2 反检测

技术说明
DGA 域名算法生成域名，每日/每轮更新，无法提前黑名单
短暂会话连接时间极短（几秒到几分钟），减少被网络分析窗口捕获的概率
无 C2 特征文件不在设备上留下 C2 配置文件，连接参数仅存在于内存
TLS 指纹伪装使用 Safari 原生 TLS 栈，指纹与正常浏览一致
HTTP 路径伪装请求路径模仿合法 API（如 /api/v1/config、/update/check）

6.3 反检测对比

维度CorunaDarkSword
域名策略多层轮换（前端+中转+后端）DGA 自动生成
基础设施伪装云服务混入VPS 直接连接
TLS 对抗完全模拟 Safari使用系统 TLS 框架
流量分析规避模仿合法 App API 频率短暂会话减少分析窗口
蜜罐检测有无（简单架构不需要）
反扫描器设备指纹认证无（水坑触发本身即为认证）

7. 已知 C2 基础设施案例

7.1 Coruna C2 基础设施

根据 Citizen Lab 和 Lookout 的公开报告，Coruna 的 C2 基础设施有以下已知特征：

  • 域名注册：通过隐私注册商批量注册，注册信息使用虚假邮箱和电话
  • 托管位置：中转层分布在多个云区域（us-east-1、eu-west-1、ap-southeast-1），利用地理分散增加关闭难度
  • CDN 前端：使用 Cloudflare 或类似 CDN 隐藏后端真实 IP
  • 证书：使用 Let's Encrypt 免费证书或自签名证书（部分场景使用商业 CA 签发）
  • 已知模式：水坑页面 URL 常包含特定参数结构，如 ?v=<版本>&c=<目标ID>

7.2 DarkSword C2 基础设施

根据 Project Zero 的分析，DarkSword 的 C2 有以下已知特征：

  • DGA 域名：使用特定种子生成的域名，每日更换，模式可通过逆向分析预测
  • IP 托管：偏向使用小型 VPS 提供商（而非主流云），降低基础设施成本
  • 证书：自签名证书或短期有效 Let's Encrypt 证书
  • 流量特征：单次 HTTPS 会话即可完成，HTTP 请求头中可能包含 Base64 编码的设备标识

7.3 基础设施演化趋势

从公开报告的时间线来看，两套 C2 体系都在演化：

时间事件影响
2023 Q3Coruna 首次大规模部署暴露多层 C2 架构，部分域名/IP 被公开
2024 Q1Project Zero 公开 DarkSword 分析DGA 算法细节泄露，Apple 修补相关漏洞
2024 Q2Coruna 部分 C2 基础设施被封禁暴露云服务依赖的弱点，中转层开始向更小众托管迁移
2024-2025新一代 C2 设计出现两套体系开始融合：Coruna 引入 DGA，DarkSword 增加备用通道

8. 检测与防御

8.1 网络层检测

检测点方法
DGA 域名使用 DGA 检测算法（如 n-gram 分析、域名长度/熵阈值），对每日新域名自动识别
TLS 指纹异常对比 ClientHello 与声称的 User-Agent 是否匹配（如 Chrome UA + Safari 指纹 = 异常）
HTTP 路径模式分析请求路径、参数结构，与已知合法 App API 模式对比
流量频率异常检测非人类操作模式的请求频率（如精确 30 秒间隔）
证书异常标记短期证书、自签名证书、与声称服务不符的证书

8.2 设备层检测

检测点方法
异常网络连接监控后台进程的主动外连（非用户操作触发）
DNS 查询异常检测高频子域名查询（DNS 隧道特征）
进程网络行为系统进程（如 mediaserverd）不应产生网络连接
内存中 C2 配置内存取证搜索硬编码的域名、IP、证书指纹

8.3 威胁情报

情报类型价值
C2 域名/IP 黑名单直接阻断已知 C2，但有效期短（需持续更新）
TLS 指纹库识别特定 C2 实现的 TLS 异常
基础设施关联通过证书、ASN、注册信息关联多个 C2 节点
DGA 种子预测若 DGA 算法被逆向，可预测未来域名并提前阻断

8.4 防御建议

建议优先级
部署 TLS 检测（TLS Inspection）高 — 可检查加密流量内容，但需管理证书信任链
DNS 过滤 + 威胁情报高 — 阻断已知恶意域名与 DGA 模式域名
出站流量基线中 — 建立正常设备流量基线，检测异常外传
证书透明度日志监控中 — 检测攻击者新签发的证书
锁定模式极高 — 禁用非必要网络连接，限制攻击面

9. 总结

Coruna 与 DarkSword 的 C2 通信协议设计体现了两种截然不同的运营哲学：

Coruna：持久化运营型

  • 多层架构，抗封禁能力强
  • 丰富的心跳机制支持长期监控
  • 多通道回传确保数据可达性
  • 代价：基础设施复杂、维护成本高、暴露面大

DarkSword：短暂任务型

  • 扁平架构，简洁高效
  • 单次会话完成任务下发与数据回传
  • 与无持久化策略完美配合
  • 代价：抗封锁弱、不支持实时监控、重启后需重新投递

从防御视角，C2 是攻击链中最容易被外部检测的环节——漏洞利用在设备内部、沙箱逃逸在系统内部、数据存储在进程内部，但 C2 通信必然穿越网络边界。这意味着：

  1. 网络层是最有效的检测切入点——TLS 指纹分析、DGA 域名检测、流量模式分析可在不接触设备的情况下发现异常
  2. 基础设施关联分析可放大检测价值——一个 C2 IP 可关联到多个目标设备，封禁一处保护多处
  3. 威胁情报共享是核心策略——公开已知的 C2 基础设施模式，帮助整个社区提升检测能力
