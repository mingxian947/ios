Coruna 内核提权与 PAC 绕过技术

编制日期：2026-10-13 数据来源：Google Project Zero、Apple Security Advisory、公开安全研究 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

Coruna 内核提权阶段是攻击链中从系统级权限跃迁到 root 权限 + 内核读写 的关键环节。在沙箱逃逸后，攻击者需要进一步突破内核级保护，包括 PAC（Pointer Authentication Code） 等硬件级控制流完整性机制。

本文深入解析 Coruna 如何实现内核提权以及 PAC 绕过技术。

核心内容：

  1. 内核提权目标与挑战
  2. PAC 机制与绕过技术
  3. Coruna 内核漏洞利用原理
  4. 从内核提权到完全控制
  5. 与 DarkSword 提权路径对比

风险等级：严重（Critical）。

3. PAC 机制与绕过

3.1 PAC 原理

Pointer Authentication Code（PAC） 是 ARMv8.3+ 的控制流完整性机制：

函数指针 / 返回地址
        ↓
使用密钥签名（PAC 指令）
        ↓
存储：[指针值 + PAC 签名]
        ↓
调用前验证（AUT 指令）
        ↓
  ┌─ 签名有效 → 执行
  └─ 签名无效 → 异常

3.2 PAC 保护的指针类型

类型说明
代码指针函数指针、虚表指针
返回地址栈上的返回地址
数据指针某些关键数据结构指针

3.3 PAC 绕过技术

技术原理难度
签名泄露泄露 PAC 密钥/上下文极高
XPAC 攻击利用 PAC 高位未签名（指针异或）高
签名绕过找到不检查 PAC 的代码路径中–高
PAC 预言侧信道预测有效签名极高

3.4 Coruna 的 PAC 绕过

Coruna 可能使用的技术（基于公开信息推断）：

  1. 签名绕过：找到不验证 PAC 的内核代码路径
  2. XPAC 攻击：利用指针异或操作绕过 PAC
  3. ROP：不修改指针，复用现有代码片段

4. Coruna 内核漏洞利用

4.1 可能的漏洞类型

类型说明案例
IOKit User Client驱动接口内存破坏历史常见
内核内存管理XNU VM 子系统缺陷历史常见
竞态条件TOCTOU 漏洞难度高
逻辑缺陷权限检查遗漏难度中

4.2 利用流程（简化）

沙箱逃逸后（系统级权限）
        ↓
KASLR 绕过（信息泄露）
        ↓
获得内核基址
        ↓
利用内核漏洞（IOKit/内存管理）
        ↓
内核内存破坏 → 控制流劫持
        ↓
绕过 PAC（签名绕过/XPAC/ROP）
        ↓
修改 cred → uid = 0（root）
        ↓
获得 task_for_pid(0)
        ↓
完整内核读写能力

4.3 关键技术点

KASLR 绕过：

  • 通过信息泄露获得内核指针
  • 计算内核基址

控制流劫持：

  • 覆写内核函数指针/虚表
  • 或 ROP 链复用现有代码

PAC 绕过：

  • 找到不验证 PAC 的路径
  • 或使用 ROP 避免修改指针

权限提升：

  • 修改进程 cred 结构 → uid = 0
  • 获得 task_for_pid(0) → 内核任务控制

7. 硬件级保护的影响

7.1 KTRR/PPL 的影响

保护影响Coruna 应对

保护影响

结论：A17+ 设备上，Coruna 类攻击难度极大。

9. 总结

Coruna 内核提权是攻击链的第四阶段：

维度现状
目标root 权限 + 内核读写
挑战PAC、KTRR、PPL、KASLR
技术PAC 绕过 + 内核漏洞利用
结果完全控制设备

技术要点：

  1. PAC 绕过是关键（签名绕过/XPAC/ROP）
  2. 内核漏洞实现控制流劫持
  3. 修改 cred 获得 root 权限
  4. A17+ 设备 SPTM/TXM 大幅提高难度
