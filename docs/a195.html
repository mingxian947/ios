Coruna 与 DarkSword 场景下的司法鉴定与专家意见：能不能用，取决于"你是怎么知道的"

1. 执行摘要

  • 事件结束后，技术团队最常见的诉求是"找一家机构出个报告"。但报告的价值不取决于结论有多肯定，而取决于结论能不能被另一个人用同样的方法复核。
  • 核心命题一：鉴定意见的可采性，建立在三件事上：检材的真实性、方法的可靠性、结论与检材的对应关系。 三者缺一，结论再正确也无法使用。
  • 核心命题二："谁来做"不如"按什么做"。 司法鉴定机构、专家辅助人、内部技术负责人，三种角色的资质与产出形式不同，但都要回答同一个问题：这个结论是怎么得出来的（#178）。
  • 核心命题三：手机取证的现实限制必须先说清楚。 设备可能处于锁屏、加密、或关键日志已被滚动覆盖的状态；鉴定意见必须写明"在何种取证条件下得出"，而不是假装条件理想。
  • 核心命题四："未发现"是一种结论，而且是最常被误用的一种。 它只能说明"在该方法、该范围、该时点下没有观察到"，不能说明"不存在"（#181）。
  • 核心命题五：鉴定范围要在委托前写死。 事后扩大范围，意味着重新取证、重新计时、重新付费，而且新结论与旧结论的关系会变得难以解释。
  • 一句话结论：把鉴定当成"把已有事实变成可复核的陈述"，而不是"请专家替我下结论"；委托书写得越具体，报告越能用。

3. 三个角色，三种产出

角色资质基础能做什么不能做什么产出形式
司法鉴定机构司法行政机关登记在登记范围内出具鉴定意见超出登记范围的事项鉴定意见书
专家辅助人专业能力，经当事人聘请或法庭许可就专门性问题提出意见、质证代替鉴定机构出具鉴定意见专家意见、出庭说明
内部技术负责人对自有系统的了解陈述事实、说明处置过程以"专家"身份对第三方作结论情况说明、事实陈述

第一行与第三行之间最容易混淆。 内部团队写的情况说明，在证据体系里是"当事人陈述"性质，不是鉴定意见；把它当成鉴定意见使用，会在质证环节被直接击穿。

选择哪一种，取决于你要解决的问题：要认定"设备上有没有某类痕迹"，通常需要鉴定；要说明"我们做了什么处置"，内部陈述即可；要解释"这个痕迹意味着什么"，往往需要专家辅助人。

4. 委托前必须定的六件事

事项要写到什么程度不写清的后果
鉴定事项一句话一个命题，可判定真假报告答非所问
检材范围哪些设备、哪些数据、哪个时间窗事后发现漏项，需重新委托
方法允许或要求的方法类别方法争议导致结论被质疑
时限初稿、正式报告、可能的补充与监管或诉讼节点错位（#184）
报告形式是否需附原始数据、是否需出庭出庭时无准备
费用与变更何种情况算变更、如何计价中途加价或停工

第二行与第三行是专业机构最希望委托方写清、而委托方最常略过的两项。 写得越具体，机构越能在委托范围内给出确定结论；写得越模糊，报告就越倾向于写"无法判断"。

5. 检材的同一性与保管链

检材从离开设备到进入实验室，中间任何一次转手都可能成为质证点。保管链至少要记录七个要素：

  1. 谁提取（姓名、机构、角色）。
  2. 何时提取（UTC，注明原始时区）。
  3. 何地提取（设备位置、网络环境）。
  4. 如何提取（工具、版本、方式）。
  5. 提取到什么（镜像、备份、导出文件；哈希值）。
  6. 交给了谁（交接双方签字、时间）。
  7. 存放在哪（介质、编号、访问控制）。

第五项的哈希值是整条链的锚点。 没有哈希，就无法证明"实验室里分析的这份"与"当时提取的那份"是同一份。

一个常见的错误是：内部团队先"整理"了一遍数据，再交给鉴定机构。整理过程没有记录，就等于把保管链切断在起点。

6. iOS 设备取证的现实条件

鉴定的结论强度，很大程度上取决于取证时设备处于什么状态。委托时应当如实说明：

设备状态可取到的取不到的
未锁屏、已解锁文件系统、部分应用数据、系统日志已滚动的历史日志
锁屏但已配对备份、部分共享数据受保护的用户数据
关机或重启后未解锁极有限绝大部分用户数据（受加密保护）
已恢复出厂 / 已抹除通常无历史内容

表格第三行是最容易被误解的一行。 "关机保存"在很多人看来是保护证据，实际上可能让后续取证失去大部分可及数据。事件期的正确做法是先固定、再决定是否重启或抹除，而不是凭直觉操作（#188 云备份篇的"先固定、后解读"同样适用）。

以上都是取证条件的说明，不涉及任何绕过设备保护的方法。任何要求"绕过"的委托，都应当由法律顾问判断其合法性后再决定。

7. 结论的四种强度

强度表述适用条件
确定"可以认定……"有直接、可重复验证的证据
高度可能"高度可能……"多项独立证据指向一致，但缺直接证据
可能"不能排除……"存在证据，但存在合理解释
无法判断"依据现有检材无法判断"检材不足或方法不适用

第四行不是失败。 一份诚实写"无法判断"的报告，在质证时比一份勉强写"确定"的报告更有价值——后者只要被指出一处方法论缺陷，整份报告的可信度都会被拉低。

写报告的人要抵抗一种压力：委托方希望结论"有用"。但有用的结论是能被复核的结论，不是听起来确定的结论。

8. 报告里最常被挑战的五个点

  1. 方法有没有被验证过。 工具版本、参数、已知样本的测试结果。
  2. 结论与检材是否一一对应。 报告里的每个判断，能不能指回具体的文件或记录。
  3. 有没有考虑替代解释。 只列支持结论的证据，会被问"那另一种解释呢"（#178 的反面假设）。
  4. 时间戳是否统一。 不同来源的时间没有换算到同一口径，是常见硬伤（#192）。
  5. "未发现"的范围是否写明。 是"没找"还是"找了但没有"，差别巨大。

这五点的共同内核是：可复核性。 一份报告的每一句话，都应当能让另一个有资质的人按同样步骤走一遍。

9. 什么时候不需要鉴定

鉴定成本高、周期长，并非所有事件都需要。以下情况可以先不做：

  • 事实本身没有争议，争议在于处置是否及时（这是流程问题，不是技术问题）。
  • 结论只需要支撑内部决策，不涉及对外主张或法律程序。
  • 检材已经无法满足鉴定条件（设备已重置、日志已覆盖），此时鉴定的产出很可能是"无法判断"。

判断标准只有一条：这份鉴定意见将被谁、在什么场合、用来支持什么命题。 回答不了这三个问题，就先不委托。

一个折中做法是：先做一次范围明确的初步技术评估（由内部或受委托方完成），根据结果再决定是否需要正式鉴定。初步评估的产出是"是否需要鉴定"，不是"结论"。

10. 加固清单（八条）

  1. 先写命题：一句话一个可判定的问题。
  2. 固定检材：提取即哈希，转手即签字。
  3. 保留原始件：分析在副本上做，原件只存不动。
  4. 记录条件：设备状态、工具版本、时间口径，全部写入。
  5. 要求替代解释：每条结论都要有反面假设的讨论。
  6. 允许"无法判断"：不逼迫机构给确定结论。
  7. 事前约定出庭：报告可能被质证，提前安排。
  8. 报告与底稿分离：报告对外，底稿自留，两者不混。

11. 八条常见误解

  1. "机构越大结论越硬。" 可采性取决于方法与对应关系，不取决于机构规模。
  2. "报告越厚越有用。" 厚度不等于可复核性。
  3. "鉴定能证明是谁干的。" 技术鉴定通常只能证明"发生了什么"。
  4. "内部报告可以当鉴定用。" 性质不同，质证时会被区分。
  5. "设备关机保存最安全。" 可能让后续取证失去大部分可及数据。
  6. "先整理再送检更方便。" 无记录的整理会切断保管链。
  7. "未发现就是没有。" 只代表在该方法、范围、时点下没有观察到。
  8. "鉴定做完就结束了。" 报告还要面对复核、补充与出庭。

12. 与既有各篇的接口

  • 与 #177 衔接：受委托方接触检材的权限，由授权文件界定。
  • 与 #178 对接：报告属于"意见轨"，事实轨另建。
  • 与 #179 对接：向办案单位提交的材料分级，鉴定意见属 M1/M2 层级。
  • 与 #183 对接：追偿中的因果链，需要鉴定意见支撑"若无其过失"的论证。
  • 与 #188 对接：云备份作为检材时，其固定顺序与解读边界同源。
  • 与 #192 对接：运营商材料作为鉴定依据时，时间口径必须统一。
  • 与 #194 对接：联合材料进入鉴定，来源等级要可追溯。

13. 总结

司法鉴定与专家意见的价值，可以用一句话概括：它把"我知道"变成了"你可以自己验证"。

  1. 命题先于检材：先想清楚要证明什么。
  2. 方法先于结论：没有可复核的方法，结论无法使用。
  3. 诚实先于确定：写"无法判断"，比写错"确定"更有价值。

做到这三条，报告才可能在复核、质证与追偿的场合真正发挥作用。
