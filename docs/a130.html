iOS 显示与屏幕内容捕获的攻击面：屏幕上正在放的东西，是怎么在你没点"分享"的情况下离开的

1. 执行摘要

  • 这一族的名字应该叫"像素跟着合成器走，不跟着沙箱走"。前面十四根竖条里，被处理的对象依次是进来的字节（#118 文件格式、#122 卷结构、#123 线上报文）、进来的调用（#119 用户态接口、#127 第三方插槽）、进来的设备与信号（#121 有线配件、#125 定位与传感器、#129 号码与短信）、进来的操作请求（#126 辅助信息与外设触发），以及留下之后被合在一起的内容（#128 本地索引与聚合）。本篇处理第十五种，也是最后一类方向：内容被画到屏幕上之后。它的核心命题是：授权模型管的是"能不能采集"，显示层管的是"已经在屏幕上"，而显示层里没有权限模型，只有"这块内容能不能被合成出来"。 #66/#88 那套隐私面板口径在这一点上出现第三个系统性漏检（第一次是 #127 的槽位、第二次是 #128 的聚合）。
  • 三层切分：D1 渲染与合成层（App 画出图层 → 窗口服务器合成 → 帧进入显示与共享缓冲；这一层的安全表达方式是"内容自己声明这块要保护"）、D2 捕获与再导出层（系统截屏与录屏、会议与直播的屏幕共享、无线镜像与有线投屏、车机与外接显示、打印与导出、通知与锁屏的显示本身）、D3 归属与留存层（捕获出来的那一份落在谁的相册、谁的服务器、哪台并不属于你的设备上，谁能删、谁能看）。缺陷密度在 D2（通路多、粒度粗、授权一次覆盖全域），长期风险在 D3（副本不在你的设备上，因此你的撤销动作够不到它），D1 是这套体系唯一一处还能勉强表达意图的地方，而它的表达方式恰好是最弱的那一种。
  • 六个"显示即在场"的触发点 T1–T6。两个最反常识：T4 镜像即交接——画面一旦被投给接收端（会议服务器、电视、车机、协作软件的中继），约束它的是那台设备的策略，不是你这台的设置，你在 iOS 里做的所有显示相关开关在那一端一律失效；T5 指示器只说"有捕获"不说"谁在看、看到什么、去了哪"——录制与共享的可见提示是真实的，但它的语义是"某个捕获正在进行"，范围、内容与去向都不在它表达的范围里。把指示器读成"我被告知了全部"，是本族最常见的误判。
  • 与 #126 的关系必须写清楚，因为两者都涉及"别人看到了你的界面"：#126 读的是无障碍树——结构化的控件、标签与语义，代价是"能读也能操作"，入口是无障碍开关；本篇读的是像素——不需要任何 App 开启无障碍能力，也不需要被读取的那个 App 配合，入口是显示通路本身。两者共同点是都不提权、都不越狱、都在你自己的会话里发生，因此记录与本人操作不可区分（#126、#127、#129 之后，这是第四种不提权的伤害形状：被读的不是数据，是画面）。
  • 与 #128 的关系是同一条律的两次成立：M3 沙箱不外推。#128 说某 App 的数据受该 App 的口径约束，不因它被系统索引而转移；本篇说某 App 的内容受该 App 的容器约束，不因它被渲染到屏幕上而自动多出一层保护——画出来之后，它进入了合成缓冲，从这一刻起它属于"屏幕上正在发生的事"，而不属于任何容器。
  • 后果落 #91 的 C1 机密性读取（画面被读到，且读到的是已经被解读过的内容：验证码、对话、病历、证件、代码、余额）、C7 追踪与元数据可见（在场者与接收端不需要看懂内容也能画出画像：谁在用哪个 App、什么时候、多久）、C6 安全控制旁路（DRM 黑屏、录屏审计、会议水印这类显示侧控制被绕过或假装在）。可逆性上是本系列最坏的一档之一：像素一旦被读到就不可回收，副本落在别人的设备上就归别人管（接 #92 的"不可逆子集活在账户与政策层"，但这一格的不可逆发生在物理在场这个最古老的层面）。它还给后果表添一格新东西：读者在设备之外——这一族的读者可以是一 room 之隔的人、也可以是另一台机器上的一段录制，两者都不在你的设备上产生任何事件；#125 首创的判定污染在这里第二次成立：会议录制与投屏画面会作为"当时确实这样显示过"的证据写进第三方记录。
  • 端侧可观测性处在中间偏弱：比 #129 强（那边连"号码被转移"都没有本地事件，这边至少有录制指示与镜像目的地），与 #126 同档（开关与会话状态可见，行为与范围不可见）。能当场核对的：谁正在被允许捕获、当前是否存在共享会话、画面被投到了哪台设备、截屏产生的文件落在哪。永远核对不到的：被捕获的画面包含哪些图层、会议服务器留了多久、谁在什么时候截了你发的内容、接收端那台设备有没有再投一次。因此本篇不提供"如何发现自己被捕获"的判定式，只提供列通路 + 收范围 + 外部核对三件事。
  • 个人杠杆的形状介于 #127 与 #128 之间：通路是你自己启动的，能关的确实是这些通路（共享、镜像、锁屏显示、通知内容显示、被投画面里的应用范围），但D3 那一份副本关不掉——它已经不在你的设备上。正向结论也要写下来：iOS 上任何第三方捕获都必须有一次用户可见、可撤销的启动，并有系统级指示；这是它与 Android 屏幕捕获生态的结构性差异（接 #112），也因此本族的伤害形状偏向"一次显示即一次披露"，而不是"长期被录"。
  • 一条方法论结论：只用 #66/#88 的授权面板、#127 的槽位清单、#128 的来源清单做审计，都会漏掉这一族，因为没有任何一项授权对应"内容正在被显示"这件事——显示不是一个需要申请的能力，它是设备被造出来的目的。本篇因此需要的是一张通路清单（这条内容会以哪几种方式离开屏幕）加一张在场者清单（此刻谁能看到这块屏），而不是又一个开关清单。

2. 这根竖条补的是哪一块

系列里已有若干篇擦到过屏幕、录制与指示器，但没有一根从"内容被渲染成像素之后，它会以哪些方式离开这台设备"出发把通路测绘成表。这是第十五根竖条，攻击面子族的第十二个成员（#118 文件与媒体解析器、#119 用户态系统服务、#121 配件与有线连接、#122 文件系统与磁盘结构、#123 网络协议栈、#124 密码学与密钥生命周期、#125 定位与传感器、#126 辅助功能与外设控制、#127 第三方扩展插槽、#128 本地索引与跨 App 聚合、#129 蜂窝订阅与号码身份，以及本篇）。

已有它回答的问题本篇不重复的部分
#88 权限模型与隐私指示器对抗分析授权口径：谁能采集、TCC 与 Entitlement 怎么发、指示器怎么被对抗该篇管的是"有没有权限采集麦克风/摄像头/位置"这一侧。本篇的对象是已经在屏幕上显示的内容，它不需要任何一项采集权限；显示本身不是一个被授权的能力，所以隐私面板里没有对应条目。交界：授权与指示器的语义归 #88，像素的再导出与归属归本篇

一句话定位：其他各篇问"这段字节/这次调用/这份内容会不会被错处理"，本篇问"这块画面现在正被谁看到，以及它会不会被看到它的人再交出去一次"。

3. 三层测绘：D1 渲染与合成 / D2 捕获与再导出 / D3 归属与留存

  ┌─ D1 渲染与合成层 ─────────────────────────────────────────────┐
  │ App 画出图层 → 窗口服务器合成 → 帧进入显示与共享缓冲            │
  │ 安全表达：这个图层要保护（密码输入、受保护内容黑屏）、这块区域   │
  │ 不给别人、这个内容不进录屏                                      │
  │  粒度：整窗 / 整层        强制方式：内容自己声明      可核验性：几乎无
  └───────────────────────────┬───────────────────────────────────┘
                              │ 合成即"一份可读的当前画面"
  ┌─ D2 捕获与再导出层 ────────▼──────────────────────────────────┐
  │ 系统截屏与录屏 · 会议/直播的屏幕共享 · 无线镜像与有线投屏 ·      │
  │ 车机与外接显示 · 打印与导出为 PDF · 通知与锁屏与前台建议的显示   │
  │  谁决定：一次用户启动 + 通路本身的范围规则（全屏 / 单窗 / 单应用）│
  │  粒度：会话级（授权覆盖整个屏幕，不覆盖"那一个窗口"）             │
  └───────────────────────────┬──────────────────────────────────┘
                              │ 交出即再归属
  ┌─ D3 归属与留存层 ──────────▼──────────────────────────────────┐
  │ 落在：别人的相册 / 会议平台的录制与转写 / 中继服务器缓存 /       │
  │ 接收端设备（电视、车机、投影、对端手机）/ 企业审计留存           │
  │  谁能删：持有那一份的人        你的撤销动作能到达吗：**不能**      │
  └──────────────────────────────────────────────────────────────┘
  • D1 的结构性事实：机密性是内容自己请求的，不是系统强制的。 这一层能表达的意图只有"这个图层要保护"，而它的粒度是整个窗口/图层，不是内容。于是一屏上的保护与不保护是拼在一起的：被保护的从来不是"这条信息"，而是"这一块画层"。密码输入框与验证码弹窗之所以命运不同，不是因为系统判断了敏感度，而是因为各自的实现请求了不同的画层属性。#123 的"判定项里没有你说的粒度"在这里换了对象：判定项里没有"这段内容敏感"这个粒度。
  • D2 的结构性事实：授权的单位是会话，范围的单位是屏幕。 用户点下"开始共享"的那一次确认覆盖的是整个屏幕的这段时间，而不是"这一个窗口"或"这一类内容"。这就是为什么"我只共享那个窗口"仍然会漏——因为通知、键盘候选、来屏弹窗、后台任务的界面变化都发生在同一块屏上，而它们由别的进程画（接 #128：合成后的画面跨沙箱可见）。这一段和 #126 的"一次授予、全域生效"是同一条律的第三次成立。
  • D3 是本族长期风险所在，也是本篇唯一没有任何设备侧杠杆的一层。 副本一旦交出，它归那份副本的持有者管：能不能删、看多久、给谁看，取决于会议平台、接收端设备和对方的习惯，不取决于你的设置。#107 的"撤销不对称"在这里走到极端：你连那份副本的存放位置都无法列举（#129 至少还能向服务商核对，这里连"哪一份"都不知道）。
  • 三层的"谁能修"再次不对等：D1 的画层属性与降级策略由 Apple 决定，D2 的粒度（能不能只共享一个窗口、镜像能不能限制内容类型）一部分由 iOS 决定、一部分由会议与协作软件决定，D3 完全由接收方与平台的数据留存政策决定。所以本篇的"谁必须改"一列里，外于 Apple 的条目接近一半（与 #129 同一形状），个人杠杆集中在 D2 的收范围与 D3 的事前约定（不投敏感内容，而不是投了之后再要求删）。
  • 跨层的第一条律：显示不是能力，是目的。 整个设备的设计目标是把内容画出来，因此这一族不会像 #127 的插槽或 #119 的接口那样有一个"关掉它"的对象。这也是本篇的处置逻辑必须是收窄内容进入屏幕的方式与在场条件，而不是"关闭显示"。

4. 六个"显示即在场"的触发点

编号触发点系统在你没确认之前做了什么关闭难度
T1渲染即复制：内容被画成帧并合成帧进入共享的显示缓冲，"正在显示的"与"可以被读到的"从此是同一份数据；画层属性只覆盖声明了它的那一块关不掉（关掉显示就等于关掉设备）
T2一次启动即会话级授权：用户开始录屏或共享授权覆盖这段时间的整块屏幕，而不是被选中的那个窗口；期间所有进程画出的内容都在范围内可关（不启动就没有），但范围不可细到内容
T3选一个窗口仍是全屏可见：单窗共享/单应用共享来屏通知、键盘候选、系统弹窗、权限询问由别的进程画在同一块屏上；它们是否进入画面由通路的范围规则决定，不取决于你的选择部分可关（可在进入前打开专注模式/静音并关闭内容显示）
T4镜像即交接：画面被投给接收端设备或平台从这一刻起，约束画面的是那一端的策略（录制、留存、再转发、谁能观看），你这台的显示相关设置在它身上没有作用可关（不投即可），但投出之后收不回
T5指示器只说"有捕获"：录制/共享状态被显示系统如实告诉你"有捕获正在进行"，但它不表达范围、图层构成、目的地与留存期；读它的人常常把它读成"我知道全部了"不是缺陷：指示器是真实防线，误读才是问题（接 #125 的"指示器即完整可见"）
T6显示即前置披露：锁屏、通知预览、前台建议内容在进入设备之前先被画到屏上；读者是同处一室的人，不是攻击者；解锁保护数据访问，不保证屏幕可见性（#126 那条锁屏结论在显示层的等价物，#128 T4 的推广）可关（关闭锁屏内容显示、通知分组与预览、建议显示）
  • T4 与 T5 是给读者的两个认知冲击：T4 说明这一族的"外发"不需要任何网络出口配置——画面本身就是载荷；T5 说明这一族唯一真实的可见性信号，其语义被大多数人读得比它实际表达的更宽。
  • 与 #129 的 T3"重新签发不需要旧凭证在场"对照：那边是关系可以在你没有察觉时被变更，这边是画面可以在你没有参与时被复制。两者共同点：动作的完成不需要攻破设备，甚至不需要设备被触碰。
  • 与 #126 的 T1/T2 对照：那边入口是一组看起来无害的无障碍开关与音频/摄像头触发；本篇入口是"你正在看屏幕"这件事本身，因此本篇的触发不需要任何一次授予——除了 D2 里那些需要用户启动的通路。

5. 通路族 × 缺陷倾向 × 谁能修 × 个人能关吗

  • 主导缺陷类别是逻辑与授权缺陷、信息暴露、归属混淆三格；内存破坏一格在这里基本不出现（图形栈与驱动的缺陷归图形栈篇/#82/#118，本篇不重复统计）。
  • 一个诚实的观察：这张表里"个人能关吗"最强的一排是通知与锁屏显示（改一次配置，效果当场可见），最弱的一排是在场者观看与 D3 归属——前者要靠行为与场合，后者根本不在设备上。这和 #129 的"S1/S2 关不掉、S3 可逐项替换"是同一种非对称，但方向不同：#129 的杠杆在替换依赖，本篇的杠杆在决定什么内容值得进入屏幕。

6. 七个反复出现的契约违背

  • M1 机密由内容自声明：能不能被读到，取决于画它的那一段代码有没有请求保护属性，而不是系统或用户判断过它敏感。保护的是画层，不是信息——所以同一句话在两个不同 App 里命运完全不同。
  • M2 沙箱不外推：某 App 的内容受该 App 的容器与授权约束，这一条不因它被渲染到屏幕上而转移，也不因它被合成而多出一层保护。#128 M3 的显示层版本；也是本篇与 #88 的分界所在（#88 管授权口径，本条讲的是授权之外的东西）。
  • M3 指示器不等于范围：可见提示表达的命题是"有捕获在进行"，不包含"包含哪些图层、投给了谁、留多久"。把指示器读成完整告知，是把一个二元信号当成一份清单。
  • M4 一次启动即全域覆盖：授权的粒度是会话，范围的粒度是屏。与 #126"一次授予、全域生效"、#127"一个开关即全量输入可见"同族，第三次成立。
  • M5 接收端不继承策略：镜像/共享之后，管着那份画面的是那一端的留存与访问规则。你的每一次撤销（关闭投屏）只切断此后的流，不回溯已经到达的那一份。
  • M6 副本无归属：截屏与录制产生的文件不属于你的设备的所有权范围，它属于持有它的那台设备/平台。你的删除、抹机与"最近删除"都不覆盖它——这是 #122 与 #128 的"删除了就没了"反驳在本族的第三次出现，且这一份连列举都做不到。
  • M7 关闭只对未来生效：#107 的撤销不对称第四次成立（#123 N6、#125 M7 与本篇同一律）；这里多一层：已经显示过的那一段，无法从任何记录里撤回，因为它没有记录。
  • 这七条里有四条（M1、M3、M5、M6）不是软件缺陷，是表达方式与物理现实的默认设定，所以 #79 的硬化曲线与 #114 的修复形态在这里只能作用于 D2 的粒度，对 D1 的语义与 D3 的归属几乎无从下手：没有一行代码可以改的东西比 #129 更多。

7. 后果形状与可逆性（对齐 #91）

  • C1 机密性读取（本族主导）：被读到的是已经被解读过的内容——不是数据库字段，而是"你此刻正在看的那一条"：验证码、对话、证件、病历、余额、代码、审批界面。它的特殊之处在于不需要任何权限、也不需要攻破任何一段代码；#90 的起始位置表里，这一族的最低门槛是 P4 物理在场，而最高档 P2/P3 的远程接收端（会议录制、对端设备）同样成立。
  • C7 追踪与元数据可见：不需要看懂画面也能画像——哪个 App 在用、用了多久、什么时候切走（接 #95 的聚合追踪；#128 的合成推断在这里同样成立：连续几帧就能推出关系与日程）。
  • C6 安全控制旁路：DRM 黑屏、会议水印、录屏审计这类显示侧控制是内容方与组织侧的防线，它们被绕过的后果不由你承担，但你会误以为"被保护的都保护了"（M1 的另一面）。
  • C2 完整性篡改（轻度但真实）：投屏与共享画面是可以被替换/伪造的显示通路；观众看到"确实这样显示过"，而源端并没有。判定污染在 #125 之后第二次成立：伪造的界面进入会议录制与投屏画面后，会作为第三方的记录长期存在，而那里的损失不由设备厂商赔。
  • 新增后果格：读者在设备之外。#126/#127/#129 各自说明过"设备侧没有工件"，本篇把这一格写死：这一族的读者可以完全不与你的设备发生任何关系——一个坐在你旁边的人、一台已经收到画面的电视。它意味着任何"检查设备就能排除"的判断在本族都不成立。
  • 可逆性：通路可当场切断（关投屏、停共享、关内容显示），内容不可回收。所以处置顺序仍是 #116/#129 的原则——先做不需要判断的动作（先收 T6 与 T4：把不需要显示的内容关掉、把不需要的投出停掉），再谈事后核对；而不是先追查"谁看到过"——那一问在本族大多没有答案。

8. 五步审计法：列通路，不是列开关

  1. 列通路：把所有"能让屏幕内容离开这块屏"的方式列出来——截屏、录屏、会议共享、直播、无线镜像、有线投屏、车机、外接显示、打印与导出、长截屏与滚动截屏、锁屏与通知预览。判定式一句话："这次显示会结束在这台设备里吗？" 不会 → 归本族；会 → 归 #88/#126。
  2. 列在场者与接收端：这张表是本族的"关系清单"（#129 §8）与"槽位清单"（#127）的等价物——此刻谁能看到这块屏（同处一室的人、共享会议的对端、投到的那台设备）；每一项写出"它留存吗、留存归谁"。结构可枚举，留存不可核验。
  3. 当场降级（按可见伤害排序）：先收 T6（锁屏与通知内容预览、前台建议——成本最低、收益最直接，效果当场可见）；再断 T4（不投、不共享敏感内容；必要时只投一个应用且提前压制来屏内容）；最后处理 D3（事前约定：会议录制、水印与留存的口径要在投之前问，不是投之后要求删）。
  4. 外部核对：向会议/协作平台核对录制的留存与访问清单（这是本族唯一能拿到"那一份在哪儿"的渠道）；向接收端核对（电视/车机是否保留最近画面、平台是否自动重连）。设备侧没有这类记录。
  5. 验证与留档：改完之后做一次真实回归——锁屏看一眼有没有内容、发一条通知看预览、投一次屏确认画面构成；把通路表与在场者表存成一页带时间戳的基线（接 #104 的季度巡检表；本族属于只能部分端侧验证那一行）。

能自己判定的三件事：当前有没有共享/录制会话（能看到）、画面被投到了哪台设备（能看到）、锁屏与通知显示什么内容（能看到并改）。

永远无法在设备侧判定的三件事：被捕获的那一份里包含了哪些图层、会议平台留了多久并给谁看过、谁在你发出去的内容上按了截屏。

9. 加固清单

个人七项

  1. 关闭锁屏与通知中心的内容预览（含横幅显示），把"显示即前置披露"这一格直接收掉——本族个人杠杆最高、效果最可验证的一项。
  2. 投屏/共享前打开专注模式并关闭来屏通知；不要把验证码、审批、证件、病历、财务页面放进任何会被共享的画面；需要展示时用只投单个应用并接受它的范围限制。
  3. 会议前后各做一次画面构成自检：桌面上有没有别的窗口、浏览器标签、通知中心；共享期间不用通用剪贴板传敏感串（接 #110 的跨设备边界）。
  4. 不用第三方"防截屏/截屏提醒"类说法做决策依据：iOS 上没有可依赖的截屏通知。任何声称能查到"谁截了你的内容"的工具都不成立（§10）。
  5. 打印、导出 PDF、长截屏之后，把它当成已经离开的副本对待：能删的删、能撤回的撤回（撤回通常不可用），并把"这份内容值得被复制出去吗"作为导出前的默认问题（M6）。
  6. 高敏感场合使用物理口径：角度、时长、是否解锁状态显示、屏幕朝下；这是本族唯一不依赖任何厂商修改的杠杆（在场者那一行）。
  7. 半年一次"外部核对"：向常用会议/协作平台核对录制与转写的留存与访问范围，把结论并入 #104 的季度巡检表（本族属于只能部分端侧验证、其余靠外部核对那一行）。

组织五项

  1. 把共享与录制纪律写进制度而非工具：默认不投含个人数据/客户数据/凭证的界面；演示材料一律使用专用测试数据，而不是"把生产界面遮住一半"。
  2. 会议平台侧明确三件事并公示：录制是否默认开启、留存多久、谁能访问；把这三项写进对外交付与合规口径（D3 只能事前约定，不能事后撤销）。
  3. 录屏审计与远程支持工具要按新增攻击面登记，而不是按控制项验收：它合法、有用，同时把"所有人画面长期可回看"变成一份可被滥用或外泄的数据集（接 #118/#123 的"替你解析 = 新建一个靶子"，这里是"替你录制"）。
  4. BYOD 与外包场景写清一条边界：员工个人设备上的显示内容，组织有没有权录制与回看；这一条不在 MDM 能力清单里，需要单独同意（与 #120 的关系型授权同源，#128 的组织口径相邻）。
  5. 事件响应剧本加一格：画面被误投/误共享后的处置（立刻停止通路 → 向平台索取录制清单与删除路径 → 评估判定污染范围（录制里的错误内容会不会写进别人的记录）→ 不要试图通过设备侧取证还原"谁看过"，那条路不存在）。

10. 可观测性：中间偏弱，且只在会话维度

想核对的事设备侧能否查说明
此刻是否有录屏/共享会话能状态与时钟区的指示是真实信号
画面投到了哪台设备能（部分）会话期间可见；断开后不留目的地清单
锁屏/通知会显示什么内容能，并可当场改本族唯一"改了就能看见效果"的一格
截屏产生的文件能在照片/文件里可见；但这只是你这台设备的那一份
被捕获的画面里包含哪些图层不能合成在系统内进行，不提供逐图层清单
会议平台留了多久、谁看过录制不能需要向平台核对，属外部渠道（接 #129 同构）
接收端有没有把画面再投/再录一次不能那一端的事件不进你这台设备
谁在你收到的内容上按了截屏不能iOS 不提供跨 App 的截屏通知；任何声称可查的说法都不成立
历史投屏/共享的发生时间清单不能会话结束基本没有可审计工件（同 #126 那条限制）
  • 结论：本族会话状态可见、内容与留存不可见。因此本篇提供通路清点 + 收范围 + 外部核对三件事，不提供"如何发现自己被捕获"的判定式——指示器覆盖不到的通路，判定式就覆盖不到；这一点与 #125/#126/#127/#129 同一档诚实度，比 #128 更弱（那边来源清单可完整枚举，这边的接收端清单只能当场看）。
  • 任何声称能在设备上查到"截屏流水/被录制历史/投屏目的地清单"的说法都不成立；任何把"设备上没找到可疑 App"当作排除依据的判断在本族也无效——这一族的读者可以是一个坐在你对面的人，或一台电视。

11. 十条常见误解

  1. "有录制圆点就说明没人偷偷录。" 圆点如实说明"有捕获在进行"，不说明范围、图层构成、目的地与留存期（M3/T5）。
  2. "我只共享那个窗口，别人就只能看到那个窗口。" 来屏通知、系统弹窗与键盘候选由别的进程画在同一块屏上，是否进入画面取决于通路的范围规则（T3）。
  3. "屏幕上那点东西，别人拿到也没用。" 被读到的是已经解读过的内容：验证码、审批界面、证件、病历；画面本身就是载荷（C1）。
  4. "受保护内容会黑屏，所以系统会保护所有内容。" 保护的范围是内容方标记的那一块画层，不是"敏感"这个判断（M1）；那条黑屏保护的是内容方的利益。
  5. "截屏会有通知，所以我知道谁截了。" 通知（若有）说明你自己截了屏，不是别人截了你看到的东西；iOS 不提供跨 App/跨设备截屏审计（§10）。
  6. "投屏走的是内网，安全。" 画面到达接收端之后受那一端策略管辖，内网不改变归属（M5/T4）。
  7. "装了 MDM 就管到显示层。" MDM 管得到配置与限制，管不到"谁在这块屏前坐着"和"会议平台留多久"（与 #128 那条"装了 MDM 就覆盖了"同一形状）。
  8. "会议录制是公司的行为，与我无关。" 录制里包含你的画面与发言，成为第三方记录的一部分；它是 C6 判定污染的第二现场（那里赔钱的不是设备厂商）。
  9. "锁屏显示无所谓，别人又打不开。" 解锁保护数据访问，不保证屏幕可见性（T6/#126 那条锁屏结论的显示层等价物）。
  10. "只有要上镜的人才需要担心。" 默认显示预览、默认投屏可用、默认会议自动录制都是默认配置，不是风险人群的选择；#90 的位置表里，这一族的最低门槛只需要一次同处一室。

12. 总结

本篇把十五根竖条里最后一类方向——内容被画出来之后——测绘成表：D1 渲染与合成（机密由内容自声明，粒度是画层而不是信息）、D2 捕获与再导出（授权以会话为单位、范围以整屏为单位，缺陷密度在此）、D3 归属与留存（副本不在你设备上，因此撤销够不到它，长期风险在此）。它的三个不可回避的结论是：这一族的入口不是能力授予而是显示本身，所以没有任何一个开关叫"关掉显示"；这一族的读者可以完全不接触你的设备，所以全系列其余各篇的工件式自检在这里部分失效；以及这一族的处置重心是决定什么内容值得进入屏幕，以及进入屏幕时谁在场——把"会被复制出去"当成显示之前的默认假设，而不是之后的补救。也正因如此，它和 #126、#128 一起构成本系列的"可见性三篇"：#126 问谁能读你的界面并替你按下，#128 问谁能把你留下的内容合在一起看到，本篇问此刻这块屏正被谁看到。
