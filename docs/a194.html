Coruna 与 DarkSword 场景下多家受害者的联合处置：共享指标最容易，共享结论最难

1. 执行摘要

  • 定向投放很少只打一家。当第二家、第三家发现同一类痕迹时，联合处置几乎是必然选择——但联合处置的收益与风险，不在同一个层级上。
  • 核心命题一：共享技术指标最快，也最容易出错。 一个未经核实的域名或哈希扩散到十家，会同时产生十份误报，并让真正的痕迹淹没在噪声里（#161）。
  • 核心命题二：共享结论最慢，也最危险。 结论一旦离开原始上下文，就会被当成"共同认定"；而每家的数据范围与置信度并不相同（#178）。
  • 核心命题三：联合的正确产物不是一份联合声明，而是一份共同事实底稿。 各家在同一张事实表上补充自己的行，结论各自得出，对外口径按职责分别表述。
  • 核心命题四：共享有边界，边界不由热情决定。 个人信息、合同保密、监管调查中的材料、以及竞争敏感信息，四类内容各有各的限制（#184）。
  • 核心命题五：协调结构必须只有一个中枢。 两个协调方等于没有协调方；轮值可以，并行不行。
  • 一句话结论：先共享"我观察到了什么、用什么方法、置信度多少"，再谈"所以我们认为"；顺序反了，联合就会变成共同犯错。

#174 解决"多起案件能不能比"，本篇解决"多家组织愿不愿意、能不能、以什么形式共享"。前者是方法问题，后者是信任与边界问题。

同时本篇与 #177（外部服务商的委托与授权边界）互补：#177 讲一家委托外部的边界，本篇讲多家之间横向共享的边界。

3. 联合的三个真实收益与三个真实成本

先算账，再决定要不要联合。

收益说明
扩大样本单家看到的是一段痕迹，多家拼起来才看得出模式
对上游形成压力供应商更愿意回应"多个客户同时报告"的问题（#180）
分摊成本鉴定、监测、对外沟通的部分工作可以共用（#195）
成本说明
口径污染一家的错误指标被多家引用，纠正成本成倍增加
信息外溢共享材料在多方之间流转，控制力随节点数下降
协调开销会议、对齐、审批，占用的正是处置最紧张的人力

结论不是"不要联合"，而是"先确定共享层级，再建立协调结构"。 没有这两样，联合的收益会被成本吃掉。

4. 共享的四个层级

按"信息密度"从高到低，风险也从高到低：

层级内容共享建议主要风险
L1 原始载体镜像、日志原始文件、设备备份原则上不横向共享，只由受委托方在授权范围内处理（#177）不可控扩散，且可能含他人个人信息
L2 技术指标域名、IP 段、文件哈希、行为特征谨慎共享，标注置信度与观察时间假阳性扩散、指标过期
L3 事实纪要时间、对象、观察、方法、置信度推荐共享，这是联合的主产物需去标识化，避免夹带判断
L4 判断与归因"是谁做的""动机是什么"最后共享，且必须署名到组织容易被转述为"共同认定"

L3 是分水岭。 大多数联合处置失败，是因为要么停在 L2（只换指标，拼不出模式），要么直接跳到 L4（各家还没对齐事实就开始下结论）。

L2 与 L3 之间有一个容易被忽略的纪律：指标必须带"观察窗口"与"判定方法"。没有这两项，一条指标在别人那里就是一条无法验证的传闻。

5. 共同事实底稿的六个字段

一份能被多家同时使用的底稿，每一行至少包含：

字段填写要求
时间UTC，注明原始时区；区分"发生时间"与"发现时间"
对象设备、账号、应用、网络位置；去标识化后仍可对照
观察只写看到的，不写推断的
方法怎么看到的：日志、流量、用户报告、外部通报
置信度确定 / 高度可能 / 可能 / 无法判断（#178 要求"无法判断"必须是一个合法取值）
来源等级自家观察 / 同行共享 / 供应商通报 / 公开信息

第六个字段是多边协作的关键。 同一行事实，来源等级不同，对外可引用程度就不同；不标注，就会被默认当成"已证实"。

底稿的维护规则只有两条：谁补充谁署名，谁修改谁留痕。 不允许匿名编辑，也不允许覆盖式修改。

6. 协调结构的四种形态

形态适用规模优点缺点
单一协调方2–5 家决策快协调方负担重，且需被信任
轮值协调5–15 家分担负担交接期容易断档
行业信息共享组织15 家以上有既有流程与保密框架流程慢，颗粒度粗
受委托第三方任意专业、可隔离成本高，且需明确授权（#177）

无论哪种形态，有三条纪律是不变的：

  1. 只有一个中枢。 对外口径、材料分发、会议节奏，都由中枢统一。
  2. 频道与议题分离。 技术细节走技术频道，对外表述走协调频道，避免"技术讨论被直接引用"。
  3. 会议纪要当天发。 隔夜的纪要靠回忆补，是口径分歧的起点。

7. 共享的五条边界

边界具体限制处理方式
个人信息受害者名单、员工信息、客户数据去标识化；名单不横向共享（#179）
合同保密供应商协议中的保密条款共享前确认条款是否允许
监管调查调查中的材料可能受限由法律顾问判断可共享范围（#169）
竞争敏感业务数据、客户结构、定价与安全事实分开，不进同一份材料
对外口径未经确认的结论只共享事实，结论各自表述

第三行最容易出事：监管调查期间的材料，往往并不是"不能给别人看"，而是"给谁看需要先问过"。这个判断不应由技术团队单独做出。

8. 指标共享的误伤机制

一条指标从 A 家传到 J 家，会经历四次变形：

原始观察 → A 家归纳 → 群组转发 → B 家二次归纳 → 公开引用

每一次变形都可能丢掉三样东西：观察窗口、判定方法、置信度。丢到最后，一条"某域名在 10 月出现过"会变成"某域名是本次攻击的基础设施"。

三个对策：

  1. 附原始观察摘要。 每个指标后面跟一句"在哪台设备、什么时间、以什么方式看到"。
  2. 设定有效期。 指标有寿命，过期指标要显式标记（#161）。
  3. 允许撤回。 发出方发现指标有误，必须能在同一频道发出撤回通知，并说明影响范围。

9. 联合对外表述的三种规模

规模适用场景形式
联合技术通报事实已对齐，需要提醒同行一份事实为主的通报，署名到组织
各自声明 + 相互引用对外口径需分别控制各家声明事实一致，详略不同（#181）
单一主体代表法律或监管要求统一口径由被授权方代表，其余各方书面确认

"联合声明"不是默认选项。 它意味着多家共同为一个判断背书，而在定向投放里，各家的数据范围几乎不可能完全相同。多数情况下，第二种规模已经足够。

10. 加固清单（八条）

  1. 先定层级：L1 到 L4，先说清楚这次共享到哪一层。
  2. 建事实底稿：六字段，谁补充谁署名。
  3. 指标带窗口：观察时间、方法、置信度，缺一不可。
  4. 单一中枢：对外口径与材料分发统一。
  5. 频道分离：技术讨论与对外表述分开。
  6. 纪要当天发：不留隔夜补记。
  7. 共享前过边界清单：五条边界逐条确认。
  8. 保留撤回权：指标有误能撤回，底稿有误能更正。

11. 八条常见误解

  1. "共享越多越有帮助。" 超出边界的共享，会制造新的风险。
  2. "指标共享就是协作。" 指标只是最低层级，拼不出模式。
  3. "大家都同意就是事实。" 共识不等于证据。
  4. "联合声明更有分量。" 也更难撤回。
  5. "匿名共享更安全。" 匿名让责任与来源都无法追溯，反而降低可用性。
  6. "小圈子共享不会外溢。" 节点越多，外溢概率越高。
  7. "会议纪要可以后补。" 后补的纪要会被时间戳暴露（#181）。
  8. "出了事再建群。" 协调结构应当事前存在。

12. 与既有各篇的接口

  • 与 #157 衔接：名单与目标分层，属于各家的内部信息，不进入共享。
  • 与 #161 对接：指标的观察窗口与有效期，在本篇是共享的前提。
  • 与 #174 对照：跨案对比的方法，是联合分析的技术基础。
  • 与 #177 衔接：受委托第三方的授权范围，决定它能否接触 L1。
  • 与 #178 对接：底稿的六字段，与记录分层的要求同源。
  • 与 #184 对接：多法域下的共享限制，由法律顾问判断。
  • 与 #195 对接：联合材料进入鉴定时，来源等级必须可追溯。

13. 总结

多家联合处置，真正的难点不在"愿不愿意共享"，而在"共享什么、共享到哪、由谁代表"：

  1. 共享事实，不共享判断。
  2. 共享带方法，不带结论。
  3. 共享有中枢，没有并行。

做到这三条，联合才可能既扩大视野，又不制造新的错误。
