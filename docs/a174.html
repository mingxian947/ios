Coruna 与 DarkSword 场景下的跨案对比方法与统计口径：什么可比、什么不可比、以及"同源"到底要证明几层

1. 执行摘要

  • 本族讨论里出现频率最高的一句话是"这和之前那起是同一个团伙"。这句话一旦被写进报告、董事会材料或对外声明，就会变成一串后续判断的前提：预算按它分配（#171）、名单按它排序（#157）、防御按它加固（#160）。而它很少被拆开检验——因为它听起来像是一个事实，实际上至少是三层独立的判断。本篇处理的就是把这句判断拆成可以分别验证的部分，以及由多起案例汇总出结论时避免统计失真的方法。
  • 核心命题一："同源"不是一个是/否问题，而是三层问题：事件关联、工具链同源、行为体归属。 三层的证据门槛依次上升，而报告里最常发生的错误是用第一层的证据支持第三层的结论（"两个域名解析到同一个 IP"→"同一个组织所为"）。
  • 核心命题二：可比的不是"事件"，是"事件里可测量的量"。 两起事件可以在目标类型上相似而在技术上毫无关系，也可以技术上高度重合而受害者完全不同。跨案比较必须先声明比较的是哪一个量，否则所有结论都建立在"看起来像"上。
  • 核心命题三：公开案例库不是事件总体的样本。 进入案例库的门槛是"被发现、被披露、被记录"——这三道门槛各自筛掉一批，且筛选与后果相关（越严重越可能被披露，越成功越不可能被发现）。因此"在我们统计的 N 起案例中，有 M 起…"这句话，N 是分子，不是分母。
  • 核心命题四：统计口径的四个陷阱——分母缺失、幸存者偏差、归因漂移、时间窗口——每一个都足以让一份看起来很严谨的统计得出相反结论。它们无法被"更努力地收集数据"消除，只能被写在结论旁边。
  • 核心命题五：案例库的价值不在于"归因"，而在于"预测下一次的形态"。 即使永远无法确定是谁，工具链与投递形态的演化仍然可以被统计：哪一类入口在增多、哪一种绕过在失效、哪一段时间窗口在收窄。这些结论不需要归因就能指导防御，而它们恰恰是最少被整理的部分。
  • 一句正向结论：把每一句"和之前那起一样"改写成一个可回答的问题：哪一层一样、依据是什么、如果不是同源这个结论还成立吗。

2. 这一篇补哪一格

#78 处理的是行为体归因方法论：如何从技术痕迹、基础设施、行动模式推定"是谁"。那一篇的问句是"是谁"。

本篇处理的是案例之间的可比性与汇总口径：问句是"这两起能不能放在一起比、放在一起之后能得出什么"。归因只是其中一层证据，而多数跨案统计在归因之前就已经错了。

#90 处理攻击者起始位置 P0–P5，#94 处理暴露画像——两者提供了"挂到每个案例上的坐标"。本篇提供的是坐标系的用法：同一坐标上的两个点是否可比、坐标缺失时如何标注。

#161 处理检测指标的生命周期，#174 与它的关系是：指标是案例库最重要的一列，但不是唯一一列；只看指标会导致把"共享同一批域名"误读为"同一批人"。

#169 处理共享的去标识化——共享的是指标与形态，本篇则是"拿到别人的案例之后如何入库与比较"的方法；二者共同构成案例库的输入侧。

3. "看起来一样"的四种相似度

同样是"像"，背后可以是四种完全不同的关系。

相似度含义典型证据它能支持什么它不能支持什么
表象相似受害者类型、行业、时间接近公开报道中的描述提示"可能存在同一波行动"任何技术与归因结论
战术相似使用同类手法（如定向投递 + 0-click）TTP 级描述（#169 的共享层）说明"同一类能力在流通"说明是同一批人
工具链同源载荷、加载器、基础设施存在可关联的痕迹代码复用、域名/证书模式、编译特征说明"同一条供应链"说明是同一个操作方
行为体归属指向具体的组织或国家背景多源独立证据 + 情报交叉政策与法律层面的判断直接的技术处置

四层不是四个等级，而是四个不同的对象。 常见错误有三：

  1. 跨层跳跃。 用工具链证据支持行为体结论，中间那一层（谁买了这条供应链）没有证据。本族的商业供给生态（#77）意味着同一条工具链可以卖给多个客户。
  2. 反向跳跃。 因为"不是同一个行为体"就否认工具链关联，从而放弃本可共享的检测指标。
  3. 把表象相似当成弱证据。 表象相似不是"弱证据"，它不是证据——它是提出假设的起点，而不是支持结论的依据。

4. 可比性的五个维度

两起事件要放在同一张表里比较，至少要在五个维度上分别声明可比性。

维度可比要求不可比时的处理
时间同一时期（如同一季度）跨越多年时，工具链与防护基线都已变化，只能比"形态"不能比"成功率"
目标同类受害者（行业/角色/规模）不同类型目标的可比性需显式论证；否则分组统计
技术同一入口类别（0-click / 链接 / 应用）不同入口的成功率不可直接相加（#90 的 P 级不同）
基础设施是否共享可追溯的元素共享域名不等于共享运营方（见第 7 节）
后果同一分级（#91 的 C1–C7）不同级别的后果不能求平均；应分别计数

三个操作规则：

  • 先分组、再求和。 本族事件的样本天然稀疏，任何"总体成功率"都必须先按入口类别与目标类型分组；把不同入口的案例合并成一个比率，等于把不同分母强行相加。
  • 缺失维度要标注，而不是补零。 案例库中最危险的一列是"未知"被当成"没有"（例：未观察到外传 = 没有外传）。
  • 每个结论后面写"适用于哪一组"。 "在本组 8 起案例中"与"在本族事件中"是两个完全不同的断言。

5. 统计口径的四个陷阱

陷阱机制例子纠正
分母缺失只统计"已知的案例"，把分子当总体"我们分析了 12 起案例，9 起绕过了锁定模式"明确写出"这 12 起是从多少个来源中筛出的、筛选标准是什么"
幸存者偏差成功的攻击不会被记录"公开案例中多数在 48 小时内被发现"承认该结论只适用于"被发现的那一部分"；不要外推到全部
归因漂移同一事件在不同来源被归到不同行为体，汇总时被重复计数或错分一起事件在 A 报告里属于 X，在 B 报告里属于 Y，统计里算了两次以"事件"为主键，不以"行为体"为主键；记录多源分歧
时间窗口案例的选择性截取"近三个月案件激增"——恰逢披露季固定窗口 + 同比；标注披露节奏

一条元规则：任何跨案统计的结论，都应当附带"它可能错在哪"。 这不是谦逊，而是让读者能判断该结论能否用于他们的场景。

6. 案例库的字段设计

一份可用的案例库不需要大，需要列对齐。以下字段覆盖了比较所需的最小集合。

#字段取值形式为什么需要
1事件 ID内部唯一编号（不以行为体为主键）避免归因漂移导致重复计数
2时间首次可观测 / 首次披露 / 处置完成三个时间常不同，混用会扭曲统计
3受害者类别行业 + 角色（不给具体名称）分组统计的基础
4目标规模受影响人数/设备数的量级用于加权，而非求平均
5入口类别0-click / 链接 / 应用 / 物理（#90）不同入口不可直接相加
6投递面水坑 / 定向消息 / 应用分发与 #162 的链路分类对齐
7利用的技术类别按 #81 的缺陷类别可比的最小技术单位
8绕过/持久化手法按公开分类描述，不写实现支持"演化"统计
9基础设施线索域名族、证书模式、托管层（脱敏，见 #169）支持工具链关联
10加载器/载荷特征结构特征、而非哈希清单哈希寿命短（#161）
11后果分级#91 的 C1–C7后果不可平均
12可逆性是/否/部分与 #101 的"关系结束凭据仍可用"同构
13检测窗口从投递到发现的时间衡量防御有效性的核心量
14关联证据等级表象/战术/工具链/归属（第 3 节）每一条关联都标等级
15归因分歧多源归属 + 分歧说明保留不确定性
16指标指标类型 + 有效期（#161）唯一可直接用于防御的一列
17信息来源公开报告/自建/共享（#169 的 TLP）可追溯性与可再分发性
18已知未知明确列出未确认项防止"未知被当成没有"
19复现条件是否可被独立验证决定结论强度
20复盘状态内部复盘是否完成案例库与改进闭环的连接点

三条设计原则：

  • 不要以行为体为主键。 一个事件可能有多个归属主张；一个行为体可能有多次行动。以事件为主键，才能同时容纳"一对多"与"多对一"。
  • 每一列都要能填"未知"。 不允许留空，因为留空与"没有"无法区分。
  • 指标列必须带有效期。 否则三个月后整张表看起来"什么都对"。

7. 同源判定的证据分级

把第 3 节落到可操作的判定上，给出三级证据与各自的"能说到什么程度"。

等级证据形态可支持已知的混淆源
S1 强多类独立证据同时指向同一工具链/同一操作方（代码复用 + 基础设施 + 行为时序 + 第三方交叉）"很可能是同一条工具链/同一批操作"供应链复用、团队人员流动、外包
S2 中单一类别内的强关联（如罕见的代码特征、独特的加载顺序）"可能同源"同一套商业工具被多个客户购买（#77）
S3 弱域族重叠、证书模式相似、目标类型相近、时间接近只支持"值得进一步核查"批量注册、模板化基础设施、同一投递服务

三条使用纪律：

  1. S3 不能堆叠成 S1。 十个弱信号不等于一个强信号；它们往往共享同一个混淆源（例如都来自"同一家投递服务商"，而该服务商服务多个客户）。
  2. 结论的强度不得超过证据等级。 在报告里，"可能同源（S2）"与"同源（S1）"是两个不同的断言，对预算与决策的影响完全不同（#171）。
  3. 写出反证条件。 对每个判定，写明"如果发现什么，这个判定就不成立"。这是让判定可被复查的唯一方式。

8. 三种"看起来同源其实不同"的情形

情形表现为什么容易误判正确读法
共享供应商两起事件的基础设施高度重合同一家投递服务/托管商服务多个客户（#162）反映的是供给市场，不是同一操作方
工具流转载荷结构完全一致工具被转卖、被复制、被泄露（#77）反映的是工具生命周期，不是同一批人
模仿手法与目标高度相似后来者借用已知手法降低研发成本反映的是公开情报的扩散，不是同一来源

三者的共同特征是：关联指向的是"共享的东西"，而不是"共同的人"。 在案例库里，这三类应当有独立的标记，否则它们会在统计中不断被当作"同源证据"，虚高出一个并不存在的"活跃团伙"。

9. 从案例库能得出与不能得出的结论

能得出不能得出
哪一类入口在增多（按季度、按分组）某一行为体的"成功率"（分母不可知）
哪一类技术手法在失效（检测窗口缩短）本族的"总体规模"（公开样本有偏）
哪一种投递面在集中（与 #162 的链路分类）特定组织是否被"点名"（需 S1 证据）
检测窗口的中位数变化行业之间的风险排名（口径不可比）
指标的有效期在缩短（#161）防护措施的有效性（除非有对照组）
事件间的工具链关联网络"下一次一定还会用同一手法"

最好用的一类结论是"窗口类"：从投递到发现、从发现到处置、从处置到恢复的中位时间。它们的分母清晰（都是你自己的案例）、口径可控、且直接可行动。

"这两起能不能一起比"本篇

一个常见的流程错误是顺序颠倒：先做归因、再统计、最后才问"这些案例可比吗"。正确的顺序是先建口径、再入库、再做归因——因为归因结论会污染案例库的分类，而分类决定了统计。

12. 八条常见误解

  1. "基础设施重合就是同一批人。" 同一家服务商可以服务多个客户；重合首先指向供给市场。
  2. "载荷一样就是同源。" 工具会流转、会被转卖、会被复用；同样指向的是工具链。
  3. "公开案例多了，说明攻击变多了。" 也可能只是披露变多了；必须固定窗口并看同比。
  4. "我们的统计覆盖了所有已知案例，所以是全面的。" "已知"本身就是筛选结果，且筛选与严重程度相关。
  5. "案例数越多，结论越可靠。" 若口径不一致，案例越多，错误越被放大。
  6. "归因不确定，就没有价值。" 指标与形态的统计不需要归因即可指导防御（第 9 节）。
  7. "不同来源的结论可以取多数。" 归因不是投票；分歧本身是最重要的信息，应当被记录而不是被抹平。
  8. "跨年比较可以看趋势。" 跨年时工具链、防护基线与披露习惯都变了；跨年只能比较"形态"，不能比较"成功率"。

14. 总结

问题一句话答案
"同源"要证明几层三层：事件关联、工具链、行为体；证据不可跨层
两起事件能比吗先声明比的是哪一个量；五个维度分别判可比性
统计为什么总会偏分母缺失、幸存者偏差、归因漂移、时间窗口
案例库怎么建20 列、事件为主键、允许"未知"、关联标等级
不归因能得出什么窗口类、形态类、指标类结论足够指导防御
怎么让结论可信写上口径、附上局限、写明反证条件

把"和之前那起一样"拆成三个问题：哪一层一样、证据够不够、如果不是同源结论还站得住吗。
