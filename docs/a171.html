Coruna 与 DarkSword 场景下的董事会与高管层事件治理：谁签字、预算从哪来、以及决策如何被记住

1. 执行摘要

  • 本族事件的一个结构性事实是：技术团队能做的事，几乎全部需要某个不在技术团队里的人签字。 隔离一段业务需要业务负责人同意，清空并重装一批设备需要预算授权，聘用外部取证方需要采购豁免，对外承认"我们被定向攻击了"需要法务与高管共同决定，而这些决定没有一个是安全团队可以单独作出的。前二十篇把这些动作写得很细（#166 的清除判定、#151 的沟通分级、#157 的名单分级），但没有一篇处理"谁有权批准"这件事——而它决定了前二十篇里至少一半的方案能不能真的被执行。
  • 核心命题一：事件中真正稀缺的不是技术能力，是决策带宽。 一场本族事件在头 72 小时会产生数十个需要拍板的岔口，而高管层的可用注意力以小时计。没有预授权的组织，会把事件变成一场排队等签字的会议：技术团队在等、业务在等、证据在消失（#170 的证据时钟）。
  • 核心命题二：治理的质量不体现在"决策正确"，体现在"决策可被复述"。 事后（董事会复盘、监管问询、保险理赔、诉讼）没有人能还原当时的全部信息，唯一能依赖的是当时写下的记录。因此本篇把"留痕"放在"决策"之前讲：一份写清楚的决策记录，比一个事后被证明正确的决定更有治理价值，因为前者可以被检验，后者只能被相信。
  • 核心命题三：预算不是"批不批"的问题，是"从哪个口袋出、谁承担超支"的问题。 安全预算、IT 运维预算、法务预算、保险赔付（#168）四个口袋的规则完全不同，而事件中的支出会横跨四个口袋。没有事先约定"事件支出的口袋顺序"，就会出现"先花掉最容易被质疑的那笔钱"——通常是最该花的那笔（外部取证与律师）。
  • 核心命题四：对股东的表述不是公关问题，是会计与披露问题。 一句话说错，会在数月后以更正、问询或诉讼的形式回来。本篇给出的纪律是：只陈述已确认的事实、只承诺可控的动作、把"未知"明写成未知——与 #151 的三栏陈述同构，只是读者换成了董事会与市场。
  • 核心命题五：董事会最容易犯的错，是用"是否发生了泄露"这一个问题，替代了十个真正需要它决定的问题（第 10 节）。本族事件里，"泄露了什么"往往要数月才能回答，而"要不要停机、要不要通知、要不要付这笔钱"必须在数天内回答。
  • 一句正向结论：把治理设计成"事前签好四份预授权、事中只做判断题、事后只补记录"。签字不该发生在最需要速度的那几天。

2. 这一篇补哪一格

#160 处理的是技术控制面：管控栈能看见什么、能阻断什么、哪些开关真的生效。那是"能力"。

本篇处理能力之上的授权层：谁允许动用这些能力、动用需要什么代价、以及这个允许如何被记录。两者的关系是：#160 决定了"你可以做什么"，#171 决定了"你能不能做"。

#151 处理对外沟通的内容与分级，#169 与 #175 处理出口的两条通道（报送与公开披露）。这三篇的读者是外部；本篇的读者是组织内部最高层，且它必须先于它们发生：没有董事会层面的口径授权，任何对外表述都可能在半天内被收回。

#104 处理季度巡检与例外台账——那是平静期的常态治理。本篇处理事件期的非常态治理：两者共享同一套"记录、分级、升级"的骨架，但节奏差三个数量级。

#120 处理人员离场、#167 处理供应商合同、#168 处理保险——这三篇分别提供了本篇所需的三个外部接口：人员与角色、合同义务、赔付口径。

3. 事件是一连串要签字的动作

把一场本族事件拆开，会看到一张"谁有权决定什么"的清单。这张清单不需要在事件中生成，它应当在平静期就存在。

时段决策需要谁不做会怎样
0–4h是否隔离受影响网段/设备安全负责人 + 值班高管（可预授权）扩散；且后续取证边界被污染
0–8h是否启动外部取证/律师预授权的单一签字人保管链断点；程序时钟晚启动（#170）
0–12h是否暂停某项业务业务负责人 + 高管业务时钟与证据时钟冲突（#170 第 3 节）
0–24h是否通知受影响人（初步）法务 + 高管；部分辖区另有义务（#151）通知延迟本身成为独立问题
24–72h是否清除并重装安全负责人 + IT + 业务 + 高管证据销毁或暴露延长，二选一（#166）
24–72h是否向监管报送（如适用）法务 + 高管（+ 董事会通报）时限错过（#169）
72h+是否对外披露、以什么口径高管 + 董事会（重大时）表述反复，信任成本上升
数周预算追加、是否动用保险高管 + 财务 + 董事会（超阈值时）关键支出被卡在审批流里
数月是否追责、是否进入正式程序董事会时效与举证窗口流失

这张表的用法不是"照着执行"，而是在平静期标出每一行的"当前签字人是谁"。一旦某一行的签字人是"待定"或"需要开会决定"，它就会在事件当天成为瓶颈。

4. 决策权的四个层级

治理失效最常见的形态不是"没人负责"，而是层级错配：技术决定被抬到董事会，战略决定被压在技术团队。

层级该决定不该决定典型错配
技术层隔离范围、取证顺序、检测规则、清除方式是否通知、是否披露、花多少钱被要求"先出个影响评估再动"
管理层（安全/IT/法务负责人联合）处置节奏、外部资源启用、材料分级（#170 的 L1–L3）对外口径的最终措辞被要求"自己判断要不要报监管"
高管层业务取舍、预算、对外表述、与董事会沟通具体技术动作被拉进"这个域名要不要封"
董事会重大事项的知情与批准、追责、战略调整事件战术被要求"批准一份技术方案"

三条判据：

  1. 越靠近"不可逆"，层级越高。 清除与重装不可逆、对外披露不可撤回、解除某人职务不可逆——这些必须由高管层及以上决定。
  2. 越靠近"时间敏感"，层级越低。 隔离与保存请求应当在预授权下由值班人直接执行，事后通报即可。
  3. 同一件事只能有一个签字人。 "安全部和 IT 部共同决定"在实践中等于"没人决定"。

5. 预授权：事件前应当签好的四份东西

这四份文件把"事件中的签字"提前到平静期，是本篇最有操作价值的部分。

#预授权内容要点谁签有效期与复核
1处置与隔离授权授权值班人在何种触发条件下可直接隔离设备/网段、可直接发起保存请求，无需逐级审批高管（必要时董事会备案）年度复核；触发条件变更时重签
2外部资源启用授权授权在事件确认后 N 小时内启用预选的取证方与律师，含单笔上限与总上限高管 + 财务随供应商合同（#167）更新
3清除与重建授权明确"在满足何种取证条件后可以清除"，以及"谁可以宣布该条件已满足"高管 + 法务与 #166 的验收标准同步
4对外口径授权明确谁能以组织名义发言、在何级事件下可说到什么程度、哪些表述必须升级高管 + 法务（重大时董事会）每次口径变化后更新

四份预授权的共同结构是：条件 + 主体 + 上限 + 复核。缺任何一项，它在事件中都会退化成一纸空文：

  • 没有条件，值班人不敢动，因为不知道"什么算触发"。
  • 没有主体，会出现三个人同时声称有权。
  • 没有上限，财务会在事后质疑每一笔支出。
  • 没有复核，授权会在人员变动后失效而无人知晓。

6. 预算从哪来：三个口袋与"事后追认"的代价

口袋规则事件中的角色主要风险
常态安全/IT 预算年度计划内、按科目承担可预期的部分（加固、检测、日志留存）事件中追加会打乱年度计划，需要重新审批
事件预备金 / 应急授权提前设定的额度与触发条件承担头 72 小时的外部资源与紧急采购若无预设，最快路径是走特批，而特批需要时间
保险赔付按保单条款与报案纪律（#168）承担部分取证、法律、通知与业务中断成本赔付不等于预付：多数情形需要先支出后报销，且受限于分项限额

三个结构性事实：

  1. 事件中最先要花的钱，往往是最容易被事后质疑的那笔。 外部取证与律师费单价高、成果不直观、且"事后看起来也许不必"。因此它最需要预先设定的额度，而不是逐笔审批。
  2. 保险不是现金流。 把"有保险"当成"有钱花"，会在事件第一周发现账户里没有可用额度；现金流的准备必须独立于保单。
  3. "事后追认"是最贵的审批方式。 它意味着先花钱、后解释；而解释要面对"当时为什么这么急"的追问。预授权的价值就在于把这次解释提前到平静期完成。

7. 决策留痕：写什么、谁写、存在哪

留痕不是写会议纪要，而是写可被复述的判断。四个字段即可：

字段写法反例
当时知道什么列出依据与来源（哪个系统、谁说的、何时）"情况不明"
当时不知道什么明确写出未知项与它对决策的影响省略未知，只写结论
决定了什么一句话动作 + 范围 + 生效时刻"加强防护"
谁批准、谁反对具名，含保留意见"会议通过"

三条纪律：

  • 只追加、不改写。 与 #170 第 7 节的"只增不改的时间线"同源；后续更正以追加条目形式出现，附更正理由。
  • 一项决策一条记录。 把十个问题揉进一份纪要，会让每一个问题的"当时依据"都变得不可还原。
  • 保留反对意见。 反对意见不是负担，它是组织"考虑过并选择不采纳"的证据；删掉它，就等于把"深思熟虑"变成"没想到"。

存放位置需要事先指定：它必须在事件中仍可访问（不能只放在受影响的系统里）、权限明确（谁能读、谁能写）、不被日常工具覆盖（不在会被清理的聊天工具里）。很多组织的决策记录最终只存在于某个人的聊天窗口里，这在事后毫无价值。

8. 信息向上流动：什么必须上董事会

触发是否上董事会说明
确认发生定向攻击且影响范围未定是，24–48 小时内"未定"本身就是需要董事会知情的事实
需要突破常态预算阈值是与预算规则绑定
需要对外披露 / 涉及监管报送是与 #169、#175 联动
涉及高管本人或董事会成员的账户/设备是利益冲突必须回避（与 #120 的争议离场纪律同源）
涉及重大业务中断是与 #172 联动
单台设备、已封堵、无外传迹象通常否，按月汇总但要保留"为什么判断不需上报"的记录
疑似但未确认视规模，建议记入月度报告避免"永远在调查中"的信息黑洞

三个形式要求：

  • 固定节奏 vs 事件节奏分开。 月度报告是常态；事件期间是滚动更新。把两者混在一起，会导致事件更新淹没在月度格式里。
  • 格式统一，内容分层。 一页纸：已知/未知/已决定/待决定/需要的支持（预算或授权）。技术细节作为附录。
  • 每次更新必须包含"上次更新以来变化了什么"。 否则董事会无法判断事态是在收敛还是在扩散。

9. 对股东的表述：三种场景与一条纪律

场景常见形态主要陷阱做法
主动披露公告、财报说明、致股东信过度承诺（"已完全控制""数据未泄露"）只写已确认事实 + 已采取的动作 + 后续更新机制
被动问询分析师提问、媒体询问、投资者关系渠道回答超出已核实范围统一口径，不知道就说"待核实"，并给出更新时间
财报/定期报告口径风险因素、重大事项、或有负债前后口径不一致与 #168 的保险口径、#173 的合同责任口径对齐

一条纪律贯穿三者：表述的强度必须与证据的强度匹配。

  • 有 L2/L3 级证据（#170 第 9 节）才可以说"已确认影响范围"。
  • 只有 L1 内部判断时，只能说"正在核实"。
  • "没有发现证据"不等于"没有发生"；这两句话在任何对外文本里都不能互换。

这条纪律的实际价值在于：它让所有对外表述在下一次更新时仍然成立。 危机沟通里最贵的错误不是说少了，而是说多了之后要收回。

10. 董事会最容易问错的六个问题

错的问题为什么错该问的问题
"泄露了什么？"数月后才能回答；此刻问它只会得到猜测"现在决定不了的事有哪些？需要什么才能决定？"
"谁的责任？"在事件中期问责任，会让所有人停止上报"现在的决策链条清楚吗？有没有卡住的地方？"
"什么时候结束？"结束时间不可控；追问会压缩取证"我们现在在哪个阶段？下一步的判定条件是什么？"
"花了多少钱？"过早聚焦成本会抑制必要的支出"预算够不够撑到下一个决策点？"
"我们的防护是不是不够？"这是一个数月后才该回答的问题"这次暴露出的、现在就能改的三件事是什么？"
"能不能保证不再发生？"没有人能保证；承诺会变成日后的把柄"哪些措施可以验证生效？谁来验证？"

这六个"该问的问题"有一个共同点：它们问的是"现在的决策质量"，而不是"过去的责任归属"。 本族事件的调查周期长，董事会的价值在于维持决策带宽，而不是提前审判。

11. 高管个人的暴露

签字意味着承担。这不需要渲染，只需要把事实摆清楚：

  • 签字 = 你知道这件事。 事后关于"我不知情"的陈述将不再成立；因此签字前必须确认自己读懂了记录（第 7 节的四字段）。
  • 批准 = 你认可当时的依据。 如果依据是"下属说没问题"，那就要把这句话写进记录，而不是只签一个名字。
  • 越权批准与不批准都会留下痕迹。 超出预授权范围的批准需要在记录里写明理由；拒绝批准同样应当记录——它可能正是后来被追问的那一环。
  • 利益冲突必须回避。 当事件涉及本人设备、本人账户或本人下属时，由他人代行并记录。

本篇不对任何个人的法律责任作出判断；涉及具体义务（披露义务、忠实勤勉义务、报告义务）的部分以当地执业律师与监管规则为准。

13. 八条常见误解

  1. "这是技术事件，董事会不需要介入。" 本族事件在头 72 小时必然产生预算、业务取舍与对外表述三类决定，全部超出技术层权限。
  2. "预授权等于放权，风险太大。" 预授权恰恰是限定：它写明条件、主体与上限；没有预授权才是无边界授权（谁都可能临时拍板）。
  3. "记录等事件结束再补。" 事件结束后补的记录不再是记录，而是回忆；它无法证明"当时知道什么"。
  4. "保险会兜底，不用预备金。" 赔付通常后置且受分项限额约束；现金流必须独立准备。
  5. "口径统一就是统一说辞。" 统一口径的核心是统一事实边界，不是统一措辞；措辞可以不同，能说的范围必须一致。
  6. "董事会问得细一点显得尽责。" 问不可回答的问题只会得到猜测，而猜测一旦进入记录，就会成为日后被引用的依据。
  7. "先定责才能推动整改。" 事件中期定责会切断上报；整改与追责应当在调查收敛后分别进行。
  8. "我们的规模不至于需要这套东西。" 本族事件的成本结构（#154）与组织规模无关：一台关键人员的设备就足以触发全部上述决策。

14. 与既有各篇的接口

篇目它解决什么本篇如何接上

15. 总结

问题一句话答案
事件中的真正瓶颈是什么决策带宽，不是技术能力
签字该发生在什么时候事前（四份预授权），而不是事件当天
预算怎么安排三个口袋：常态、预备金、保险；现金流独立于保单
记录写什么知道什么/不知道什么/决定了什么/谁批准谁反对，只增不改
什么时候必须上董事会范围未定、超预算、需披露、涉高管本人、重大业务中断
对股东说什么只写已确认事实、只承诺可控动作、未知写成未知
董事会该问什么现在决定不了什么、卡在哪里、还缺什么

治理的目标不是让事件中的每个决定都正确，而是让每个决定都能在六个月后被复述。
