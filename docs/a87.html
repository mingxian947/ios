iOS 智能组件与输入通路攻击面：视觉解析、语音链、键盘与神经引擎上的新边界

编制日期：2026-10-28 数据来源：Apple Platform Security 文档、Apple Machine Learning / Core ML / ANE 公开技术说明、WWDC 视觉与语音议题、Apple Security Releases 组件条目、Google Project Zero、Citizen Lab 与 Amnesty 披露、语音识别与 ML 安全学术文献（对抗样本、模型输入解析）、iOS 分析社区公开笔记、本系列前 83 篇分析 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

本系列把 WebKit（#3、#39）、图形栈（#58、#82）、媒体解析（#37、#44）、协议（#72）都拆过了，但有一条不断长大的面没被单独命名：系统里的智能组件与它们的输入通路——图像/文本识别、语音识别与合成、键盘预测、以及承载模型执行的神经引擎（ANE）。

七条结论：

  1. 这一族的能力特征正好落在攻击链最贵的位置上："不需要用户交互就能处理外部数据"。照片里的文字、来电里的语音、消息附件里的图像，都会在用户点任何东西之前被系统解析——与 #37、#60、#71 描述的 0-click 前提同构。
  2. 它同时具备两个不利属性：代码高度复杂且包含大量第三方数学库/模型运行时（对齐 #82 §3 的"生态代码"问题），运行位置常在特权服务或独立扩展宿主里（对齐 #52 的解析隔离思想）。
  3. ANE 与安全协处理器一样，是一个并行信任域（#64、#27）：它有独立固件与调度路径，系统级缓解（PAC、堆硬化、SPTM）对它不必然生效。这与基带（#72）是同一个结构问题，而讨论远少于基带。
  4. 键盘与预测文本是一条被长期低估的数据聚合通路：它天生要看用户输入内容，历史上多次出现"键盘扩展可读取全部输入"的问题（#83 §3.3 提到宿主边界，本篇把它放进智能通路语境）。
  5. 语音链的风险不只在内核，也在云端与本地混合处理：请求会包含音频特征或文本转写，跨越 #20 的数据覆盖类别与 #69 的中继链路，形成新的隐私与凭据面。
  6. 对抗样本/模型层攻击在 iOS 场景的实际威胁，目前远小于内存安全类；不要把它写成"AI 黑客"故事——真正危险的是"解析器里的老式 OOB"，而不是模型被骗。这一条是本篇最重要的表述纪律。
  7. 可观测性与其它智能面一样差：处理成功不留工件，失败才崩溃。因此防御手段主要是关闭/降级解析能力与版本对齐，不是检测（§7）。

2. 这条通路长在哪里

外部不可信数据              系统智能组件                        执行位置
──────────────────────────────────────────────────────────────────────
图片/视频（消息、网页、相册） → 视觉解析、文本识别、场景理解      → 系统服务 / 独立扩展宿主
音频（通话、语音留言、Siri）  → 语音识别、语言理解、合成          → 本地 + 云端混合
键入文本                     → 预测、纠错、翻译、听写            → App 进程 + 系统服务
模型文件（Core ML 等资源）    → 模型加载与编译                    → ANE 调度 + 驱动接口
传感器数据                   → 姿态/活动/健康推断                → 协处理器与服务
组件族输入来自哪里是否需要用户交互为什么危险
图像中的文本识别（Live Text 类）相册、相机、消息/邮件里的任意图像否（系统在展示时即分析）图像 → 解析器 → 内核/服务内存破坏的完整 0-click 形态（对照 #37 的 ImageIO）
视觉与相机处理管线相机、视频通话、扫描部分与图形/驱动族相邻，跨 IOAccelerator（#58、#82）
语音识别与听写语音留言、Siri、键盘听写需触发但无需点击内容音频解析链 + 跨云端数据流出（#20、#69）
键盘预测与语言模型所有文本输入否（持续运行）聚合能力最强：它能看到你在其他 App 里打的字
翻译与文本处理服务剪贴板、网页、消息中的外语部分自动文本解析栈与内存密集；与 #66 的剪贴板提示同域
模型运行时与 ANE随 App 分发的模型资源否（加载即执行准备）模型文件是"外部可控的二进制输入"，解析器在驱动/固件层（#82 的接口形态）
健康与活动推断传感器否数据敏感度极高，且落在协处理器信任域（#64、#72）

3. 缺陷类别映射（对齐 #81 的第二根轴）

智能组件族主导缺陷类别为什么不吃哪些缓解
图像/视频解析OOB 读写、整数→OOB、UAF尺寸/行跨度计算多，缓冲区由外部图像决定与 #37、#44 同类：类型硬化帮助有限
文本/字体与语言处理OOB、未初始化读、逻辑类编码/字形/边界条件复杂，且国际化路径覆盖不均边界检查一致性
语音前端（编解码与特征提取）整数、OOB、竞态实时流处理 + 缓冲复用堆隔离对流式缓冲帮助有限
模型加载与编译类型混淆、整数、逻辑/授权模型格式是外部可控结构化数据，且有版本兼容层与 #82 的驱动外部方法同构
键盘与预测逻辑/授权误用为主缺陷往往不是内存错误而是"能看什么、存到哪、谁可同步"完全不吃内存安全缓解（#81 §3.8）
ANE / 协处理器依实现而定，公开信息最少独立固件 + 跨域接口系统级缓解不必然覆盖（#64、#72）

关键判断：这一族的最高风险项不是内存错误，而是"聚合能力被合法使用"（键盘、语音、健康）。这与 #66 §3 的 B 路径完全同构：找一个既有敏感数据可见性、又处理外部输入的进程。智能组件恰好两者都满足。

4. 投递面：谁能触发这些解析器

投递渠道触发方式是否需要用户交互与本系列的接口
消息类附件（图像/音频）系统预处理/预览即解析低（部分无需点开）#71、#37、#60
网页/内嵌图像渲染时解析低#14、#3、#21
日历/邮件/联系人里的媒体后台拉取与索引否#65（无交互投递第一公里）
相册同步与云端媒体库下载缩略图/索引时否#69、#74
蓝牙/近场传输的媒体接收预览中#69、#72
语音唤醒与 Siri 触发音频流需触发（但可由外部音频）#83 §3.4 的界面类风险

防御含义：这些渠道里，只有少数是可以由用户关掉的（预览、索引、自动翻译、唤醒）。把它们逐条列成开关清单是 §7 的主要内容。

5. ANE 与协处理器：又一条并行信任域

属性现状判断依据
独立调度与固件ANE 有独立执行与任务提交通路，不完全等价于普通内核驱动#64、#27 的同构推理
系统缓解覆盖PAC/CSM/堆加固主要作用于主内核执行路径，不必然覆盖协处理器固件内部#64 关于"并行信任域"的结论
公开研究密度远低于基带与内核；可引用的利用实例极少观察性结论，不夸大
攻击面位置真正的近期风险在任务提交接口与模型解析（主机侧），不在固件内部猜测#82 的外部方法视角
防御抓手版本对齐 + 不装来源不明的模型/工具类 App；对高危者关闭不必要的智能处理§7

表述纪律：这一节必须诚实。目前没有公开证据表明存在"ANE 固件级武器化利用"。正确的写法是：它在架构上属于与基带同类的独立域，因此"上限不受主系统缓解保护"，但已发生的风险仍集中在主机侧解析器。把架构可能性写成已发生的威胁是本系列反复纠正的那类错误（#62、#80 §9）。

6. 数据与隐私侧（比内存漏洞更常发生的损失）

通路流出内容谁能拿到加固
云端语音识别音频特征/转写文本，绑定账户标识（可重置的，非设备永久 ID）服务侧、法律调取、账户泄露时你本人关闭不必要的听写；对高危角色使用无账户/受控环境；理解"重置标识符"的边界
键盘学习与个性化词表与使用统计，跨设备同步同步链路、备份关闭"自设备学习/同步"于敏感岗位；对齐 #69
照片索引与视觉标签图像内容派生特征云端索引（是否本地处理取决于设置与版本）检查 iCloud 照片相关处理设置；敏感相册隔离
健康与活动推断极高敏感度健康 App 授权、第三方 App、备份逐项撤销授权；健康数据落强保护类（#83 §3.1、#84 §2.2）
Siri 建议与通知智能使用习惯、通信对象本地为主，但同步/备份会带派生数据高危角色可关闭建议类能力
剪贴板智能操作（翻译、识别）复制内容任何有权读剪贴板的 App（系统只提示不阻断）敏感值不走剪贴板（#66 §3、#83 §3.2）

这一节是本篇的"多数人会真正受害"部分：它不需要漏洞，只需要默认设置与你没注意到的同步开关（对照 #86 §5 的 stalkerware 逻辑——能力被合法使用）。

7. 加固清单（按可关闭性排序）

7.1 个人/高危个体

□ 自动更新（解析器缺陷唯一通用防线，#80 §3）
□ 高危者开锁定模式：会同时收缩部分自动处理与媒体触发面（#34）
□ 键盘：只保留系统键盘；删除所有第三方输入法与键盘扩展（聚合能力面，#83 §3.3）
□ 听写/Siri 触发：不确定就关；车载/公共场合尤其
□ 照片视觉搜索/记忆类功能：敏感岗位关闭
□ 健康类授权逐项核查，只保留必要项
□ 剪贴板：敏感值不用剪贴板传递；关注读取提示
□ 输入法/翻译等派生功能的跨设备同步关闭
□ 不装"AI 增强/滤镜/工具"类来源不明 App（模型解析面 + #86 的 A/E 层风险）

7.2 组织/平台

动作说明
把"智能组件相关条目"纳入 #85 的族标签组件名如视觉/语音/模型相关服务，单独统计趋势
业务 App 避免自建模型加载不可信资源模型文件按不可信输入处理（长度/结构校验、隔离进程）
敏感岗位设备禁用第三方键盘与听写用 MDM 策略落地
采购含 AI 能力的 SDK 时问三件事是否云端处理、数据留存、模型来源
检测预期设低该族失败才崩溃、成功不留工件（#63、#76）

7.3 开发者（自研智能/解析功能）

□ 外部媒体/模型一律视为不可信输入：长度、维度、层级数上限，拒绝即静默降级
□ 解析放在受限进程/扩展宿主，最小 device 授权（#82 §5.3、#52）
□ 不在特权进程内做格式猜测；优先用系统框架而非自带老解码器
□ 模型资源签名/来源校验 + 更新走受控通道
□ 敏感字段不写日志、不进崩溃上报（#76）

8. 常见误解纠正表

误解事实
"AI 组件的新风险是对抗样本骗过模型"在 iOS 真实入侵场景中，风险来自解析器里的传统内存缺陷与聚合授权，不是模型被骗（§3、§5）
"ANE 是独立处理器所以更安全"独立域意味着系统缓解不必然覆盖，既可能更安全也可能更不设防，取决于接口审计（#64）
"语音都在本地处理"取决于功能与设置，部分链路存在云端处理与账户标识；要按功能逐项看（#20）
"第三方输入法只是打字工具"它是聚合能力最强的宿主之一，能看见跨 App 输入（#83 §3.3）
"关闭 Siri 就够了"真正的持续聚合来自键盘、视觉索引与健康推断，不在唤醒
"系统智能功能默认都是安全的"默认值多为可用性优先；数据流出边界要看逐项开关（§6）
"这类攻击一旦成功必然有异常崩溃可查"逻辑/授权类不崩溃；内存类才可能崩溃，且利用成功同样可以不崩溃（#63、#82 §8）

10. 总结

#结论
1智能组件与输入通路是一条持续净增长的攻击面，其核心特征是"无需交互即处理外部数据"，与 0-click 前提同构
2主导缺陷类别是 OOB/整数/UAF（解析器）与逻辑/授权误用（聚合能力），后者完全不吃内存安全缓解
3ANE 属并行信任域，主系统缓解不必然覆盖；但已公开的风险集中在主机侧解析与任务提交接口，不要把架构可能性写成已发生的威胁
4键盘/预测/视觉索引/健康推断构成最强的合法数据聚合面，多数人的真实损失来自这里而非漏洞
5投递渠道大多不可关（附件预览、索引、同步），能关的是第三方键盘、听写、视觉搜索、跨设备派生同步
6该族检测预期必须设低：成功处理不留工件，因此防御杠杆在版本对齐与能力关闭
7开发者侧的正确姿势是把媒体与模型资源当完全不可信输入，并在受限宿主里解析

一句话总结：iOS 的智能功能为了"懂你"而必须先看你的内容——照片里的字、嘴里的话、指尖的输入都在你点下之前被系统解析过；这让它在架构上同时具备 0-click 的触发条件和最敏感的可见性，而它真正的日常风险不在模型被骗，而在解析器的老式越界和那些你从没关过的聚合开关。
