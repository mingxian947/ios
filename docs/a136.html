iOS 上 WhatsApp 群控现象的观察与识别：你看到的"很多人都在说"，可能是同一只手在翻页

1. 执行摘要

  • 这一族的名字应该叫"数量不是证据，它是被制造出来的东西"。前面二十一格的位置依次是进来的字节（#118 格式、#122 卷、#123 报文）、进来的调用（#119 接口、#127 插槽）、进来的设备与信号（#121 配件、#125 定位、#129 号码）、进来的操作请求（#126 辅助功能）、留下之后被合在一起的内容（#128 索引与聚合）、画到屏幕上的内容（#130 显示与捕获）、到达时被你认出成谁（#131 标识与呈现）、验证之后存续下来的能力（#132 凭证与会话）、按下之后交给谁执行（#133 派发）、什么时候被执行（#134 调度）、一次发送覆盖多少人（#135 批量投递）。本篇是第二十一根竖条，它接在 #135 后面，因为 #135 解决的是一个身份对很多人，本篇解决的是很多身份对一个人——而且这很多身份可能属于同一只手。
  • 核心命题：群控不攻破任何账号，也不攻破任何设备。它做的是把"很多人同意"这个人类判断的替代品生产出来。 在 iOS 端，你无法看到控制侧的一切：谁写了那段文案、几个账号在同一时刻被排上队、素材从哪台机器分发出去——这些全部在别人的基础设施里。你唯一能看到的是它的呈现层残留：数量、时间分布、素材同源、关系结构这四类一致性。而人类的默认推理是"这么多人都在说，那大概是事实"，这就是本族真正攻击的对象——不是你的账号，是你的判断。
  • 三层切分：K1 身份层（一次协同需要多少个可发言身份，每个身份绑着什么、谁能把它收回去、换绑与注销的代价）；K2 控制层（文案、素材与发言次序从哪里产生——这一层在本篇被明确划为不可观察对象，因为设备上看不到它，也不提供任何改进它的方法）；K3 呈现层（在接收端的会话里，协同最终只能以"几个互不相干的联系人说了几乎同样的话"这种形态出现，而这一形态与真实共识在界面上没有区别）。风险密度在 K3，因为判定是在那里被污染的；不可逆点在 K1，因为身份的可回收性决定了一个假象能被维持多久、以及被拆穿之后还能不能重开。
  • 六个核对点 O1–O6（素材同源、时间簇、关系结构、资料页形态、号码形态、发言角色）。必须先说清楚它们的性质：这六个是"疑问生成器"，不是"判定表"。 每一个都有完全无辜的解释（同一批朋友看到同一条新闻、同一个群活动在同一分钟热闹起来、新号段刚放号、家人共用素材），所以它们的正确用法是降低信任并要求独立核验，而不是给出"这是群控"的结论。没有任何端侧方法能证明协同——证明需要平台服务端数据与合法程序（#105、#62）。
  • 一条方法论结论：用 #66 的隐私面板、#127 的槽位清单、#128 的来源清单、#130 的通路清单、#131 的对象—显示对照、#132 的能力持有人、#134 的资格—拉起表、#135 的批量能力清单做审计，全都会漏掉这一族。原因是同一个：前二十三张清单的审计对象都是"一个 App 能对我做什么"，而本族的对象是"一批身份彼此之间的关系"——这在 iOS 的任何面板里都不是一个可枚举的东西。 本篇需要的是第九个系统性漏检的补丁：一张跨会话的同源素材登记表（我在多少个互不相干的会话里见过同一段文本、同一张图、同一个链接版本），它不能自动采集，只能手工记，这是本篇给出的最诚实也最没用的一个建议——但它确实是唯一可行的那个。
  • 后果上它给出第十种不提权的伤害形状：以数量冒充共识的在场。#126 借系统功能、#127 借你请进来的代码、#129 在别人的系统里你就是本人、#130 被读走的是画面、#131 借你自己的手、#132 未经同意的共同持有、#133 合法承接、#134 无人值守窗口、#135 合法的批量在场；本篇的形状是伤害作为"气氛"——它不需要你相信任何一条消息，它只需要让反对意见看起来是少数。
  • 可观测性的诚实定位是全系列最弱的一档，比 #135 更弱：#135 至少还有成员列表、加入方式、链接这些本机构件；本篇要看的"协同"这件事根本不在任何一端的客户端落盘——控制侧不落盘在你的设备，发送侧的协同记录只在平台服务端的统计与风控里，接收侧只有你自己的会话。与 #135 同格：那个量不是被隐藏了，是本地不存在。
  • 正向结论只有一句：在本族，唯一可靠的防御是"把数量从证据降级为线索"，然后要求一条与数量无关的独立核验路径。 具体做法是三步：不因为多少人说过而改变判断；对结论去做一次渠道外的核验；对已经被说服过这件事的自己，做一次事后记录（因为它会重演）。任何"识别群控"的端侧自动化都不成立，包括模型打分——它只能给出与本族同样不可靠的猜测。

2. 这根竖条补的是哪一块

系列里已经有几篇擦到了"很多身份"这件事：#135 测绘了一个身份如何一次触达很多人（寻址、批次、到达），它的结论是"收件人看不出这是一次批量投递"；#97 给了社会工程的四步链条（触发、身份、授权、不可逆），它处理的是一个人怎么失守；#86 讲恶意与滥用 App 的分发生态；#131 讲一个名称在你的界面上被渲染成官方；#132 讲凭证与会话作为存续能力；#129 讲号码作为身份与验证通道；#130 讲屏幕内容作为一种被读走的证据；#128 讲本地索引如何把散落内容合在一起。

但这些位置都缺同一格：一批账号被同一处指挥（或同一份素材指挥）时，接收端能看到什么、不能看到什么、以及看到的那些东西应该怎么用。 #135 是"一"对"多"，本篇是"多"对"一"；#97 讲你信了谁，不讲"很多人同时让你觉得你不合群"；#131 讲一个显示名的伪造，不讲显示名以外的行为一致性。

这是第二十一根竖条，也是第二条不在 iOS 内部的一根：它落在一个第三方通讯 App 的滥用形态上。它仍然属于这个系列，因为它造成的可见性缺口正好由 iOS 的审计口径产生——系统按"App + 权限"暴露风险，而这里的风险单位是"一批身份之间的协同"，它既不是权限也不是接口，系统在结构上无法替你枚举它。

与相邻各篇的分界必须写死：

  • 与 #135：那一篇是投递（一次动作覆盖多少收件人），本篇是协同（多少身份被同一处指挥）。两者的观察者位置也不同：#135 里你是收件人之一且不知道其余收件人是谁；本篇里你是唯一在场的人之一，而你不知道其余在场的人是不是同一个人。分界线是：本篇不讨论批次规模与速率参数，只讨论"多"这个印象是怎么被生产出来的。
  • 与 #97：那一篇给失守的断点与举报动作（判定层，心理与流程轴）；本篇给让失守显得合理的那个环境（数量层，可观察痕迹轴）。同一句话在这里继续适用：你用来警惕的那个信息本身，是谁写的、以什么身份发的——本篇负责"有多少人同时以什么身份发"。
  • 与 #131：那一篇讲一个标识被渲染成什么；本篇讲一组标识被组织成什么。#131 的"显示即属主"在本族的第三次成立（显示成很多人 ≠ 真的是很多人）。
  • 与 #132：那一篇讲一个身份的凭证与存续能力；本篇讲很多身份的持有关系——一个身份被谁收回、注销后它的发言是否还留在你的会话里（答案是留，#107 的撤销不对称在本族第七次成立）。
  • 与 #129：那一篇讲号码是验证通道；本篇讲号码是身份的可分发单位——协同需要号码，所以号码的形态、区号与可用性会留下聚集痕迹。#129 的"号码即身份"在本族第五次成立，但必须加一句限制：号码形态只能生成疑问，不能生成结论，任何号段都有大量正常用户。
  • 与 #130/#128：屏幕内容是可被读走的证据，本地索引会把散落内容合成可查询对象；本篇给的是当这两件事在同一台设备上发生时，反而为你所用——你可以用 #128 的来源清单和 #130 的画面核对，把"我在别处也见过这段"变成一条可查记录。这是本篇唯一一个把系统缺陷反过来当防御用的位置。
  • 与 #61：那一篇是端到端协议与系统接收通路的取证边界；本篇不讨论密码学，只讨论会话文本与媒体作为证据对象的可导出性与留存边界。

3. 三层切分：身份、控制、呈现

3.1 K1 身份层——不可逆点在这里

一个"很多人"的印象需要若干可发言身份。你在这台设备上能知道的只有它们的外部约束：

身份的要素你在接收端能看到你永久看不到谁能终止它
账号（号码绑定）号码、头像、简介、上次_seen_时间（若双方可见性允许）该号码绑定过哪些设备、注册时的验证路径持有验证要素的人，其次才是平台处置
显示身份（名称/头像）当前渲染值历史值与改名次数账号自己（平台一般不校验）
组织身份（企业认证徽标）徽标与商业名称申请时提交的材料与审核边界平台（慢、且只对未来生效）
群内资格是否在成员列表里、何时被加入谁批准的、被加之前是否已在别的群群管理员，其次平台
注销之后已发消息仍在你的会话里（可能显示为"已注销账号"）注销前它属于谁无人——已经发过的话无法收回

三条结论：第一，身份的可回收性决定假象的寿命——一个能被其持有人随时重开的身份集合，比一个被封掉的账号集合危险得多，而这两者在你的界面上完全一样。第二，注销不等于消失（回到 #107：关闭只对未来生效），它对你的会话、备份与截图没有任何清除能力。第三，认证徽标解决的是"这个主体申请时被核验过"，永远不解决"此刻这句话说得对不对"——#135 的 M5 在这里升级为 M3（见 §6）。

3.2 K2 控制层——本篇明确不观察的对象

协同的另一半——文案从哪来、由哪些身份按什么次序发出、素材如何分发——全部发生在你的设备之外。本篇的处理方式是把它当作不可观测背景，只承认三件事：

  • 它存在，并且成本结构决定了它的形态：能同时运行的身份数量、能维持的时间跨度、能被消耗掉的重置代价，共同决定你看到多少条、持续多久（这是 #90 的预算/对手矩阵在本族的用法）。
  • 它不产生任何只在你设备上的痕迹。所以你无法用本机的日志、通知历史或截图证明它。
  • 它被平台侧的统计看见（协同检测、批量风控、异常账号簇），而这些数据对你和对我都不开放。因此本族的处置动作只能走到"举报 + 保留证据 + 独立核验"，走不到"我自己验证它是群控"。

这一层不提供任何方法。 任何"如何让多个身份看起来互不相干"的内容都属于操作指导，本篇不写，见文末说明。

3.3 K3 呈现层——风险在这里

协同到达你眼前之后只剩四类可核对的一致性：

一致性你在 iOS 上的核对动作它能支持什么结论它的无辜解释
素材同源同一段文本、同一张图、同一个链接版本是否出现在互不相干的会话里"这不是自发讨论，是一次分发"同一条新闻、同一个官方公告被转发
时间簇这些话是否几乎同时出现（只看"是否同一时段"，不比较间隔数值）与"自发"不一致群内话题刚被提起时的正常热闹
关系结构发言者之间是否彼此相识、是否同一批被拉进群"它们的关系是任务性的"同事、同学、同一活动报名者
资料页形态头像/简介长期一字不变，或全部在同一天变化低（仅作疑问）家人共用头像、公司统一形象

第四类的权重必须写得很低，因为它最容易被误用成对普通用户的画像。本篇不给出号码段、注册时间窗或行为节奏的判定阈值——给出来就等于给操作方一份改进清单，而本族的目的是让接收者少信一点，不是让接收者自认为掌握了检测技术。

4. 六个核对点：O1–O6 是疑问生成器，不是判定表

  • O1 素材同源（权重最高）：同一句几乎一样的话出现在三个彼此没有交集的会话里。这是唯一一个你可以自己在本机验证、且能形成记录的一项（对照 #128 的来源清单做跨会话比对；截图留存按 §5 的证据表处理）。
  • O2 时间簇：不要记"相隔几秒"这种数值（它既不稳定也不该被当标准），只记"这几条来自互不相识的账号、出现在同一个我很短的空闲里，让我感觉已经很多人说过了"。
  • O3 关系结构：谁把你拉进群、拉你的那个账号在你的通讯录里吗、它的名字和头像是否与你已知的任何人有交集。WhatsApp 上你看不到成员之间的关系，所以这一项的正确产出是"我不知道"——把"我不知道"写进台账（#104），是本族唯一可执行的加固。
  • O4 资料页形态：长期静止或同批变化都只降低信任，不提高结论。
  • O5 号码形态：区号、可拨通性、号码与自称身份不符——这些能提示"这个人未必是他声称的那个人"，但不能提示"这些号是一伙的"。任何号段都有海量正常用户；把 O5 用作判定，就是把本族方法变成一种对新用户的歧视。
  • O6 发言角色：只在被拉群后立即开口、从不语音、从不回应一个具体到只有当事人才答得出的问题、被追问时把话题拉回文案主线。这一项是最有判别力的，也是唯一一个必须靠你主动提问才能触发的。

一条使用规则：O1 到 O6 中任何单独一条都不构成理由；它们的作用是让你去走 §8 的独立核验，而不是替你把"不信"这一步省掉。

6. 七类契约违背：本族真正的攻击对象是推理

  • M1 数量即真实性。把"很多人在说"读成"大概是事实"。这是全系列最普遍的一条，也是本族唯一必需的成功条件——协同不需要说服你，只需要让你以为已经有人被说服了。
  • M2 同现即共识。几个账号同时出现即被读成一个群体的意见（#135 的"批次不落盘"在这里变成它的对偶：同一批次里的身份彼此也可能互相不知道，但它们在你眼里构成了"大家"）。
  • M3 徽标即主体。"这个账号被核验过"被读成"这句话说得对"；核验对象是申请，不是语义（#131 显示即属主在本族第三次成立，#135 的 M5 升级到这里）。
  • M4 活跃即真人。会回复、会点赞、会发表情被读成背后有人；活跃度不是人格证明。
  • M5 号段即判定。这一条是反对性的：它写在这里是为了禁止一种用法——把号码形态当作结论。本族的所有核对点都是疑问，不是结论；把它们当结论使用，伤害落在普通新号用户身上，而协同方毫无损失。
  • M6 退出即消失。退群、拉黑、注销都只对未来生效；已形成的"很多人说过"这个印象，以及你手机里的那份副本，都不随之消失（#107 撤销不对称第七次成立）。
  • M7 举报即挽回。处置通常终止未来发言，不消除已经造成的判定污染，也不向你告知处置结果（这是 #133 M6"标记不解释"的同格：系统给结论不给理由）。

7. 后果落点（接 #91 的后果轴）

  • C1 决策错误 → 财务与账号不可逆损失：本族的终点极少是"被骗了一条消息"，而是"因为很多人说好，所以转了账 / 加了群 / 交了验证码"。三个不可逆点：N1 支付与转账；N2 加入新群并同意被继续拉入更多群（这会把你自己变成 #135 意义上的一个投递面）；N3 提供验证码或授权（这是 #97 链条的最后一步，也是 #132 意义上的能力移交）。三者的共同点：都在数量印象形成之后发生，且都不能靠"后来发现是假的"回退。
  • C2 隐私与关系图谱：为了核实而加陌生人、进群，按 #135 的 T2 立刻把号码与头像交给全群（#95 的追踪原料）。核对本族的行为本身就在产生暴露——所以顺序必须是"先做不需要判断的核对（渠道外核验），再考虑需要接触的动作"。
  • C3 声誉与关系伤害：组织侧最重的后果是沟通通道整体失去可信——一次被识破的品牌冒用之后，"我们群里发的通知都可能是假的"这种折价会长期存在，且无法逐条撤销。
  • C4 服务与费用滥用：与 #135 同账，本篇解释它为什么是"很多人"在引流而不是一个人。
  • C5 可用性：对个体是骚扰与静音成本、是"要不要退群"的决策负担；对组织是对外的沟通不可信；对高危个体（#108）是定向的多人施压与来源污染——当一批身份同时出现在你的来源周围，你保护联系人的难度不是加一点，是换一种方法。
  • C6 判定污染第五次成立（#125 首创、#130 第二次、#133 第三次、#135 第四次）：本族的污染方式与前四篇都不同——它污染的不是某一条事实，而是"大家怎么想"这个量。一次协同发言会留在你的记忆里，比留在会话里的时间长：会话可以删，"当时很多人都这么说"这个印象无法删除，而且它会在你之后每次同类决策时被重新调用。这是全系列里最难处理的一种 C6，因为处置对象在你自己的推理里，不在任何一台服务器上。
  • C7 归因失效：与 #131（没有第二种形态）、#132（没有可指认的时刻）、#133（那一跳不落盘）、#134（无人窗口里分不清谁按的）、#135（批次不落盘）都不同——本族的失效是"协同"这个事实本身在客户端没有任何表示：即使每个账号都发了言，也没有任何一处的数据表示它们是同一处指挥。所以本族的归因上限是"无法归因"，不是"证据不足"。
  • 可逆性的特殊位置：本族的补救以降权与隔离为主——静音、退出、把相关会话从决策依据里摘出来、要求一条独立核验路径；对组织还包括公开承认发生过冒用（因为对沟通不可信这种伤害，唯一有效的修复是把它说出来并给出替代核验渠道）。

8. 五步审计法与判定式

8.1 个人侧：收到"很多人都在说"时的四问 + 一步

  1. 这段内容是否出现在别的地方？（O1，本机跨会话比对；命中即降权）
  2. 这些人彼此认识吗，还是只认识我？（O3；正确答案通常是"我不知道"，把不知道记下来）
  3. 去掉数量之后，这条主张还剩什么证据？（把"三个人也这么说"删掉，看剩下的句子能否独立成立——这是本篇唯一要求你做的判断动作）
  4. 有没有一个与这群人无关的渠道能核验？（打官方电话、进官方 App、看自己的账户状态——与 #97 的第四步同格）
  5. 只有前四问都指向"仍有疑问且这件事可逆"时，才考虑接触性动作（进群、私聊、加好友）。

8.2 判定式（可执行、可验证）

一次协同的印象 = 数量 × 同时性 × 相似度。 三项你都能在本机核对，但核对的结果只能用来降权，不能用来定性。 因此本族的正确判定式是："当我因为人数而打算改变判断时，我是否有一条与人数无关的核验路径？"——没有，就不改判断；这一步可以当场验证，且完全由你控制。

8.3 组织侧：五个动作

  1. 给出一个渠道外的核验路径，并把它写进所有正式通知里（"凡涉及付款，请从官网入口登录查看，任何群内链接都不作数"）。这是唯一能中和 M1 的措施，因为它把判断依据从数量换成了状态。
  2. 公告组与大群里的通知做二次确认（发布后通过另一个独立渠道重复一次，让员工核对两处一致）。
  3. 对外身份用可核验载体承载，并明确"名称不是身份"（#131 的呈现缺陷在组织侧最贵）。
  4. 被冒用时公开通报，而不是私下删帖——伤害在沟通可信度上，所以修复也必须在沟通上做。
  5. 在季度巡检表（#104）里加一行："本季是否出现过被多人同文案联系的事件；核验路径是否有人真的用起来。" 这行的价值不是发现攻击，而是检验第 1 项是否有效。

9. 设备端可观测性——本篇的诚实边界

  • 能核对的：会话文本与媒体、成员列表、加入方式、你自己的截图、跨会话的素材一致性。全部限于你自己参与的会话，且只能人工比对。
  • 不能核对的：身份背后的持有关系、控制侧的一切、同一批身份是否还联系过别人、平台是否已经处置。这些不在客户端，也不在任何端侧可以查询的接口里。
  • 结论上限："降低信任 + 要求独立核验"，不是"证明协同"。把上限提高的任何工具、评分或模型，都是把疑问当结论，属于误报制造机，并且按 §6 的 M5，它同时是一种歧视。
  • 与相邻各篇同格的位置：这是第三个"风险单位不在这台设备上"的竖条（#129 的签发方、#132 的服务端会话、#135 的批次统计），本篇是第四个，而且它比前三个更彻底：前三个至少存在一个可被合法程序调取的服务端记录对象，本族的"协同"是平台内部的分析结论，通常不作为可调取的数据存在。
  • 必须写出的自我限制：本篇的核对点清单如果被操作方读到，同样是一份"如何让协同更不明显"的清单。因此本篇刻意不给阈值、不给节奏、不给参数、不给实现（见文末说明），并且把每一项都写成"降低你自己的信任"而不是"识别别人"。

10. 加固清单

10.1 个人（按当场可验证排序）

  1. 给"人数"降级：把改变判断的资格从"多少人说过"换成"我能否在群外核验"。这一条不需要任何设置，且今天就能生效。
  2. 开启并保留通知历史与关键会话截图（易失证据先固定；对照 §5 的保留时间列）。
  3. 群成员可见性收紧：不加入陌生群；已加入的、只为一次活动而存在的群，活动结束后退出（#135 的 T2 与 T3 同时收敛）。
  4. 不因为"群里都是同事/同乡/同好"就降低核验——关系标签是 M2 最常见的入口。
  5. 把 O1 的比对变成一个习惯动作：遇到"很多人说"时，用聊天记录搜索看这段句子是否出现在别的会话（这是唯一能本机自动完成的核对）。
  6. 接触性动作前置成本：进群、加好友、私聊陌生人之前，先完成 §8.1 的第 3、4 问。
  7. 举报前先把材料补齐（成员列表 + 加入方式 + 时间 + 导出），举报本身会让材料失去上下文；处置只对未来生效（M7）。

10.2 组织 / 企业侧

  1. 所有通知自带渠道外核验路径，并规定"群内链接不构成付款或授权依据"。
  2. 对外身份集中管理：谁能建公告组、谁能以公司名义发言、离职后如何收回（接 #120 的关系类授权必须创建方撤销）。
  3. 一次冒用事件的通报模板要预先准备好，因为事发时最贵的就是"我们还没决定怎么说"。
  4. 员工侧培训只讲一件事：凡以"很多人都在问/都收到了"开场的话，都不构成依据。这比讲攻击手法有效。
  5. 与 #104 的季度台账合并，把 §8.3 第 5 项作为固定一行。

10.3 高危个体（接 #108）

  1. 把你可能出现在的群当作可被投放的场所：一次定向协同施压不需要攻破你的设备，只需要制造"周围人都这么认为"。
  2. 来源保护：联系人不知道哪些群是被布置的，所以"进群"这件事必须进入你的最小化清单；对疑似投放环境，采用只在受控设备上进入的做法（与 #110 的角色分离同格）。
  3. 心理成本要写进方案：本篇这种攻击的收益形式是让你怀疑自己的判断，方案书里应留一条"判定污染应对"——出现这个感觉时回到独立核验路径，而不是回到记忆里的人数。

11. 十条常见误解

  1. "很多人同时说，说明这是真的。"——说明有人同时说了。这两句话的区别就是本篇的全部内容。
  2. "能识别群控的软件很多。"——没有任何端侧方法能证明协同；能给出"识别"的只能是猜测，且猜测的误伤落在新注册号码与外籍普通用户身上。
  3. "认证了就可信。"——认证核验的是主体申请，不核验语义（M3）。
  4. "举报了就没痕迹了。"——处置对未来生效；你的会话里那些话仍然在，你的印象也仍然在（M6/M7）。
  5. "退群就安全了。"——退群即失去成员列表与加入方式，这是你唯一的核对材料；先记录，再退出。
  6. "注销的账号发的消息也就没了。"——不消失；它变成"已注销账号"继续留在你的会话与备份里。
  7. "这是平台的事，跟我无关。"——平台侧统计确实是你拿不到的，但唯一能改变结果的变量是你自己的核验路径。
  8. "我一眼就能看出来。"——把 O1–O6 当判定用的人，最常见的结果是误判无辜者、放过协同者；本篇的判定式（§8.2）刻意把结论换成了动作。
  9. "这是 iOS 的安全问题。"——不是：iOS 在这里没有任何缺陷，它的缺陷只有一条——审计口径按 App 与权限组织，所以这类风险对它不可见（第九个系统性漏检）。
  10. "防范群控就是要学会检测。"——你不需要检测它，你只需要不让数量参与你的判断。这条是本族唯一稳的收益。

12. 与既有各篇的接口

  • 接 #135（群发/批量投递）：一多对少 vs 少对多的镜像关系；两篇合起来才构成完整的"通讯滥用"：投递面 + 协同面。
  • 接 #97（社会工程与诈骗）：那一篇的四步（触发/身份/授权/不可逆）在本族仍然成立，但本篇解释为什么"身份"这一步会被大量身份代替——当身份多到看起来像环境，判定就不再做在单条上。
  • 接 #131（标识与呈现）/#132（凭证与会话）/#133（链接与派发）：呈现层与身份层给"它是谁"，会话层给"它能存续多久"，派发层给"点下去之后到哪"；本篇给"有几个它在场，以及这三者无关"。
  • 接 #129（号码与订阅）：号码即身份第五次成立，同时本篇给出一条 #129 没有的限制：号码形态不可作为判定依据。
  • 接 #130（显示与捕获）/#128（索引与聚合）：这两篇的系统缺陷在本族第一次被反过来用作防御手段——跨会话比对与画面核对。
  • 接 #116（入侵时间轴）/#62（可采性）：§5 的证据族表沿用 #116 的"先记录再处置"与服务器侧活得最久两条。
  • 接 #90（攻击者起点）/#91（后果）/#92（可用性）：本族的对手位置是 P2/P4 的组织化投放（不是 0-click，也不针对设备），后果主要落在 C1 决策污染与 C3/C5 的沟通可信度上。
  • 接 #104/#108/#110/#120：季度台账的一行、高危个体的最小化清单、角色分离的受控设备、组织侧的关系类授权回收。
  • 接 #86（滥用分发）/#83（第三方 App 缺陷）：那两篇讲 App 自身怎么被滥用；本篇讲App 的正常使用如何被组织成一种压力。

13. 总结

本篇把整族的场地放在一个不在 iOS 内部的位置：一批身份被同一处指挥时，接收端看到的世界。它给出的不是检测技术，而是一条更根本的降级——数量不具备证据资格。三层里，K2（控制层）被明确写成不可观察且不提供方法，K1（身份层）给出不可回收性带来的寿命问题，K3（呈现层）给出四个可核对维度和一个只允许降权的判定式。它的后果是全系列最难处置的一种判定污染：污染对象在你自己的推理里，不在任何服务器上，所以既删不掉也调取不到。正向结论只有一句：当你因为人数而想改变判断时，先问自己有没有一条与人数无关的核验路径；没有，就不改。
