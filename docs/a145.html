iOS 局域网服务发现与本地信任的攻击面：同一个网段不是网络，它是一个没人签名的通讯录

1. 执行摘要

  • 这一族的名字应该叫"本地网段是一个无鉴权的信任域"。前面二十九根竖条的位置依次是进来的字节（#118 格式、#122 卷、#123 报文）、进来的调用（#119 接口、#127 插槽）、进来的设备与信号（#121 配件、#125 定位、#129 号码）、进来的操作请求（#126 辅助功能）、被合在一起的内容（#128 索引与聚合）、画到屏幕上的内容（#130 显示与捕获）、到达时被你认出成谁（#131 标识与呈现）、验证之后存续下来的能力（#132 凭证与会话）、按下之后交给谁执行（#133 派发）、什么时候被执行（#134 调度）、一次发送覆盖多少人（#135 批量投递）、很多身份怎么被组织成一种气氛（#136 群控与协同）、内容被生产时附带的上下文（#137 采集与容器）、你亲手搭的执行器（#138 自动化编排）、离线落地的内容（#139 模型包）、不在场的改版（#140 远程配置）、一次解锁即一次登录（#141 通行密钥）、以设备名义作出的判决（#142 风控指纹）、修一次身份变一次（#143 硬件完整性）、交付到别人的治理之下（#144 内容外发）。本篇是第三十根竖条，它补的是这条链上唯一还没被单独测绘过的一段：你的设备走进一个网络之后，系统替你相信了什么。
  • 核心命题：本地信任的失效几乎从不是"网络被攻破"，而是"同一网段"这个物理事实被当成了一种资格。 mDNS/Bonjour 里那行服务名、SMB 共享列表里那台设备、UPnP 里"我可以给你开一个端口"的那句应答、captive portal 里那个强制门户——它们全部由对端自述、全部无签名、全部由系统自动采信，而且全部在你还没决定要不要信任之前就已经完成了采信。
  • 三层切分：N1 发现与宣告层（谁在网段里说了什么，以及"说了"为什么等于"算数"）；N2 挂载与自动连接层（系统替你做的六个不需要你点头的动作：加入设备列表、自动连接、打开门户、拉起协议栈、建立对等路由、把本地地址写进上层会话）；N3 边界与撤销层（"本地网络"权限的真实半径、它管不到的部分、以及关掉之后已经发生的部分）。风险密度在 N1，因为那里没有任何身份机制；不可逆点在 N2，因为自动动作不产生可回滚的事务。
  • 一条方法论结论，也是第十八个系统性漏检：用 #66 的隐私面板、#103 的出口与证书清点、#123 的协议可达性表去做局域网审计，全都会漏掉这一族。原因是同一个：那三份清单审计的单位是"我的流量往哪里去、被谁解析"，而本族的伤害单位是"我在这一秒被谁看见、我对谁可达"——这两件事在系统里没有同一个可查对象。 iOS 上没有一张表告诉你"此刻这个网段里有哪些设备把你列进了它的清单"，也没有一张表告诉你"你设备上自动挂载/自动连接了哪些本地目标"。本篇需要的是第十八个补丁：一份"网段信任台账"——每个常用网络里，谁可宣告成你的名字、你可以自动连到哪些目标、这些目标由谁治理。这份台账和设备端一样，只能手写。
  • 后果上它给出第十九种不提权的伤害形状：以网段名义作出的自动信任。 没有漏洞、没有提权、没有任何校验被绕过：你连上一个合法存在的 Wi-Fi，系统按契约完成了一次合法发现。与其它十八种形状的分界要写死：#142 的判决由别人的判据作出、#143 的身份由一次物理干预改变、#144 的失控发生在交付之后，本族的条件更靠前——它发生在"连上"的那一秒，而"连上"这个动作在 iOS 上不需要理由也不需要告知。 这也是为什么本族的处置重心不在网络设置，而在"哪些网段值得被记住"这一条选择上。
  • 撤销不对称在本族第十三次成立（#107）：关闭"本地网络"权限、忘记这个 Wi-Fi、关掉 Wi-Fi，全部只对未来生效。已经公告出去的本地主机名与设备名、已经建立的自动连接、已经被门户页拉起的那次会话、已经写进对端日志的 MAC 与主机名，没有任何一条开关能够追回。#131 的"显示即属主"在本族第六次成立：你在"其他设备／可用设备"列表里看到的一行名字，与那个名字实际指向的一台机器，不是同一个东西——在这个协议里，名字由被看见的那一方自己填写。
  • 正向结论只有一句：把"连上网络"重新定义成"进入一个信任域"，然后在连上之前决定这个域值不值得被记住。 具体动作只有三类，且全部当场可验证：用网络的性质决定连不连（能不能承受被这个网段里的任何人看见）；用权限档位决定谁能进来（本地网络权限逐 App 关到最小）；用忘记网络决定哪些域留在设备上（记住的每一个 Wi-Fi 都是一个未来会自动复发的信任域）。

2. 这根竖条补的是哪一块

系列里已经有多篇擦到过网络：#103 测绘了网络出口与传输信任层（流量往哪走、谁签发了根证书），#123 测绘了网络协议栈实现层（报文到达那瞬被解析到哪一层，其中 R2 明确点到"同链路广播"），#72/#26 测绘了基带与无线固件（无线电那一侧的执行域），#121 测绘了配件与有线连接（到达即握手），#129 测绘了蜂窝订阅与号码身份，#131 测绘了标识与呈现（名字与对象分离），#132 测绘了凭证与会话，#144 测绘了内容外发到别人设备上（其中"投屏设备名可被自述"就是本族的一个具体症状）。

但这些位置都缺同一格："在同一链路上"这件事本身是一种什么样的信任授予，以及它在 iOS 上以哪些形式在无人点击的情况下被兑现。 #123 讲的是字节被解析（内容层），本篇讲的是身份被采信（信任层）；#103 讲的是出口（我信任谁替我转发），本篇讲的是入口（谁可以对我宣告）；#144 讲的是内容交到别人手上，本篇讲的是在交出去之前，那台机器就已经通过了一次不需要理由的自我介绍。

这是第三十根竖条，位置在 iOS 内部与外部的交界处（本地链路层），但它造成的可见性缺口是协议口径的：系统按"App + 权限"暴露风险，而本族的最小风险单位是"一次链路加入 + 一个网段的宣告面"，两者不同尺度。

与相邻各篇的分界必须写死：

  • 与 #123（协议栈）：那一篇的对象是报文内容与解析深度（缺陷密度在 L2/L3 解析器）；本篇的对象是宣告与采信（缺陷密度在"没有任何身份机制"这一契约层）。分界线：本篇不讨论解析缺陷、内存破坏与协议模糊测试；同一个 mDNS 报文，#123 问"解析器会不会崩"，本篇问"解析完之后系统为什么相信它"。
  • 与 #103（出口与传输信任）：那一篇的信任授予是显式安装的（描述文件、根证书、配置好的代理与 VPN），撤销者是你或 IT；本篇的信任授予是隐式发生的，撤销者只有物理位置——你离开这个网段，或者它离开。
  • 与 #72（基带与无线）：那一篇的边界是无线电固件的执行域；本篇完全在上层，不涉及 AP/基站侧实现。唯一的接口是 #72 的 R 分类中"同链路可达"那一档，本篇给的是那一档里的信任语义。
  • 与 #121（配件与有线）：那一篇的到达是你插上的（有物理动作、有授权弹窗）；本篇的到达是你走进去的（无动作、无弹窗）。这条差别正是本族的特殊性：没有意图表达的信任授予，就不会有意图记录可供事后审计。
  • 与 #131（标识与呈现）：#131 的"名字与对象分离"在本族是协议级事实而不是 UI 选择：本地服务名由宣告方自填、无签名、可随时改。本篇是 #131 那一律在本系列里最硬的一次落地。
  • 与 #132（凭证与会话）：那一篇讲验证之后存续的能力；本篇讲验证之前就已经建立的可达性——本地链路信任往往是"凭证之外的第二套准入"。
  • 与 #144（内容外发）：那一篇的接收端名字不可证真，其不可证真的原因由本篇给出：发现协议里没有属主这一概念。

3. 三层切分：宣告、自动采信、边界

3.1 N1 发现与宣告层——网段里没有"身份"这个字段

本地服务发现的全部机制共享同一个设计前提：宣告方说自己是什么，就是什么。

宣告类型谁在说说了什么有没有签名你设备上的表现
mDNS／Bonjour 服务公告网段内任意设备服务类型＋自填的实例名＋主机名＋端口无"其他设备""打印""家庭"列表里那行字
主机名与设备名广播任意设备一台机器的名字（常含用户名、型号）无名字出现在你面前，成为选路依据（→ #144 M2）
SSDP／UPnP 设备公告路由器、电视、打印机、摄像头"我是媒体服务器""我可以为你映射端口"无系统/App 自动拉取设备描述 XML
SMB／AFP 浏览列表网段内文件服务共享目录名与描述通常无（域内才有）文件 App"网络位置"、播放器设备树
Wi-Fi 热点与门户任意 APSSID＋强制门户页无（开放网络）自动弹出的登录页、 captive portal 检测
蓝牙可发现与配对提示任意周边设备设备名（自填）配对才有密钥，发现没有弹窗里的名字（→ #121 相邻但方向不同）
点对点本地路由（隔空投送、就近协同）附近设备由账户或本机名推导的显示名部分有可达对象集合被自动扩大

四条结论：第一，"发现"与"认证"是两个阶段，而 iOS 上你只看得见后一个阶段的界面。 列表在你决定之前就生成了，生成列表这件事本身不需要对端证明任何东西。第二，宣告里最有价值的字段恰恰是免费的：设备名经常泄露"谁的设备"（人名、公司、部门）、SSDP 的描述 XML 经常泄露型号与固件版本——这两条合起来就是 #95 意义上的指纹，但在本族它不需要任何请求，只需要你连上。 第三，名字可被任意改写且改写不留记录，这是 §10 第一条误解的根源。第四，N1 里没有任何一格可以由你关闭到零：关闭"本地网络"权限管的是 App 能不能发现，不是设备本身在不在网段里宣告——这两件事经常被混为一谈。

3.2 N2 挂载与自动采信层——六个不需要你点头的动作

自动动作触发条件界面提示后果
自动加入记住的网络走到范围内状态栏一个图标一次完整的信任域进入，无人决策
自动连接开放／弱防护网络命中"自动加入公开热点"类策略常无出口与本地两侧同时不受你控制（本地侧归本篇）
拉起强制门户页系统探测到需登录一个页面，可关闭页面内容完全由网段决定；它是少数"内容由陌生人提供、却在系统级界面渲染"的通路
抓取本地设备描述服务公告出现无型号、固件、能力集被写入设备本地状态与 App 缓存
建立本地对等通路同一账户／附近／同网段弱#144 的剪贴板跨设备、#134 的本地唤醒在此有了传输层
自动挂载／重连网络位置曾经成功连接过无上次的凭据会被用于这次——而对端身份不在重连的校验项里

三条结论：第一，本族真正的失效点在最后一行：自动重连校验的是"这个网络名/这条链路还在"，不校验"这个网络还是那个网络"。这是全系列"名字与对象分离"在传输层的唯一落地形式，也是 SSID 克隆这一类手法的攻击面所在（本篇只描述该结构性缺口，不提供任何实现路径）。第二，这些动作都不产生事务：没有"取消挂载"这一说，因为你从来没有主动挂载过——这正是 N2 不可逆的原因：无法回滚一个从未被承诺过的动作。 第三，"提示存在"与"提示有效"是两件事：门户页可以显示任何文字，自动连接可以连进任何同名网络，因此界面上的确认信息在本族的证据价值接近于零（#131 在本族第六次成立的准确形态）。

3.3 N3 边界与撤销层——"本地网络"权限的真实半径

你以为它管它实际管它管不到
"这个 App 能不能访问局域网"该 App 主动发起的本地网络连接系统服务自己的发现与公告；你被别人看见这件事
关掉就"断开本地"一个调用面已缓存的设备清单、已建立的会话、已公告出去的主机名
忘记网络＝离开信任域未来的自动加入对方日志里已经留下的你的标识
关掉 Wi-Fi＝安全传输通路蓝牙侧发现（另属 #121）、蜂窝下的本地可达（另属 #129）
私有地址＝匿名每次联网换一个 IPv6 临时地址本地主机名、mDNS 实例名、SSDP 里的设备描述——这些不靠 IP 也照样说清你是谁

三条结论：第一，"本地网络"权限是 App 侧的调用闸门，不是网段侧的信任边界——这是本族最普遍的一项误读，也是第十八个系统性漏检的确切机制：审计的人查了权限面板，就以为审计完了本地风险。第二，本族的暴露是双向的：你能看到谁（读权限面板可以答），以及谁能看到你（iOS 上没有对应视图）。第三，唯一真正的撤销是物理离开，而"离开"在自动化意义上极弱——因为你记住的每一个网络都会在下次回到范围内时自动恢复整套信任。风险密度在 N1，不可逆点在 N2，可处置面在 N3 的"忘记网络"这一格，这是本篇的结构结论。

4. 八个核对点（全部可当场在本机验证）

#核对什么怎么看判读
P1我记住了哪些网络设置 → 无线局域网 → 已知网络（逐条，含"自动加入"状态）每一条都是一个未来会自动复发的信任域；列表长度就是历史暴露的半径
P2哪些 App 能进我的局域网设置 → 隐私与安全性 → 本地网络全开＝文件类、投屏类、HomeKit 类、播放类 App 都能自主抓取本地设备；逐个按最小化
P3我的设备在这个网段里怎么被叫设置 → 通用 → 关于本机 → 名称，并对照任意"其他设备"列表这个名字会随每次公告出去；含真实姓名／工号／车牌即为可识别暴露
P4有没有在自动开门是否开着"自动加入公开热点"类策略、是否允许未确认的网络切换任意为真＝连上哪个网段不由你决定，N2 整层对你失效
P5门户页出现过没有回忆/检查近期被强制弹出的登录页，以及当时在里面输过什么在门户页输入的任何内容，接收方是那个网段本身（不是运营商、不是 Apple）
P6文件 App 里有没有旧的网络位置文件 App → 浏览 → 网络位置，逐条删除不再使用的这是本族最容易清干净的一格，且清掉之后能当场验证（列表变空）
P7家庭／打印里的设备清单家庭 App、设置里的打印机、播放器的设备树每一项都是一次"曾经采信过某个宣告"的存量记录；离开的设备要删
P8私有地址与限用共享状态Wi-Fi 详情里"私有 Wi-Fi 地址"是否开、是否对特定网络固定关闭＝跨网段可被关联；对某个具体网络长期关闭＝该网络可以稳定认出你

判定顺序建议：先 P1 与 P4（决定"我在不在无意识状态里换信任域"），再 P3 与 P8（决定"别人能认出我认到什么程度"），再 P2/P6/P7（App 侧与存量清理），最后 P5（唯一一条需要回忆、无法自动检测的）。 P5 是本族唯一一个"只能靠事前习惯、事后无从举证"的格子——与 #139 的 C7、#144 的 P4 同构。

5. 存续表

动作关掉权限之后忘记网络之后离开网段之后
mDNS 公告（我 → 网段）不停（系统级）停停，但回来即恢复
设备清单缓存（网段 → 我）App 侧新读取被拒部分随网络配置清除仍在，直到手动清
网络位置／挂载不影响需要单独在文件 App 删不影响记录存在
强制门户会话不影响凭证不自动清会话按超时存续
对方日志中的主机名与地址无法撤回无法撤回无法撤回，且永久
已建立的本地对等通路视 App 实现常停停
打印机／家庭设备登记不影响不影响不影响——必须手动删除
蓝牙可发现与配对不影响（另属 #121）不影响需要手动关闭或取消配对

三条结论：第一，本族的存续记录大量落在"设备上的登记项"而不是"当前的连接状态"，所以只看"我现在连的是什么"会系统性低估暴露面——你以为已经离开的网络，通过一条打印机登记继续持有你的能力。第二，"离开网段"是一种撤销，但它是所有撤销里最弱的一种：它不删任何东西，而 P1 里那一条条已知网络保证了它会自动重新发生。第三，唯一彻底的是"忘记 + 手动清登记"这一组合，这也是 §10 把清单形式定为"逐条删除而不是逐条检查"的原因。

6. 七类契约违背

  • M1 可达即认识。 链路可达被当成"这台设备与这次联网属于同一个世界"。协议上没有"网段属主"这一概念，所以任何在同一广播域里的宣告都会被平等地列进同一张表——包括那张表本来是给你看的。
  • M2 宣告即真实。 服务名、实例名、设备描述由宣告方自填，采信方不做任何核验。这不是实现缺陷，这是发现协议的设计前提：它优化的是"零配置"，代价是"零身份"。
  • M3 记住即同意。 一次成功连接被当作对未来所有同名链路的授权。系统记得的是名字，校验的也是名字，而名字不属于任何一个属主。
  • M4 同名即同物。 SSID、设备名、共享名都是可重用的字符串；"这个网络"在设备上从来没有一个跨会话稳定的身份标识，所以"回到同一个网络"这句话在本族没有一个可被验证的对应物。
  • M5 门户即服务方。 强制门户页出现在系统级界面里，用户据此把它读成"网络方提供的官方页面"。渲染位置提供了权威感，而内容来源完全由那个网段决定——这是本族里由界面层级制造信任的最纯粹的一例（与 #131 的"显示即属主"直接同构）。
  • M6 关权限即关风险。 "本地网络"权限被读成"我的设备是否暴露于局域网"。它管的是 App 的出站调用，不管设备自身的被看见面，也不管系统级存量登记。
  • M7 失败即信息。 连接失败、门户不跳、找不到设备、挂载超时——这些失败把"你在这个网段、你在找什么、你的型号与固件是什么"完整交付给对端。这是"失败即信息"在本系列的第十五次成立（#138 第八、#139 第九、#140 第十、#141 第十一、#142 第十二、#143 第十三、#144 第十四之后）。

其中 M1、M2、M3、M4、M6 不是软件缺陷：可达性由广播域决定、宣告由协议设计决定、记忆由"零配置"这一产品目标决定、重名由字符串的可重用性决定、权限半径由 API 分层决定。按 #93 的分层，这五格归 L1（架构与契约层）——"更新到最新系统"对它们全部无效，因为把它们改掉的代价是把"连上就能用"这一核心价值改掉。M5 归 L3（交互与认知层），可以用习惯收敛；M7 归 L2，取决于对端与协议实现。本篇是 L1 占比最高的一篇（七格中五格），这也是它处置重心必须落在"选网络"而不是"改设置"的结构原因。

7. 后果落点（接 #91 的后果轴）

  • C1 被识别：设备名＋主机名＋设备描述里的型号与固件，构成一个不需要任何权限、不需要任何请求的静态画像。这个画像在你就绪之前就已经交付完毕。
  • C2 被定位到物理位置：能认出你的设备，就等于确认你在这个网段、这个房间、这个时刻。这是 #95 的追踪在本族的空间版本——它精确到"哪一栋哪一层"，而不是"哪一天"。
  • C3 能力被扩大：曾经登记的打印机、家庭设备、网络位置在离开后仍然持有连接与凭据。受损的不是数据，是"未来的通路"。
  • C4 凭证落入陌生属主：门户页输入、SMB 账号、"此网络受信任"的点击——这些凭证的接收方是那个网段本身，通常没有法人、没有审计、没有保留策略。
  • C5 组织侧的合规与举证后果：在受监管环境里，一台设备自动连入未登记网段并按本地信任交换数据，可能已经构成一次未申报的数据出口；而设备端没有能证明"这一秒它连的是哪个网段"的历史记录。本族在失能轴上的具体形态是"连上"这件事不留时间线，所以无法自证"我那时并不在那个网络里"。
  • C6 判定污染（本族不新增该格的成立次数）：#137/#138/#140/#142 已把这一格计到位；本篇只提供它的本地来源——对端日志里那个自填的设备名与临时地址，会成为别人台账与风控记录里"你"的名字，而这个字符串由宣告方决定，也可能由伪造方决定。
  • C7 关系与信任后果：一次"我连的那个网段把内容播给了整间屋子"或"那个门户页显示了我公司的名字"之后，人对公共网络的默认信任会永久下调。这一格伤害的不是数据，是"零配置"这一便利本身的可持续度。

第十九种不提权的伤害形状就是 C1＋C2 的合成：以网段名义作出的自动信任。 不需要恶意存在也可以成立——大多数情况下被宣告出去的设备名与型号只是被"看见"了，没有被利用；但这一族的特殊性恰恰在于：条件由物理邻近决定，所以它的发生频率远高于任何需要交互的形状。 与其它十八种形状的分界要写死：#144 需要一次你的交付、#142 需要一次别人的判决、#143 需要一次物理干预，本族只需要你走进一个房间。 处置重心因此只能落在"记住哪些网络"这一条选择上。

8. 审计法与判定式

8.1 个人三步（十分钟内可完成）

  1. 清历史：把 P1 的已知网络逐条审一遍——凡是不能回答"这个网络是谁的、我为什么还要自动连它"的，一律忘记；把 P6 的网络位置、P7 的打印与家庭设备清单里已离开的目标逐条删除。这一步是本族唯一能当场看到结果的清理。
  2. 改自述：把设备名（P3）改成一个不含姓名、工号、车牌、公司、部门的通用名。这一步的成本是一次改名，收益是切断 C1/C2 里最便宜的那一半。
  3. 分档：把网络按"允许自动加入／必须手动确认／绝不连接"三档分类，然后把 P4 的自动加入策略调到与分档一致。关键是把"公司访客网、商场、机场、酒店房间、朋友家"这几类明确归入哪一档——绝大多数人从没做过这个分类，所以默认全部落在"自动加入"。

8.2 判定式

我连上的这个名字，是一个网段，还是一个属主？这个属主有没有义务不在别人面前宣告我的名字？

三个衍生问句：

  • 如果这个网段里的任何人都能看见我的设备名和型号，我能接受吗？——不能接受，就把这类网络归入"必须手动确认"。
  • 我在这个网络里输过的账号，未来会不会被另一个人用同一个网络名收到？——会（M3/M4），所以受监管的数据不走这类通路。
  • 一年之后这个网络还留在我设备上什么？——答案应该是"什么都没有"，而验证它只需要看 P1/P6/P7 三张清单。

8.3 组织侧五个动作

  1. 网段分域：把访客、员工、设备（IoT）、管理四类本地流量在 VLAN 上分开——本族唯一真正有效的组织侧缓解是缩小广播域，因为 M1 是契约层的，无法靠提示解决。
  2. 禁无身份本地服务：SSDP/UPnP 端口映射、无密码 SMB 共享在有替代方案时一律关闭；对确实需要的场景用命名与固定地址登记，让"那台设备"至少可核对。
  3. 门户策略：强制门户不收集任何可识别个人身份的输入，保留期与目的成文；并在员工告知里明确写"门户页的接收方是本网段运营方"——这一句是 C4 唯一可对冲处。
  4. 设备命名规范：统一改名规则（禁真实姓名与工号），把 P3 从个人习惯升级为组织策略。
  5. 已知网络策略：MDM 侧对"自动加入公开热点""允许未确认网络切换"给出显式配置而不是留默认，并把"忘记网络"纳入离职与设备回收清单（接 #120）。

8.4 高危个体（接 #108）

对记者、维权者、跨境差旅与谈判参与人，本篇的风险模型要更严：任何公共网段都按"里面有人在监听宣告、也有人在克隆名字"来假设；任何设备名都按"会被记录并与地址关联"来准备。 具体做法是三条：高危场合用不带本机名的设备名；不进入不登记的网段；到敏感现场前主动忘记历史网络，回来后重新逐条加。 这三条听起来麻烦，但它们的本质是把 M3"记住即同意"重新变成"每次都同意"——那是本篇唯一能对抗结构性缺陷的手段。

9. 设备端可观测性——本篇的诚实边界

能核对的：已知网络列表与其自动加入状态（P1）；本地网络权限的逐 App 档位（P2）；本机对外宣告的名字（P3）；自动加入策略（P4）；文件 App 的网络位置存量（P6）；打印与家庭设备登记（P7）；私有地址开关（P8）。

核对不到的，且永久核对不到：

  • 谁此刻能看见我——iOS 上不存在"入站可达性"视图，这是本族与全系列其它任何一篇最大的差别：其它缺口是"看不清对方"，本族是"看不到自己被别人看"。
  • 这个网段里还有哪些设备在宣告、它们自填了什么；
  • 上一次连的那个名字，与这一次连的这个名字，在系统里是否曾经是同一个物理网络（M4 的直接后果）；
  • 门户页的提供方是谁、留存多久；
  • 任何"我曾经在某网段暴露过什么"的时间线——它不存在，所以 C5 的举证失能无法用日志对冲。

必须写死的三句：

  1. 本族的审计对象有一半在网段里，不在设备上，因此第十八个补丁"网段信任台账"只能手写：由网络名称、地点、责任方、你的分档四列构成。
  2. "设备端看不到入站"不等于"入站不存在"；对处置而言，唯一稳妥的应对同一条：不要把不能在广播域里说出口的名字、账号与内容带进这个网段。
  3. 改名、忘记网络、清登记这三件事的效果可以当场验证；"我在这个网段被认出的难度"这一最终指标不能当场验证——请把它记成习惯而不是记成结论。

10. 加固清单（按当场可验证排序）

10.1 个人（七项）

  1. 改掉设备名：设置 → 通用 → 关于本机 → 名称，去掉真实姓名、工号、车牌、部门（成本一次，收益永久）。
  2. 逐条清已知网络：只留你真的会回去并且答得出属主的；其余忘记。这一条是本族性价比最高的动作，因为它同时消掉 M3 与 M4 的未来效力。
  3. 关掉自动加入开放网络，把"是否切换到更优网络"这类自动决定看清并显式化。
  4. 本地网络权限按最小化逐 App 关：不播本地音乐、不投屏、不连本地设备的 App 一律关到无。
  5. 不在门户页输入任何可复用凭证：需要账号的网络，要么改用蜂窝，要么用一次性／专用账号（接 #110 的多身份轴）。
  6. 删除已离开的登记：文件 App 网络位置、打印机、家庭设备、播放器设备树——按"这个目标我还指得出人吗"判删。
  7. 公共与差旅场合开私有 Wi-Fi 地址，并避免长期对某一固定网络关闭它。

10.2 组织（五项）

  1. 广播域分 VLAN／分 SSID，访客与员工与设备三类物理或逻辑隔离。
  2. 无身份本地服务（UPnP 映射、无密码共享）默认禁用；必要项进设备台账并固定命名。
  3. 门户页策略成文：不收集身份、明确告知接收方、保留期与销毁责任人。
  4. 设备命名规范＋已知网络清理纳入入职/离职流程（与 #120 的交接清单合并）。
  5. 把"你连的网络是谁的"这一问句写进安全培训的固定题面——本族没有面板可查，所以唯一可持续的控制是让人每次自己回答一次。

10.3 高危个体

在 10.1 之外再加三条：敏感现场不携带存有已知网络的主设备；到敏感地点前主动忘记、事后逐条重加；对外宣告的名字按"会被归档三年"来起。 高危场景的默认档位应该是"必须手动确认"而不是"自动加入"——因为本篇的 M3 只在无人决策时生效，把决策点交回给人就是把它关掉。

11. 十条常见误解

  1. "关了'本地网络'权限，局域网攻击面就没了。"——那是 App 的出站调用闸门；设备自身的宣告、系统级发现与存量登记都不在它管辖内（M6）。
  2. "列表里的名字就是那台设备。"——名字由被看见的一方自填，无签名、可随手改（M2）。
  3. "连上过一次的网络安全可靠。"——系统校验的是名字，不是身份；同名不等于同物（M3/M4）。
  4. "门户页是官方页面，因为它在系统界面里弹出来。"——渲染位置提供权威感，内容来源完全由那个网段决定（M5）。
  5. "换了私有地址就匿名的。"——设备名、主机名与 SSDP 描述照样说清你是谁（P3/P8）。
  6. "开蓝牙才是风险，Wi-Fi 本地没什么。"——两条通路各自独立；本篇管的是链路侧，蓝牙侧在 #121。
  7. "离开那个网络就没痕迹了。"——对方日志里的名字与地址不随你离开而消失（§5 第四行）。
  8. "打印机、家庭设备留着没关系。"——它们是"未来的通路"型存续记录，删除才是唯一收敛（C3）。
  9. "发现连接失败说明网络很安全。"——失败反馈本身就是交付出去的信息（M7，第十五次成立）。
  10. "这是网络管理员的事。"——本族唯一完全归你的两格是记住哪些网络与叫什么名字，两格都不需要任何权限即可执行。

12. 与既有各篇的接口

  • #123（协议栈）：同一批报文，两篇问的问题不同——那一篇管解析深度，本篇管采信语义；#123 的 R2"同链路广播"在本篇得到它的信任层解释。
  • #103（出口与传输信任）：那一篇的授予是显式安装、由你或 IT 撤销；本篇的授予是隐式发生、只能由物理离开与手动清理处置。
  • #131（标识与呈现）：M2/M5 是 #131 两律在本地链路上的最硬落地；"显示即属主"在本族第六次成立。
  • #144（内容外发）：那一篇"接收端名字不可证真"的原因由本篇 N1 给出。
  • #121（配件与有线）：同为"到达即建立"，差别在本族无意图表达、因此无意图记录。
  • #132（凭证与会话）：本地链路信任往往是凭证之外的第二套准入；门户与 SMB 凭证的归属问题落在本篇 C4。
  • #95（追踪与指纹）：本族给出其空间版本——不需要请求、不需要权限的静态画像交付。
  • #110（多身份与落点）：门户页专用账号、命名分档都直接引用其架构轴。
  • #120（离职与交接）：已知网络与登记项清理应是同一张清单。
  • #107／#91／#93：撤销不对称第十三次成立；后果轴与缺陷分层——本篇七格中五格归 L1，是全系列 L1 密度最高的一篇。
  • #146（下篇预告）：本篇的"上一次连的是什么"依赖一个时间线，而这个时间线在 iOS 上恰恰不存在——时间戳与顺序基准的可信度问题将由 #146 单独测绘。

13. 总结

本篇把第三十根竖条——连上网络之后系统替你相信的那部分——测绘成表：N1 发现与宣告（风险密度所在，因为协议里根本没有身份字段）、N2 挂载与自动采信（不可逆点，因为自动动作不产生可回滚的事务）、N3 边界与撤销（可处置面只有"忘记网络"与"改名"两格）。三个不可回避的结论是：这一族的入口不是缺陷而是零配置这一产品目标本身——M1 可达即认识、M2 宣告即真实、M3 记住即同意、M4 同名即同物、M6 关权限即关风险五格全部按 #93 归 L1，把它们改掉等于放弃"连上就能用"，所以它们不会通过更新消失；这一族的伤害形状是以网段名义作出的自动信任，它与其它所有形状的分界在于条件由物理邻近决定，不需要你做任何事；以及这一族的处置第一次以清理历史与改变自称为主，因为设备端既看不到入站，也留不下时间线。

它还给出一个必须写死的判断：本系列此前所有的可见性缺口都是"看不清对方"，本篇是唯一一个"看不见自己被看"。 你能查谁可被你访问，你无法查谁可看见你——这两件事在系统里不对称，而不对称的那一侧恰恰是暴露发生的那一侧。所以第十八个补丁"网段信任台账"必须由人手工维护：每一张网段的名称、地点、责任方与你的分档，写在你自己的纸上，不写在设备上。

它与此前各篇构成一条完整的链条：#142 问谁在替你的设备作判决，#143 问修一次之后身份还是不是原来那个，#144 问你把内容交到了谁的治理之下，本篇（#145）问你连上的那个名字背后有没有一个属主。 四篇合起来说的是同一件事的四个层次：判决的主体、身份的载体、副本的归属、以及信任的来源——iOS 只在这四层里替你管理"你设备上那一份"，而本系列的伤害从来发生在"别人手上、别人网里、别人名下"那一份。
