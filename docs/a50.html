Coruna 与 DarkSword 水坑投递基础设施与目标识别机制

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Amnesty International、Lookout、GitHub Security Lab、公开 CVE 情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

投递（Delivery） 是全链条攻击中唯一必须与目标发生接触的环节，也因此是攻击者暴露风险最高、防御者最易观察的一环。漏洞在设备内部、内存操作在系统内部，但"把目标引到一个页面"这件事必然发生在公共网络空间。

Coruna 与 DarkSword 均以水坑攻击（Watering Hole Attack） 为主要投递方式，但在基础设施构建与目标识别精度上呈现明显差异：

  • Coruna：大规模水坑网络 + 精细目标筛选 + 分层载荷交付，倾向于覆盖大量潜在访客后精准命中
  • DarkSword：小规模定向投递 + 极简探测 + 一次性交付，倾向于低噪声单点触达

本文从站点获取路径、注入方式、基础设施层级、目标识别算法、投递规避、以及防御者的观测点六个方面展开分析。

2. 水坑攻击的结构

2.1 基本模型

        目标人群                     攻击者关注点
    ┌────────────────┐
    │ 记者 / 活动人士 │
    │ 特定机构员工    │──→ 他们共同访问哪些网站？
    │ 某会议参会者    │
    └────────────────┘
             ↓
    ┌────────────────────┐
    │  选择承载站点       │  ← 高信任度、目标必访
    │  (行业协会/媒体/论坛)│
    └────────────────────┘
             ↓
    ┌────────────────────┐
    │  植入恶意脚本       │  ← 入侵 CMS / 供应链 / DNS / 中间层
    └────────────────────┘
             ↓
    ┌────────────────────┐
    │  访客环境探测       │  ← 版本/地区/身份筛选
    └────────────────────┘
             ↓
    ┌────────────────────┐
    │  命中者加载利用链   │  ← 仅对合格目标返回 exploit
    └────────────────────┘

核心逻辑：水坑的价值不在于流量规模，而在于流量纯度——一个只有 200 名访客但全部是目标人群的行业论坛，价值远高于 10 万泛流量的新闻站。

2.2 为什么 iOS 攻击偏爱水坑

原因说明
WebKit 攻击面成熟历史漏洞储备最丰富的入口
无需安装任何软件访问即触发，无需用户下载
可跨平台筛选同一页面能区分 iOS/Android/Windows 访客，只投 iOS
可拒绝非目标对安全研究人员/爬虫返回干净页面，降低暴露
投递成本低一个被入侵站点可持续产出多次入侵
归因困难站点所有者往往不知情，攻击路径不直接指向委托方

3. 承载站点的获取路径

攻击者"控制"一个页面的方式有多种，检测与防御手段也各异。

3.1 路径一：直接入侵站点

手法说明特征
CMS 漏洞利用WordPress/Joomla 等插件漏洞恶意代码常注入主题/插件 PHP 文件
凭证窃取/爆破管理员账号弱口令、FTP 凭证泄露后门文件常伪装为模板/上传目录资源
已知 webshell 复用使用被兜售的既有后门隐蔽性依赖站点本身长期被入侵

防御信号：文件完整性监控（FIM）、CMS 更新日志、异常管理员登录。

3.2 路径二：第三方供应链注入

这是影响面最大的路径——恶意代码来自站点引用的第三方资源。

注入点说明现实案例类型
统计/分析脚本访客分析、A/B 测试脚本被篡改Magecart 类，水坑也复用
广告网络通过广告位投递恶意脚本，可精准定向恶意广告（Malvertising）
CDN 上的公共库被劫持或被替换的 JS 库版本依赖投毒
嵌入组件聊天、支付、地图小部件单一供应商影响上千站点

攻击者偏好：广告与统计脚本可按国家/设备/时段定向投放，天然具备目标筛选能力，是低成本水坑的首选。

防御信号：SRI 校验、CSP、第三方脚本哈希白名单、渲染结果比对。

3.3 路径三：网络中间层注入

手法说明现状
HTTP（非 HTTPS）改写运营商/公共 Wi-Fi 网关向明文页面注入脚本HTTPS 普及后已少见
强制门户（Captive Portal）公共 Wi-Fi 登录页被篡改会议/机场场景风险
DNS 劫持域名解析指向恶意 IP需配合证书伪造，难度高
透明代理/中间设备企业网关、家路由固件被植入供应链攻击路径

关键限制：HSTS 与 HTTPS 普及大幅抬高了这条路径的成本，但路由器固件层面的注入仍可行——这也是国家级攻击者的优势区。

3.4 路径四：自建站点（"合法外观"水坑）

攻击者直接建设看似可信的站点引导目标访问：

形式说明
仿冒组织网站克隆目标所在机构的公开站点
议题诱饵站围绕目标关心的话题（如某地区政治事件）建站
会议/活动页伪造会议注册页，通过邮件邀请目标访问
shortened URL 引导通过短信/邮件缩短链接隐藏真实域

优点：完全掌控，可反复修改 exploit 逻辑，不受第三方站点方影响。

缺点：需要额外的社会工程把目标引过来，转化率低于寄生式水坑。

4. 基础设施层级设计

4.1 三层基础设施模型

成熟水坑攻击通常把"承载页面"与"利用代码"分离：

第 1 层：承载层（Hosting Layer）
        └─ 被入侵的合法站点 / 第三方脚本
           只包含极小的探测代码，无 exploit 内容
                    ↓ 探测结果上报
第 2 层：决策层（Gate / Triage）
        └─ 攻击者控制的判定服务器
           评估是否投递，返回"是/否 + 链标识"
                    ↓ 命中后拉取
第 3 层：载荷层（Payload Distribution）
        └─ 实际 exploit 代码 + 后续模块
           按目标版本动态返回对应链条

分离的价值：

价值说明
静态抓取只拿到探测层安全研究员/爬虫访问时看不到 exploit
exploit 可热更新换链不需重新入侵站点
精准计数决策层掌握"多少人探测/多少人命中"
降低暴露承载层无恶意内容，站点方自查难以发现

4.2 Coruna 的基础设施特征

特征说明
多域名分层探测域名、决策域名、载荷域名分离，互不复用
云 + VPS 混合中转使用知名云（混入合法流量），载荷使用小众 VPS
合法证书使用 Let's Encrypt 或商业 CA，避免证书告警
UA/指纹白名单已知安全厂商出口 IP、爬虫 UA、研究环境特征 → 返回干净页面
长周期投放一个水坑可持续运营数月，多目标逐步命中

4.3 DarkSword 的基础设施特征

特征说明
更少层级探测与利用更接近，减少往返延迟（适配短会话）
DGA 域名载荷/通信域名按算法生成，生命周期极短
CDN 使用部分投递路径借助 CDN 边缘节点隐藏源站
单次交付为主命中后一次返回所需全部内容，减少后续请求次数

5. 目标识别机制（Targeting）

这是水坑攻击最被低估、也最具防御价值的技术环节。攻击者必须知道"该把 exploit 给谁"。

5.1 识别维度全景

类别信号采集方式
平台iOS / Android / Windowsnavigator.userAgent、平台特性
iOS 版本13–18.x 具体版本UA 中的 OS 字段
设备型号iPhone X / 13 / 15，iPadUA、屏幕参数、devicePixelRatio
芯片代际决定是否启用 PAC型号间接推断 + 特性探测
JIT 可用性判断锁定模式尝试触发 JIT 编译并计时/检查行为
语言/地区navigator.languages、时区JS 标准 API
网络环境在线/离线、蜂窝/Wi-Finavigator.onLine、连接类型 API
访问上下文document.referrer判断从哪来（邮件/某平台）
行为特征停留时长、滚动、交互真人 vs 爬虫判定
历史访客本地存储 / Cookie / 指纹避免对同一人反复触发
身份线索表单填写、登录状态、URL 参数站点自身数据被读取

5.2 分层筛选逻辑（典型实现）

访客到达
  │
  ├─[1] 非 iOS？ → 返回正常页面（不浪费资源、不暴露）
  │
  ├─[2] 已知安全厂商 / 爬虫 IP 段？ → 返回正常页面
  │
  ├─[3] 无头浏览器 / 自动化特征？ → 返回正常页面
  │     (WebDriver 标志、缺失插件、时间精度异常、
  │      WebGL 渲染器为软件实现、屏幕尺寸异常)
  │
  ├─[4] 已重复访问过多？ → 返回正常页面（避免诱导怀疑）
  │
  ├─[5] 启用锁定模式？ → 中止（保护零日，避免在无收益场景消耗）
  │
  ├─[6] iOS 版本不在任一链条覆盖范围？ → 返回正常页面
  │
  ├─[7] 地区/语言/时区不匹配目标画像？ → 返回正常页面
  │
  └─[8] 全部匹配 → 加载对应版本的利用链

关键点：绝大多数访客在第 8 步之前就被拒绝。这解释了为什么水坑页面在研究员访问时"看起来完全正常"——不是没被入侵，而是攻击者不认为研究员是目标。

5.3 目标识别的运营含义

现象解释
"我访问那个网站没有异常"你可能不匹配目标画像，攻击者主动对你隐藏
"同一站点在不同设备表现不同"版本/地区筛选的直接证据
"站点被入侵数月无人发现"极低触发率 + 无恶意静态内容
"研究员拿到的是残缺样本"探测层被捕获，载荷层未下发

对防御者的重要提醒："访问站点未见异常"不能证明站点干净。 需要按目标画像（含未升级 iOS 设备）复现，或从网络侧观测载荷下发行为。

5.4 Coruna 与 DarkSword 的识别精度对比

维度CorunaDarkSword
版本判定精细，映射到 5 条链精细，单链窄窗口
锁定模式检测有，检测到即中止有
反爬虫/反研究员强（IP 段、行为、UA 白名单）中（依赖短生命周期）
地域筛选有（多客户场景需要）有，更偏向单目标
重复访问控制有弱（会话短，重投递本身即预期）
探测阶段可观测性多层请求，较易发现单层，较隐蔽

6. 社会工程辅助层

水坑的技术注入之外，往往还需要把目标引到页面上：

手法说明
定向邮件/私信邀请访问"会议议程""请愿书""新闻调查"页面
社交话题诱导在目标关注的社群发布看似相关的链接
搜索引擎投毒SEO 优化使伪造页面在目标搜索词中靠前
合法内容夹带在真实新闻/报告中嵌入引用链接（含恶意站点）
日程/日历邀请日历项中的会议链接指向水坑

Coruna 类长期运营更依赖寄生式水坑（不需主动引导，目标自然会来）。

DarkSword 类定向投递更可能结合主动引导（短窗口内需确保目标访问）。

7. 投递规避与反检测

7.1 内容层规避

手段说明
无恶意静态内容承载页只含探测代码，扫描器找不到 exploit 签名
加密/编码的探测逻辑字符串与 API 名称混淆，规避语义检测
动态构造通过多层 eval/Function 构造，避免静态可搜索
短生命周期载荷域名存活数小时至数天

7.2 传输层规避

手段说明
合法证书不触发证书告警
常见端口全部走 443，混入 HTTPS 主流
CDN 前置隐藏源站真实 IP，抗封锁
请求伪装载荷下载伪装为普通 JS/JSON 资源请求

7.3 触发层规避

手段说明
条件触发需满足"iOS + 特定版本 + 特定地区"才下发
一次性触发同一访客/同一设备指纹只投递一次，避免重复暴露
交互依赖要求真实滚动/点击/停留，防止自动抓取
时间窗仅在特定时段（如目标工作时间）激活

8. 防御与检测

8.1 站点方（如果你是潜在水坑承载者）

措施作用
Content-Security-Policy限制可执行脚本来源，阻断第三方注入生效
Subresource Integrity (SRI)固定第三方脚本哈希，被篡改即拒绝执行
文件完整性监控（FIM）发现被植入的后门文件
第三方脚本资产清单明确每个脚本的供应商、权限、更新渠道
管理员凭证加固禁用弱口令、开启 MFA、审计登录
CMS/插件及时更新消除最常见入侵入口
渲染结果基线比对定时用"目标画像"复现访问，对比返回内容差异
出站请求监控页面是否加载了白名单外的域名
强制 HTTPS + HSTS阻断中间层明文注入

8.2 组织/网络侧

检测点方法
条件化内容证据同一 URL 对不同 UA/参数返回不同响应 → 服务端做目标筛选
探测型请求序列页面加载后仅上报少量数据、不加载资源
二段式加载探测后数秒内出现新的脚本域名请求
短生命周期域名大量域名生命周期 < 7 天且高熵
新注册域名命中注册龄 < 30 天的域名被 iOS 设备解析

8.3 个人侧

措施说明
及时升级 iOS版本筛选环节直接判定"不投递"
启用锁定模式检测环节触发攻击中止
对议题诱饵保持怀疑水坑高度依赖目标兴趣点，"正好是你关心的话题"本身就是信号
避免不明缩短链接无法预判真实域名
公共 Wi-Fi 谨慎中间层注入风险区

8.4 高价值技巧：用"目标画像"复现取证

对怀疑被水坑的站点，安全团队应按目标画像构造访问环境：

  • 使用未升级的老版本 iOS 真机（研究员的 iPhone 通常是最新版 → 攻击者不投递）
  • 从目标所在地区/时区/语言的出口访问
  • 保持真实浏览行为（滚动、停留、点击）
  • 记录完整 HAR、所有请求域名、响应体差异

这一步往往是从"页面看起来正常"到"拿到完整链条"的分水岭。

9. 总结

结论内容
1. 投递是最脆弱的一环攻击者能控制设备内的所有事情，但必须把目标引到一个公网可观测的页面
2. 分层是核心设计承载层无恶意内容、决策层筛选、载荷层动态下发——这使"抓取页面"不足以取证
3. 目标识别是主要伪装攻击者对 99% 的访客显示为正常网站；"访问无异常"不等于"站点干净"
4. 供应链注入影响面最大广告与统计脚本天然具备定向能力，一个供应商被攻破可波及上千站点
5. 修补 + 锁定模式打击筛选逻辑攻击者在探测阶段就会放弃已修补/受保护的访客，这是最高性价比的防御
6. 复现需要扮演目标用老版本真机与目标地区环境访问，是获取有效样本的关键方法

给防御者的一句话建议：

不要问"这个网站有没有恶意代码"，而要问"如果我是一个未升级的、符合目标画像的访客，这个网站会给我什么"。水坑攻击的本质是条件化内容分发，防御观测必须重建触发条件。
