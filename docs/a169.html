Coruna 与 DarkSword 场景下的监管报送与行业共享：报给谁、报什么、以及共享本身带来的新暴露

1. 执行摘要

  • 这一篇处理同一个事实的两种去向：报送（向主管部门，义务驱动、有法定时限）与共享（向同业、CERT、行业组织，自愿驱动、有边界）。前二十篇把"对谁说"写到了 #151（受影响人、外部、监管的沟通义务），但没有一篇处理报送之后那份材料本身的命运：它被谁保存、被谁再分发、被谁与什么合并——而这份材料的价值，对攻击方而言不低于 #157 那份名单。
  • 核心命题一：报送与共享是两种行为，混用会同时违反两边的规则。 用共享的宽松去处理报送，会漏掉法定的时限与内容；用报送的名义去共享，会让你把一份本该只给监管方的材料递给同业。二者的共同点是：都以"事实"为原料，因此原料的写法决定了后面所有环节。
  • 核心命题二：报送材料里最危险的不是技术细节，是身份与关联。 一份写着"某公司于某日被定向投递，影响某部门三名员工"的报送，对攻击方的价值是：确认命中、确认你已知、确认你的响应阶段（#154 的 S0–S5）。因此报送的最小事实集必须只回答义务要求的问题，而不是把 #147 的十项记录表原样附上。
  • 核心命题三：共享的价值集中在指标（IOC），风险却在上下文。 一条域名、一个哈希、一条规则，去标识化后价值仍然完整；而"这条指标来自哪个受害者、何时出现、影响了哪些账户"——这三句话才是让指标变得可用的部分，也是让接收方（乃至泄露后的任何一方）能反向定位你的部分。共享指标，不共享出处，是本篇给出的第一条纪律。
  • 核心命题四：去标识化不是一次操作，是一条链条。 单条记录去标识不等于合并后不可识别（#128 的"数据跟着索引走"在共享场景的复现）：三条分别脱敏的记录，合并起来往往重新指向唯一一家机构。因此共享前必须问的是"这批材料合并后能不能唯一指向我们"，而不是"这条里有没有写名字"。
  • 一句正向结论：把报送与共享当成两个独立的产品来做：报送求"符合义务且不超出"，共享求"可用且不可回溯"。二者的共同底座是你已经写好的三栏陈述（#151 的已知/推断/未知），因为它同时满足"不漏报"与"不夸大"。

2. 这一篇补哪一格

#151 处理的是沟通的方向与内容：对内、对受影响的人、对外（含监管）三向，B1/B2/B3 三级触发，W1 可行动通知 / W2 事实说明 / W3 归因陈述三类不得混写，十二个通知字段与八个治理字段。那一篇解决"说什么"，本篇解决"送出去之后"。

#149 处理的是你被告知的窗口，其中第 10 节"组织侧告知回流六要素"已经指出：员工收到的提示是观测数据。本篇把它推一步——你报送出去的材料也是别人的观测数据，而它会在很长一段时间里被存档、被比对、被引用。

#161 处理指标的生命周期，#162 处理服务商协作，#157 处理名单保密。本篇与这三篇构成"情报的出口侧"：你手里的东西一旦离开，就同时变成别人的资产与你的负债。

3. 两条独立的流水线

维度报送（义务侧）共享（自愿侧）
驱动法定义务、合同义务、监管要求互惠、行业惯例、自我保护
时限由规则决定，通常自"知悉"起算，分初步与最终由你决定，可以是事后数周
内容必须覆盖义务要求的字段；不要求的不必给由你裁剪，以"可用"为标准
接收方确定的机构与人一个群体，成员会变化
主要风险迟报、漏报、超范围提供二次暴露、再接合、被再分发
谁签有授权的人（见 #171 的签字链）安全负责人 + 法务共同确认

把它们做成一张流程图的人，通常会在事件当天犯同一个错误：把给监管的那份材料转给同业群，因为"反正已经写好了"。

4. 报送材料的最小事实集（六项）

  1. 时间线：知悉时间、发现方式、当前阶段（用 #154 的 S0–S5 表述比用"正在调查"更有信息量，也更安全）；
  2. 影响对象类别：不写姓名，写"某业务线的员工账户"这种类别；
  3. 涉及的系统类别：自建、SaaS、托管——这三类的责任人不同（#167、#159）；
  4. 已知手法的类别：只写类别与阶段，不写细节（细节属于取证材料，不属于报送）；
  5. 已采取的动作：隔离、凭据轮换、通知、监控加强——只写完成态，不写计划；
  6. 下一次更新的时间与联系人。

这六项之外的任何内容，都要能回答"义务是否要求"。 不能回答的，就不要放进去——不是隐瞒，而是范围纪律：#151 的"已知/推断/未知"三栏在这里的作用，是让你在不超范围的前提下不漏项。

5. 报送的四个坑

坑表现后果
把"不确定"写成"没有"为了报送材料的完整性，把尚未查清的部分写成"未发现异常"一旦后续证实相反，你面对的是"前后不一致"，而 #154 已证明"未发现"本身就是信息量很低的结论
把客户信息当证据打包附上原始日志、账户清单、设备标识接收方未必需要，而它一旦泄露，你无法主张"这不在我们控制范围内"
报送与对外口径不一致报送写"定向攻击"，对外写"未发现针对性证据"三处说法不一致时，最弱的那一份会代表你的全部可信度（#151 的同一条）
把"已报送"当"已处置"报送完成即内部结案#166 的结案基线包不会因为报送而缩短，复发判定也不会因此变松

6. 共享的去标识化四级

级别做法还能回答什么残留风险
L0 原样直接给材料全部只在有明确互信协议、且接收方受同等约束时可用
L1 移除直接标识去掉名称、域名、IP、账户手法、时间窗、阶段中等：时间 + 行业 + 规模三项合并常常唯一指向一家
L2 泛化行业、规模、时间都改为区间只回答"某类组织在这一时段遭遇了什么"低
L3 只留 TTP只给行为模式与检测思路（#148 的 C5 机制级以下）几乎只回答"怎么防"最低，但价值也最低

决定用哪一级的不是礼貌，是问题。 你要向同业问的是"你有没有见过这种投递节奏"，那就只需要 L2；你要问的是"这条域名你是否也见过"，那就是 L1 的指标级共享，且只给指标不给上下文。

7. 再接合：三条分别脱敏的记录如何重新指向你

设 A 记录写"某制造业组织，2026 年 10 月"，B 记录写"受影响约 40 人，涉及财务与法务"，C 记录写"攻击者使用了某类投递路径，在某个星期三"。三条单独看都无法定位；但接收方手里往往还有 #149 提到的那类公开信息（研究机构发布、平台通知、行业通报）：

只有几家企业同时满足"制造业 + 40 人 + 那个星期三有异常" ——而攻击方同样能拿到这三条。

可执行的三条防线：

  1. 时间泛化：共享用的时间统一改为月或季度，内部保留精确时间；
  2. 人次泛化：不给精确人数，给区间；
  3. 组合检查：共享前把这一批材料当成一个整体问一次"合并后是否唯一"，而不是逐条检查。

第 3 条是本篇认为最容易被跳过、而收益最高的一步，它与 #128 的方法论完全一致：风险不在单条，在合并。

8. 互惠的另一面：你也是接收方

拿到同业共享的同时，你承担了三项义务，而它们常常不在你的制度里：

  • 保护义务：对方按 L1 给你，你不能按 L0 用；材料进入你的系统后，就受你自己的保留与访问控制约束（#157 的"材料即情报"）；
  • 再分发限制：多数共享带 TLP 一类的标记（红/琥珀/绿/白），标记是约束不是注释；把一条琥珀色材料转进公开群，是最常见的一次性失信；
  • 溯源义务：当对方问"这条指标后来确认了吗"，你必须能答——这要求你在 #161 的指标生命周期里，为共享出去的指标单独留一栏。

9. 受害者二次暴露：报送与共享材料的保管

这类材料有一个反直觉的性质：它们比事件本身更容易泄露。 因为它们被存放在沟通工具、共享盘、邮件附件里——正是 #144、#152、#153 反复证明的那一层。

因此，报送与共享材料要像 #157 的名单一样管理：

控制项要求
载体单一受控位置，不用协作工具频道、不用群聊传文件
访问按人授予，事件结束后 30 天内复核并收缩
命名不写机构名与案件编号到文件名里（文件名会出现在预览、通知与截图里）
版本每次对外发送留版本号与发送记录
销毁按 #166 的留存矩阵处理，销毁留证明

10. 六个失败模式

  1. 一份材料三处用：报送、同业、客户，用同一份文档，结果各自的要求都不满足。
  2. 把"共享得多"当成"合作得好"：共享量不是信任的度量，共享的克制才是。
  3. 去标识化只看单条：合并后仍能定位，且定位结果会先出现在研究机构的报告里。
  4. 报送内容由技术写、由公关发：两个环节各改一遍，最后两边的说法不一致。
  5. 不登记共享清单：半年后没人知道"我们到底给出去过什么"。
  6. 把报送当结案：报送是义务的完成，不是风险的结束（#166 的第 7 节：结案是状态不是终点）。

11. 加固清单

个人与小团队

  • 若你被要求配合报送或共享，只提供被问到的字段，其余用"未知，可在 X 日内补充"；
  • 共享指标时只说指标与时间区间，不说来源机构与你自己的处置阶段；
  • 保留一份"我提供过什么给谁"的记录（一行一条，含日期与版本）。

组织

  • 把报送与共享拆成两条流程、两份模板、两个签字人；
  • 在模板里预置 §4 的六项与 §6 的四个级别，让每次填写不需要临场判断；
  • 建立共享台账：日期、对象、级别、内容摘要、标记、到期复核日；
  • 每年做一次再接合检查：把上一年度对外提供过的材料合并起来，看能否唯一指向本组织；
  • 把报送材料纳入 §9 的保管控制，与名单同级。

12. 八条常见误解

  1. "报送越详细越好"——详细应留给取证材料，报送只求符合义务。
  2. "同业共享是免费的帮助"——它同时是一次不可撤回的信息交付。
  3. "去掉了公司名就安全了"——时间、行业、规模三项合并足以定位。
  4. "指标共享没有风险"——指标本身低风险，但"我们见过这条指标"是高风险事实。
  5. "标记只是礼貌"——标记是可追责的分发约束。
  6. "监管会替我们保密"——保密义务在你这边同样成立，两者不互相替代。
  7. "报告写完就完事了"——报告里的每一句，都会在半年后被重新引用。
  8. "我们没有什么可共享的"——多数组织至少有一条"这类投递最近在本行业出现过"的时间信息，而那一条恰恰是最容易被反向利用的。

14. 总结

#结论
1报送和义务、共享和自愿，是两条流水线，不要让它们共用一份材料
2报送只写义务要求的六项；细节留给取证材料
3共享指标，不共享出处；出处是让指标可用、也让你暴露的部分
4去标识化要按"合并后是否唯一"来验收，而不是逐条检查
5标记（TLP 一类）是约束；再分发是最常见的一次性失信
6报送材料本身比事件更容易泄露，按名单同级保管
7"已报送"不是"已处置"，也不缩短 #166 的结案条件
8三处口径必须一致，不一致时最弱的那一份代表你

一句话总结：

报送回答"我必须让谁知道"，共享回答"我愿意让谁用来防"。 这两件事共用同一批事实，却要求完全相反的动作：前者要求不漏，后者要求不多。 把这两件事写在同一张模板上，就是在事件当天用一次忙碌换来一次长期暴露。
