iOS 人身安全与被持续控制场景：当攻击者是一个住在一起的人

本文是防御视角的清点与处置方法，不提供可利用代码，不包含任何监控他人设备、规避检测或实施控制的操作指引。面向正在被亲密关系、家人、同住者或前伴侣持续查看/定位/控制设备的人，以及需要给出建议的咨询、支援场景。文中所有动作都是"查看自己设备上的合法设置项并收回授权"。

1. 为什么这是一个独立的方向

系列里的框架全部默认对手是陌生人：#90 的 P0–P5 从远程 0-click 排到物理接触，#94 的人群画像按设备与场景划，#95 处理"我不知道谁在采集我的数据"，#97 处理"我不认识但冒充官方的人"。

被亲密关系者持续控制的场景把这些默认全部推翻：

常规假设在这一场景里
对手拿不到你的密码对手知道密码，可能是他/她替你设置的
对手需要利用漏洞对手不需要任何漏洞，用合法功能与合法流程
攻击是一次性的攻击是持续的，重点是"被发现的成本"而不是"入侵成本"
加固越严越安全加固动作本身可能被察觉，反而升级风险（这是本篇与普通加固文最大的区别）
设备是你的资产设备/账户可能是共同财产，处置涉及法律归属

一句话：这一层的攻击面不是 iOS 的实现缺陷，而是"共享的信任"没有收回机制。所以评估口径不是"有没有漏洞"，而是：谁能在不接触我设备的情况下看到我在哪里、我在和谁说话、我买了什么。

对照 #89 的结论"损失范围由密钥与账户治理决定"——在这里同样的结构成立，只是主语从"银行"换成了"另一个人"。

2. 五类合法 foothold（先清点，再决定动不动）

按"撤销难度"排序，不是按危害排序。每一项都只写在哪里看、怎么收回。

① 账户层（最难处理，影响最大）

  • Apple ID 是谁注册的：如果当初由对方协助注册、恢复邮箱/手机号是对方的，那么对方在任何设备上都能通过"忘记密码"重新拿到你的全部数据（iCloud 备份、钥匙串、照片、信息，见 #69/#74）。这一条优先于所有设备侧加固。
  • 双重验证的接收方：核对受信任电话号码与设备清单（设置 → 你的姓名）。只要验证码落在对方手里，改密码无效。
  • 家庭共享：组织者能看成员的购买与订阅记录；屏幕使用时间的家庭组织能看成员的活动汇总（内容取决于设置粒度）。
  • 订阅与付款方式：默认付款方式、家庭共享的订阅，都会在账单通知里暴露消费与购买（与 #89 同源）。

收回顺序不能倒：先把验证因子换成只有自己掌握的 → 再换密码 → 再核对设备清单 → 最后才是改设置项。反过来做，对方一次重置就回到原状。

② 定位与"查找"层

  • 查找网络里的位置共享对象清单（家人、朋友）。
  • 自己的设备是否出现在别人的"查找"里（设备被标记为家庭共享设备）。
  • 未知物品提醒：iOS 会提示疑似跟随的未知配件（AirTag 类）。收到提示时先记录时间、地点与提示内容截图，再按提示中的流程查看与处置。
  • 照片的地理元数据与共享相簿、iCloud 照片图库（共享图库成员能看到你新拍的照片及位置）。

这一层最容易在换新设备后自动恢复：只要登录同一个 Apple ID，共享关系与设备清单会跟过来（#96 的残留表在这里逐字适用：关系不会因为你换手机而消失）。

③ 设备与配置层

  • 设备清单里的旧设备：对方仍在使用的旧 iPhone/iPad/Mac 会持续同步信息、照片、密码。
  • 描述文件与设备管理（设置 → 通用 → VPN 与设备管理）：任何非本人安装的配置都应记录来源（#67/#86）。企业托管/MDM 场景下，可见性与限制策略由注册方下发。
  • 屏幕使用时间：对方若掌握屏幕使用时间密码，就能远程设置通信与联系人限制、查看部分活动汇总，且该密码独立于设备密码。
  • 锁屏可访问内容：通知预览、控制中心、"查找"、医疗卡、SOS 页面在锁屏下是否可见（#84 的四态矩阵在这里是操作口径而不是取证口径）。
  • 密码本身：如果对方知道解锁密码，前面所有加固都是零。面容/触控里是否有不认识的重叠或替代外观（#84 专门讨论过）。

④ 通信与内容层

  • 信息的"文本消息转发"到其他设备、同一 Apple ID 在 iPad/Mac 上自动接收（#71/#69）。
  • 共享的邮箱账户与日历订阅：订阅的日历会把行程写在对方设备上。
  • 备份：iCloud 备份内容随账户走；一旦账户共享，备份等于镜像（#74）。
  • 剪贴板接力、Handoff（#69）：在同一个账户与同一网络下，你复制的内容可能出现在另一台设备上。

⑤ 应用与第三方层

  • 被要求安装的"防丢/查找/家庭安全"类 App，很多具备位置、通信或活动上报能力（#86/#95 的滥用生态）。
  • 通过第三方账户（共同账号、共享会员、代付）产生的可见性——这类不在 iOS 里，只能在对应服务的账户设置里收回。

3. 清点表：一次做完约 40 分钟

建议按顺序勾，每项写"有 / 无 / 不确定"。"不确定"本身要保留，不要为了清零而乱动。

#核对项位置若为"有"的处置
1受信任手机号/恢复邮箱设置 → 你的姓名 → 登录与安全换成只有你控制的号码与邮箱（第 ① 优先）
2设备清单同上页底部移除不认识的与对方在用的旧设备
3家庭共享组织者与成员设置 → 你的姓名 → 家人共享退出/移除，订阅账单逐个核对
4屏幕使用时间密码与设备配对设置 → 屏幕使用时间改为自己掌握；解除"通过另一台设备管理"
5位置共享对象查找 → 人员逐个取消；核对"查找我的 iPhone"设备归属
6共享相簿/共享图库照片退出共享；核对新照片是否仍被看到
7信息转发与多设备接收设置 → 信息关闭转发；退出不属于自己的其他设备上的信息
8描述文件与设备管理设置 → 通用 → VPN 与设备管理记录来源后移除；企业托管需走管理方
9锁屏可见内容设置 → 面容 ID 与密码 / 通知关闭锁屏通知预览、控制中心、"查找"等
10未知配件提醒设置 → 隐私与安全检查；查找记录提醒的日期/位置/内容
11密码与生物识别面容 ID 与密码更换密码；核查是否有不认识的替代外观
12三方账户与代付各服务自身设置分离账户、取消代付与共享会员

4. 与普通加固最大的不同：顺序里包含"不察觉"约束

#80 与 #95 的建议是"发现异常立刻收紧"。在这一场景里，"立刻、集中、一次性"往往是最危险的：所有设置同时改变，等于通知对方"我在检查"。

因此本篇只给原则，不给固定时间表：

  1. 先做不可逆性最低的动作（查看、记录、截图、抄下设备清单里的型号与名称），把收回类动作留到你判断安全的时点。
  2. 收回顺序按危害排：验证因子与账户 > 定位共享 > 设备清单 > 配置与描述文件 > 通知与外观类设置。前两项才是决定"能不能被重新拿到"的。
  3. 改完不再回到旧账户：如果最终方案是新建 Apple ID，绝不能从旧设备恢复备份到新账户——备份里带着共享关系、密码与历史（#96 接手设备流程的反向适用）。
  4. 保留证据优先于清除痕迹：与 #92 的结论一致——远程抹除会把证据一起灭失。若涉及事件处置、保护令或诉讼，先固化（截图、原始通知、时间线记录），并考虑把副本放在你独占控制的账户或线下位置。
  5. 共同财产与法律归属：设备/账户可能是共同财产，擅自转移在部分司法辖区会产生法律后果。本篇不构成法律意见；涉及此类问题先咨询当地专业渠道或支援机构。

5. 三种处境下的最小方案

处境目标只做这三件事
仍同住、无法让对方失去访问降低可见性，不触发对抗① 锁屏通知预览与控制中心关掉；② 密码换掉并确保只有你知道；③ 最敏感的一段通信搬到只有你控制的账户/设备上
准备离开 / 正在办理保住证据与账户主权① 验证因子换成独占（号码、恢复邮箱）；② 位置共享与设备清单清点并记录；③ 证据固化到独占存储，不要抹除设备
已经分开，但持续被定位/骚扰断链 + 可举证的记录① 全量清点（第 3 节 12 项）；② 新建独立 Apple ID 并不恢复旧备份（新设备从空状态设置）；③ 保留每一次提醒与消息的时间线，走平台举报与法律渠道

高危个体的一条硬原则，与 #89/#94 完全同构：最敏感的信息不要落在这台可能被对方合法访问的设备上。设备加固做到 90 分，也挡不住"对方知道密码"或"账户是他/她注册的"。

6. 六个常见误解

误解事实
"换一台新 iPhone 就断了"登录同一 Apple ID 后，共享关系、设备清单、备份内容全部跟过来（#96）
"改了密码就安全了"若恢复邮箱/受信任号码仍在对方手里，重置一次即回到原状（第 ① 项）
"关闭定位服务就够了"查找网络、共享相簿、日历订阅、家庭共享购买记录是四条独立通路，各要单独收
"对方装不了监控软件"多数可见性来自合法功能与合法授权，不需要任何恶意 App（这正是 #83/#89 那句结论的重演）
"先远程抹除设备最保险"涉及证据时抹除会连带灭失你自己的举证材料（#92 的顺序原则）
"把所有异常一次清掉最干净"集中变更本身就是信号；第 4 节的顺序约束是为了让你能安全地做完

7. 一句话结论

这一场景的评估口径要换掉：不问"iOS 有没有漏洞"，只问"有哪些授权是当年给出去的、现在还能不能收回、由谁收回"。

  • 90% 的可见性来自账户与关系层，不来自设备层：先验证因子，再谈加固。
  • 清点表（12 项）一次约 40 分钟，先记录、后收回，收回顺序按危害排。
  • 若涉及新设备：从空状态设置，不恢复旧备份。
  • 若涉及处置或法律程序：证据先于清除，并咨询当地专业渠道；本文不构成法律意见。

设备侧维持 #80/#84/#95 的既有结论即可。真正需要动手的是账户与关系这一层——而且它需要在你判断安全的时点动手。
