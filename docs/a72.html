iOS 基带与无线固件攻击面：蜂窝、Wi-Fi、蓝牙链上的远程边界分析

编制日期：2026-10-24 数据来源：Apple Platform Security 与无线/基带更新文档、Google Project Zero、Citizen Lab 关于远程植入的公开分析、Black Hat / USENIX 关于基带固件安全与 OTA 更新机制的公开研究、CVE 情报库 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

基带是 iOS 设备上最独立的攻击面：它有自己的处理器、自己的实时操作系统、自己的固件与更新通道，并且在设备锁屏、系统未解锁、甚至主系统看似关机时仍然处于活动状态（蜂窝注册本身要求它持续收发网络信令）。历史上"通过无线电远程植入"这一命题几乎全部落在这类并行处理器上。

四条结论：

  1. 基带不是主处理器上的一个驱动，而是一个并行信任域：它通常可以直接访问主内存（DMA），因此"基带→主机"是一条天然存在的边界穿越路径，与 #64 讨论的启动链信任域同构，但方向相反。
  2. 无线攻击面有三类不同性质的入口：协议信令解析（网络侧下发的信令，可来自伪基站）、空口基带处理（物理层实现缺陷）、以及帧格式解析（短信/PDU、彩信、Wi-Fi/BT 帧）。其中前两类无需目标任何交互，也不需要互联网连接。
  3. 因此基带风险的"0-click"程度高于本文系列里任何一条软件通路：它的成本不依赖漏洞库存（伪基站/自有频谱设备），依赖的是实现质量，而这部分的公开审计与补丁响应 historically 远弱于主系统。
  4. 对防御方，可行的控制只有四类：及时更新（含基带固件）、关闭不必要的高层无线能力、把"基带可读主内存"这条路径用硬件隔离收紧（Apple Silicon 侧的 DMA 保护与 SPTM 类机制，见 #64）、以及对高危目标的物理层措施（无线电静默/专用屏蔽环境）。

              ↑ 边界穿越方向（防御重点）

应用处理器系统整体iOS 软件更新—是高（日志、崩溃、工件）

结构性判断：可观测性从左到右递减，攻击者的操作空间递增。基带与无线固件是整台设备上"证据最少、审计最少、公开漏洞研究也最少"的区域——这不代表它们没有缺陷，只代表我们不知道（与 #62 的"未发现≠未感染"纪律同源，此处用于架构而非个案）。

3. 入口分类与前置成本

入口攻击者位置目标是否需要动作需要互联网？覆盖半径现实门槛
R1 网络信令（核心网侧）运营商铺设点 / 伪基站否否蜂窝覆盖区高（频谱设备 + 协议知识）
R2 空口实现（L1/L2）近场无线电否否数十米—数百米高（SDR + 固件逆向）
R3 高层格式解析（SMS/PDU、MMS）短信网关否（送达即解析）否（走蜂窝）任意有信号处中
R4 Wi-Fi 帧/管理帧解析近场 AP/客户端多数否（扫描即处理）否局域中
R5 蓝牙发现与配对协议近场部分否（发现阶段）否局域中（与 #71 的自动预览属同一"处理早于决策"逻辑）
R6 基带→主机边界穿越已取得基带代码执行否否—极高（需两步能力）

成本对比（与 #49 的原语升阶梯一致）：R1/R2 不需要任何"目标点击"，也不需要拥有互联网侧基础设施，因此在归因上极难——目标设备上没有可指向攻击者域名的工件（这与 #47 的 JA4/SNI 检测、#63 的狩猎剧本形成直接对照：这类路径根本不走 IP 出站）。

4. 与主系统攻击链的关系

链条形态说明与软件链的区别
C1 基带独立驻留载荷只存在于基带固件/内存，主机侧无进程主机取证几乎看不到；重启/系统更新才可能清除（#45、#64）
C2 基带→主机注入经共享内存/DMA 触发主机侧代码执行起点在沙箱之外，#52/#68 的沙箱语义对其无意义
C3 主机→基带（反向）已提权代码改写/滥用基带能力用于隐蔽外发（蜂窝承载）与抗清除
C4 与推送/消息通路混合无线层负责送达与唤醒，软件层负责落地与 #65、#71 的"送达即处理"叠加

C1 的防御含义最重要：如果驻留在基带固件里，那么"重装系统""恢复出厂"这类主机侧清洗动作不一定清除它——清除依赖基带固件被重新刷写。这是为什么对高危目标要把"完整系统更新（含基带固件版本变化）"与"备份恢复"当作不同动作来对待（也与 #70 的工件灭失讨论对应：基带侧没有工件可供验证）。

5. 可观测性与检测：诚实的能力边界

检测手段能否覆盖无线侧说明
设备侧流量/DNS 指标（#47、#63）不能（R1/R2 不走 IP）无出站即无指纹
崩溃群体基线（#63 HUNT-04）间接仅当缺陷造成主机侧可观测崩溃
备份工件（#70、#62）不能基带侧不产出用户态工件
蜂窝注册异常统计（终端射频日志）部分需专用工具与解锁态，覆盖有限
网络侧（运营商/伪基站检测）可行但外部需独立频谱监测能力，非设备方能做
固件版本一致性核对可行比对上报的基带版本与应然版本（MDM 可采集部分字段，#67）
行为侧异常（无主机进程却有数据活动）部分与 #65/#69 的时间线矛盾模板同构

结论：基带攻击面在设备方几乎不可检测。防御预算因此应集中于三处——补丁与固件版本一致性、能力关闭（不需要的无线电功能）、以及对极少数高危角色的物理层与流程控制。任何声称"可通过日志发现基带植入"的方案都应要求对方说明证据来源。

8. 总结

#结论
1基带是独立处理器 + 独立固件 + 独立更新通道的并行信任域，不是主系统的一个驱动
2无线侧入口 R1–R3 不需要目标任何动作，也不需要互联网连接，覆盖半径由频谱决定
3这类路径不产生 IP 出站，因此基于流量与 DNS 的检测体系对它们完全无效
4若载荷驻留在基带固件，恢复出厂不必然清除，覆盖它的是"含固件版本的完整更新"
5基带可观测性极低，防御应从"检测"转向"能力关闭 + 版本一致性 + 物理层控制"
6与软件链相比，无线链的归因难度更高，因此在事件评估里应单列一类而非并入 APT 软件画像
7对绝大多数用户，及时更新与关闭不必要射频能力已覆盖现实风险；无线植入假设仅适用于极少数高危角色

一句话总结：Coruna 与 DarkSword 这类链条争夺的是把主机侧软件缺陷串成完整入侵的能力，而基带与无线固件是 iOS 上唯一"不需要经过主机、也不需要经过互联网"的攻击面——它的防御代价因此完全不同：不是补丁纪律与锁定模式就够，而是要接受"这一层我们基本看不见"，并据此把控制放在固件更新一致性、射频能力关闭和物理层措施上。
