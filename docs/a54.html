Coruna 与 DarkSword 模块化载荷编排与插件体系

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Lookout、Amnesty International、ESET、公开 CVE 情报 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

一款能在 iOS 上完成"逃逸 + 提权"的利用套件，只解决了如何进入；真正产生持续威胁的是进入之后做什么、如何组织这些能力。这就是载荷架构（Payload Architecture） 要解决的问题。

Coruna 与 DarkSword 在载荷架构上的差异，是理解两者战术定位的关键：

  • Coruna：分层插件体系——小型引导器 + 按需下发的功能模块 + 任务队列 + 本地状态，本质是一个"可扩展运行时"
  • DarkSword：一次性单体执行流——所有能力在一次会话中构建、执行、销毁，无模块仓库、无任务队列

本文从分层模型、模块生命周期、任务编排、模块保护与分发、状态管理、可扩展性六个维度解析两套体系，并说明"为什么模块化是现代商业间谍软件的核心竞争力"。

2. 载荷架构的分层模型

2.1 通用分层

┌──────────────────────────────────────────────┐
│ L0 引导层（Bootstrap / Loader）                │
│    极小体积、最低依赖；提权后首先建立执行环境      │
├──────────────────────────────────────────────┤
│ L1 核心运行时（Core Runtime）                  │
│    模块加载器、任务调度、加密、日志、自保护         │
├──────────────────────────────────────────────┤
│ L2 通信层（C2 Transport）                      │
│    心跳、指令接收、重试、多通道                   │
├──────────────────────────────────────────────┤
│ L3 功能模块（Capabilities / Plugins）           │
│    采集/监控/定位/凭证/文件/音频/持久化…           │
├──────────────────────────────────────────────┤
│ L4 数据管道（Data Pipeline）                    │
│    序列化、压缩、加密、分片、外传、清理            │
└──────────────────────────────────────────────┘

2.2 为什么要分层

动机说明
降低初始落地体积引导层小，被捕获的信息价值低
能力解耦修改采集逻辑不影响通信层，可独立更新
按需加载只加载当前任务所需模块，减少内存驻留与特征面
版本适配不同 iOS 版本加载不同实现，上层逻辑不变
多客户复用同一运行时 + 不同模块集 = 不同产品形态
失效隔离单模块崩溃不必然导致整体失陷

这正是"exploit-as-a-service"商业模式的技术基础：模块化让一套系统能服务多个客户、多个任务场景，摊薄极高的漏洞研发成本。

3. Coruna 的模块化架构

3.1 引导层设计

特征说明
极小入口提权完成后仅建立最小执行能力，不携带完整功能
环境探测采集设备/版本/权限信息，决定后续加载哪套模块
运行时解包从 C2 拉取加密模块包，在内存/落地位置解包
失败降级探测到环境不支持某模块则跳过该能力，不中止整体

3.2 模块清单与调度

Coruna 采用任务队列 + 模块清单的经典 implant 模式：

[Module Manifest]  ─ 描述可用模块、版本、依赖、能力
       ↓
[Task Queue]       ─ C2 下发的待执行任务（含参数、条件、优先级）
       ↓
[Scheduler]        ─ 判断条件是否满足（解锁态/充电/网络类型/时间窗）
       ↓
[Module Loader]    ─ 按需加载并执行模块
       ↓
[Data Pipeline]    ─ 结果进入外传管道

任务条件表达（典型设计）：

条件类型示例
时间指定时段执行（配合目标作息，降低异常时段流量）
状态设备解锁 / 锁屏 / 充电中
网络仅在 Wi-Fi 下执行大流量外传
事件触发特定 App 启动、特定联系人消息到达
依赖前置模块已成功（如已取得 keychain 权限）

3.3 典型模块集

根据 Citizen Lab / Lookout 公开分析，Coruna 类套件的模块集合通常包括：

模块类别能力
消息采集SMS/iMessage/第三方 IM 数据库读取与增量同步
通讯录/日历联系人、日程批量导出
凭证提取Keychain 批量导出（详见本仓库 #53）
媒体采集照片库、视频、录音文件批量外传
实时监听麦克风激活、通话音频
位置跟踪GPS/基站/Wi-Fi 定位，可周期性上报
App 活动前台 App、浏览历史、输入行为
设备控制截屏、开启相机、静默拍照
加密资产钱包种子、交易所凭证
持久化启动项写入、更新检查
自保护环境检测、反分析、清除

3.4 模块分发与更新

机制说明
增量更新只下发变更模块，减少流量与暴露
版本协商引导层报告当前模块版本，C2 决定下发内容
按目标定制不同目标加载不同模块集（最小必要原则，降低单点损失）
热替换运行中可替换模块，无需重新植入

4. DarkSword 的一次性执行架构

4.1 无模块仓库的设计

DarkSword 由于放弃持久化，其载荷架构呈现完全不同的形态：

[水坑页面下发全部所需代码/参数]
        ↓
[逃逸 + 提权（内存中）]
        ↓
[一次性任务包解析]  ← 任务清单在会话开始时全部下发
        ↓
[内存中构建能力例程] ← 不加载"模块文件"，而是构造可执行逻辑
        ↓
[顺序执行采集]      ← 无调度器、无条件等待（时间受限）
        ↓
[打包 → 外传 → 清除]
缺失的组件原因
模块清单 / 仓库无持久化存储位置，也无法长期维护版本
任务队列会话时长不允许排队等待条件满足
调度器无后台常驻，无"稍后执行"的可能
增量更新每次会话从零开始，不存在"已安装模块"状态

4.2 "能力内联"取代"模块加载"

DarkSword 的工程取向是把能力内联进单一流水线：

设计选择说明
精简功能集只做小体积高价值采集（凭证、token、密钥、近期消息）
无长周期监听放弃实时麦克风/持续定位这类需要常驻的能力
一次批量执行所有采集顺序完成，不分次调度
参数由页面下发C2 地址、任务清单、加密密钥都在页面下发时确定

4.3 架构带来的能力上限

无法做到原因
持续监控无常驻
事件触发采集无调度器
大文件批量外传会话时长与稳定性限制
等待解锁窗口无持久化，不能"等明天"
多轮任务迭代每次需重新完整走一遍链条

但换来的收益也很明确：

收益说明
几乎无设备侧痕迹无模块文件、无清单、无状态
无需维护植入状态不追踪"哪些模块已安装"
重启后无残留天然反取证
单点失败影响小不存在"整套 implant 被提取分析"的风险

5. 架构对比

5.1 组件级对比

组件CorunaDarkSword
引导层✅ 独立小型 loader⚠️ 融合在利用链中
核心运行时✅ 常驻❌ 会话内临时构建
模块清单✅❌
任务队列✅❌（一次性任务包）
条件调度器✅❌
模块热加载✅⚠️ 仅会话内
状态持久化✅❌
增量更新✅❌
数据管道✅ 多通道分片✅ 单次批量
自保护模块✅✅（更依赖无痕）

5.2 能力矩阵

能力CorunaDarkSword
长期驻留监控✅❌
事件触发采集✅❌
大批量数据外传✅❌
实时音频/定位✅❌
跨重启存活✅❌
按需定制模块集✅⚠️ 靠任务包参数
文件痕迹中极低
备份可捕获✅ 可发现❌ 不可发现
单次任务完成速度慢（可分多次）快（必须一次）
目标适配灵活度高低

5.3 设计哲学对照

Coruna      = "在设备上建立一个可扩展的小型操作系统"
              → 能力强、覆盖广、痕迹多、需要运营投入

DarkSword   = "一次内存中的突击行动"
              → 精准、隐蔽、能力受限、成本在重新投递

两者都合理，取决于任务定义——这是本系列反复出现的权衡主线。

6. 模块保护与反分析

6.1 分层加密

载荷架构中，模块本身需要被保护：

环节保护手段
传输TLS + 载荷层额外 AES/ChaCha20
静态（Coruna 落地时）模块文件加密存储，运行时解密
内存中关键代码段延迟解密，缩短明文驻留时间
完整性模块签名/哈希校验，防被篡改或降级
混淆符号剥离、控制流平坦化、字符串加密

6.2 模块间 ABI 设计

现代 implant 通常定义内部 ABI：

每个模块导出:
  - 元信息（ID、版本、依赖列表、能力标签）
  - init(参数) → 状态句柄
  - run(句柄, 任务参数) → 结果缓冲区
  - cleanup(句柄)

攻击者收益：新模块可独立开发测试，不用重新构建整个 implant。

防御者收益：ABI 与元信息结构是相对稳定的特征来源——同一厂商不同版本的模块头结构常相似，可用于聚类归因。

6.3 反分析设计

手段说明
环境检查检测调试器、模拟器、已知分析工具特征
沙箱/虚拟化指纹CPU 特性、设备型号一致性检查
自杀逻辑检测到分析环境即中止/清除，拒绝暴露
代码完整性自检检测被 hook/插桩
按需解密静态样本中看不到完整逻辑

DarkSword 的反分析更多来自架构：不落地 ⇒ 无法静态分析。这是"无痕"最本质的价值。

7. 与其他套件的横向对照

将 Coruna/DarkSword 放入更广的载荷架构谱系中：

套件载荷架构特征
Pegasus（NSO）经典三层（KiteRisa/Carthage 等）+ 大量功能插件 + 任务队列 + 反取证模块
ForcedEntry 系列载荷极简，依赖单点突破 + 有限采集
Predator（IntelCere）强模块化，后期版本转向文件less 混合策略
Triangulation以持久化 + 固件层驻留为核心，模块化程度高
Coruna平台化多链 + 模块化采集 + 长期运营
DarkSword一次性内存执行 + 无模块体系 + 短时突击

演化趋势（重要）：

第一代：植入完整 implant + 全功能常驻（痕迹大）
    ↓
第二代：小型 loader + 按需模块加载（减少静态特征）
    ↓
第三代：能力内联 + 无持久化（消除文件特征）
    ↓
当前趋势：混合模式 — 主体无持久化 + 极小必要状态留存

这条趋势线说明：模块化并未消失，而是从"落地的模块仓库"迁移为"C2 侧的模块仓库"。攻击者的模块化能力从设备端转移到服务端，设备端越来越干净。

8. 防御与检测

8.1 针对 Coruna 类模块化架构

信号说明
异常目录中的可疑文件族模块集中存放，常伴随机/半随机命名
文件批量新增但无 App 安装记录模块热加载痕迹
启动项/Agent 异常持久化引导层
周期性的"小请求 + 偶发大上传"心跳 + 模块下发 + 数据外传模式
模块加载时的短时代码签名异常未签名/临时授权代码执行
增量同步型数据流相同数据集反复少量新增（任务队列驱动）

8.2 针对 DarkSword 类一次性架构

信号说明
匿名可执行内存页非 JIT 进程出现 PROT_EXEC 区（最强信号）
加载页面 → 数秒内新域名外连一次性突击的时间特征
短时高上行流量 + 随后完全静默采集外传后消失
mediaserverd/守护进程异常线程注入后的执行痕迹
同目标反复被触发每次重启后需重新投递 ⇒ 攻击频次高（重要行为特征）

8.3 通用架构级检测原则

原则说明
看行为序列而非单点特征模块化与一次性架构在"时间序列"上都异常
建立正常基线设备/App 正常外连频率与体量
保留网络侧证据唯一能跨越重启的证据源
优先内存/运行时取证第三代架构的主要检出方式
威胁情报关注 ABI/结构相似性用于厂商归因聚类

8.4 最有效的降维打击

措施为什么有效
每日重启直接摧毁模块化架构的"跨重启状态"，同时迫使一次性架构重新投递（增加暴露次数）
锁定模式链条到不了载荷层，模块化无从谈起
快速强制升级同上
限制设备侧存放高价值秘密载荷架构再精妙，提取不到有价值数据就是零收益

9. 总结

结论内容
1. 载荷架构决定"能拿到什么"漏洞链决定能否进入，模块化程度决定进入后的能力边界
2. 模块化是商业模式的技术基础exploit-as-a-service 需要一套运行时服务多客户多场景，非模块化架构无法支撑
3. Coruna 是"操作系统式"implant清单 + 队列 + 调度 + 热加载 + 状态，能力全面但痕迹多
4. DarkSword 是"突击行动式"载荷无模块体系、内联能力、一次完成，隐蔽性强但能力受限
5. 模块化正在从设备端迁往服务端设备端越来越干净，攻击智能越来越多留在 C2 侧下发
6. 无持久化天然偏好小体积高价值数据架构直接塑造目标选择（凭证/密钥优于照片库）
7. 重启是对两种架构都有效的低成本反制破坏 Coruna 的状态、增加 DarkSword 的投递频次

一句话总结：

载荷架构的选择，本质是在说"我要什么样的任务"。 长期全面监控 → 需要 Coruna 式模块化驻留； 精准快速取密 → DarkSword 式一次性突击更划算。 防御者应从架构特征反推任务意图——这比识别单个模块更能预测攻击者的下一步。
