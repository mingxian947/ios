Coruna 与 DarkSword 场景下的证书与签名材料：事件里最沉默、也最不可撤回的资产

1. 执行摘要

  • 设备、账号、会话都能"收回"；签名材料一旦泄露，你失去的是"未来所有产物都可信"这件事。它是事件里唯一不能在事后补救到原状的资产。
  • 核心命题一：签名材料的失守，通常不以"被黑"的形式出现。 它更常见的形式是：离职者仍持有、构建机无人看管、测试证书被当生产用、描述文件在共享盘里放了三年。
  • 核心命题二："吊销"不是无代价动作。 吊销一张证书会同时影响所有使用它的产品；因此必须区分"泄露"与"疑似"，并准备好替代路径。
  • 核心命题三：证书治理的核心是清单，而不是技术。 谁签发了什么、有效期到哪天、绑定到哪些产物、谁能吊销——四件事说不清，处置就无法开始。
  • 核心命题四：信任链是一次性的。 一旦某个中间环节被替换，之前所有"已验证通过"的记录都需要重新审视（#181 审计与认证中的历史事件陈述）。
  • 核心命题五：这件事没有"事后修好"，只有"提前设计"。 短周期证书、自动化签发、分离的签名环境，是唯一能承受事件的形态。
  • 一句话结论：把签名材料当作"高价值、低可见、不可逆"的资产单独治理，而不是附件在发布流程末尾的一个步骤。

3. 六类签名与信任材料

类别作用泄露后果撤回难度
应用签名证书证明产物来源可签发未授权产物高（影响存量）
描述文件授权在哪些设备上运行可扩大授权范围中
企业分发材料内部大规模分发可向非授权设备分发高
推送与通知密钥向你的应用发通知可伪造通知中
服务端 TLS 证书证明服务身份可冒充服务中（可轮换）
信任根与自建 CA全局信任可签发任意受信证书极高

最后一行是"事件级的核按钮"。 自建 CA 一旦泄露，唯一的补救是重新建立信任，而那意味着所有终端都需要更新——成本按用户量线性增长。

4. 清单：四张表，必须在事件之前存在

表内容更新时机
资产表证书/密钥/描述文件清单，含序列号与到期日每次签发
属主表每一项的负责人与备份保管人人员变动时
绑定表每项材料绑定到哪些产物与环境每次发布
使用记录何时、由谁、在哪个环境中被使用每次签名

第三张表是事件期最有价值的。 它把"某张证书泄露"直接转换成"以下这些产物需要重新签发"，而不需要事后反查。

5. 事件判定：泄露、疑似、滥用，三种状态

状态判定依据首要动作对外口径
泄露材料副本出现在不应出现的位置立即吊销 + 重新签发内部通报 + 受影响方告知
疑似持有环境出现异常访问或人员变动收紧访问 + 加强监控 + 准备替代暂不对外
滥用出现未授权产物或异常分发吊销 + 追查 + 版本核验按影响范围告知

"疑似"这一档经常被跳过。 实践中大量事件停在"疑似"，因为证明"泄露"需要时间，而处置又不能等；这时正确做法是准备替代并按"疑似"管理，而不是在两种极端之间摇摆。

6. 吊销的真实代价：一张影响面表

在按下吊销之前，先填完这张表：

受影响面问题若不评估的后果
存量产物已发布的包是否仍能安装/运行大面积不可用
自动更新更新链路是否依赖该证书更新中断
外部集成合作方是否依赖固定证书集成失败
用户侧操作是否需要用户手动干预支持成本激增
时间窗重新签发与验证需要多久服务中断时长失控

第五行决定了"先吊销还是先准备"。 若替代路径需要两周，而泄露是确定的，正确的顺序通常是并行推进：一边准备替代，一边收紧而不吊销，直到切换完成。

7. 阻断继续使用：四个可逆动作

  1. 收紧签发环境的访问。 立即生效、可回退、影响面小。
  2. 保留审计轨迹。 采集签发日志与使用记录，注意不要覆盖。
  3. 监控异常产物。 建立"是否有未经授权的产物出现"的观察点。
  4. 准备新材料的试用签发。 在隔离环境中验证替代证书的兼容性。

四个动作都不需要立即吊销，但都能显著降低继续失血的速度。

8. 签发环境的三条硬规则

规则内容原因
分离签名环境与开发环境物理/逻辑分离开发机的任何问题都不应影响签发
最小只有签发流程能读到私钥人越多，泄露面越大
自动短有效期 + 自动续期人工流程是过期与遗漏的主要来源

三条规则的核心是一致的：减少"人接触私钥"的次数。 任何一次人工接触，都是一次不可审计的暴露。

9. 与外部协作时的边界

  1. 鉴定机构需要材料，不等于需要私钥。 提供签名记录与产物哈希即可（#195）。
  2. 律师需要事实，不需要副本。 描述"何时发现、谁接触过"，比交出一份密钥副本更安全（#183）。
  3. 上游平台需要配合，不等于需要你的私钥。 多数吊销流程只需要标识与授权证明（#187）。

这三条的共同点：任何外部方都不应获得私钥本身。 一旦给出，就等于把"未来"也交了出去。

10. 加固清单（八条）

  1. 建四张表：资产、属主、绑定、使用记录。
  2. 分离签名环境，任何人不得在开发机上持有生产私钥。
  3. 缩短有效期，用自动化续期替代人工记忆。
  4. 定期核验绑定表，发布前自动比对。
  5. 准备替代路径：每类材料至少有一次性演练过的更换流程。
  6. 离职即轮换：接触过私钥的人员离开，按"疑似"处理。
  7. 监控异常产物：建立产物与证书的对应关系。
  8. 演练一次吊销：在非生产环境中走完全流程（#176）。

11. 八条常见误解

  1. "证书没泄露就不用管。" 未记录、未绑定、无人负责，比泄露更难查。
  2. "吊销随时可以做。" 吊销会同时影响全部存量产物。
  3. "有效期长一点省事。" 长有效期意味着泄露后的暴露窗口更长。
  4. "备份放共享盘最保险。" 那是泄露最常见的起点。
  5. "改密码就等于收回了。" 私钥文件不会随密码更改失效。
  6. "这是运维的事。" 签名材料同时是安全、发布与法律对象。
  7. "签名了就是可信的。" 签名只证明来源，不证明内容安全。
  8. "这件事没有征兆。" 人员变动、构建机异常、共享盘访问，都是可观察的前兆。

13. 总结

签名材料是唯一一类"丢了就回不到原状"的资产：设备可以重装，账号可以重建，会话可以失效，而一张泄露的私钥会永久性地削弱"你的产物可信"这件事。

可执行的原则只有三条：

  1. 清单先于技术：四张表比任何工具都重要。
  2. 缩短暴露窗口：短有效期、自动化、分离环境。
  3. 先准备再吊销：把不可逆动作放在可逆动作之后。

把签名材料从"发布流程的最后一步"提到"独立治理的高价值资产"，这篇文章的目的就达到了。
