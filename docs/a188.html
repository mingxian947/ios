Coruna 与 DarkSword 场景下的云备份与云端留存：它不是备份，是一份会被长期读取的证词

1. 执行摘要

  • 多数设备事件里，最完整的"历史"不在手机上，而在云端：备份、同步、照片库、健康数据、通讯录、设备名录。它们在用户看来是"备份"，在调查者看来是一份会自动更新、且长期保留的证词。
  • 核心命题一：云备份是"末态快照"，不是"过程记录"。 它记录"备份那一刻的状态"，不记录"它是怎么变成这个状态的"。用它证明"有什么"容易，证明"什么时候进来的"很难。
  • 核心命题二：同步与备份是两套机制，回答的问题不同。 同步回答"现在有什么"，备份回答"上次完整状态是什么"；混用会把时间线搞乱（#146 时间与顺序基准）。
  • 核心命题三：云端留存的价值在事件之前就已决定。 备份频率、保留份数、是否加密、密钥在哪里——这些设置决定了事后你能拿到多少，而它们几乎从不在事件期间被调整。
  • 核心命题四：加密在这里是双刃剑。 端到端加密保护了内容不被平台读取，同时也意味着"向平台要内容"这条路基本走不通；能走的只有"用你自己的密钥恢复"。
  • 核心命题五：处置顺序错了会毁掉证据。 先"清理备份防止再感染"、再"调查"，等于先烧掉卷宗再开始读。
  • 一句话结论：把云备份当成一份需要先固定、后解读的证据，而不是一项需要随时保持"干净"的服务。

3. 四类云端留存，各自的证据特征

类别典型形态时间分辨率主要用途主要局限
完整备份周期性设备快照天到周证明"某日状态"、找回被删数据无过程、只覆盖被备份的数据域
增量同步通讯录、日历、备忘录、健康分钟到小时证明"何时出现某条目"版本历史有限，删除后可能立即消失
媒体库照片、视频上传时刻时间与地点线索云端时间戳≠拍摄时间
设备与账号名录已登录设备、密钥、恢复方式变更即时判断是否有未授权接入只给"当前状态"，不给历史

第一行与第三行的混淆最常见。 备份里的照片时间戳是"这张照片进入备份的时刻"或"文件修改时间"，不是"拍摄时刻"；而照片的 EXIF（若未被剥离）才更接近拍摄时刻。两者可以差好几天。

4. 为什么必须"先固定、后解读"

云端留存有三个持续变化源：

  1. 自动轮转。 备份按份数轮转，旧的被覆盖；同步数据按条目覆盖，旧版本不保留。
  2. 设备继续写入。 只要设备在线，同步就会持续发生，异常条目会与正常条目混在一起。
  3. 处置动作本身。 改密码、退登录、恢复备份、抹除设备——每一个动作都可能触发云端侧的大规模变更。

因此正确顺序是：

盘点（有哪些留存） → 固定（导出/截图/记录版本） → 隔离（阻断继续写入） → 解读（比对与时间线）

"隔离"不等于"删除"。 隔离是让设备不再向云端写入（例如暂停同步、断开该设备的网络），删除是不可逆的销毁。在完成固定之前，不要做任何不可逆动作。

5. 固定动作清单：六件事，按可执行性排序

顺序动作产出注意
1导出账号侧设备与密钥名录截图当前接入状态保留时间戳
2记录备份的"最近备份时间"与"备份大小"备份存在性与频率不要立即下载全量
3暂停同步、将设备置于隔离网络阻断继续写入不关机，避免丢失内存证据
4导出可自助导出的数据域通讯录/日历/健康等记录导出时刻
5对关键条目做条目级截图版本与时间含界面时间
6若需全量，经专业意见后下载镜像副本下载过程本身可能改变状态

第五项经常被跳过。 条目级截图（某条备忘录的"最后修改"、某个联系人的"添加时间"）比全量导出更能支撑时间线，且成本低到可以在十分钟内完成。

6. 端到端加密意味着什么，不意味着什么

说法正确理解
"加密了，所以安全"只保证平台读不到；不保证持有账号凭据的人读不到
"加密了，所以查不了"内容层面基本如此；元数据层面（接入记录、设备名录）可能仍可见
"我有密钥，所以我随时能恢复"前提是密钥没被同一次入侵带走；恢复密钥的保管是本篇之外的一门功课
"开加密会丢功能"部分服务功能受限，这是取舍，不是漏洞

关键推论： 如果攻击者获得了账号凭据，端到端加密并不能阻止他把数据同步到自己的设备上——因为对系统而言那是"合法设备"。因此云端事件的判断重点，从"内容是否泄露"前移到"是否出现了新设备、新会话、新密钥"（#159）。

7. 云端留存能证明什么，不能证明什么

命题云端留存能支持吗说明
某条数据在 T 时刻存在于账号中能备份或版本记录
某条数据在 T 时刻首次出现弱只有在增量历史足够细时才成立
设备在 T 时刻被某人操作不能操作主体无法从留存中推出
某应用在 T 时刻安装了某版本弱取决于是否被备份域覆盖
存在未授权设备接入能（部分）设备名录 + 接入时间，但需账号侧配合（#187）

第三行最容易被误用。 "某账号在此时同步了某文件"不等于"某人在此时操作了设备"。把主体推断写进结论，会在复核时被直接推翻。

8. 处置中的四个常见自毁动作

  1. 先清空备份"防止再感染"。 备份是末态快照，清空后你失去了唯一的基线。
  2. 直接抹除设备并重装。 在未做设备侧固定前，这等于销毁主要证据（#158 清除判定与复机验收标准另有一层：抹除≠验收）。
  3. 立刻修改所有密码并退出所有设备。 必要，但请先截图设备名录与接入记录，再执行；否则你失去了"入侵时存在哪些设备"的事实。
  4. 在事件群里转发备份链接。 一次转发就把一份受控证据变成了不可控副本（#178）。

四个动作都出于善意，共同点是在固定之前做了不可逆操作。

9. 与外部协作时的三条纪律

  1. 交出副本，不交出原件。 给顾问（#177）或鉴定机构（#195）的材料是副本，原件与哈希清单留在自己手里。
  2. 登记每一次读取。 谁在什么时候读了哪一份，写进决策日志（#184）。
  3. 区分"用于处置"与"用于举证"。 前者可以粗，后者必须可复核；不要把两者混成一份文件（#178 的两条轨道）。

10. 加固清单（八条）

  1. 先盘点再动手：设备名录、备份时间、可导出数据域，三张清单。
  2. 固定优先于清理：任何不可逆动作之前必须有副本。
  3. 隔离不等于删除：用断网与暂停同步代替删除。
  4. 条目级截图：关键条目的修改时间比全量导出更有用。
  5. 记录一切时刻：导出时刻、截图时刻、发现时刻，标注来源与时区。
  6. 区分内容与元数据：加密影响内容，不影响（部分）元数据判断。
  7. 副本分级：处置用、举证用、对外披露用，三档分开。
  8. 定期演练：备份与恢复流程若从未演练，事件期一定出错（#176 长期能力建设与培训有效性）。

11. 八条常见误解

  1. "有备份就等于有证据。" 备份是末态，不是过程。
  2. "云端时间戳就是事件时间。" 它只是"进入云端的时间"。
  3. "端到端加密让我完全安全。" 它防平台，不防持有凭据者。
  4. "出事了先把备份删掉。" 那是最快毁掉调查的做法。
  5. "全量下载越早越好。" 下载过程本身会改变状态，且可能耗时数天。
  6. "备份里有就是设备上有。" 备份域是被选择的子集。
  7. "改密码之后就没问题了。" 未授权设备与密钥需要单独收回（#159）。
  8. "云端记录能证明是谁做的。" 只能证明"发生了什么"，不能证明"谁"。

12. 与既有各篇的接口

  • 与 #159 直接衔接：云端留存的盘点结果，就是账号侧闭环的输入。
  • 与 #187 互补：先看自己有什么，再决定向平台要什么。
  • 与 #146 对接：所有时间戳都要标注来源，不可混用。
  • 与 #158 对接：抹除与恢复的顺序，必须服从证据保全。
  • 与 #177 / #195 对接：副本交付与鉴定意见的边界。
  • 与 #176 对接：备份与恢复演练，是能力建设的固定科目。

13. 总结

云备份最容易被当成"保险"，其实它是"卷宗"：它记录的是某个时刻的状态，而不是事件的过程；它由你日常的设置决定，而不是由事件期的努力决定。

三条可执行的原则：

  1. 先固定，再隔离，最后解读。
  2. 要条目级时间，不要只做全量镜像。
  3. 内容靠密钥，元数据靠名录；两条线分开判断。

把云备份从"需要维持干净的服务"改写为"需要先固定再解读的证据"，本篇文章的目的就达到了。
