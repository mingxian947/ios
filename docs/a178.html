Coruna 与 DarkSword 场景下的调查记录：哪些材料默认"永远不会被读"

1. 执行摘要

  • 事件调查产生的东西里，报告只占很小一部分。真正决定后果的往往是那些没人打算给别人看的材料：群聊里的推测、白板照片、会议纪要里的"可能是内部人"、临时表格里未经验证的名单、顾问邮件里的半句话。本篇讨论这些记录的形态、寿命与被读到的概率。
  • 核心命题一：记录的默认读者不是你。 写的时候默认读者是自己人，读的时候可能是监管、对方律师、审计、收购方、甚至公开庭审。这个错位是所有记录风险的根源。
  • 核心命题二：事实与判断必须分开存放。 事实轨（发生了什么、依据是什么）与意见轨（我们倾向认为、可能是谁、大概损失多少）混在一份文件里，等于让意见跟着事实一起出门。
  • 核心命题三："内部讨论"不是一种法律状态。 标记"内部""机密""请勿外传"不改变它是否可被要求交出的性质；能改变性质的只有委托关系与取得方式，而这需要事前安排，事后补不了。
  • 核心命题四：记录的价值与风险同源。 写得越充分，调查越有效，同时也越可能成为对你不利的材料。解法不是少写，是分层写、分层存、分层授权。
  • 核心命题五：删除不是解法，是加重情节。 事件后的记录销毁，几乎总会被发现（备份、对方留存的副本、邮件服务器、协作工具的版本历史），且会改变别人对你全部结论的信任。
  • 一句话结论：把每一条记录写成"如果明天被陌生人读到，它是否仍然准确、克制、可解释"的样子。

2. 这一篇补哪一格

#177 处理请谁进来、授权到哪。本篇处理他们和你写下来的东西——委托关系决定了部分材料能否获得保护，记录纪律决定了剩下的材料是否经得起被读。

#164 处理访谈怎么做：见谁、问什么。本篇处理访谈记录长什么样、存在哪、谁能看。

#105 处理平台方的合法披露边界（数据在哪、谁能调）。本篇是你自己的材料在类似请求下的处境。

#117 处理第三方（保险/支付/平台）索取的 S1/S2/S3 强度。本篇补充第三种读者：审计与交易对手（#181、#182），以及它们对记录完整性的要求恰好相反——审计要"有记录"，诉讼要"少记录"，这个张力只能靠分层解决。

#170 处理跨境取证与司法协助的时间尺度。本篇不论程序，只论材料本身的形态。

3. 调查记录的六种形态与各自的寿命

同一件事会以六种形态存在，寿命与可控性差别很大。多数组织只管理了第一种。

形态典型载体寿命你还能控制吗主要风险
正式报告定稿 PDF / 交付文档长能（版本管理）结论被当作唯一事实版本
工作底稿表格、脚本输出、分析笔记中部分未验证的推断被当作结论引用
通讯记录邮件、群聊、工单评论很长弱半句话在断章后变成相反意思
会议记录纪要、白板照片、录音中部分"可能""也许"在转述中消失
系统日志访问日志、审计日志、备份取决于留存策略能（但常被遗忘）保留期短于争议期
元数据文件属性、版本历史、发送记录最长几乎不能证明"谁在什么时候知道了什么"

最后两行的组合最常见也最致命：日志早就滚动删掉了，但邮件还在。于是你能证明自己说过什么，却证明不了自己做过什么。

4. 双轨记录：事实轨与意见轨

分开不是形式主义，而是让两类材料可以走不同的路。

事实轨应当具备四个特征：可追溯到来源、可复核、不含评价性形容词、写完就不再改（有错另出更正页）。它回答"发生了什么"。

意见轨可以包含推测、倾向、未经验证的假设、责任判断。它回答"我们怎么看"。它的价值极高——反面假设往往就在这里——但它的读者应当被严格限定。

维度事实轨意见轨
内容日志、镜像观察、账号行为、时间点归因倾向、内部嫌疑、损失估计、策略取舍
写法陈述句 + 来源编号明确标注"判断""假设""待验证"
存放证据库（有访问日志）受限目录，专人保管
读者需要用它做事的人决策小圈子 + 顾问
被外部读到时通常仍是事实可能被读成"你早就怀疑某人"

一个实用判据：如果一句话里出现"显然""应该是""很可能就是"，它属于意见轨，不该出现在给外部看的事实材料里。

5. 三类读者，三种索取逻辑

记录会不会被读，取决于谁想要、依据什么要。三类读者的逻辑完全不同，应对方式也不同。

读者依据典型时间点能拒绝吗记录纪律的重点
监管 / 执法法定权力事件后数周至数月通常只能就范围与方式协商完整性、一致性、可追溯
诉讼对方 / 仲裁程序规则下的证据交换数月到数年有理由可主张，但需专业判断避免自相矛盾的不同版本
审计 / 认证 / 交易对手合同或标准要求周期性，与事件无关可以限定范围与形式记录必须存在且能解释

注意第三行的逻辑与前两行相反：前两类怕记录多，第三类怕记录少。同一套材料要同时满足"能证明我处理过"和"不多到伤自己"，唯一可行的办法就是第 4 节的分层——给审计看事实轨与流程证据，不给意见轨；而对前两类读者，则依赖事前建立的委托关系，而不是事后的整理。

6. 保护不是自动的：三个成立条件

很多组织以为"请了律师，材料就受保护了"。现实中，保护需要同时满足三个条件，缺一个就失效。

  • 条件一：委托关系真实存在且早于材料产生。 事件发生后才补一份委托合同，对之前的材料通常不起作用。
  • 条件二：材料的产生目的是获取专业意见，而不是日常运营。 同一份报告如果同时用于经营决策、对外宣传，性质会变得模糊。
  • 条件三：材料的流转范围受控。 转发给无关的第三方、贴进大群、放进共享盘，都可能被理解为放弃保护。
常见做法是否有助于保护说明
事件后请律师并让顾问向律师汇报是关键在于汇报线，不在合同抬头
把报告同时发给全员"统一认识"弱化流转范围扩大
在普通工单系统里讨论归因不构成属日常运营记录
律师参与的访谈，纪要以律师名义出具是但事实部分仍需准确
事后把已有文件"补"进律师卷宗通常无效产生时间与目的都可被质疑

以上三条是通用结构，具体是否成立、在哪个法域成立，必须由执业律师判断——本篇不提供任何规避披露的方法。

7. 可读性设计：假设每一条都会被读

把"会不会被读"作为写作时的默认前提，会产生一组很具体的习惯。

  • 不写没有依据的定性：不写"内部有人配合"，写"账号 X 在 10-14 03:12 有一次未见对应登录源的会话，尚未解释"。
  • 不用夸张词：把"完全失控""彻底沦陷"换成可核对的描述。
  • 假设与结论分开编号：假设 1、假设 2，后面写"支持/不支持/未验证"。
  • 给每个数字标口径：损失 300 万是直接支出、还是含业务中断、还是含客户补偿？口径不同，数字差十倍（#174 的统计口径是同一件事）。
  • 记录"没做的事"和原因：这在事后被读到时，是最有力的一类材料——它证明取舍是有意识的，不是遗漏。
  • 版本可追溯：每一版保留，更正另出说明页，不覆盖。

最后一条常被嫌麻烦，但它是唯一能让"前后不一致"变成"有据可查的演进而非撒谎"的机制。

8. 七种自毁式记录

写法为什么会伤到自己更好的写法
"应该是内部人干的"断章后成为偏见证据"尚未解释的账号行为见附录 B"
"已经处理干净了"若后续有残留，变成虚假陈述"截至 X 时，已知入口已关闭；未覆盖范围见第 6 节"
群聊里讨论受害者是谁个人信息扩散，且不可撤回用编号指代，名单单独存放
把推测写成表格的"结论"列表格被引用时推断变成事实结论列留空，另设"判断"页并标注置信度
删除"看起来不利"的段落版本历史仍在保留并写明为何不采纳
用同一份报告对外与对内口径被迫迁就最保守的读者对内详版 / 对外简版，事实部分一致
不留"未完成事项"结案后出现"以为做过了"交接清单第 4 项（#177）

9. 加固清单（八条）

  1. 事实轨/意见轨分库，权限不同，命名可辨。
  2. 通讯渠道收敛：事件期间指定一个渠道讨论归因，其他渠道只谈执行。
  3. 每份材料标注目的："用于内部决策""用于对外披露""用于保险核定"——目的决定形态。
  4. 日志留存期 ≥ 争议期：按最长的可能争议周期设定，而不是按存储成本设定。
  5. 版本不覆盖：更正另出页，保留旧版。
  6. 第三方材料单独登记：谁给的、什么时候、给了什么、允许怎么用。
  7. 访谈纪要双签：受访者确认事实部分，意见部分单独归档。
  8. 结案时做一次"外部读者演练"：抽三份材料，假设被陌生人读到，看是否有无法解释的句子。

10. 八条常见误解

误解实际情况
"标了机密就不能被要求交出"标记不改变性质；性质由来源与关系决定
"内部材料不算正式文件"群聊、工单、白板照片都会被当作记录
"删掉就没了"备份、对方副本、版本历史通常还在
"先写详细，以后再删减"删减痕迹本身就是问题；一开始就分层写
"请了律师所有材料都受保护"需同时满足委托真实、目的正当、流转受控
"审计要的越多越好"审计要的是能证明流程存在的最小充分集，不是全部
"两套口径更安全"事实部分必须一致，只有详略可以不同
"记录只是给现在的团队看的"它的主要读者在未来，且通常不是你选的人

12. 总结

问题一句话答案
最危险的记录是哪一类通讯记录与元数据：寿命最长、控制最弱
事实与意见要不要分开要，否则意见会跟着事实一起出门
"内部""机密"有用吗不改变可被要求交出的性质
保护怎么获得事前建立委托、限定目的、控制流转，具体由律师判断
删除可以吗不可以；且几乎总会被发现
写作的默认前提假设这条记录会被陌生人读到
审计与诉讼的要求冲突怎么办分层：给流程证据与事实轨，不给意见轨

最好的记录，是十年后被人读到时，你仍然愿意承认那是你写的。

说明

  • 本篇讨论调查记录的形态与记录纪律，不构成法律意见；特权是否成立、披露义务的范围、以及各法域的差异，须由执业律师判断。
  • 本篇不提供任何规避披露、删除证据或误导审查的方法；相反，所有建议均指向记录的准确、分层与可追溯。
  • 不涉及任何具体案件的材料，也不对任何真实事件的记录处理作事实断言。
