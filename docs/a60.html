iOS 0-click 利用技术演化史：从短信解析链到 Coruna 与 DarkSword

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Amnesty International（Pegasus 项目）、Lookout、Meta/WhatsApp 安全公告、Apple 安全发布页、CVE 情报库 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

0-click 是 iOS 攻击史上最难防御的一类能力：它不需要受害者点击、不需要授权、不需要设备解锁，甚至不需要任何一次用户交互留下线索。

本文不重复单条利用链的技术细节（那些在 #36、#37、#38、#39、#43 已分别展开），而是提供十年演化视角：

  1. iOS 的 0-click 为什么几乎全部落在解析器代码上——攻击面选择的内在逻辑
  2. 从 2016 年 Trident 到 2026 年 Coruna/DarkSword，入口位置发生了哪几次可辨识的迁移
  3. 每一次迁移背后的驱动因素：Apple 缓解措施、供应链经济学、目标画像变化
  4. 0-click 与 1-click 在成本、寿命、归因难度上的结构性差异（与 #52 的"0-click 经济学"衔接）
  5. 对防御者最有用的部分：0-click 的检测为什么先天受限，以及还能做什么

一句话预判：0-click 的演化方向不是"更隐蔽"，而是"更早"——从应用层解析器向基带、向启动阶段、向协议处理层下沉，因为只有下沉才能拿到"任何交互之前"这个时间窗口。

2. 先定义清楚：0-click 的三个层次

"0-click"这个词被用得太粗，导致防御决策经常建立在错误假设上。真实的能力分层是三级：

层次定义受害者状态代表入口防御可行性
L1 无交互不需要用户点击或确认设备正常使用中，屏幕可能亮消息推送、URL 预取、后台解析高（可关功能）
L2 无渲染甚至不需要用户打开应用/收到可见消息用户完全不知情，通知可被撤回预渲染、缩略图生成、VoIP 信令中（需关掉功能，如 #37 的预渲染）
L3 无解锁首次引导后设备从未解锁即可触发设备处于锁屏、文件系统类保护未打开基带、安全启动早期阶段、内核网络栈低（依赖硬件与固件质量）

关键区别在数据保护上：L1/L2 拿到代码执行后，仍受 Data Protection 类约束（见 #53），必须等解锁窗口才能读钥匙串与多数用户数据；L3 若发生在解锁前，攻击者面对的是 Complete 类不可读，只能等——这解释了为什么大量 0-click 链仍要配合一次交互或等待解锁：不是入口不够早，而是密钥不可得。

层次是否触发隐私指示器是否有崩溃概率用户可否作证时间锚点
L1可能有（麦克风/相机）有可（"收到过一条消息"）有（消息时间戳）
L2通常无有不可弱（消息可能已删除）
L3无低（基带独立）不可无

三条清晰规律：

  1. 每一代攻击面都比上一代"更深一层"：短信链接（应用层）→ 图像解析（框架层）→ 字体/PDF（排版层）→ 基带（硬件固件层）。
  2. 暴露方式从"用户察觉"变成"遥测察觉"：2018 年还能靠"消息被撤回"发现，2023 年只能靠内核崩溃日志与网络异常（见 #48 的四条检测流程）。
  3. 0-click 没有消失，只是变贵了：L3 能力至今仍是极少数供应方拥有；主流商业套件仍以 L1/L2 为主，把成本压在"投递一次成功一次"的可靠性工程上（#49）。

4. 为什么 iOS 的 0-click 几乎都在解析器

这是本文最重要的结构性解释，也是防御者唯一能举一反三的点。

用户数据      →  需要授权/UI →  攻击者拿不到
用户交互      →  需要点击     →  不再是 0-click
────────────────────────────────────────────
外部输入自动进入的通路 = 0-click 的全部可能入口：

  网络包 ──▶ 内核/协议栈 ──▶ 基带固件        [L3，极稀缺]
  推送  ──▶ APNs 服务 ──▶ 通知展示解析      [L1]
  消息  ──▶ 消息服务 ──▶ 富媒体预渲染        [L2]
  呼叫  ──▶ VoIP 信令 ──▶ 字体/媒体解析      [L1-L2]
  链接  ──▶ 浏览器/WebView ──▶ JSC/WebKit    [L1，需一次点击]

共同特征：这些代码必须在无用户参与的情况下，把不可信字节解析成结构。而解析器天然是"输入完全由攻击者控制、执行流由代码逻辑决定"的位置——安全缺陷的最高产形态。

属性解析器代码常规应用逻辑
输入可达性无需授权即可投递需权限/交互
代码复杂度极高（格式规范 + 历史兼容）中
内存安全大量 C/C++（#61 讨论的语言迁移进度）逐步迁移
沙箱位置BlastDoor/独立服务（#52）应用沙箱
0-click 适配度最佳不适用

由此可推一条防御优先级定律：

关闭一条"外部输入自动解析"通路，等于关掉一整类 0-click 入口；而打补丁只能关掉某一条具体漏洞。Apple 在 iOS 17 引入的"通讯安全"类功能（如附件预览过滤、链接预览关闭、iMessage 表情搜索关闭）本质上就是在削减 L2 通路的自动性（与 #52、#57 的"移除型防御优于检测型防御"一致）。

5. 入口分层对比：拿到执行之后仍然不同

即便都成功执行代码，不同入口带来的后续能力完全不同，这直接决定攻击链要写多长：

入口起始权限域是否需要沙箱逃逸是否需要内核提权解锁依赖典型链长度
WebKit（浏览器/WebView）WebContent 强沙箱必须（#40、#43）必须（#41）高4—6 环
消息预渲染（ImageIO/核心媒体）框架服务，权限略高通常需要需要中3—5 环
VoIP/呼叫信令网络服务进程视实现需要中3—5 环
字体/排版解析与消息路径重叠需要需要中4—6 环
基带独立处理器，跨核边界不适用（另需应用侧链）不适用低（可解锁前）2 环 + 跨域
启动早期/Boot ROM引导阶段不适用不适用无极短但不可持久（#34）

这就是为什么基带类 0-click 被认为最危险：它把"解锁依赖"这一项从链上移除（L3），而应用侧链再强也绕不过密钥可用性约束（#53）。

同时它也是最贵的：基带代码不公开、调试环境稀缺、失败即变砖风险，导致能做的供应方屈指可数，且几乎不可能出现在泄露工具包里。这与 #65 的供应链分层结论呼应——入口层次与供应链层级高度相关。

6. 0-click 与 1-click 的结构性对比

维度0-click1-clickCoruna/DarkSword 位置
单条漏洞采购价极高（数倍到十倍级）中两者混用（#49）
利用窗口寿命短（易被异常发现而关停）长（用户持续浏览）—
可靠性要求极苛刻（无法重试触发）宽松（可诱导重开页面）0-click 分支需大量回退路径
归因难度高（无用户证词、无 URL）低（有链接、有时间点）见 #66
目标筛选成本需精确画像避免浪费可批量撒网水坑筛选（#50）
事后取证抓手内存 + 网络浏览器历史 + 站点日志DarkSword 无痕型更难（#45）
对防御方最经济动作削减自动解析通路 + 补丁关闭 JIT/锁定模式（#57、#34）两者皆有效

一个常被误解的点：0-click 不必然比 1-click 更难检测。恰恰相反，因为它无法承受"用户点第二次"的失败，攻击者必须在真实设备上一次成功，这使得链中每一步的容错设计更复杂、崩溃概率更高、遥测异动更明显（参见 #47 关于崩溃统计异动的讨论、#51 关于内核信息泄露的必要性）。而成熟的 1-click 水坑链可以做得更安静。

7. 检测：0-click 的先天受限项与现实抓手

常规检测前提0-click 下是否成立后果
用户上报可疑链接/附件常不成立失去最早的时间锚
消息/通知可作为证据部分不成立（可被撤回、删除）服务端日志成唯一时间线
浏览器历史记录完全不适用主机侧无痕迹
设备端进程审计不成立（iOS 不提供）无批量主机遥测
网络流量必须发生成立唯一可靠抓手（#59 结论 4）
崩溃/诊断日志群体异动部分成立（取决于攻击者容错水平）滞后指标，适合回溯

现实抓手按可行性排序：

  1. 保留 90 天以上 DNS/SNI/NetFlow：0-click 与外泄都靠它（#46、#59）
  2. 消息平台服务端的元数据请求：合规路径，时效性强
  3. Apple 推送/通知配置异常：企业侧可查设备是否收到非预期推送通道
  4. MVT 类内存与备份扫描：对 Coruna 型落地驻留有效，对 DarkSword 型失效（#45、#47）
  5. 崩溃日志的群体统计：只适合版本发布后的回溯，不适合实时告警（#48）

必须承认的失效项：面对 L3（基带/解锁前）能力，上述五项全部退化。防御手段只剩硬件代际选择与固件更新节奏，这也是 #67 强调"设备代际本身就是安全决策"的原因。

不使用未知来源消息附件L1/L2行为成本高危角色
保留网络元数据（组织侧）不削减入口，但恢复可检测性存储成本企业必备

重启是被严重低估的手段：对无持久化内存驻留体系（#45），一次重启等于强制攻击者重新完成整条链。对 L1/L2 攻击者，这意味着每一次都要消耗一条仍然有效的 0-click 漏洞——把"一次性攻击成本"变成"周期性攻击成本"。这是少数以极低代价改变对手经济模型的防御动作。

10. 总结

#结论
10-click 需按"无交互/无渲染/无解锁"三层区分，三层的防御成本相差一个数量级
2iOS 的 0-click 集中于解析器，因为那是唯一"不可信字节自动进入代码"的通路
3十年演化主线是入口下沉：应用层 → 框架层 → 排版/媒体层 → 无线电与启动阶段
4解锁依赖是 0-click 的隐性天花板，基带类能力靠消除这一项体现价值
50-click 不一定更难检测：不可重试的可靠性要求反而放大崩溃与遥测异动
6削减自动解析通路与定期重启，是性价比最高的两个非补丁手段
7面对 L3 能力，现有端侧检测手段整体失效，只剩硬件代际与固件节奏

一句话总结：iOS 0-click 的历史不是"漏洞越来越隐蔽"，而是"攻击面不断下沉到用户交互之前"——因此防御的真实杠杆在于把自动解析通路和解锁窗口关小，以及用网络元数据保留期与定期重启，把一次性攻击变成持续成本。
