Coruna 与 DarkSword 及主流 iOS 攻击套件横向技术对比

编制日期：2026-10-18 数据来源：Google Project Zero、Citizen Lab、Amnesty International、Lookout、ESET、Apple 安全公告、各套件公开分析报告 性质：防御性安全研究分析（Defensive Security Research），不提供可利用代码

1. 执行摘要

单看一个攻击套件，容易把它的能力当成"特例"；把近十年的公开案例放在一起看，才能识别出结构规律：哪些环节反复成为突破口、哪些防御真正改变了攻击者行为、哪些能力演化是必然趋势。

本文对 Trident、ImageIO 链、FORCEDENTRY、Pegasus（各代）、Triangulation、Coruna、DarkSword、GHOSTBLADE、Predator 等主流 iOS 攻击套件，在 12 个技术维度上做系统横向对比，并从中提炼五条演化规律与四条防御结论。

这是本 Coruna/DarkSword 系列的收官篇——把前面所有单点分析放回历史坐标系中。

这是本表最重要的观察：iOS 15 引入 BlastDoor 之后，公开的 0-click iMessage 链显著减少，攻击重心回落到 1-click WebKit 水坑。

结论：这是架构性防御真实改变攻击者行为的实证案例。它没有"防住攻击"，但它把攻击推向了成本更高、暴露面更大的路径。

3.3 初始执行组件选择

组件类别代表优点缺点
WebKit/JSCTrident、Coruna、DarkSword、Predator攻击面巨大、漏洞密度高、可控 JS 环境受 BlastDoor 无关但也受 JIT 硬化影响
ImageIO2018 链支持 0-click（自动渲染）面较窄，被重点加固
CoreText/PDFFORCEDENTRY0-click、字体格式复杂度极高单点依赖，一个洞用完即止
VoIP 栈2019 Pegasus、FORCEDENTRY无需接听即可触发需第三方 App 配合
基带Triangulation完全 0-click、绕过主系统沙箱成本极高、漏洞极稀缺

观察：组件选择的本质是在"漏洞密度"与"交互成本"之间做权衡。WebKit 密度最高但需点击；基带可 0-click 但近乎不可得。

3.4 逃逸面演化（关键趋势）

第一代：IOKit 驱动直接漏洞（Trident 时期）
    ↓  IOKit 面被大量审计 + 收紧
第二代：Mach IPC / XPC 校验缺陷
    ↓  IPC 校验加固
第三代：媒体/后台服务进程滥用
    ↓  服务沙箱收紧
第四代：GPU / ANGLE / WebGPU（Coruna、DarkSword）  ← 当前主战场
    ↓  图形栈逐步修补中
第五代：跨层耦合（Triangulation：基带 → 内核 → SEP）  ← 能力天花板

为何 GPU 成为当前热点（详见本仓库 #52）：

判据GPU/ANGLE
沙箱必须放行✅ 渲染必需
实现复杂✅ GL/WebGPU 语义极复杂
代码年轻✅ WebGPU 新 API
C/C++ 实现✅ ANGLE 为 C++
跨权限边界✅ 用户态服务 + 内核驱动
审计密度⚠️ 相对低于 IOKit 传统面

六项全中——这是系统性攻击面评估的结果，不是运气。

3.5 持久化策略谱系

完全持久化 ─────────────────────────────────→ 完全无持久化
   ↑                          ↑                    ↑
Trident / 早期 Pegasus    Coruna(部分)        DarkSword
Triangulation(含固件)     Predator
策略代表动机代价
强持久化早期 Pegasus、Triangulation长期控制、跨重启痕迹最多、易被归因
部分持久化Coruna平衡覆盖与隐蔽仍需清除逻辑
无持久化DarkSword极致隐蔽每次需重新投递、失去实时监控

演化压力来源：Amnesty MVT（2021）等基于备份工件的检测工具成熟 ⇒ 落地文件范式的检出率系统性上升 ⇒ 攻击者向无持久化迁移。

这是一条清晰的因果链：检测工具的进步直接塑造了攻击架构的演化方向。

3.10 漏洞消耗与复用模式

模式代表说明
自研独占FORCEDENTRY、Triangulation极高投入，单点能力
多链储备 + N-day 复用Coruna用已修补但目标未更新的漏洞，节省零日
泄露链复用GHOSTBLADE直接采用其他套件泄露的 exploit
采购/供应商提供多数商业套件漏洞市场（如前 Chapeau、Cygna 等供应商）

关键事实：GHOSTBLADE 证明exploit 是可流转资产。同一组漏洞可在不同套件、不同客户之间流通。

防御含义（重要）：修补一个漏洞可同时防护多个套件、多个客户场景。这直接改变了补丁优先级计算的逻辑——不是"这个 CVE 影响几个产品"，而是"这个 CVE 出现在几条在野链条中"。

4. 演化规律提炼

规律一：防御每前进一步，攻击就迁移一个面

IOKit 加固 → 转 XPC/IPC → 转媒体服务 → 转 GPU/ANGLE → (下一个: ?)

预测下一批热点（基于"沙箱必须放行 + 实现复杂 + 审计不足"三判据）：

候选面理由
WebAssembly / 新 Web API新增能力，审计密度低
AI/模型相关子系统功能必需 + 新代码 + 复杂输入解析
网络协议解析（QUIC 等）复杂状态机，新实现
健康/传感器数据服务沙箱内可达 + 数据高价值
受信任组件内部逻辑（非绕过而是滥用）SPTM/TXM 时代必须面对

规律二：检测工具进步直接重塑攻击架构

Amnesty MVT（2021）成熟 ⇒ 落地文件范式检出率上升 ⇒ Coruna 加强清除、DarkSword 干脆不落地。

投资检测工具的价值不只是"抓到更多"，而是"迫使攻击者改变架构、增加其成本"。

规律三：0-click 是稀缺资源，1-click 是运营主力

历史上公开的 0-click 总数极少（ImageIO、FORCEDENTRY、Triangulation 等屈指可数），而绝大多数实际入侵来自 1-click 水坑。

原因：

  • 0-click 无法预探测 ⇒ 失败率高、暴露风险大
  • 0-click 漏洞极贵且不可再生
  • 1-click 可通过目标筛选达到很高有效成功率

防御含义：不要把资源全押在"防 0-click"上，减少链接点击暴露的性价比更高。

规律四：漏洞是资产，会流通、会泄露、会复用

GHOSTBLADE 复用泄露链、Coruna 大量使用 N-day ⇒ 漏洞库是可复用、可交易、可泄露的资产。

推论：一个漏洞被修补并不意味着它消失——它在旧版本设备上永远有效。"未更新的存量设备"就是攻击者的弹药库。

规律五：硬件强制正在改写规则

时代攻击模型
2016–2020泄露 + 任意写 ≈ 提权成功
2020–2023需同时突破 PAC + KTRR/PPL
2024+ (A17+)SPTM/TXM 使内核写不再足够，需攻受信任组件本身

这是最重要的结构性变化：攻击从"绕过软件检查"转向"寻找被信任组件的缺陷"。GPU 驱动、固件、协处理器成为必争之地。

6. 防御结论（从横向对比中得出）

结论 1：攻击链的每一环都有大量套件卡在同一处

环节卡点频率防御投资回报
投递（水坑触达）高（依赖用户点击）中（教育 + 站点加固）
初始 RCE（JSC/解析器）极高极高（锁定模式禁 JIT）
逃逸（GPU/IPC）高高（禁 WebGPU、优先修补驱动）
提权（PAC/KTRR/SPTM）中高高（硬件升级带来质变）
数据提取（解锁窗口）极高（无人绕过）高（重启 + 少存秘密 + 硬件密钥）
外传（网络）极高（必然暴露）最高（网络侧日志是唯一通用手段）

结论 2：没有任何套件同时做到"广覆盖 + 无痕 + 强能力"

这是防御者可以利用的结构性矛盾：

想要必须放弃
覆盖老版本（Coruna）接受落地与痕迹
极致隐蔽（DarkSword）放弃长期监控与批量数据
真 0-click（Triangulation）付出不可持续的漏洞成本

推论：防御策略应当迫使攻击者做出不利取舍。例如"全员每日重启"使无持久化套件失去价值；"全员快速升级"使多链套件失去目标；"保留网络日志"使隐蔽性投资失效。

结论 3：可被检测的永远不是"最聪明的环节"，而是"必须与外界交互的环节"

设备内的一切都可被清除去，但投递要触达公网、外传要穿越网络边界。这两点是永恒暴露面。

结论 4：学术与公民社会研究是整个防御体系的实际主力

发现者揭露的套件
Citizen LabTrident、Coruna、Triangulation 等
Google Project ZeroDarkSword、多条链技术细节
Amnesty Security LabPegasus 项目、MVT 工具
WhatsApp/MetaFORCEDENTRY
Lookout / ESET / 商业厂商Predator、多个样本

Apple 自身并未及时发现多数在野利用。 这提示任何组织：不要依赖厂商单方面保护，独立情报源是必要补充。

8. 总结

#结论
1iOS 攻击史是一部攻击面迁移史：IOKit → IPC → 媒体服务 → GPU/ANGLE → 跨层（基带/SEP）
2BlastDoor 与 MVT 是改变攻击者行为的两个架构性事件——一个抬高 0-click 成本，一个抬高落地成本
3Coruna 代表"广度派"（多链、平台、长期运营），DarkSword 代表"深度派"（精工、无痕、短期突击），二者是同一权衡的两端
41-click 水坑是当前绝对主力，防御投资不应只押注 0-click
5漏洞是可流通、可泄露、可复用的资产——存量未更新设备 = 攻击者弹药库
6SPTM/TXM 时代要求攻击者转向"被信任组件本身的缺陷"，攻防重心正在向硬件与固件层迁移
7网络侧是唯一对所有套件都有效的检测面——攻击者无法清除你的 DNS 日志
8独立研究（Citizen Lab / Project Zero / Amnesty）是实际主力检出来源，组织应具备或对接这类情报能力
9攻击者无法同时做到广覆盖、无痕与强能力——防御的价值在于迫使对方做不利取舍
10修补速度是最被低估的防御能力：所有多链套件的战斗力都来自目标的更新延迟

收官结语：

把九套攻击体系放在同一张表上，看到的不是九个不同的故事，而是同一个权衡在九个时点上的不同解。 iOS 的防御纵深每加固一层，攻击者就向"下一个合法可达、尚未被审计的组件"迁移一步。 因此真正有效的长期防御不是"补更多洞"，而是缩短补丁部署时延、收紧功能必需的暴露通道、并投资那些攻击者无法清除的检测面（网络与情报）。
